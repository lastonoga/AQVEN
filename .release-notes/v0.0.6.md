# AQVEN 0.0.6

**Alpha.** 0.0.x means the API and the project file formats can still change between minor
versions. `aqven` pins `aqven-llm==0.0.6`, so the two packages move together.

Same day as 0.0.5, one thing added: OpenCode. A project created by `aqven new` already handed
Claude Code its server through `.mcp.json` and Codex through `.codex/config.toml`. OpenCode reads
neither — it takes MCP servers from the `mcp` key of a project `opencode.json` — so it started
with no `aqven` tools at all. Now that file is written for it too.

## Highlights

- **`opencode.json` is generated** — by `aqven new` and by `aqven skills sync`, and checked by
  `aqven skills status`, next to `.mcp.json` and `.codex/config.toml` (`161f025`)
- **One JSON writer, three clients** — the MCP writer is now a single parameterized strategy, so
  OpenCode inherits the merge rules Claude Code had: your other keys and other servers survive a
  sync, an `aqven` server you edited yourself is kept and reported instead of overwritten, and a
  file JSON cannot parse (JSONC with comments) is left untouched (`161f025`)
- **Nothing to configure for the rest** — `AGENTS.md`, `CLAUDE.md` and the skills in
  `.agents/skills/` reach OpenCode natively from the project root; no symlinks, no paths into
  another project's folder (`161f025`)
- **Docs** — the agent setup page gained an OpenCode column and registration section, including
  the `cwd` rule for a session started above the project root and `opencode debug config` as the
  way to see what OpenCode merged; the FAQ in both READMEs and on the landing page names OpenCode
  (`161f025`)

## Install

```sh
uv tool install aqven==0.0.6
```

Python 3.14 is required; `uv` fetches it. In an existing project: `uv add "aqven==0.0.6"`, then
`uv run aqven skills sync <package>` to have `opencode.json` written into it.

## Breaking changes

None found in `v0.0.5..v0.0.6`. Studio's chat still runs Claude Code or Codex; OpenCode connects
from your own terminal, not as a chat backend.

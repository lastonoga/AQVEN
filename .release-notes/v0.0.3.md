# AQVEN 0.0.3

**Alpha.** The biggest change since the project started, and it removed a public kind — read
"Breaking changes" before upgrading a 0.0.2 project.

77 commits over two days built the Research layer: run a series of experiment attempts, get
statistics and findings, and watch it live in Studio.

## Highlights

- **Series engine on DBOS** — a series of experiment attempts, statistics computed with scipy, findings written as project files, driven over REST, MCP and the new `aqven series` command (`8e385ea`)
- **Experiments** — one factor per experiment: an agent, a prompt, a use or a flow (`cd859b2`), grouped, marked new, archived, ordered by last activity (`1c83f5c`)
- **Agent skills shipped in the engine** and managed with `aqven skills` (`06f5811`)
- **Rate limits that are actually respected** — per-model lanes with `auto`, `fixed` and `fail` strategies (`49e0f8c`), a probe attempt first, and one requeue of a rate-limited attempt (`ba46199`)
- **Spend control** — the cap lives in `aqven.yaml`, is edited in Studio Settings (`63c2bf6`), and a series paused near the cap can be continued or stopped from Studio (`1e2dcec`)
- **Outcome policies** — `fail | retry | fallback` per agent, with an error outcome (`1d07971`); `on_item_error` decisions and recovered items are visible on the run page (`0332c3d`, `9f77aed`, `5271e74`)
- **Dataset media as project files** — the blob store is a cache now (`193481f`)
- **Live research updates** on the project event channel, one Studio stream with targeted refresh (`5537e7d`)
- **Studio rebuilt around Flow and Research modes** (`dd78313`, `a7f1cf3`, `9bf6783`, `d512ac0`), first-run settings with editable keys (`695c1b7`)
- **Cost is honest** — actual call cost falls back to the provider price table, unknown is never reported as `0` (`f2a27bb`); no estimate before a series starts (`0b0af5b`)
- **Dev console** with run/step lines, noise filters, verbosity flags and a JSONL log (`c5294ed`); **hang diagnostics** — SIGUSR1 stack dumps and an event-loop stall watchdog in `aqven dev` / `aqven serve` (`dd32a02`)
- **Landing navbar shows the latest release and its date** (`2aa6a36`); five use cases lead the landing page with a new `/use-cases/` page (`647eceb`)
- Fixes for cross-project module reloads (`e89c5e7`), the working copy never being compiled for execution detail (`81416a7`), and a bounded DBOS executor pool (`dda9d81`)

## Install

```sh
uv tool install aqven==0.0.3
```

Python 3.14 is required; `uv` fetches it. In an existing project: `uv add "aqven==0.0.3"`
(this pulls in `scipy` and `numpy`).

## Breaking changes

- **The `Eval` kind, the eval runner, the gate, `optimize` and dataset batches are removed** (`686d360`). Research with experiments and series replaces them.
- **CLI**: `aqven eval` and `aqven optimize` are gone; `aqven series`, `aqven datasets`, `aqven skills` and `aqven hook` are new (diff of `packages/aqven/src/aqven/cli.py` between `v0.0.2` and `v0.0.3`).
- The hard-coded model capability table is gone and the framework no longer gates on model capabilities — strict and image output are what the flow sets (`4f8a8a3`, `a7b3702`).

# AQVEN 0.0.3

**Alpha.** The biggest change since the project started, and it removed a public kind — read
"Breaking changes" before upgrading a 0.0.2 project.

126 commits over two days built the Research layer: run a series of experiment attempts, get
statistics and findings, and watch it live in Studio.

## Highlights

- **Series engine on DBOS** — a series of experiment attempts, statistics computed with scipy, findings written as project files, driven over REST, MCP and the new `aqven series` command (`8a1bb3c`)
- **Experiments** — one factor per experiment: an agent, a prompt, a use or a flow (`c983470`), grouped, marked new, archived, ordered by last activity (`be15df9`)
- **Agent skills shipped in the engine** and managed with `aqven skills` (`6905a3b`)
- **Rate limits that are actually respected** — per-model lanes with `auto`, `fixed` and `fail` strategies (`537d3a1`), a probe attempt first, and one requeue of a rate-limited attempt (`18151c7`)
- **Spend control** — the cap lives in `aqven.yaml`, is edited in Studio Settings (`18b5acc`), and a series paused near the cap can be continued or stopped from Studio (`585bcb9`)
- **Outcome policies** — `fail | retry | fallback` per agent, with an error outcome (`0271260`); `on_item_error` decisions and recovered items are visible on the run page (`b9a2b18`, `5043d3a`, `0020b86`)
- **Dataset media as project files** — the blob store is a cache now (`130512d`)
- **Live research updates** on the project event channel, one Studio stream with targeted refresh (`8ae8b6f`)
- **Studio rebuilt around Flow and Research modes** (`09d42d8`, `fc95928`, `3674392`, `a6cab57`), first-run settings with editable keys (`3f48ed0`)
- **Cost is honest** — actual call cost falls back to the provider price table, unknown is never reported as `0` (`72a8425`); no estimate before a series starts (`1fdcc23`)
- **Dev console** with run/step lines, noise filters, verbosity flags and a JSONL log (`918a0b4`); **hang diagnostics** — SIGUSR1 stack dumps and an event-loop stall watchdog in `aqven dev` / `aqven serve` (`a592aec`)
- Fixes for cross-project module reloads (`02a8ba7`), the working copy never being compiled for execution detail (`1d9df75`), and a bounded DBOS executor pool (`dd00d4d`)

## Install

```sh
uv tool install aqven==0.0.3
```

Python 3.14 is required; `uv` fetches it. In an existing project: `uv add "aqven==0.0.3"`
(this pulls in `scipy` and `numpy`).

## Breaking changes

- **The `Eval` kind, the eval runner, the gate, `optimize` and dataset batches are removed** (`7fa865c`). Research with experiments and series replaces them.
- **CLI**: `aqven eval` and `aqven optimize` are gone; `aqven series`, `aqven datasets`, `aqven skills` and `aqven hook` are new (diff of `packages/aqven/src/aqven/cli.py` between `v0.0.2` and `v0.0.3`).
- The hard-coded model capability table is gone and the framework no longer gates on model capabilities — strict and image output are what the flow sets (`87d149d`, `d1b65f1`).

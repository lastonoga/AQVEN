# Платформа надёжных AI-воркфлоу — проектная документация

Комплект описывает, **как именно** мы строим платформу, в которой Claude или любой MCP-агент
собирает, запускает, отлаживает и в цикле чинит типизированные многошаговые LLM-воркфлоу,
а человек видит и правит всё визуально.

Исходная постановка задачи — [00-source-spec.ru.md](00-source-spec.ru.md). Она остаётся неизменной:
это то, что хотел заказчик. Всё остальное в комплекте — ответ на вопрос «как это сделать
на живых библиотеках сентября 2026 года».

## Как это писалось

Ни один факт в комплекте не взят по памяти. Версии, сигнатуры и ограничения проверялись
метаданными PyPI JSON и `npm view`, установкой пакетов, чтением исходников Python-пакетов, `.d.ts`,
встроенной документации пакетов и официальных доков, а часть — запуском кода. Черновики исследования
лежат в [research/](research/) — 46 заметок, около 1,9 млн символов, с пометками `UNVERIFIED:` там,
где подтверждения не нашлось. Пробы Python-стека выполнялись вне репозитория 2026-09-16, их результаты
приведены в research/py-*.md и research/studio-api-inventory.md. Часть проб шла на CPython 3.12.4, а движок
фиксирует 3.14: повтор на 3.14.7 — в спайке фазы 0 ([ADR-0025](adr/0025-python-engine.md), открытый вопрос 20).

Исследование опровергло несколько положений исходной спеки. Все опровержения собраны
в [DECISIONS.md](DECISIONS.md) и разобраны в ADR. Отклонения от спеки при переходе на Python
(VoltAgent, экспорт) — [ADR-0025](adr/0025-python-engine.md) §7.

## Карта комплекта

**Переход движка на Python.** Решение владельца от 2026-09-16 оформлено в ADR-0025…ADR-0029: движок —
Python на Pydantic AI и DBOS, описание воркфлоу — YAML, студия остаётся на TypeScript. Чистка комплекта
сделана частично: ✅ — документ вычищен 2026-09-16; ⚠️ — не вычищен или вычищен не до конца, пометка называет ADR,
которые его меняют; при расхождении прав ADR. Оставшаяся чистка — L-36 в [99](99-open-questions.md).
Документ без пометки тоже может упоминать VoltAgent, `ai@6`, Zod или pg-boss — эти места устарели
по [ADR-0025](adr/0025-python-engine.md).

## Что зафиксировано жёстко

Полностью — в [DECISIONS.md](DECISIONS.md). Коротко:

- Определения воркфлоу — **файлы в репозитории проекта**, база — перестраиваемый индекс, история — git
  ([ADR-0017](adr/0017-files-as-source-of-truth.md), детали — [files-first/](files-first/)). Формат — YAML поверх
  Pydantic-моделей описания, код шагов — функции Python по ссылке `module:function`, IR — производный артефакт
  сборки, в дерево не коммитится ([ADR-0026](adr/0026-yaml-spec-and-code-refs.md)).
- Движок — **CPython 3.14**, вызовы моделей — **Pydantic AI 2.43.0**, надёжное исполнение — **DBOS 2.31.1**
  (SQLite локально, PostgreSQL 18 в проде), HTTP-клиент — только **httpx2**; `apps/studio` — TypeScript 6.0.3
  ([ADR-0025](adr/0025-python-engine.md)).
- Своё — ядро доверия: IR, компилятор, исполнитель IR и исполнители узлов с гарантиями, реестры, MCP-контракт,
  политика гейтов. Остальное берём готовым: чекпоинт шага, восстановление и fork прогона, очереди (DBOS), вызов
  модели с проверкой выхода и повтором, бюджеты (Pydantic AI), прогонщик экспериментов (pydantic-evals),
  статистические тесты (scipy, statsmodels), хранилище трасс и датасетов (Langfuse), HTTP, SSE и MCP (FastAPI, mcp),
  канвас, таблицы.
- Экспорт в другие фреймворки отменён: интеграция — вызов воркфлоу по HTTP и MCP (`aqven serve`) и импорт
  модуля-wheel в Python-проект ([ADR-0025](adr/0025-python-engine.md) §7).
- Имена MCP-тулов — только `snake_case`: точки из §13.1 спеки невалидны.
- Одной strict-схемы на всех провайдеров не существует: схема компилируется под профиль
  пары (IR-схема × провайдер).
- Исходов вызова модели три: `ok` / `refusal` / `truncated`. Обрезанный ответ чинить запрещено.
- Мультитенантность в данных с первого дня, продуктовая поверхность v1 — одно-тенантная.

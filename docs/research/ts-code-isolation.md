# Исполнение пользовательского TypeScript: синтез и рантайм

> Вопрос среза: чем загружать TS-определения на фазе синтеза, чем исполнять тела `code`/`tool`-узлов в прогоне, и какая изоляция реально нужна при нашем профиле угроз.

Два разных момента исполнения, и путать их нельзя:

| | Синтез (build) | Рантайм (run) |
|---|---|---|
| Что исполняется | файлы определений целиком: импорты, циклы, генерация узлов | тела `code`-узлов (чистые) и `tool`-узлов (эффекты) |
| Чем кончается | IR (`flow-spec.normal.json`) | значение выхода узла |
| Главный риск | недетерминизм попадает в IR | бесконечный цикл, утечка, скрытый эффект |
| Блокер из 10-runtime.md §2 | — | **план — сериализуемый список шагов без замыканий, исполнение файлов не читает вовсе** |

Последняя строка — главный факт среза. Снимок плана в базе не может хранить замыкание. Значит тело
`code`-узла обязано быть **текстом** (или байткодом), извлечённым на синтезе, а не функцией из модуля.

## 1. Сравнение механизмов изоляции

| Механизм | Реальная изоляция | Лимит памяти | Лимит времени | Запрет сети | Старт | TS | Зрелость 2026 |
|---|---|---|---|---|---|---|---|
| `node:vm` | **нет** (докой прямо сказано) | нет | только синхронный код | по умолчанию `fetch` нет, но восстанавливается из `constructor.constructor` | ~0.26 мс | нет | стабилен как примитив, не как защита |
| vm2 | нет, CVSS 9.8 в январе 2026 | нет | частично | нет | дёшево | нет | **исключён** |
| isolated-vm | да, отдельный V8 Isolate | да (`memoryLimit`) | да (`timeout`, включая async через `applySync`) | да, хост ничего не отдаёт | ~единицы мс | нет | maintenance mode + `--no-node-snapshot` + CVE 2026 |
| worker_threads | **нет** (тот же процесс, `require`/`fs`/`net` доступны), но ресурсы изолированы | **да**, убивает поток | **да**, `terminate()` рвёт цикл | нет сам по себе | ~9.5 мс | через loader | ядро Node, максимальная зрелость |
| Процесс + `LocalSandbox` / Deno | **да**, уровень ОС / флаги разрешений | да | внешний `kill` | **да** (`allowNetwork:false`, `--deny-net`) | десятки-сотни мс | любой | у нас уже принят для агентов |
| QuickJS (wasm) | да, wasm-граница | `setMemoryLimit` | `setInterruptHandler` | нет API вообще | ~мс | нет | ниша, ~×30-50 медленнее V8 (UNVERIFIED: точный множитель) |

## 2. Наш профиль угроз честно

Код пишет владелец и его агент. Злоумышленника внутри `code`-узла нет. Значит защищаемся **не от
побега, а от ошибки**. Требования из [03-core-language.md §2.4, §5](../03-core-language.md):
`pure(code)` — статический анализ, запрет недетерминизма, сети, глобалов.

| Риск | Реален у нас | Чем закрывается |
|---|---|---|
| Бесконечный цикл агентского кода | да, самый частый | `worker.terminate()` |
| Утечка памяти, съевшая процесс | да | `resourceLimits.maxOldGenerationSizeMb` |
| Недетерминизм (`Date.now`, `Math.random`) | да, ломает реплей | подмена глобалов + запрет анализатором |
| Целенаправленный побег из песочницы | нет | не платим за это |

**Минимально достаточный механизм: worker_threads + пустой `node:vm`-контекст внутри воркера.**
Воркер даёт лимит памяти и убийство зависшего цикла; `vm` внутри воркера даёт пустой глобал без
`require`/`process`/`fetch`. Вместе — ровно четыре нужных свойства, без цены isolated-vm (нативный
аддон, maintenance mode, `--no-node-snapshot`) и без цены процесса на узел.

```ts
interface CodeSandbox { run(body: string, input: unknown, limits: Limits): Promise<unknown> }
```

Один пул воркеров на процесс, ~9.5 мс амортизируются; внутри воркера контексты по 0.26 мс.
`InlineSandbox` (`vm` без воркера) — для тестов, за тем же интерфейсом (Strategy). Апгрейд до
isolated-vm или процесса — ещё одна реализация того же интерфейса, если появится чужой код.

## 3. Загрузка TS на синтезе

| Инструмент | Что делает | Замер | Когда брать |
|---|---|---|---|
| esbuild 0.28.2 | бандлит дерево определений в один CJS | **41 мс / 50 файлов** | CLI-компиляция, CI, продовый билд плана |
| jiti 2.7.0 | require-хук с файловым кешем | 183 мс холодно, **50 мс** тепло | hot reload канваса |
| tsx 4.23.13 | esbuild-loader для процесса | ~900 мс на холодный процесс | dev-запуск, `tsx watch` |
| @swc/core 1.16.2 | нативный трансформер | сопоставим с esbuild | если понадобятся legacy-декораторы |
| Bun / Deno | нативный TS | — | отдельный рантайм, мимо нашей оси версий |

Все **стирают типы, а не проверяют их**: проверка — отдельный проход `tsc --noEmit` (6.0.3 по
[DECISIONS.md](../DECISIONS.md)), не на горячем пути канваса. Лучший devx для канваса даёт jiti:
hot reload одного файла без пересборки дерева, 50 мс на круг. Для выпуска — esbuild: один артефакт.

## 4. Детерминизм синтеза

Синтез — это тоже исполнение кода, и его недетерминизм попадает прямо в IR: `Date.now()` в имени
узла даст новый `spec_hash` на каждый билд, и семантический дифф версий ([18](../18-export-and-conformance.md))
превратится в шум. Поэтому синтез исполняется в том же воркере, с подменёнными глобалами:

Подменяем в контексте синтеза `Date` (фиксированная эпоха), `Math.random` и `process.env`
(read-only allowlist) — бросают `NondeterminismError`. Три уровня, каждый ловит своё:

| Уровень | Что ловит | Цена ошибки для автора |
|---|---|---|
| Статический анализ AST на синтезе (уже есть для `code`, [03 §2.4](../03-core-language.md)) | прямые `Date.now`, `Math.random`, `process.env`, `import` вне списка | ошибка компиляции с позицией в файле |
| Подмена глобалов в контексте | то, что пришло косвенно (через зависимость, `globalThis['Ma'+'th']`) | `NondeterminismError` с именем API |
| Двойной прогон синтеза и сравнение `spec_hash` | всё остальное, включая порядок обхода `Map`/`Set` и I/O | «синтез недетерминирован» в CI |

Третий уровень — единственный честный детектор и самый дешёвый: синтез стоит 41 мс, прогнать дважды
не жалко. То же правило уже применяется у нас к канонизации YAML ([04 §6.2](../04-ir-schema.md),
«второй и третий проход дают идентичные байты») — просто на шаг раньше.

## 5. Хеширование тела `code`-узла

Хешировать исходник нельзя: переформатирование сменит `release_hash` и заставит перевыпускать релиз
без изменения поведения. Хешировать AST дорого и привязывает хеш к версии парсера. Проверенный
ответ — **хешировать нормализованный вывод esbuild**, и таких хеша два:

| Хеш | Как считается | Устойчив к | Чувствителен к | Куда идёт |
|---|---|---|---|---|
| `body_hash` | `sha256(esbuild.transform(src, {loader:'ts', minifyWhitespace:true}))` | форматирование, отступы, точки с запятой, типы (стираются) | переименование переменных | `spec_hash` → `release_hash` |
| «alpha»-хеш | то же с `minify:true` (манглинг имён) | ещё и переименование локальных переменных | только поведение | детект переименования и семантический дифф ([04 §7](../04-ir-schema.md)) |

Проверено на probe:

```
minifyWhitespace  "const f = (x: number) => {\n  return x + 1;\n}"  ->  b6efb1dffd
minifyWhitespace  "const f=(x:number)=>{return x+1}"                ->  b6efb1dffd
minifyWhitespace  переименование f->g, x->y                          ->  41ea823bff
minify            переименование f->g, x->y                          ->  e3a5d15c16 (равен исходному)
```

Два следствия: (1) **версия esbuild становится частью хеш-функции** — пинится и входит в домен
`wf/node-body/v1+esbuild@0.28.2`, апгрейд = миграция хешей, как у канонизатора; (2) типы стираются,
поэтому смена сигнатуры без смены тела `body_hash` не двигает — и это верно, контракт узла живёт в
IR (`in`/`out` из реестра типов), а не в TS-аннотации.

## 6. VoltAgent-специфика

| Ограничение | Откуда | Что из этого следует |
|---|---|---|
| План — сериализуемый список шагов **без замыканий**, «исполнение файлов не читает вовсе» | [10 §2](../10-runtime.md) | тело `code` в снимке — строка, а не функция; синтез обязан её извлечь |
| Чекпоинт пишется после каждого шага, лежит в `metadata.__voltagent_restart_checkpoint` | [DECISIONS.md](../DECISIONS.md) | вход/выход `code`-узла обязан быть JSON-сериализуем; `Map`, `Date`, класс не переживут рестарт |
| «Ни один узел ядра не превращается в несколько шагов без нужды» | [10 §2](../10-runtime.md) | `code` не заводит отдельный шаг под песочницу: пул воркеров живёт на уровне процесса |
| `LocalSandbox` уже принят, при отсутствии провайдера **бросает** | [19 §9](../19-security-and-policies.md) | тот же fail-closed переносим на воркер: нет `resourceLimits` — не стартуем |
| Весь Workspace API помечен EXPERIMENTAL, ходим через фасад `@wf/sandbox` | [19 §9](../19-security-and-policies.md) | `CodeSandbox` кладём за тот же фасад, одна точка замены |

## Вывод для нас

**Берём:**
- `worker_threads` + `node:vm` внутри воркера как единственную реализацию `CodeSandbox`. Обосновано
  профилем: нужны таймаут, лимит памяти, пустой глобал, детерминизм — все четыре закрыты, все
  проверены probe'ом. Цена: ~9.5 мс на воркер (амортизируется пулом), 0.26 мс на контекст.
- esbuild 0.28.2 для выпуска (41 мс на 50 файлов), jiti 2.7.0 для hot reload канваса (50 мс тепло).
- `body_hash = sha256(esbuild minifyWhitespace)` с версией esbuild в домене хеша; второй хеш на
  `minify:true` — для детекта переименования, не для `release_hash`.
- Двойной прогон синтеза со сравнением `spec_hash` в CI как детектор недетерминизма.
- Подмена `Date`/`Math.random`/`process.env` в контексте синтеза — второй эшелон после AST-анализа.
- Фасад `@wf/sandbox` из [19 §9](../19-security-and-policies.md) расширяем интерфейсом `CodeSandbox`.

**Не берём:**
- **vm2** — CVE-2026-22709 CVSS 9.8, >20 побегов за историю: поток advisories в SBOM без выгоды.
- **isolated-vm** — нативный аддон, maintenance mode и `--no-node-snapshot` на весь процесс ради
  защиты от угрозы, которой у нас нет. Держим как вторую реализацию интерфейса на случай чужого кода.
- **QuickJS/wasm** — изоляция отличная, но нет TS и нет Node API для `tool`-узлов.
- **Deno/Bun как песочница** — вторая инсталляция рантайма мимо оси версий [DECISIONS](../DECISIONS.md).
- **Голый `node:vm` без воркера** — ни лимита памяти, ни убийства цикла, ни таймаута на async.

**Что это меняет в уже принятом:** ничего не ломает. Тело `code`-узла и сегодня обязано быть текстом
с `body_hash` ([04 §4.2](../04-ir-schema.md)) — TypeScript-авторинг лишь меняет, откуда этот текст
берётся: не из YAML-скаляра, а из извлечённого на синтезе исходника функции. `release_hash`,
семантический дифф и конформанс-экспорт работают поверх ровно того же IR.

**Открытый вопрос:** как синтез извлекает текст тела функции из TS-модуля — AST-экстракция по месту
вызова хелпера (`code({ fn })` → исходник `fn`) или отдельный файл на узел. Первый ломается на
замыканиях над переменными модуля, второй многословен. UNVERIFIED: обе схемы не проверены probe'ом.

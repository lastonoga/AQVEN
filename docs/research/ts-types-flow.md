# Срез 6: типы TypeScript как носитель контрактов воркфлоу

> Вопрос среза: что из «топология — данные, узлы — контракты» реально держится системой типов TS, а что остаётся работой компилятора над IR.

## Что нашли

Всё в таблице проверено запуском в `scratchpad/probe-ts` (TypeScript 6.0.3, `@voltagent/core` 2.10.0, zod 4.6.2, `skipLibCheck: true`, `strict: true`, Node 20.19, M-серия).

Официальные рекомендации по производительности: интерфейсы вместо пересечений, подтипы вместо union «больше дюжины элементов», именованные типы вместо анонимных выводов, аннотации возвращаемых типов, `skipLibCheck`, `isolatedModules`, 5–20 проектов в workspace — [TypeScript Wiki: Performance](https://github.com/microsoft/TypeScript/wiki/Performance). Важная поправка по нашему замеру: предупреждение про union относится к union **объектных** типов; union строковых литералов на 600 членов стоит копейки.

## 1. Сквозной вывод: работает на прямой, вырождается на развилке

Паттерн один и тот же у всех: generic-билдер, у которого последний тип-параметр — накопитель. `createWorkflowChain` — ровно он, и `CURRENT_DATA` переписывается каждым шагом без единой ручной аннотации:

```ts
const w = createWorkflowChain({ id: "p", name: "p", input: z.object({ a: z.string() }), result: z.object({ n: z.number() }) })
  .andThen({ id: "s1", execute: async ({ data }) => ({ n: data.a.length }) })
  .andThen({ id: "s2", execute: async ({ data }) => ({ label: data.n > 3 ? "big" : "small" }) })
  .toWorkflow();
```

На `s2` `data` уже `{ n: number }` — вывод сквозной. Ломается это в трёх местах, и все три — ровно наши узлы:

| Конструкция | Что становится с типом | Следствие для нас |
|---|---|---|
| `andWhen` (условный шаг) | `NEW_DATA \| CURRENT_DATA` | следующий `andThen` обязан разобрать union; без дискриминанта разбор невозможен |
| `andBranch` | `Array<NEW_DATA \| undefined>` — sparse-массив | идентичность ветки теряется полностью: «какая ветка сработала» типом не выражено |
| `andAll` / `andRace` | вывод из кортежа шагов | требует `as const`-кортежа; любой динамический массив шагов даёт `NEW_DATA[]` и всё |

Вывод по пункту: **линейная цепочка типизируется бесплатно, граф — нет**. Наш `join`/`merge` обязан быть узлом с явным объявленным дискриминированным union (это уже требование [05-type-system.md §1.1](../05-type-system.md), «union с обязательным дискриминантом → `z.discriminatedUnion`»), иначе TS отдаёт `T | undefined`-кашу. Это аргумент не против TypeScript, а за то, что топология остаётся данными: билдер выражает порядок, но не доминирование.

UNVERIFIED: возвращаемый тип `.toWorkflow()` — сигнатуру не смотрели. Если он стирает `CURRENT_DATA` до `Workflow<INPUT, RESULT>`, то `.d.ts` пакета остаётся маленьким и граница файлов дешёвая; если нет — обязательна ручная аннотация экспорта (см. §5).

## 2. Zod 4 как единственный источник: подтверждено, ничего не ломаем

[05-type-system.md](../05-type-system.md) уже фиксирует ровно эту схему, и замеры её подтверждают: одно объявление → `z.infer` (TS-тип), `.parse` (рантайм), `z.toJSONSchema` (провайдер), обход декларации (текст промта). Переход на TypeScript-авторинг **ничего здесь не меняет** — он только убирает YAML-обёртку вокруг того же `TypeDecl`.

| Потребитель | Механизм | Статус |
|---|---|---|
| Тип IR / тип шага | `z.infer<typeof Decl.schema>` | работает, ноль дополнительного кода |
| JSON Schema провайдера | `z.toJSONSchema` + профиль через `override` | решено в 05, профили `openai-strict` / `anthropic-strict` |
| Форма для человека | та же декларация + `views` | решено в 05 |
| Текст промта | генератор обходит `fields`/`valueDescriptions` | решено в 05 |

Единственное, что добавляет TS-авторинг: `satisfies`. Он даёт проверку декларации против контракта **без** расширения выведенного типа — это то, чего не даёт ни аннотация (`: TypeDecl` схлопывает литералы), ни голый литерал (не проверяется):

```ts
export const BeachEntry = {
  id: "BeachEntry",
  description: "Тип входа в море",
  values: { sand: "Песчаный вход", pontoon: "Понтон", rocks: "Камни или риф" },
} as const satisfies EnumDecl;

export type BeachEntry = keyof typeof BeachEntry.values;
```

Branded-типы (`TypeId`, `ViewName` через `unique symbol`) в 05 уже есть — они ловят перепутанные идентификаторы, но **не** ловят несуществующий идентификатор: `allowedSet: "dynamic"` проверяется только рантаймом. Это первая честная граница иллюзии.

## 3. Реестр типов в TS: три требования и как они закрываются

| Требование | Механизм | Цена |
|---|---|---|
| (а) описания enum попадают в промт | `values` — обычный объект `Record<value, description>`, генератор `{{ output_format }}` читает его как данные | ноль; это уже так в 05 |
| (б) компилятор проверяет полноту `switch` | `keyof typeof values` + ветка `default: { const _e: never = v; return _e; }` | подтверждено ошибкой `TS2322 … not assignable to type 'never'`; 600 кейсов = 0.03 s |
| (в) агент добавляет значение enum программно | значения живут в объектном литерале, а не в TS-`enum` и не в union-алиасе → правка через `ts-morph` 28.0.0 (MIT) или обычный AST-патч | после правки **все** неполные `switch` в проекте падают компиляцией — это фича, а не регресс |

TS-`enum` для этого не годится: он вводит рантайм-объект и номинальную типизацию, не даёт места под описание значения и хуже правится AST. Оставляем объектный литерал + `z.enum(Object.keys(...))` — проверено, `z.toJSONSchema` даёт корректный `{"type":"string","enum":[…]}`.

## 4. Честная граница: типы TS против правил компилятора над IR

| Правило | Выразимо в TS? | Комментарий |
|---|---|---|
| Тип слота = тип источника (R-T\*) | **да**, вдоль цепочки | структурная совместимость; на развилке — только после явного narrowing |
| Полнота `switch` по enum (R-41) | **да** | через `never`, замерено |
| Наличие обязательного поля / nullable | **да** | `nullable` вместо `.optional()` — правило 05 держится и типом |
| Кардинальность «один / много» | **частично** | `T` vs `T[]` — да; «ровно N», `minItems`/`maxItems` — нет (кортежи ломаются на динамике) |
| Доминирование (источник доминирует потребителя, R-44/R-C6) | **нет** | билдер даёт линейный порядок вызовов, а не доминирование в графе; обратные рёбра и `andDoWhile` типы не видят вовсе |
| Ацикличность графа контекста (R-C6) | **иллюзия** | нельзя сослаться на ещё не созданный шаг — но это ограничение API, а не типа; через id-строку цикл строится свободно |
| Бюджет токенов и окно профиля (R-C7, R-T9) | **нет** | значение, а не тип |
| Совпадение значений enum в тексте промта с реестром (R-T7, R-T8) | **нет** | текст — строка; ловится только анализом шаблона |
| Существование ID в `allowed_set` | **нет** | branded-тип даёт идентичность множества, не членство в нём |

Итог границы: **типы ловят локальные контракты «выход→вход», компилятор над IR ловит всё глобальное — достижимость, доминирование, бюджеты, соответствие текста реестру.** Если типы объявить достаточным доказательством, мы потеряем ровно те правила, ради которых [07-compiler.md](../07-compiler.md) и существует. Типы — первый фильтр в IDE, а не замена проходам компилятора.

## 5. Производительность тайпчекера: измерено, угрозы нет

Генератор `gen.mjs` строил N файлов по D шагов `.andThen` каждый, полный `tsc --extendedDiagnostics`.

| Конфигурация | Шагов всего | Types | Instantiations | Check time | Total | Память |
|---|---|---|---|---|---|---|
| пустой файл | 0 | 87 | 0 | 0.00 s | 0.14 s | — |
| 1 × 5 | 5 | 33 454 | 87 159 | 0.25 s | 0.72 s | 222 MB |
| 1 × 20 | 20 | 34 489 | 89 394 | 0.26 s | 0.67 s | 231 MB |
| 1 × 50 | 50 | 36 559 | 93 864 | 0.28 s | 0.70 s | 236 MB |
| 1 × 100 | 100 | 40 009 | 101 314 | 0.31 s | 0.72 s | 239 MB |
| **50 × 20** | **1 000** | 118 230 | 291 470 | **0.82 s** | 1.41 s | 363 MB |
| **50 × 40** | **2 000** | 184 290 | 440 470 | **1.16 s** | 1.72 s | 470 MB |

Читается так: базовая стоимость — не цепочки, а сами `.d.ts` VoltAgent (679 файлов, 33 k типов ещё до первого шага). Каждый шаг добавляет ~69 типов и ~149 инстанциаций **линейно**. Проект «50 воркфлоу по 40 шагов» — 1.16 s чистой проверки; tsserver с `incremental` переваривает это без деградации. Порог, за которым больно, по этим коэффициентам примерно 20 000+ шагов, а не 2 000.

Реальные потолки, которые надо знать:

| Потолок | Значение | Проверено |
|---|---|---|
| Хвостовая рекурсия условного типа | `Acc<1000>` — ок, `Acc<1200>` — `TS2589` | запуск на TS 6.0.3 |
| Union строковых литералов | 600 членов + 600 кейсов `switch` = 2 485 типов, 0.03 s | запуск |
| Union объектных типов | «больше дюжины» — деградация, [TS Wiki](https://github.com/microsoft/TypeScript/wiki/Performance) | официальная рекомендация |

Правила, которые из этого следуют и которые надо записать в `CONVENTIONS.md`: `skipLibCheck: true` и `isolatedModules: true`; интерфейсы вместо пересечений; рекурсивные типы-утилиты с явным счётчиком глубины; **обязательная аннотация экспортируемого типа воркфлоу** — иначе анонимный накопительный тип цепочки утекает в `.d.ts` пакета и умножается на каждого импортёра; никаких union из объектных типов в реестре без дискриминанта.

## 6. Обратное направление: IR → типы

Агент правит IR — типы для кода должны догонять. Схема односторонняя и без второго источника истины:

```
registry.ir.json  ──emit──▶  packages/gen/src/registry.generated.ts  ──import──▶  авторинг воркфлоу
```

| Шаг | Чем | Почему не иначе |
|---|---|---|
| Эмит деклараций из IR | свой эмиттер поверх `ts-morph` 28.0.0 (MIT) | генерим мы структуру `TypeDecl`, а не голый TS-тип — `json-schema-to-zod` 2.8.1 и `quicktype-core` 26.0.0 дают только схему без описаний, представлений и происхождения |
| Проверка «код и IR не разошлись» | CI: перегенерировать и сравнить хеш (`canonicalize` + sha256, уже в 05) | дифф файла, а не сравнение типов |
| Правка значения enum агентом | AST-патч объектного литерала → регенерация IR | цикл замкнут в обе стороны, источник истины остаётся один |

Генерируемый файл только один и только на чтение: авторинг воркфлоу его импортирует, но никогда не редактирует. Это соответствует [ADR-0017](../adr/0017-files-as-source-of-truth.md) — файлы остаются источником, база индексом.

## Вывод для нас

**Берём.** Гипотеза «код строит граф, а не исполняет его» фактами подтверждается: накопительный generic-билдер VoltAgent даёт сквозной вывод типов без единой аннотации, а стоимость — линейная и на нашем масштабе (2 000 шагов → 1.16 s) незначимая. Конкретно берём: generic-накопитель как форму авторинга; `as const satisfies` для деклараций реестра; `keyof typeof values` + `never` для полноты `switch`; branded `TypeId`/`ViewName` (уже в 05); zod 4 как единственный источник (уже в 05, менять нечего); односторонний эмит `IR → registry.generated.ts` через `ts-morph`.

**Не берём.** Типы как доказательство корректности графа. Доминирование, ацикличность, бюджеты контекста, членство в `allowed_set`, соответствие текста промта реестру — ни одно не выражается в системе типов TS, и попытка их туда затащить даст рекурсивные типы у потолка 1000 и `TS2589` вместо внятной ошибки. Эти правила остаются проходами [07-compiler.md](../07-compiler.md) над IR. Не берём TS-`enum`, кортежи для кардинальности, union объектных типов без дискриминанта.

**Где гипотеза ломается и что с этим делать.** Сквозной вывод держится только на линейной цепочке. На `andBranch` тип схлопывается в `Array<NEW_DATA | undefined>`, на `andWhen` — в `NEW_DATA | CURRENT_DATA`, и идентичность ветки исчезает. Значит, авторинговый DSL **не может** быть тонкой обёрткой вокруг `createWorkflowChain`: наши `switch`, `join` и `parallel` обязаны возвращать явный дискриминированный union из реестра, а не выводить его из формы вызовов. Иначе получится ровно та «иллюзия типов», о которой предупреждает §4: IDE зелёная, а проверку делает уже рантайм.

**Что осталось непроверенным.** UNVERIFIED: сигнатура `.toWorkflow()` (стирает ли накопитель — от этого зависит размер `.d.ts` на границе пакетов); UNVERIFIED: замеры под `skipLibCheck: false` и под tsserver в редакторе, а не батчевым `tsc`; UNVERIFIED: как устроен накопитель у Effect 3.22.2 и Mastra 1.66.0 — сравнение с VoltAgent не делали, только у VoltAgent смотрели реальный `.d.ts`.

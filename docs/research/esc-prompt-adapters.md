# Срез B: адаптеры данных для промтов

Статус: research draft, 2026-09-14. Вопрос: как промт получает данные, которых нет в выходах узлов.

## Вывод

Гипотеза «escape hatch = узел графа» подтверждается с поправкой: **адаптер — не новая сущность, а
роль**: узел `code`/`tool` с эффектом `pure|read`, чей выход привязан к слоту через `ContextNeed`.
Декларация `resolver:` рядом со слотом допустима как **сахар авторинга** (приём Cube.js: `sql` рядом
с мерой), но компилятор обязан развернуть её в именованный узел до IR. Ломается гипотеза на мелком
конце: узел на каждую тривиальную проекцию засоряет канвас — §8, правило двух ярусов.

## 1. Текущий механизм и чего не хватает

Есть: шесть видов контекста ([09 §2](../09-context-model.md)), `from:`-локаторы, `ttl` у `data`, `load`/`retrieve`
= `tool` с `effect: read` ([03 §2](../03-core-language.md)), провенанс с `origin_class`/`value_sha256`/`expires_at`
([09 §7.1](../09-context-model.md)). Шаблон (liquidjs, `strictVariables`) вычислять не умеет вовсе — и менять это не надо.

| Сценарий заказчика | Выразимо сегодня | Что мешает |
|---|---|---|
| S1. Агрегат по прошлым прогонам («доля отказов по направлению за 30 прогонов») | нет | `load` = `tool` с `tool_ref`, запиненным по хешу схемы. Новый запрос = новый тул в реестре платформы. Автор проекта не может написать запрос **в проекте** — это ровно та стена, о которой заказчик |
| S2. Дёрнуть внешний API и вставить результат | нет | `ContextSource` не имеет поля эффекта; вида для `external` нет. `tool` с `effect: external` требует `idempotency_key` и таймаут ([03 §2.3](../03-core-language.md)), а слот их не несёт |
| S3. Список примеров по условию («те же направление и сезон, score>0.8, ≤5, по убыванию») | частично | у `knowledge` `filters?: Record<string, string\|number\|boolean>` — **литералы**; динамичен только `query_from`. Фильтр по выходу другого узла не выражается |
| S4. Вычисляемый слот («дней до вылета» = `diff(run.date, request.date)`) | **нет класса** | шесть видов не содержат «посчитано чистым кодом»: `generated` определён как «выход предыдущего LLM-узла» с `trust: untrusted`. Выход `code`-узла подать в слот нечем — дыра в таксономии, не в эргономике |
| S5. Донастройка «того, чего нет» вообще | нет | все шесть видов — закрытый enum резолверов (`sourceResolvers: Record<kind, SourceResolver>`). Расширение = правка платформы |
| Побочная находка | — | `ttl` дублируется: на потребности (`source.data.ttl`, R-C5) и на узле (`tool.ttl_ms`). Источник истины должен быть один — предлагается узел |

## 2. Форма адаптера: узел или свойство слота

| Критерий | A. Отдельный узел графа | B. Свойство слота `resolver:` |
|---|---|---|
| Провенанс | `node_id` + `path` есть по построению, `value_sha256` считается один раз | придётся синтезировать псевдо-`node_id`; «откуда это» ведёт в текст шаблона |
| Трасса | свой спан, свои `aqven.timing.*` | вложен в спан LLM-узла, латентность добычи неотличима от латентности модели |
| Кассета | запись `cassette-req/v1` на порту тула ([18 §7](../18-export-and-conformance.md)) | либо своя кассета, либо реплей недетерминирован (kill-критерий 5) |
| Канвас | видно | не видно — это и есть провал 09 §8.2 #66 |
| Переиспользование двумя промтами | один узел, два `need` | два вызова, два похода в БД |
| Цикл `query_from → need → need`, порядок исполнения | ребро графа: R-C6 ловит цикл, топосортировка Kahn уже есть | цикл спрятан в свойствах слотов, нужен отдельный планировщик внутри рендера |
| Эргономика записи | многословно, 3 места правки | одно место, локальность Cube.js |

**Решение: A, с B как сахаром.** `resolver:` разрешён в YAML-записи промта и разворачивается
компилятором в тройку «узел + `ContextNeed` + привязка слота» **до** построения графа контекста.
Имя узла детерминировано (`<prompt>__<slot>__adapter`), узел попадает в IR и на канвас, правка идёт по узлу
(обратной свёртки нет — как у `reduce` → `map`+`code`). Сахар без обязательного разворачивания = вариант B
со всеми потерями, «развернём лениво, если понадобится» — не опция.

## 3. Типизация

```ts
type AdapterId = string & { readonly __brand: 'AdapterId' };

interface AdapterSpec<Out = unknown> {
  id: AdapterId;
  bind: { prompt: PromptId; slot: SlotName } | { need: NeedId };
  effect: 'pure' | 'read';
  in: Record<string, Locator>;
  out: TypeRef;
  ttl: Duration | null;
  trust: TrustLevel;
  verify: readonly VerifyKind[];
  stable_within: 'none' | 'run' | 'spec_version';
  on_error: { kind: 'fail' } | { kind: 'default'; value: Out } | { kind: 'omit' };
  impl:
    | { kind: 'code'; fn: CodeRef; tests: TestsRef }
    | { kind: 'tool'; tool_ref: ToolRef; timeout_ms: number; retry?: RetryPolicy };
}

interface AdapterCtx {
  readonly run: Readonly<RunContextView>;
  readonly now: () => IsoInstant;
  readonly query: TenantScopedReadPort;
}

type AdapterFn<In, Out> = (input: In, ctx: AdapterCtx) => Promise<Out>;
```

| Поле | Правило компилятора |
|---|---|
| `effect` | только `pure \| read`. `write`/`external` в слот промта запрещены: промт не должен иметь побочных эффектов, иначе повтор рендера (repair, `on_invalid: repair(k)`) их дублирует |
| `in` | локаторы `<node>.out.path`, `$input.path`, `run.context.*`, `const`. Каждый даёт ребро `producer → need`, участвует в R-C6 |
| `out` | обязан быть структурно эквивалентен `prompt.in[slot]` после резолва `TypeViewRef` (R-C2) |
| `ttl` | обязателен при `effect: read` (R-C5); при `pure` запрещён |
| `trust` | `pure` наследует по решётке `mergeTags` входов; `read` — по умолчанию `untrusted` (09 §2) |
| `on_error: omit` | допустим, только если тип слота `optional` и шаблон закрывает его `{% if %}`: иначе `strictVariables: true` уронит рендер `UndefinedVariableError` |
| `stable_within` | `spec_version` ⇒ значение попадает в кэшируемый префикс и в `sha256` версии спеки; иначе слот выбивается из статического поддерева `MessageTag` ([08 §5.2](../08-prompts.md)) |
| `ctx` | ни `fetch`, ни `Date.now`, ни `Math.random`, ни `globalThis` — тот же статический анализ, что у `code` ([03 §2.1](../03-core-language.md)). Время только через `ctx.now` (порт часов) |
| `ctx.query` | порт, уже привязанный к `tenant_id`; RLS не обходится. Приём Cube.js `queryRewrite`/`COMPILE_CONTEXT`: фильтр безопасности подмешивается платформой, а не пишется автором (см. [esc-cube-patterns.md](esc-cube-patterns.md)) |

Шести видов не хватает: нужен седьмой, `computed` (`pure`, `trust` по решётке входов, без `ttl`) —
иначе S4 некуда положить, а приравнять выход `code` к `generated` значит объявить чистую арифметику
недоверенной и требовать экстрактор перед `switch` (R-C3). `read`-адаптеру класс не нужен: это `data`.

## 4. Прецеденты

| Продукт | Промт тянет данные сам? | Как | Чем платит |
|---|---|---|---|
| **dataprompt** (davideast, надстройка над Genkit) | да, буквально | `data.prompt.sources` во frontmatter: провайдеры `fetch` (GET по URL), `firestore` (пути с `{{request.params.x}}`), `fs` (песочница) | входная схема **выводится** из источников, а не объявляется; кэш, детерминизм и трассировка в доках не описаны вовсе. Ровно та архитектура, которую мы отвергаем |
| **Humanloop** | да | вызов тула прямо в шаблоне: `{{ google(query) }}` — результат подставляется в промт до отправки модели | добыча невидима в графе, у неё нет своего лога и своей версии; это провал «непонятно, откуда кусок контекста» |
| **Genkit dotprompt** (google/dotprompt) | нет | только Handlebars по переданному `input`; данные приносит вызывающий flow | честно, но 90% сценариев уезжают в код flow |
| **BAML** | нет | шаблон = minijinja поверх аргументов функции; вычислений с IO нет | добыча целиком в хост-коде, зато промт — чистая функция от типов. Ближе всего к нашей позиции |
| **LangChain LCEL** | нет, но добыча — узел | `RunnablePassthrough.assign(...)` / `RunnableParallel` добавляют ключи в словарь **перед** промтом; канонический RAG-паттерн `{"context": retriever, "question": passthrough} \| prompt` | адаптер виден как шаг цепочки — это и есть наш вариант A; платит отсутствием типов слотов и TTL |
| **Langfuse** | нет | `{{var}}` + prompt composition (ссылки на промты резолвятся при fetch); клиентский кэш SDK | подстановка не типобезопасна: новая переменная в UI ломает приложение молча |
| **PromptLayer** | частично | переменные + **tool variables** — подстановка определений тулов в список, не данных | динамика на уровне доступных тулов, не контекста |
| **Braintrust** | нет | `{{text}}` по `input`, промт тянется из реестра по API | добыча вне продукта |

Итог: кто разрешает промту ходить за данными (dataprompt, Humanloop), платит провенансом и воспроизводимостью;
кто не разрешает (dotprompt, BAML, Braintrust) — выталкивает 90% сценариев в хост-код. LCEL сделал добычу
явным узлом; туда и мы, добавляя типы слота, TTL, провенанс и кассету.

## 5. Кэш и детерминизм

Кассеты живут на уровне **порта модели и тула** (sha256 по канонизации RFC 8785), в `replay_strict`
промах = `CassetteMiss` ([10 §7](../10-runtime.md), [18 §7](../18-export-and-conformance.md)). Адаптер с `effect: read` — это `tool`, туда попадает бесплатно. Дописать надо вот что:

| Требование | Механика |
|---|---|
| Ключ адаптера | `sha256(adapter_id, impl_hash, canonicalize(in), out_schema_hash)`. `impl_hash` обязателен: правка тела `code`-адаптера обязана промахиваться мимо кассеты осознанно, как правка промта меняет `promptHash` |
| `pure`-адаптер | не пишем в кассету, пересчитываем. Но `impl_hash` пишем в провенанс: расхождение при реплее — ошибка `AdapterDrift`, а не тихий пересчёт другого значения |
| Время | только `ctx.now` (порт часов, уже перечислен среди портов в 18). `Date.now` в теле = ошибка компиляции. Иначе ключ меняется каждый прогон и кассета не попадает никогда |
| TTL и `freshness` | при реплее `expires_at` сверяется с **записанным** значением часов, иначе любая кассета старше `ttl` валит проверку R-C5/`freshness` на ровном месте |
| Пагинация и нестабильный порядок | результат `read`-адаптера канонизируется перед хешированием; адаптер обязан задать детерминированный порядок (`ORDER BY` с тай-брейком по первичному ключу), иначе два прогона дают разные `value_sha256` при одинаковых данных |
| Экспорт кейса | `cassetteKeys[]` кейса пополняется ключами адаптеров — иначе кейс невыгружаем отдельно от бандла |

## 6. Few-shot и ретривер как частный случай

Слот `examples` уже описан как «динамические few-shot от узла-ретривера», тип `Example<In,Out>[]`,
каждый пример валидируется схемой `in`/`out` до рендера ([08 §4](../08-prompts.md)). Это адаптер с
предустановленными полями: `out: Example<In,Out>[]`, `verify: [schema]`, `effect: read`. Обобщается,
но не растворяется: `examples` остаётся **именованным архетипом адаптера** — у него две проверки,
которых нет у произвольного: сверка типов примера с `prompt.in`/`prompt.out` и запрет пересечения с
оценочным датасетом (пример из тест-сета в промте = утечка, ломает гейты §13). `retrieve` (09 §6.1)
отдельным узлом и остаётся: своя конфигурация ANN, свои метрики, обязательные `source_id`/`chunk_id`.
Адаптер `examples` — потребитель `retrieve`, а не замена.

Конфликт, который решается явно: `cache: system+examples` требует статичного набора в пределах версии,
то есть допустим только при `stable_within: spec_version`. Динамический ретривер примеров принудительно
опускает промт до `cache: system` — проверка компилятора, а не примечание в доке.

## 7. Граница с `tool`: адаптер — сахар, а не сущность

Честный ответ: **сахар**. Второго механизма нет — есть место декларации и три сужения поверх `tool`/`code`.

| Что адаптер добавляет к `tool`/`code` | Почему это не новая сущность |
|---|---|
| Решётка эффектов сужена до `pure \| read` | подмножество существующей решётки (03 §2.1), проверка, а не новый вид |
| Декларация рядом с промтом, разворачивание в узел | синтаксис записи; в IR ничего нового, как `reduce` → `map`+`code` |
| Привязка выхода к слоту + `on_error` для слота | это `ContextNeed` плюс поле политики, которого там сегодня нет |

В IR по-настоящему добавляются два поля: класс `computed` (§3) и `on_error` у `ContextNeed`. Остальное —
записи и проверки, так что в глоссарий «адаптер» входит как роль узла: пять примитивов остаются пятью.

## 8. Где гипотеза ломается

1. **Мелкие проекции.** Узел на «дней до вылета» превращает канвас в свалку. Правило двух ярусов:
   чистое, однозначное, без IO — **вычисляемое поле view реестра типов** (там же, где форматирование
   и `sort`, 08 §2.5), версионируется с типом, узла не порождает. Узел появляется при `effect: read`,
   кардинальности >1 или ветвлении.
2. **Адаптер внутри `map`.** Привязка «узел → слот» перестаёт быть однозначной: значение — на итерацию.
   Работает, только если адаптер в теле того же `map`; сахар `resolver:` этого не выражает и обязан
   отказывать с указанием на ручной узел.
3. **Общий адаптер у трёх промтов.** Один узел, три `need`: `value_sha256` совпадает, `need_id` нет.
   Нужна дедупликация при построении графа, иначе три похода в БД за одним и тем же.
4. **`on_error: omit`** протекает в шаблон: слот обязан быть `optional` под `{% if %}`, иначе отказ
   адаптера роняет рендер. Политика ошибки и типизация слота связаны жёстче, чем кажется.

## Открытые вопросы

- `computed` седьмым видом или `generated` с полем `by: code | llm`? Первое чище для решётки доверия, второе дешевле по миграции IR — нужен ADR.
- Кто владеет `ttl`: узел или потребность (дубль в R-C5 и `tool.ttl_ms`). Предлагается узел.
- UNVERIFIED: переиспользуется ли ключ кассеты тула между `replay_lenient`-форками с правкой промта, если адаптер не менялся. Проверять счётчиком в middleware (10 §10, п. 2).
- Сверить со срезом C: «адаптер промта» и «пользовательский шаг» — одна конструкция с разными местами привязки.

# Срез C: философия escape hatch — 90% декларативно, 10% кодом, гарантии целы

Статус: research. Дата: 2026-09-14. Источники помечены; непроверенное — `UNVERIFIED:`.

## 0. Ответ на главную развилку

Гипотеза «escape hatch сам становится узлом графа» — **верна**, но не по эстетическим причинам, а
потому что альтернатива ломает инвариант 5 (всё воспроизводимо). Если код добычи данных живёт внутри
шаблона промта, то рендер промта становится актом ввода-вывода: у него появляется сеть, таймаут и
время. Тогда `run_replay_node` переигрывает не тот же промт, replay-кэш (`wrapLanguageModel`) кэширует
вызов модели, но не вход в него, а `ProvenanceTag.value_sha256` вычислять не от чего — значение не
существовало как выход узла. Поэтому: **резолвер обязан быть узлом, потому что только у выхода узла
есть `node_id`, `path`, `value_sha256`, `expires_at` и место в `workflowState`** (09 §7.1–7.2).

Где гипотеза ломается — три места, их надо закрыть явно:

| Что ломается | Почему | Чем закрываем |
|---|---|---|
| Гранулярность | 30 мелких добываний = 30 узлов; канвас нечитаем, а R2 требует читаемости графа | свёртка **в UI, а не в IR**: узел несёт `attached_to: <prompt_node_id>` и рисуется вложенной панелью узла-промта; в IR, компиляторе и трассе он полноценный узел. Это и есть «адаптер рядом с промтом» из запроса заказчика |
| Per-item добыча внутри `{% for %}` шаблона | слоту нужно значение на элемент, а узел даёт значение до рендера | запрещаем: `for` в шаблоне итерирует только по уже собранному массиву; per-item добыча — `map` + узел-источник, промт уходит внутрь `map`. Цена честная: подграф вместо скрытого N+1 |
| `ContextSource` не знает про вычисленный источник | в `09 §3.1` виды — `static / data / generated / human / run / knowledge`; выход `code`-узла не мапится ни в один, `origin_class = static` соврал бы про `trust` и TTL | добавить `{ kind: 'computed'; from: NodeId; fn: CodeRef; ttl?: string; trust: TrustLevel }` с обязательным `trust`, наследуемым по `mergeTags` от входов (`untrusted` поглощает). Без этого escape hatch отбеливает недоверенные данные |

## 1. AWS CDK — эталон многоуровневого escape hatch

Четыре уровня, каждый следующий отдаёт ровно одну гарантию. Ключевая формулировка гайда: escape
hatches «let you "escape" the AWS CDK paradigm and extend it in ways the AWS CDK designers never
anticipated. Then you can wrap all that in a new construct to hide the underlying complexity».

| Уровень | Механизм | Что сохраняется | Что теряется |
|---|---|---|---|
| L3/L2 | курируемые конструкты | типы, дефолты, IAM-политики по best practice, валидация конструкта | выразительность: «L2 constructs are developed "by hand", they may sometimes lag behind the L1» |
| L1 | `CfnBucket`, `node.defaultChild` + каст | типы по спецификации CloudFormation, синтез, диф | ergonomics, сопутствующие ресурсы и безопасные дефолты L2 |
| Raw override | `addOverride`, `addPropertyOverride`, `addDeletionOverride`, `addPropertyDeletionOverride` | синтез шаблона, `cdk diff`, деплой | типы целиком — «you can bypass all typing using raw overrides. This also makes it possible to delete synthesized properties»; путь `Properties.X.0.Y` не проверяется ничем |
| Custom resource | Lambda на CREATE/UPDATE/DELETE, `AwsCustomResource` | декларативность снаружи (обёрнуто в конструкт) | идемпотентность, откат, наблюдаемость — на авторе |

Три приёма CDK, которые переносим дословно:
1. **Escape hatch не отдельный язык, а спуск по той же лестнице.** L1 — не «плагин», а тот же объект
   графа конструктов, просто ниже. У нас так же: escape hatch — узел IR, а не аннотация над IR.
2. **Обёртывание обратно.** Итог спуска рекомендуется завернуть в конструкт. Наш аналог —
   `component_expand`: разовый `code`-узел, повторённый трижды, обязан стать компонентом.
3. **Документированный список поводов.** Гайд перечисляет три ситуации, когда лезть в hatch. Наш
   компилятор должен требовать `reason:` из закрытого перечня, а не свободный текст.

`cdk diff` остаётся работать на всех уровнях — это и есть «гарантия, которую дыра не ломает». Наш
эквивалент, который обязан выжить на всех уровнях: `flow_compile` (типы входа/выхода), трасса,
`run_replay_node`, провенанс. Всё остальное может отваливаться уровнями.

## 2. Другие системы: где дыра, какой ценой

| Система | Дыра | Цена, признанная самими авторами | Что забираем |
|---|---|---|---|
| Terraform | `provisioner`, `local-exec`, `lifecycle` | доки: «Use provisioners as a last resort. There are better alternatives for most situations»; `plan` не видит, что сделает скрипт, действия не попадают в state, идемпотентность на авторе, падение оставляет ресурс tainted | формулу «дыра вне state — дыра вне плана». Наш `state` — это IR + провенанс; escape hatch обязан писать в оба |
| Rails | `connection.execute`, raw SQL, JS во вьюхе | доктрина «progressive disclosure of complexity»: фреймворк не прячет SQL и JS, но делает так, что начать можно, не зная их | лестницу, а не забор: 90% не видят `code`-узла вообще, он не мешает старту |
| Prisma | `$queryRaw` | «writing it in TypeScript has traditionally meant giving up type safety: no auto-completion, no type safety for query results, manually written result types that drift out of date» → ответ Prisma: TypedSQL (`prisma generate --sql`) и SafeQL | **лучший прецедент**: типизировать саму дыру. Наш аналог TypedSQL — обязательный `TypeRef` из реестра на вход и выход `code`-узла, а не `unknown` |
| dbt | Jinja `{{ }}`, макросы | «overusing Jinja makes models harder to onboard, harder to review in PRs, harder to debug»; официальный совет — favor readability, даже ценой дублирования SQL | правило «макрос с третьего повторения», не с первого |
| Kubernetes | аннотации → CRD + контроллер | аннотация — нетипизированная строка вне схемы; путь взросления официально ведёт к CRD со схемой | двухступенчатость: `code`-узел (быстро, локально) → компонент/тул в реестре (типизировано, переиспользуемо) |
| Tailwind | `[arbitrary-values]` | значение вне дизайн-системы; линтер и ревью — единственный контроль, токены обходятся молча | нужна **видимая метка**: произвольное значение обязано выглядеть иначе, чем токен |
| Django | `raw()`, `extra()` | `extra()` помечен как устаревающий и опасный; `raw()` сохраняет маппинг в модель | различать дыру, сохраняющую тип (`raw` → модель), и дыру, ломающую его (`extra`). Вторую не даём вовсе |
| Airflow | `PythonOperator` | «Airflow is an orchestration framework, not an execution framework»; логика задачи внутри логики планирования — high coupling, конфликт зависимостей на воркерах, конкуренция за ресурсы | см. §5 |
| Cube.js | `sql` в `dimension`/`measure`, `COMPILE_CONTEXT`, JS в схеме | код в схеме, но результат всё равно проходит через слой семантики: pre-aggregations, кэш, RLS | подтверждение нашей схемы: код **производит фрагмент**, платформа его **размещает** (смежный срез A) |

## 3. Классификация наших дыр по уровням риска

`E0` — декларативно, `E1` — чистый код в песочнице, `E2` — код с эффектами, `E3` — обход IR.

| # | Дыра | Уровень | Что позволяет обойти | Гарантии, которые остаются | Что теряется | Что компилятор обязан потребовать взамен |
|---|---|---|---|---|---|---|
| 1 | тело `code`-узла | E1 | набор архетипов и встроенных проекций (`pick/omit/map/flatten`) | типы входа/выхода из реестра, `pure` в решётке эффектов, детерминизм реплея, провенанс, канвас, трасса | читаемость на канвасе; статическая проверка семантики тела | `in`/`out` как `TypeRef` реестра (не `unknown`), непустой набор тестов (03 §5: «непустой набор тестов»), прохождение анализатора чистоты (запрет `Date.now`, `Math.random`, `globalThis`, `process`, `fetch`), `reason` из перечня, лимит строк |
| 2 | кастомный `tool` | E2 | границу «платформа ходит наружу» | типизированный контракт, реестр тулов (R4: тул вне реестра — ошибка L1), трасса, бюджеты | детерминизм без кассеты; отсутствие сайд-эффектов | объявленный `effect: read\|write\|external`, обязательный `timeout_ms`, `idempotency_key` как чистое выражение над входом для `write`/`external`, TTL для `read`, кассета для реплея |
| 3 | резолвер слота промта | E1/E2, **только как узел** | сборку контекста рендера Builder'ом из `in:` | `strictVariables`, белый список фильтров, R-T1…R-T13, провенанс слота | ничего — если резолвер узел; **всё** (провенанс, TTL, кэш, трасса) — если он внутри шаблона | запрет любого кода внутри `.liquid`; резолвер объявляется как `ContextSource.kind = 'computed'` с `from: NodeId`; `attached_to` для свёртки в UI; запрет системных слотов под `cache` сохраняется |
| 4 | кастомный компонент | E0 | библиотеку архитектур | `component_expand` до примитивов, все правила ядра применяются к раскрытию | ничего: компонент — сахар, не дыра | раскрытие обязано компилироваться само по себе; объединение эффектов тела; своя версия и бюджет при `human` |
| 5 | произвольный TS в определении воркфлоу | E1 на фазе синтеза | ручную сборку IR через операции | IR как единственный выход: TS **строит** граф, не исполняет его; round-trip K13 | нет, если синтез детерминирован; иначе — воспроизводимость сборки | синтез в изоляции без сети и часов, детерминированный вывод (один вход → байт-в-байт один IR), результат валидируется ajv как обычный IR, дифф операций показывается человеку |
| 6 | прямая правка файла мимо операций | E3 | **всё**: компилятор, версии, аппрувы, гейты | ни одной, пока файл не прошёл импорт | R6 целиком | не даём как режим работы. Файл, изменённый мимо операций, проходит `flow_import` как недоверенный вход: полная валидация, дифф против последней версии, `version_propose` с доказательством |

Строка 6 — единственная, которую мы **не открываем**: остальные пять отдают по одной гарантии,
шестая отдаёт ядро доверия. Это и есть граница «код не ломает гарантии».

## 4. Как не дать дыре стать нормой

Одной метрики «доля логики вне архетипов» (риски спеки §19) мало: она показывает болезнь, но не
лечит. Шесть механизмов, от дешёвых к дорогим:

| Механизм | Где живёт | Срабатывание | Что делает |
|---|---|---|---|
| Обязательный `reason` из перечня | схема IR | компиляция | `no_archetype \| perf \| external_format \| migration \| experiment`. Свободный текст запрещён — по перечню строится метрика, а не грепается |
| WARN компилятора `E-ESC1` | `flow_compile` | компиляция, не блокирует | «узел `X` — escape hatch уровня E1, ближайший архетип: `verify_fix`». Кандидат вычисляется сравнением сигнатуры с таблицей архетипов (03 §6, §7.2) |
| Правило трёх | линтер репозитория | CI | три `code`-узла с одинаковым хэшем нормализованного AST → BLOCK с предложением `component_create`. Прямой перенос приёма CDK «wrap it in a new construct» и dbt «макрос с третьего повторения» |
| Обязательный тест | компилятор | компиляция, BLOCK | `code`-узел без непустого набора тестов не компилируется. Это уже зафиксировано в 03 §5 как условие сохранения смысла мутационного теста K1 |
| Отметка на канвасе | Studio | всегда | иная рамка и значок уровня (E1/E2) у узла; у промта со свёрнутым адаптером — счётчик «2 адаптера». Урок Tailwind: произвольное значение обязано выглядеть иначе токена |
| Бюджет escape hatch на воркфлоу | гейт выпуска | `G-release` | доля узлов E1+E2 > порога → WARN в отчёте версии, рост доли между версиями → требование объяснения в `version_propose(evidence)` |

Метрика для §19 уточняется до трёх чисел, иначе она не отличает здоровый рост от гниения:
`escape_ratio` (узлы E1+E2 / все узлы), `escape_duplication` (доля `code`-узлов, повторённых ≥ 2 раз),
`escape_age` (медианный возраст узла с `reason: no_archetype` — если он растёт, архетип не написали,
а дыру забыли). Третье число — самое важное: `reason: no_archetype` это заявка на архетип, и заявка
старше одного релиза означает, что дыра стала нормой.

## 5. Антипример: Airflow `PythonOperator`

Что обещалось: «любой Python внутри DAG». Что получилось, по формулировкам самой экосистемы —
«Airflow is an orchestration framework, not an execution framework», а `PythonOperator` «is an
anti-pattern»: логика задачи внутри логики планирования даёт high coupling и «will reduce your
ability of administrating your Airflow DAGs»; зависимости задач ставятся на воркеры и конфликтуют;
задачи «compete with one another for resources and can starve the cluster».

| Что сломалось | Механизм поломки | Как предотвращаем |
|---|---|---|
| Граф перестал описывать работу | вся логика в одном узле, DAG из трёх прямоугольников | `pure` в решётке эффектов: управление потоком в теле `code` — ошибка компилятора (инвариант 1), а не стилистика. `switch`, `loop`, `map` невыразимы внутри `code` |
| Планировщик стал рантаймом | нет границы между «оркестратор» и «исполнитель» | эффекты `write`/`external` доступны только `tool`, у которого обязательны `timeout_ms` и `idempotency_key`; `code` не может ходить в сеть физически (анализатор чистоты + изоляция) |
| Зависимости расползлись | `pip install` на воркерах | `code` видит только белый список чистых модулей; свои зависимости — тул в реестре с версией |
| Отладка стала `print` | нет провенанса кусков данных | `ProvenanceTag` на каждом значении; клик «откуда это» ведёт в `node_id` + `path` |

n8n Code node — та же болезнь мягче: «the n8n equivalent of dropping into raw SQL when an ORM would
do… the Code node is a last resort, with the decision order expression → Edit Fields → Code node»,
плюс порядковая разница накладных расходов на вызов. Урок: **порядок предпочтения должен быть
напечатан в продукте, а не в блоге**. У нас он печатается как WARN `E-ESC1` с именем архетипа.

## 6. Вывод: правило проектирования дыр (кандидат в 01 §4)

> **Инвариант 10. Дыра — это узел, а не исключение.** Любая возможность дописать код доступна только
> как объект IR: у неё есть тип входа и выхода из реестра, объявленный эффект, место на канвасе,
> метка происхождения у выхода, TTL и строка в трассе. Escape hatch отдаёт ровно одну гарантию из
> лестницы — выразительность вместо декларативности — и ни одной из ядра доверия: типы, провенанс,
> детерминизм реплея, версия и аппрув сохраняются на всех уровнях. Взамен свободы компилятор берёт
> плату: объявление эффектов, типизированный контракт, таймаут и ключ идемпотентности для
> эффективных узлов, непустой набор тестов и причину из закрытого перечня. Код, который прячется
> внутрь шаблона, конфига или файла мимо операций, дырой не считается — он считается ошибкой
> компиляции, потому что у него нет ни одного из перечисленных свойств.

## 8. Риски и непроверенное

| Риск | Суть | Смягчение |
|---|---|---|
| Свёртка в UI прячет дыру | `attached_to` сделает адаптеры невидимыми ровно так же, как код в шаблоне | счётчик адаптеров на узле-промте обязателен и участвует в `escape_ratio`; свёрнутое ≠ отсутствующее |
| `reason` вырождается | агент всегда пишет `no_archetype` | `escape_age` по этому значению + обязательное объяснение в `version_propose` при росте доли |
| «Правило трёх» по AST | нормализация AST даёт ложные срабатывания на тривиальных проекциях | исключить из правила узлы, чьё тело сводится к `pick/omit/map/flatten` — их надо не компонентизировать, а заменить проекцией |
| Стоимость узла-резолвера | подграф вместо одного промта увеличивает число узлов в 2–3 раза на промт с внешними данными | мерять на эталонном 15-шаговом воркфлоу (K2) до фиксации решения |

UNVERIFIED: конкретный порог `escape_ratio` для WARN в `G-release` — числа нет ни в спеке, ни в
прецедентах; предлагается калибровать по эталонному воркфлоу, а не назначать.
UNVERIFIED: оценка накладных расходов Code node в n8n (~2 ms против ~600 ms) — из статьи сообщества
(dev.to), не из официальных доков; для нашего решения не опорная.
UNVERIFIED: цитата про `PythonOperator` как anti-pattern — из Medium/Towards Data Science; официальные
доки Airflow формулируют мягче («Airflow is an orchestration framework, not an execution framework»
воспроизводится в best-practices, но слово anti-pattern — из статей).

# Срез 2: код синтезирует артефакт-граф

> Вопрос среза: работает ли на практике модель «TypeScript строит граф, а не исполняет его», и какой ценой.

## Что нашли

| Инструмент | Артефакт синтеза | В репозитории? | Предпросмотр диффает | Синтез = исполнение кода? |
|---|---|---|---|---|
| AWS CDK | cloud assembly `cdk.out/` (CFN-шаблон + ассеты) | **Нет**, `cdk.out` в `.gitignore` шаблона `cdk init` ([gitignore](https://github.com/aws/aws-cdk-cli/blob/main/packages/aws-cdk/lib/init-templates/app/typescript/.template.gitignore)); зато `cdk.context.json` **обязан** быть в git ([docs](https://docs.aws.amazon.com/cdk/v2/guide/context.html)) | **артефакт** (шаблон vs развёрнутый шаблон / ChangeSet) | да, но результат — файл |
| Pulumi | нет файлового артефакта; граф ресурсов живёт в state (Pulumi Cloud / S3) ([docs](https://www.pulumi.com/docs/iac/concepts/state-and-backends/)) | нет | **исполнение vs state**: «desired state вычисляется прогоном программы и извлечением графа объектов» ([preview](https://www.pulumi.com/docs/iac/cli/commands/pulumi_preview/)) | да, обязательно |
| SST v3 (Ion) | как Pulumi (движок Pulumi + Terraform-провайдеры) ([SST v3](https://sst.dev/blog/sst-v3/)) | нет, нужен state-backend | как Pulumi | да |
| Winglang | Terraform/CFN-конфиг из фазы **preflight** ([inflights](https://www.winglang.io/docs/concepts/inflights)) | нет | артефакт (через TF/CFN) | preflight исполняется компилятором |
| Encore | внутренняя модель приложения | нет | — (нет операции diff) | **нет: чистый статический анализ, «без запуска кода»** ([docs](https://encore.dev/docs/ts/concepts/application-model)) |
| cdk8s | YAML-манифесты в `dist/` ([cli](https://cdk8s.io/docs/latest/cli/synth/)) | **да** — единственный из шести, где артефакт коммитят (GitOps читает YAML) | артефакт (git diff по YAML + `kubectl diff`) | да |

Версии на 2026-09-14: `aws-cdk-lib@2.269.0` (modified 2026-09-10), `constructs@10.8.1`, `@pulumi/pulumi@3.262.0`, `sst@4.17.1`, `cdk8s@2.70.102`, `esbuild@0.28.2`, `tsx@4.23.13`.

## Главный раскол: синтез-исполнением против синтеза-анализом

Гипотеза «код строит граф, а не исполняет его» подтверждается — но у неё **две несовместимые реализации**, и они дают разные гарантии.

| | Исполнение (CDK, Pulumi, cdk8s, Wing-preflight) | Статический анализ (Encore) |
|---|---|---|
| Что даёт граф | побочный эффект прогона `main()` | разбор AST без запуска |
| Тьюринг-полнота авторинга | полная: циклы, `fetch`, `Date.now()` | запрещена там, где влияет на топологию |
| Детерминизм | **не гарантирован языком**, чинится дисциплиной и кэшем | гарантирован по построению |
| Цена | недетерминизм лечится ad hoc | «non-literal names produce compiler errors» — язык урезан |

Encore — прямое доказательство, что можно иметь TS-авторинг **без** исполнения. Его цена честная и измеримая: имя ресурса обязано быть литералом, объявление — на верхнем уровне модуля. Это не баг, это условие анализируемости.

## Предпросмотр: что именно диффается

Это прямая проверка нашего семантического диффа версий (`docs/07-compiler.md`, `docs/18-export-and-conformance.md`).

**Никто не диффает код.** Все шесть диффают синтезированную структуру. Но дальше расходятся:

- **CDK / cdk8s — диффают артефакт с артефактом.** `cdk synth` кладёт детерминированный файл в `cdk.out`, `cdk diff` сравнивает его с шаблоном развёрнутого стека. Артефакт — first-class значение: его можно закоммитить, отдать на ревью, сравнить два коммита между собой без доступа к облаку. **Это ровно наша модель**: IR-файл как единица сравнения.
- **Pulumi / SST — диффают исполнение с внешним state.** Артефакта нет: чтобы получить дифф, надо запустить программу и иметь доступ к бэкенду state. Двух версий кода между собой сравнить нельзя — сравнивается «прогон сейчас» против «что записано в облаке».

Второе для нас неприменимо. Семантический дифф версий спеки — это `diff(IR_v1, IR_v2)`, две версии определения, обе из git, без прогона и без рантайм-состояния. Pulumi такой операции не имеет в принципе.

Цена подхода Pulumi видна в их же документации по update plans: значения, приходящие из других ресурсов, на preview записываются как `unknown`; ресурсы, создаваемые внутри `apply()`, на preview **вообще не появляются** и падают уже на update ([update plans](https://www.pulumi.com/docs/iac/concepts/update-plans/)). Рекомендованный обход — «разбейте на стеки и передавайте через stack references». То есть: как только граф начинает зависеть от значений, известных только в рантайме, предпросмотр перестаёт быть полным. **Для нас это запрет на условные рёбра, вычисляемые из данных прогона.**

## Детерминированность

CDK — самый честный кейс. Синтез недетерминирован из коробки, потому что конструкты ходят в AWS API прямо во время синтеза (`Vpc.fromLookup`, `availabilityZones`, `LookupMachineImage`). Лечение прямое и показательное:

> «CDK записывает доступные AMI в `cdk.context.json` и использует сохранённое значение при последующих синтезах… Вы можете быть уверены, что ваши стеки всегда синтезируются в один и тот же шаблон CloudFormation» — [context](https://docs.aws.amazon.com/cdk/v2/guide/context.html)

Урок в том, **что** они коммитят: не артефакт, а *замороженные недетерминированные входы*. Артефакт `cdk.out` игнорируется git, `cdk.context.json` обязателен в git. Недетерминизм не запрещён — он вынесен в отдельный версионируемый файл, а обновление значений сделано явной командой (`cdk context --reset`). Это паттерн lockfile, применённый к синтезу.

Wing решает иначе — типовой системой. Компилятор запрещает inflight-коду (рантайм) вызывать preflight-код (топология), а preflight — вызывать inflight; мутабельные коллекции при переходе границы автоматически становятся иммутабельными ([inflights](https://www.winglang.io/docs/concepts/inflights)). Разделение фаз — это языковая конструкция, а не соглашение. **Ради этого пришлось сделать новый язык; в TypeScript таких гарантий нет.**

## Скорость: интерактивен ли синтез

Для нас это вопрос жизни канваса: правка в коде → обновлённый граф на экране.

Замер на пробном проекте (`scratchpad/probe-ts`, Node + esbuild 0.28.2, macOS arm64): DSL-модуль, объявляющий 200 узлов, бандлится, исполняется и сериализуется в JSON.

| | bundle | exec | serialize | total |
|---|---|---|---|---|
| холодный | 26.7 ms | 0.9 ms | 0.0 ms | **27.6 ms** |
| прогретый (×3) | 1.4–1.7 ms | 0.4–0.6 ms | 0.0 ms | **1.9–2.3 ms** |

То есть синтез графа из TypeScript — **интерактивная операция**, на два порядка ниже порога восприятия. Канвас может пересинтезировать на каждое сохранение файла, и даже на каждое нажатие клавиши с дебаунсом.

Медленность CDK — не свойство модели «код → артефакт», а свойство конкретной реализации. Причины, названные в issue: сбор stack trace при создании каждого `IResolvable` ([#8479](https://github.com/aws/aws-cdk/issues/8479)); jsii 1.15.0 замедлил синтез до 10× — пайплайны с 8 минут ушли на 80 ([jsii#2284](https://github.com/aws/jsii/issues/2284)); двойной прогон синтеза, когда `cdk.context.json` пуст и CLI сначала ходит в AWS, потом синтезирует заново. Ни одна причина не воспроизводится у нас: у нас нет кросс-языкового рантайма (jsii), нет lookup'ов во внешнее облако и нет причины собирать stack trace на каждый узел.

**Вывод по скорости: нам ничего не мешает. Но три вещи запрещены под страхом потери интерактивности — сетевые вызовы в фазе синтеза, кросс-языковой мост, сбор stack trace на узел.**

## Как выглядит ошибка

Закономерность железная: **качество ошибки обратно пропорционально расстоянию до исходника.**

| | Ошибка формулируется в терминах | Качество |
|---|---|---|
| Encore | кода: «compiler errors with file locations», конкретные пропущенные секреты/БД | лучшее, ошибка ловится до всякого прогона |
| Wing | кода: нарушение фазовой границы — ошибка компиляции | лучшее |
| cdk8s | артефакта (YAML), но валидация плагинами на синтезе | среднее |
| CDK | **артефакта**: CloudFormation отвечает `Invalid request`, настоящую причину приходится искать в CloudTrail ([SST](https://sst.dev/blog/moving-away-from-cdk/)) | худшее |
| Pulumi / SST | ответа провайдера; SST перешли на Pulumi в том числе ради «better error messages» ([SST v3](https://sst.dev/blog/sst-v3/)) | среднее |

Для нас это означает: **ошибки компилятора обязаны иметь source map обратно в TypeScript**. Позиция в IR — не адрес для человека. Если пользователь видит «узел `step_17` нарушает доминирование», а не «`src/flow.ts:42`», мы воспроизвели худшую часть CDK.

## Уроки провалов

| Провал | Где | Суть | Что это значит для нас |
|---|---|---|---|
| **Идентичность узла выводится из позиции в дереве** | CDK | logical ID = construct id + путь в дереве. Переименовал переменную или переложил в другой файл — CloudFormation читает это как delete+create ([identifiers](https://docs.aws.amazon.com/cdk/v2/guide/identifiers.html), [CyberArk](https://medium.com/cyberark-engineering/the-tale-of-aws-cdk-refactoring-logical-ids-and-lost-resources-fe9d91dfecd6)). Чинили 8 лет: `cdk refactor` вышел в preview только в сентябре 2025 ([анонс](https://aws.amazon.com/about-aws/whats-new/2025/09/aws-cdk-refactor-preview)) | **Самый дорогой урок среза.** Если ID узла в IR синтезируется из структуры кода, любой рефакторинг ломает семантический дифф: переименование прочитается как «удалили узел, добавили узел». ID должен быть явным и стабильным, а не выведенным |
| Артефакт протекает в авторинг | CDK | «non-obvious code behaviour leaks CloudFormation implementation details», `Export in use` требует двухшагового деплоя, откаты оставляют стек в невосстановимом состоянии ([SST](https://sst.dev/blog/moving-away-from-cdk/)) | абстракция авторинга обязана быть полной, иначе пользователь всё равно учит IR |
| Артефакт не в репозитории | CDK, Pulumi | дифф двух версий определения невозможен без облака | у нас IR должен быть коммитируемым файлом — это уже зафиксировано в [ADR-0017](../adr/0017-files-as-source-of-truth.md) |
| Недетерминизм через внешние вызовы | CDK | lookup'ы в AWS на этапе синтеза | фаза синтеза обязана быть герметичной |
| `unknown` в предпросмотре | Pulumi | ресурсы, созданные внутри `apply()`, невидимы на preview | граф не должен зависеть от рантайм-значений |
| Компания умерла, идея жива | Winglang | стартап закрылся в апреле 2025, язык продолжают как OSS ([The New Stack](https://thenewstack.io/wing-the-startup-failed-but-the-language-has-potential/)) | новый язык ради фазового разделения — не окупается. Берём идею, не язык |

## Вывод для нас

**Гипотеза подтверждается, но не в той форме, в какой сформулирована.** «Код строит граф» — не одна модель, а две, и нам подходит только одна.

**Берём — модель CDK/cdk8s, а не Pulumi:**

1. **Артефакт синтеза — first-class, файловый, коммитируемый.** cdk8s коммитит `dist/` и живёт с GitOps; это ровно наш случай. IR остаётся единицей хранения, сравнения, экспорта и конформанса. TypeScript встаёт *перед* IR, ничего в нём не меняя, и не противоречит ADR-0017.
2. **Дифф — по IR, никогда по коду.** Все шесть инструментов сходятся здесь без исключений. `docs/07-compiler.md` и `docs/18-export-and-conformance.md` не трогаются вообще.
3. **Паттерн lockfile для недетерминизма.** Если в авторинге понадобится что-то внешнее (список моделей, схема API), оно замораживается в отдельный версионируемый файл по образцу `cdk.context.json`, а не вызывается на синтезе.
4. **Синтез герметичен и быстр.** 2 ms на 200 узлов прогретым — канвас обновляется живьём. Условие: никакого I/O, никакого jsii-подобного моста, никакого stack trace на узел.

**Не берём:**

- **Модель Pulumi/SST** (граф только в state, дифф против облака). Она убивает семантический дифф версий и делает предпросмотр неполным при любой зависимости от рантайм-значений.
- **Вывод идентичности узла из структуры кода.** Самая дорогая ошибка CDK. ID узла — явный аргумент, часть контракта, переживающий переименования и переносы между файлами.
- **Свой язык ради фазового разделения.** Wing доказал и идею, и её нерентабельность.

**Цена, которую придётся заплатить — ровно та, что заплатил Encore: урезанный авторинг.** Чтобы TypeScript оставался *описанием* топологии, а не её исполнением, топологически значимые вещи обязаны быть статически видимы: ID — литералы, объявления — на верхнем уровне, никаких узлов из `await`, из `Math.random()`, из чтения `process.env`. Это и есть граница. Заказчик просит код ради экстракции данных, слияния, кастомных преобразований и запросов к API — **всё это рантайм-код внутри узла, и ничто из этого не требует, чтобы топология была динамической.** Напряжение снимается фазовым разделением в духе Wing preflight/inflight: топология статична и анализируема, тела узлов — произвольный TypeScript.

Открытый вопрос для следующего среза: **чем в TypeScript заменить компилятор Wing**, который эту границу проверяет. Исполнением (запустить и посмотреть, что построилось) — быстро, но фазу не гарантирует. Статическим анализом в духе Encore (ts-morph / TS Compiler API по оси TypeScript 6.0.3 из `docs/DECISIONS.md`) — гарантирует, но урезает DSL сильнее. UNVERIFIED: гибрид «анализ проверяет фазу, исполнение строит граф» ни в одном из шести инструментов не встречен.

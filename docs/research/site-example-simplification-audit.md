# Example-simplification audit (design doc §7)

Cross-wave audit of every published how-to and concept page (46 pages; the Start/ tutorial
sequence and studio/first-workflow.md are exempt by design — they are deliberately one
continuous showcase walkthrough) against the design doc's §7 complaint: examples that are
too large and too tightly coupled to the full showcase project (examples/lumen/, flows
support_case and judge_panel) to stand on their own. Produced by 47 parallel audit passes on
2026-09-22, each reading its one page in full and spot-checking claims against real files.

**Result: 23 of 47 pages flagged for simplification, 24 already fine.**

Citations to file paths and line numbers below are for the fix-plan author — never copy them
into a published page. See apps/site/CONVENTIONS.md.

## Pages flagged for simplification

### `apps/site/src/content/docs/concepts/agent-inference-and-the-llm-node.md`

**Current example:** The section "A real example: one prompt, three models" (lines 57–99, ~43 of 124 total lines, ~35% of the page) is the page's only example. It shows three tiny 3-line YAML snippets (node/inference/agent only) for support_case's `drafts/gemini.node.yaml`, `gpt.node.yaml`, and `mistral.node.yaml`, plus prose narrating a fourth file not shown (`nodes/polish/revise.inference.yaml`'s in/out fields) and three more files not shown as YAML but described field-by-field (`agents/gemini.yaml`, `agents/gpt.yaml`, `agents/mistral.yaml` — model string, temperature, retries for each).

**Coupling problem:** To follow this one example illustrating a single technique ("same Inference id, different Agent id"), the reader has to hold 7 distinct showcase-project files in mind at once, spread across `flows/support_case/nodes/drafts/`, `flows/support_case/nodes/polish/`, and the project-level `agents/` directory. Only 2 of each (1 node/agent pair beyond the first) is needed to prove "many Agents, one Inference" — the third model is redundant repetition of the same point. The prose also lists upstream field names ("same summary, same customer, same resolution, same knowledge-base chunks") that implicitly lean on other unexplained flow nodes (triage, prepare, route, search_kb), nudging the reader toward needing the whole flow's shape even though the page never explains those nodes. It is a real, verified example — I confirmed the referenced files exist and match the page's description — but it over-provisions the illustration relative to what the technique needs.

**Suggested fix:** Drop the third model (mistral) and keep only two node/agent pairs (e.g. gemini + gpt) — the minimum that still proves "same inference id, different agent id." That cuts the file count to track from 7 to 5 (1 inference + 2 nodes + 2 agents) and shortens the section by roughly a third, with no loss of the point being made. Optionally swap the prose paraphrase of the inference's fields for one small real snippet taken directly from `examples/lumen/flows/support_case/nodes/polish/revise.inference.yaml`'s `in`/`out` block (a handful of lines) so the reader sees the actual typed contract instead of a narrated list — still real and verifiable, not larger than what's already there. Trim "same summary, same customer, same resolution, same knowledge-base chunks" to avoid naming fields owned by other unexplained flow nodes (triage/prepare/route/search_kb).

**How this was verified:** Read the full page (124 lines) via Read, and apps/site/CONVENTIONS.md's "Правило плотности примеров" section via Bash/grep (concept pages need ≥1 example illustrating a fact, not becoming the page's own structure). Then spot-checked the real files the example describes under examples/lumen/: listed agents/ and flows/support_case/nodes/drafts/, confirmed gemini.node.yaml's and gemini.yaml's/gpt.yaml's actual contents match the page's prose (including the larger `in:` block with 7 upstream bindings that the page's shown snippet omits), and confirmed revise.inference.yaml and mistral's files exist.

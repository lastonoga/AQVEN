## Что VoltAgent НЕ даёт — наш слой

| Пробел | Наше решение |
|---|---|
| `switch` по enum | `andBranch` запускает ВСЕ истинные ветки, first-match нет → компилятор генерирует взаимоисключающие предикаты + шаг сведения |
| Лимит итераций цикла | у `andDoWhile/andDoUntil` лимита нет → счётчики в workflow state, условие генерирует компилятор (`max_iter`, бюджет, стагнация, best-of) |
| `quorum(k)`, `any`, политики ошибок веток | `andAll` падает целиком и сливает результаты в один объект → обёртка веток в Result + явные ключи + шаг сведения |
| `on_item_error` | у `andForEach` нет → обёртка элемента в Result + фильтр по политике |
| Переопределение модели и инструкций на вызове | **`model` и `instructions` нельзя передать в опциях вызова** (их нет в `BaseGenerationOptions`) → только динамические функции агента, читающие эффективную конфигурацию из контекста вызова |
| Гейты качества на уровне узла | отсутствуют — наша обёртка шага + собственные метрики |
| Возобновление по таймауту | VoltAgent сам не возобновляет → pg-boss `sendAfter` + сверяющий cron |
| Lineage форков | `replayedFromExecutionId`/`replayFromStepId` не сохраняются в типизированные поля ни в postgres@2.1.3, ни в libsql → своя таблица |
| Детерминизм реплея | timeTravel переисполняет вызовы моделей → наш replay-кэш как `LanguageModelMiddleware` через `wrapLanguageModel` |

## Структурированный вывод — опровержения спеки

1. **Одной strict-схемы на всех провайдеров не существует.** Требования OpenAI и Anthropic взаимно
   противоречивы. Профиль схемы — свойство пары (IR-схема × провайдер), компилируется под профиль.
2. **Zod 4 из коробки даёт невалидный для OpenAI strict вывод** (проверено запуском: `z.discriminatedUnion`).
   Обязателен собственный слой пост-обработки после `z.toJSONSchema`.
3. **`jsonrepair` молча фальсифицирует обрезанные ответы** (проверено запуском). Поэтому исходов вызова
   три, а не два: `ok` / `refusal` / `truncated`; ремонт применим только к `ok`-ветке, обрезанный
   ответ чинить запрещено.
4. **Потолок динамического allowed-set — около 416 значений UUID, а не 1000.** Лимиты OpenAI действуют
   одновременно (число значений и суммарная длина строк). Пороги: ≤50 — enum в схеме; выше — индексный
   выбор из пронумерованного списка.
5. Стиль схем IR по умолчанию: все поля required, опциональность через `null`,
   `additionalProperties: false`, без рекурсии. Порядок полей сохраняется как в IR, не сортируется.
6. Zod — на горячем пути данных; ajv — только на границах (валидация IR-документов и конфигов).

## Промты

- Движок — **liquidjs**, у него есть встроенный статический анализ шаблонов и типизированный AST
  (условия доступны как RPN-массив токенов). Свой мини-парсер не пишем; наш код — визитор ~400–600 строк.
- `{% switch %}` из спеки не нужен: в Liquid это встроенный `{% case %}/{% when %}`.
- Роли сообщений — кастомный блочный тег `{% message system|user|assistant %}`.
- Точка кэширования — поддерево MessageTag без динамических тегов.
- **Промт коммитится явно.** Черновик живёт в `.wf/drafts/<путь>.draft` с `base_file_hash`,
  он в `.gitignore`, вне дерева определений и мимо компилятора.
- Оценка размера — gpt-tokenizer (o200k_base) × поправочный коэффициент профиля модели.

## Данные

- PostgreSQL 18, `uuidv7()` встроен — используем как PK по умолчанию.
- Три схемы в одной БД: `app` (наши таблицы, миграции drizzle-kit), `idx` (индекс определений,
  пишет только роль `wf_indexer`) и `voltagent`
  (@voltagent/postgres делает `CREATE TABLE IF NOT EXISTS` в рантайме, 6 таблиц — не трогаем).
- `run_nodes` партиционируется помесячно `PARTITION BY RANGE (started_at)`, BRIN по времени.
- Блобы по правилу трёх зон: <8 КБ — inline jsonb; 8 КБ–1 МБ — отдельная таблица; >1 МБ — объектное
  хранилище по sha256.
- Мультитенантность с первого дня: `tenant_id` во всех таблицах + RLS.
- Векторный поиск — pgvector 0.8.6 HNSW в нашей схеме. Встроенное векторное хранилище
  @voltagent/postgres **не использует pgvector** (BYTEA + полный перебор) — не берём.
- Миграции forward-only, expand/contract, без down.

## Хранение определений: файлы — истина, база — индекс

Решение — [ADR-0017](adr/0017-files-as-source-of-truth.md), проектирование — [files-first/](files-first/).
[ADR-0016](adr/0016-git-as-release-boundary.md) заменён частично: строка про раскладку канваса в силе.

| Слой | Где живёт |
|---|---|
| Определения: воркфлоу, узлы, промты, типы, компоненты, профили моделей, агенты, тулы | Файлы в репозитории проекта |
| История правок | Git: коммит на эпизод правки, откат только движением вперёд |
| Индекс определений (`type_usages`, `type_impact`, поиск по проекту) | Postgres, схема `idx`, пишет только индексатор |
| Прогоны, трассы, чекпоинты, датасеты, кассеты | Postgres |
| Раскладка канваса (позиции, зум, свёрнутость) | Отдельный ui-канал, LWW по полю, вне спеки и вне `spec_hash` |
| Секреты | Хранилище секретов, в файле только `ref:` |

Раскладка на диске — каталог на воркфлоу, файл на узел: `flows/<flow_id>/flow.yaml` +
`nodes/<node_id>.yaml`, промт отдельным файлом (`<node_id>.prompt.md` или `prompts/<key>.md`).
Идентичность — путь в ФС, поля `id` внутри файлов нет; переименования — в append-only журнал `renames`
в `project.yaml`, его читают все резолверы lineage. Имена `^[a-z][a-z0-9_]{0,62}$`, версий в именах нет.

`base_rev` заменён на CAS по sha256 **байтов файла**: `expects[{path, file_hash}]`, коды отказа
`STALE_FILE`, `FILE_VANISHED`, `FILE_EXISTS`, `LOCK_BUSY`, `TREE_DIRTY`. Правка нескольких файлов —
транзакция `.wf/lock` → staging `.wf/txn/<ulid>` → `intent.json` → атомарные `rename(2)`. Валидатор стоит
**до** сериализации и работает на всём дереве в памяти (`blocking` не пишется, `advisory` пишется
с пометкой): у git нет точки, где слияние можно отклонить, инварианты держит валидатор, а не merge.
Прогон материализует план в снимок в базе и файлы больше не читает; авторитетен хеш содержимого,
а не commit sha. Индекс перестраиваем: `DROP SCHEMA idx CASCADE` с переиндексацией не теряет ничего.
Цена, названная честно: инвариант «невалидное не попадает в историю» перестаёт быть свойством системы
и держится хуком `flow_check` на `PostToolUse` и `wf check` в CI; закоммитить невалидное дерево можно,
**релизнуть нельзя**. Прежние обязательства в силе: секреты и значения в git не попадают, канонизация —
при записи, а не при чтении, политика расхождения множеств по умолчанию `FAIL`.

## Язык описания воркфлоу: только TypeScript

Решение и доказательства — [ADR-0018](adr/0018-typescript-authoring.md),
правила дыр — [ADR-0019](adr/0019-escape-hatch-rules.md).

- **YAML как язык авторинга не вводится.** Определения пишутся на TypeScript: типы, автодополнение,
  рефакторинг, настоящий код для экстракции, слияний и запросов к API.
- **Код строит граф, а не исполняет его.** Синтез односторонний TS → IR, билдер вызывается один раз
  и возвращает `Ref<T>`. Синтез — чистая функция: сеть, ФС, `Date.now`, `Math.random` запрещены
  и подменяются в изоляте.
- **Артефакт синтеза — канонический JSON**, коммитится в репозиторий. На нём держатся дифф версий,
  `spec_hash`, кассеты, бандл и воссоздание 1:1. YAML остаётся только в экспортном бандле.
- **Канвас правит структуру кодмодом** (ts-morph) на декларативном подмножестве; вне подмножества —
  видимая плашка «собран кодом, правьте в редакторе». Тела `code`-узлов кодмод не трогает никогда.
- Замеры: синтез 200 узлов — 27,6 мс вхолодную, 1,9 мс прогретый; тайпчек 50 воркфлоу × 20 шагов —
  0,82 с. Канвас пересобирается на сохранение.

## Версии: хеш вместо номера

Решение — [ADR-0022](adr/0022-hash-as-version.md). Поля `version` в исходнике нет.

- **Идентичность** — `spec_hash` по канонизированному содержимому, вычисляется при синтезе.
  Ею пинятся компоненты, на неё ссылается прогон, по ней строится ключ кассеты.
- **Метка релиза** (`production`, `v7`, дата) присваивается человеком при публикации и живёт
  отдельно от исходника.
- Порядок версий даёт история git и запись о релизе, а не сам идентификатор.
- В интерфейсе — короткий префикс хеша (12 символов), руками человек называет только метки.

## Escape hatch: код даёт значение, но не форму

- Код порождает **значение объявленного слота**, никогда — имя слота, набор слотов или структуру
  шаблона. Проверяется компилятором.
- **R-42:** узел без типа выхода с границами (`maxItems`, `maxLength`) не компилируется.
  Без этого теряются R-T9 и R-C7 — верхняя оценка размера промта.
- **Класс детерминированности** обязателен у узлов с эффектами: `pure` / `stable(ttl)` / `volatile`.
  Один TTL не отвечает, корректно ли переиспользовать результат при других входах.
- **Данные пользователя не попадают в фазу синтеза** — иначе кэш модели становится каналом утечки
  между пользователями.
- Политики живут в хуке `context_rewrite(needs, ctx)` после резолва источников и до рендера,
  а не внутри промта.
- Бюджет escape-узлов на промт и воркфлоу; превышение — предупреждение компилятора.

## Редактирование канваса

Канвас редактируемый руками с первого дня, тот же воркфлоу параллельно правит агент через MCP.
Подробности — [31. Редактирование канваса](31-canvas-editing.md).

- Человек правит **теми же операциями**, что агент: жест мышью → тот же `flow_patch`.
- Два канала записи: определение — файл через `flow_patch` с CAS по хешу файла; раскладка — ui-канал с LWW.
- Два уровня правки на одних байтах: Claude Code пишет файл нативными инструментами (валидация хуком
  после записи), Studio и MCP — через `flow_patch` (валидация до записи); структурные и кросс-файловые
  правки только через `flow_patch`, файловых операций в MCP не заводим.
- Undo — обратный патч, а не откат к коммиту; `flow_revert` пишет восстановленное содержимое новым
  коммитом, а не `git revert` дерева. Стек личный, правки агента молча не отменяет.
- Клиент валидирует только то, что может честно: вид порта, совместимость схемы, цикл.
  Доминирование, полнота enum и обязательные привязки — всегда сервер.

## Human-in-the-loop

- Это **узел ввода, а не подсистема задач**: шести операций `human_task_*` не существует.
- «Что ждёт меня» — `run_list({status: 'suspended'})`, ответ — `run_resume` с payload.
- Форма ввода приходит из `run_get_node` как `form_schema`, развёрнутая из типа.
- Таймаут — не операция: объявлен в узле, исполняется планировщиком.


## MCP-контракт

- **Имена тулов только snake_case**: `flow_create`, `run_replay_node`, `experiment_compare`.
  Точки из §13.1 спеки невалидны (ограничение имени тула в Messages API), имя сервера короткое — `volt`.
- Один конверт ответа: `ok`, `version{blob,etag}`, `focus`, `problems[]`, `candidates[]` с готовым
  `apply{tool,arguments}`, `next[]`, `refs[]`, `ui_url`, `truncated`.
- Фазовое раскрытие через `RegisteredTool.enable()/disable()`: одновременно ≤20–25 тулов,
  ядро 8–10 всегда включено.
- Конкурентность: server-authoritative `flow_patch` с `base_blob` (CAS по sha256 файла). CRDT не берём.
- Claude Code не поддерживает MCP sampling; resources и prompts — не опора, весь контракт в тулах.

## Качество

- Kill-критерий «компилятор ловит 100% мутантов» закрывается **своим доменным IR-мутатором**
  (мутируем IR, а не исходники). Stryker — дополнительно, nightly.
- Гейт выпуска имеет четыре исхода: PASS / WARN / BLOCK / GATE_UNAVAILABLE.
- Статистика: парный бутстрап (BCa, B=10000, фиксированный seed), McNemar для бинарных,
  Wilcoxon signed-rank для порядковых, Holm для primary-семьи и BH для secondary.
  Обязателен A/A-прогон до сравнения A/B. Минимум 200 элементов для блокирующего гейта.
- LLM-судья блокирует выпуск только при weighted kappa ≥ 0.7 и Krippendorff alpha ≥ 0.8.

## Экспорт

- Канонизация — `canonicalize@5.0.0` (RFC 8785), хеш — `@noble/hashes` sha256 с доменной сепарацией,
  префикс `sha256-`.
- Источник истины — файл YAML в рабочем дереве; JSONB — индекс. Опции сериализации фиксированы,
  якоря и комментарии запрещены.
- Бандл — детерминированный tar (`tar-stream`), хеш по `.tar`, Merkle-корень с путём в листе.
- Кассеты — свой content-addressed формат на уровне порта модели/тула, не HTTP-моки.
- Codegen — шаблонные строки + prettier, таблица эмиттеров `Record<kind, Emitter>` (Strategy).
- Вторая цель миграции для kill-критерия 14 — Mastra; LangGraph — стресс-тест семантики.

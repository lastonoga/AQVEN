# Канвас правит DSL: таблица обратимости и кодмод (срез 2)

Статус: draft. Источники: ADR-0018 (кодмод по декларативному подмножеству), ADR-0017 (файлы, CAS,
байтовый фикспойнт), ADR-0019 (R-42), `03-core-language` (семантика), `04-ir-schema` (хеши),
`dsl/shape.md` (форма литералов, срез 1).

Решение заказчика сдвинуло периметр относительно `research/ts-our-design.md` §4: модель (C)
«канвас только инспектор + `overlay.yaml`» **отменена**. DSL декларативен, соответствие
литерал ↔ узел IR один-к-одному, поэтому канвас правит само определение. Оверлея нет: скаляр,
который раньше лёг бы в `overlay.yaml`, теперь правится в самом литерале и попадает в `spec_hash`.

## 1. Таблица обратимости

Якорь у всех правок один: **узел — это `CallExpression` фабрики DSL, первый аргумент которого —
строковый литерал `id`, второй — `ObjectLiteralExpression`**, привязанный к `VariableDeclaration`.
Поиск якоря по id — `SyntaxKind.CallExpression` → `getArguments()[0].getLiteralValue() === id`,
а не по позиции в файле. Исходник — один `flows/<flow_id>/flow.ts`; «файл на узел» из ADR-0017
остаётся у синтезированного IR, у исходника его нет.

| Жест на канвасе | Кодмод ts-morph | Узел AST | Не-локальность |
|---|---|---|---|
| Добавить узел | `Block.insertStatements(i, text)` в теле билдера | `Block` замыкания `flow(...)(($) => { … })` | нет, если слоты пустые |
| Удалить узел | `VariableStatement.remove()` | `VariableStatement` | **да**: `findReferencesAsNodes()` по `VariableDeclaration`; есть ссылки — отказ (см. §3) |
| Переименовать узел | `.rename(newId)` на `VariableDeclaration` + `setLiteralValue` на арг-0 | `Identifier` + `StringLiteral` | rename идёт через language service, правит все `Ref`; запись в журнал `renames` (ADR-0017) |
| Перепривязать слот | `PropertyAssignment.setInitializer("other.out.field")` | `PropertyAssignment` внутри `in:` | нет |
| Отвязать слот | `PropertyAssignment.remove()` | там же | нет |
| Изменить параметр (`modelRole`, `timeoutMs`, `ttlSeconds`, `retry`) | `setInitializer` если есть, `addPropertyAssignment` если нет, `remove()` при возврате к дефолту | `PropertyAssignment` / `ObjectLiteralExpression` | нет |
| Изменить `concurrency`, `maxItems`, `onItemError` | то же, на литерале `map` | `PropertyAssignment` | нет |
| Добавить ветку в `switch` | `cases.addPropertyAssignment({ name, initializer })` | `ObjectLiteralExpression` поля `cases` | полнота проверяется `tsc` (TS2322 `not assignable to 'never'`), а не кодмодом |
| Удалить ветку | `PropertyAssignment.remove()` в `cases` | там же | если ветка вела `goto` в узел, узел остаётся сиротой — advisory |
| Изменить `parallel` (состав веток) | `ArrayLiteralExpression.insertElement` / `removeElement` | `ArrayLiteralExpression` | нет |
| Обернуть в компонент | четыре шага одной транзакцией: `component(...)` вставляется выше, отобранные `VariableStatement` переносятся в его тело, на их месте — один `call(...)`, входы/выходы переписываются на `p.*` | несколько `VariableStatement` + новый `Block` | **да**: единственный жест, переписывающий несколько диапазонов; требует, чтобы каждый переносимый узел был в подмножестве |
| Развернуть компонент обратно | обратная перестановка | то же | да |
| Двигать узел, зум, свёртка | **кодмода нет** | — | §4 |
| Править тело `code`-узла | **кодмода нет никогда** | — | ADR-0018, инвариант продукта |
| Править текст промта | **кодмода нет** — правка `<node_id>.prompt.md` | — | ADR-0017; меняется `prompt_pins`, не `spec_hash` |

Жест всегда описывается **по id узла и имени поля**, а не по смещению в файле: между открытием
канваса и применением правки файл мог измениться (§5), и смещения протухают, а id — нет.

## 2. Гарантия неразрушения — проба

**Правило.** Кодмод объявляет целевой диапазон `[start, end)` — узел AST, который он собирается
менять, — и после правки диапазон фактического изменения обязан лежать внутри объявленного.
Проверка механическая и не зависит от кодмода: берём байты до и после, отрезаем общий префикс
и общий суффикс, получаем фактический изменённый диапазон, сравниваем с объявленным.
Несовпадение — `NON_LOCAL_EDIT`: правка откатывается целиком (`SourceFile` не пишется на диск),
канвас показывает «правка задела код вне узла, применить не могу», и жест уходит в §3.

Проба: ts-morph 28.0.0, Node 20.19.0, исходник — DSL с комментарием, пустой строкой внутри тела
`code`-узла и `switch` с двумя ветками; три жеста одной сессией.

```
syntax errors in fixture: 0
concurrency 8 -> 16:        changed bytes [297,298) target [223,332)  local=true
switch: +case escalate:     changed bytes [971,971) target [928,973)  local=true
add node render:            changed bytes [827,827) target [183,1039) local=true
code body byte-identical: true
comment preserved: true
blank line inside body preserved: true
```

Дифф после кодмода и обязательного прогона `prettier`:

```diff
     {
       over: $.input.hotels,
       itemType: T.Hotel,
-      concurrency: 8,
+      concurrency: 16,
       onItemError: "skip",
     },
@@
       return rows.slice(0, 3).map((r) => r.hotel);
     },
   });
+  const render = code("render", {
+    in: { pitch: top3.out.head },
+    out: T.PitchText,
+    body: (i) => i.pitch.text,
+  });
 
   const pick = sw("pick", {
-    cases: { lux: top3.out.head, budget: top3.out.tail },
+    cases: {
+      lux: top3.out.head,
+      budget: top3.out.tail,
+      escalate: top3.out.head,
+    },
   });
```

Подтверждено пробой: тело `code`-узла не изменилось ни на байт (sha256/12 `65721882666c` до
и после всей цепочки, включая `prettier`), комментарий над узлом на месте, пустая строка-разделитель
внутри тела на месте, импорты и `return` не тронуты. Две вставки дали **пустой** изменённый
диапазон `[n,n)` — это чистая вставка, ни один существующий байт не переписан.

Честная граница гарантии: `prettier` может **расширить** изменённый диапазон до объемлющего
литерала — в диффе выше `cases` переехал с одной строки на четыре, потому что перестал влезать
в ширину. Поэтому объявленный диапазон для проверки берётся не от самого поля, а от **объемлющего
`VariableStatement`**; шире этого — отказ. Проверка запускается на результате прогона `prettier`,
а не до него.

Без `prettier` ts-morph ставит отступ вставки на чужой уровень (`const render` встал с отступом 4
вместо 2) — воспроизведено, совпадает с `research/ts-roundtrip-canvas` §2.

## 3. Когда кодмод невозможен

Отказ бывает трёх видов, и человек должен видеть разные плашки, потому что чинятся они по-разному.

| Вид | Причина | Область | Плашка и действие |
|---|---|---|---|
| **Вне подмножества** | в файле цикл, условие, `spread`, вычисляемый ключ, тернарник в аргументе DSL — граф порождается кодом | весь воркфлоу | «Собран кодом, правка мышью недоступна» + кнопки «Открыть в редакторе», «Развернуть в IR» (ADR-0018, необратимо, спрашивает подтверждение), «Поручить Claude Code» |
| **Узел не литерал** | `id` не строковый литерал, второй аргумент — переменная или вызов | один узел, остальной канвас живой | Узел рисуется серым, в инспекторе «значение собрано кодом, правьте в редакторе», ссылка на строку файла |
| **Правка задела чужое** | `NON_LOCAL_EDIT` из §2 или `findReferencesAsNodes` нашёл живые ссылки на удаляемый узел | один жест | «Не применил: правка вышла за узел / узел используется в `pick.in.hotels`». Для удаления — «Сначала отвязать 2 слота», список с переходом |

**Автопочинки нет и не будет ни для первого, ни для второго вида.** Развернуть цикл обратно
в литералы автоматически — это и есть обращение функции многие-к-одному, которое ADR-0018 признал
невозможным; все три известных провала (Blockly, Pagedraw, UML) ровно здесь. «Развернуть в IR» —
не автопочинка, а явный `eject` рукой человека: TS-файл удаляется, воркфлоу переходит в состояние
«без исходника».

Автопочинка есть только для того, что сломали мы сами: неверный отступ после вставки лечится
`prettier` (§6), недостающее поле литерала — добавлением, `blocking`-диагностика валидатора —
откатом жеста до записи (ADR-0017: невалидное не пишется вовсе).

Диагностика подмножества считается **до открытия канваса** одним проходом и кешируется по хешу файла:
«не тащится узел» не должно выясняться в момент перетаскивания.

## 4. Позиции узлов

Раскладка в определение не попадает: `layout: { x, y }` в литерале узла **запрещён линтом**
(набросок в `research/ts-roundtrip-canvas` §2 здесь не образец). Координата живёт в LWW-канале
Postgres по ключу `(flow_id, node_id)` — прямая строка ADR-0017.

Новый узел рождается в двух сценариях, и владелец координаты в них разный.

| Кто создал | Координата | Правило |
|---|---|---|
| Канвас (дроп на холст) | точка дропа, владелец — канвас | координата пишется в LWW-канал **после** успешного кодмода, одним ULID-эпизодом; кодмод упал — строка не пишется |
| Claude Code или человек в редакторе | координаты нет | канвас **вычисляет** её при чтении: правее самого правого источника входа, свободная дорожка по вертикали, шаг сетки. В базу не пишется, пока человек не подвинет узел руками |

Смысл второго правила: отсутствие строки в LWW — валидное состояние «позиция ещё не назначена»,
а не ошибка. Иначе правка файла агентом перестала бы быть самодостаточной. Потеря всей раскладки
(`DROP SCHEMA idx`) — косметика: граф разложится автоматически.

Переименование переносит строку LWW через журнал `renames` (ADR-0017) — иначе узел «прыгает».

## 5. Конкурентность

Канвас читает `flows/<id>/flow.ts`, запоминает `file_hash` и присылает его в `expects`
вместе с жестом. Механизм — CAS ADR-0017, отдельной схемы для канваса не заводим;
межпроцессная блокировка `.aqven/lock` защищает от одновременной записи Studio и Claude Code.

Расхождение даёт `STALE_FILE`. Тогда: перечитать файл, найти якорь **по id узла и имени поля**
(§1), сравнить текст целевого литерала с тем, что канвас видел. Литерал байт в байт тот же —
жест применяется автоматически, один раз, без вопроса: правка Claude Code была в другом месте
файла. Литерал изменился — плашка «Узел `score` изменён в редакторе», дифф литерала было/стало
и две кнопки: «Применить поверх», «Отменить мою правку». Молча не применяем ничего.

## 6. Форматирование

**Решение: `prettier` обязателен, прогоняется на весь изменённый файл, сразу после кодмода
и до проверки §2.** Он и есть канонизация TS при записи — ровно та роль, которую ADR-0017 отводит
канонизации JSON: без неё байтовый фикспойнт `write → read → write` не держится, потому что
ts-morph печатает вставки с чужим отступом (воспроизведено в §2).

Следствие, которое надо принять явно: **«репозиторий prettier-чист» становится инвариантом**,
его держит тот же хук `flow_check` на `PostToolUse` и pre-commit. На чистом файле прогон трогает
только изменённые диапазоны — доказано в §2, дифф из трёх жестов содержит ровно три изменения.
На грязном файле прогон переформатировал бы весь файл и утопил жест в шуме, поэтому канвас на таком
файле правку **не делает**: плашка «Файл не отформатирован» и кнопка `aqven fmt` отдельным эпизодом.

Проверено: `prettier` 3.9.6 умеет `rangeStart/rangeEnd` и честно держится диапазона, но исходный
отступ строки сохраняет, то есть ошибку ts-morph не чинит — как запасной режим не годится, поэтому
и не вводится.

Версия `prettier` и конфиг пинятся в `aqven.lock.yaml`. Апгрейд версии — отдельный коммит массового
переформатирования, никогда не в одном эпизоде с жестом канваса: иначе первый же жест после
апгрейда выглядит как правка всего файла.

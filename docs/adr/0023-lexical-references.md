# ADR-0023. Узлы связываются лексическими ссылками, а не строковыми путями

> Статус: принято
> Дата: 2026-09-14
> Заменяет решение о привязках в: [dsl/shape.md](../dsl/shape.md) §3
> Зависит от: [ADR-0018](0018-typescript-authoring.md)
> Доказательства: [dsl/refs-form.md](../dsl/refs-form.md), [dsl/refs-codemod.md](../dsl/refs-codemod.md), [dsl/refs-types.md](../dsl/refs-types.md)

## Контекст

Первый черновик DSL связывал узлы строковыми путями (`"$load_hotels.out"`) с проверкой через
тип-level парсер `Resolve<S, P>`. Отказ от ссылок был обоснован так: «прокси возвращает билдер
с замыканиями, id узла живёт в трёх местах».

Заказчик предложил вернуться к ссылкам. Довод оказался неприменим: **лексическая ссылка — не
прокси-билдер**. Узлы остаются `const` с объектными литералами, единственное замыкание — тело `map`.

Проверено запуском, а не рассуждением: TypeScript 6.0.3 `--strict`, Node 20.19.0, ts-morph 28.0.0,
проба `scratchpad/probe-dsl`.

| Замер (50 воркфлоу) | Строки | Ссылки |
|---|---|---|
| 20 узлов: инстанциаций / время / память | 267 038 / 0,37 с / 114,7 МБ | **130 645 / 0,28 с / 101,8 МБ** |
| 80 узлов | 1 060 058 / 1,47 с / 367,4 МБ | **526 645 / 1,03 с / 185,5 МБ** |
| 1000 узлов в одном литерале | 585 048 | **133 585** (4,4×) |

Качество диагностики (реальные тексты):

| Случай | Строки | Ссылки |
|---|---|---|
| Опечатка в имени узла | TS2322 на позиции слота | **TS2552 `Cannot find name 'lod_hotels'. Did you mean 'load_hotels'?`** |
| Опечатка в поле выхода | разбор пути типом | **TS2551 `Did you mean 'decision'?`** |
| `$item` вне тела `map` | типами не ловится | **TS2304 `Cannot find name 'hotel'`** |
| Ссылка вперёд | не ловится | **TS2448 + TS2454, ошибка компиляции** |

## Решение

**Узел объявляется значением, ссылка — обращение к нему.** IR не меняется: синтез резолвит объекты
ссылок в те же строки грамматики [04](../04-ir-schema.md) §3.1 — проверено побайтовым совпадением
с прежней формой.

**Идентификатор узла — явный первый аргумент фабрики**, а не имя переменной:

```ts
const load_hotels = tool("load_hotels", { tool: hotelsByFilters, in: { filters: input.filters } })
```

Вариант «id из имени переменной через сокращённое свойство» отвергнут доказательством: `ts-morph
rename` переменной переписывает и сокращённый ключ, то есть локальный рефакторинг **молча сменил бы
`node_id` в IR**. А `node_id` — доменный идентификатор: он в трассах, кассетах, датасетах и истории
прогонов. Это ловушка логических ID у AWS CDK, которую чинили восемь лет, и обязательство ADR-0018
прямо требует её не повторять.

Следствие: переименование узла — намеренная операция из двух частей (переменная и id-литерал)
с записью в журнал `renames` (ADR-0017), а не побочный эффект рефакторинга IDE.

**Порядок объявлений топологический.** Ссылка вперёд — ошибка компиляции. В `hotel_pitch`
достигается переносом трёх строк.

**`$item` — замыкание** `do: (hotel) => llm("score", {...})`, а не символ. Линтер ограничивает тело
одним вызовом фабрики с объектным литералом: без условий, блоков и `return`. Поэтому «код не
порождает форму» (ADR-0019) остаётся истинным синтаксически, а тело остаётся литералом под кодмодом.

### Что это даёт сверх удобства

- **Ацикличность переходит с L1 на L0.** `const` нельзя использовать до объявления, поэтому цикл
  в графе данных невыразим. Это перестаёт быть правилом компилятора и становится свойством языка.
- **Исчезает тип-level парсер путей** — одна из трёх реализаций грамматики, записанная в риски.
- **Кодмод надёжнее:** три не-локальных жеста (удаление, переименование, обёртка) делает language
  service вместо самописного разбора строк. Объявленный диапазон правки сужается с 1287 байт
  (вся запись `nodes`) до 49 байт. Поиск ссылок точен: `findReferencesAsNodes` против текстового
  поиска, дававшего ложные попадания.
- **Автодополнение работает везде** — цена строковой формы, записанная ранее, отменяется.

### Единственная потеря

Проверка «ссылка на узел, отсутствующий в списке `nodes`» уходит из `tsc` в синтез: сообщение
появляется позже и без позиции в файле, пока синтез не начнёт класть `meta.source`.

## Альтернативы

| Альтернатива | Почему отвергнута |
|---|---|
| Строковые пути с `Resolve<S, P>` | Дороже вдвое по типам, хуже диагностика, третья реализация грамматики, нет автодополнения внутри узла |
| Прокси-билдер | Замыкания, id в трёх местах, правка требует пересинтеза — исходный довод остаётся верным для прокси |
| id из имени переменной | `rename` молча меняет доменный идентификатор — ловушка CDK |
| Запись `nodes` вместо массива | Заводит третье имя того же узла |

## Последствия

**Положительные.** Дешевле тайпчек, лучше ошибки, надёжнее кодмод, ацикличность бесплатно.

**Отрицательные.** Автор обязан объявлять узлы в топологическом порядке. Добавление узла правит два
места — объявление и элемент массива. Согласованность имени переменной и id-литерала держится
линтером, а не языком.

**Обязательства.** Линтер: ограничение тела `map`, согласованность имени и id, топологический порядок.
Кодмод переименования правит обе части и пишет в журнал `renames`. Синтез кладёт `meta.source`,
чтобы ошибка про незарегистрированный узел имела позицию.

## Проверка

- `hotel_pitch` на ссылках компилируется без ошибок и синтезируется в IR, побайтово совпадающий
  с прежней формой.
- Два прогона синтеза дают идентичный файл.
- `rename` переменной без правки id-литерала ловится линтером.
- Цикл в графе данных невыразим: попытка даёт TS2448.

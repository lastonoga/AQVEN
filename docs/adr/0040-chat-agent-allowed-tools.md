# ADR-0040. Разрешения чат-агента задаёт запуск, а не файлы проекта: `--chat-allow-tool`

> Статус: принято
> Дата: 2026-09-21
> Зависит от: [ADR-0030](0030-local-browser-backend.md) §6 и поправка `A14`
> Дополняет в части `.env` и списка автоодобрений: [ADR-0030](0030-local-browser-backend.md) `A14`
> Источники: поведение `allowed_tools` и `setting_sources` — исходники `claude_agent_sdk` 0.2.154 в `.venv`; обходы защиты `.env` найдены запуском `SecretFileGuard.violation` на наборе команд 2026-09-21

## Контекст

Чат-агент Studio спрашивал одобрение на **каждый** вызов `Bash`, включая `cat aqven.yaml` и `head README.md`.
Причина — `setting_sources=[]` в [claude_options.py](../../packages/aqven/src/aqven/chat/claude_options.py):
SDK называет это «SDK isolation mode», никакие файлы настроек не читаются, значит списка разрешений не
существует вовсе, а `permission_mode="default"` вместе с `can_use_tool` отправляет каждый вызов в UI.

Очевидный ход — включить `setting_sources=["project"]` и класть разрешения в `.claude/settings.json` проекта.
Он отвергнут по трём причинам, каждая проверена:

| Проблема | Факт |
|---|---|
| Файл настроек ничем не защищён | `disallowed_tools` закрывает только временный MCP-конфиг (`McpConfigFile.locations()`), не `.claude/settings.json`. Агент правит проект, значит может вписать себе права и работать без спроса |
| Утечка пользовательской области | источник `"user"` — это `~/.claude/settings.json` разработчика; у человека, поставившего AQVEN с PyPI, там произвольная конфигурация |
| Задвоение правил проекта | дока SDK: «Must include `"project"` to load CLAUDE.md files». AQVEN уже дописывает `CLAUDE.md` и `AGENTS.md` в системный промт сам ([project_rules.py](../../packages/aqven/src/aqven/chat/project_rules.py)); включение `"project"` подало бы их дважды |
| Шаблон всё равно не помог бы | в `.claude/settings.json` из шаблона проекта нет блока `permissions` — только хуки `aqven check` |

**Отдельная находка.** `allowed_tools` шунтирует `can_use_tool`: дока SDK дважды повторяет «To gate every tool
call, use a PreToolUse hook instead». Значит для автоодобренных команд единственной защитой `.env` остаётся
хук `SecretFileGuard`, а он разбирает строку команды эвристикой. Прогон показал три прохода:

```
ALLOWED  cat .e''nv
ALLOWED  cat .en\v
ALLOWED  python3 -c "print(open(chr(46)+'env').read())"
```

Пока каждую команду одобряет человек, это терпимо: на `cat .e''nv` человек насторожится. При автоодобрении
`Bash(cat:*)` первая строка молча отдала бы ключи провайдеров.

## Решение

**Список автоодобрений передаётся из точки запуска, а не из файлов проекта.**

1. `ClaudeChatSettings.allowed_tools` → `ClaudeAgentOptions.allowed_tools`; `setting_sources=[]` остаётся.
   Цепочка: `--chat-allow-tool` → `ServerOptions.chat_allowed_tools` → `ApplicationLaunch` → `chat_parts` →
   `studio_chat_parts` → `create_claude_chat`. Решение принимает человек в командной строке, и агент не может
   его расширить: файла, который он правит, в этой цепочке нет.
2. **По умолчанию список пуст** — поведение не меняется ни для кого, кто флаг не передал.
3. **Эвристика `.env` укреплена до внедрения флага.** Сегменты команды нормализуются снятием `'`, `"` и `\`
   перед сверкой с именами `.env`, а кавычки и обратный слеш убраны из разделителей, чтобы они не разрывали
   имя файла. Два из трёх обходов закрыты.
4. **Третий обход не закрывается и не будет.** `python3 -c "..."` — произвольный код, текстовый анализ здесь
   бессилен. Отсюда правило: интерпретаторы (`python`, `node`, `sh`, `perl`) в список автоодобрений не
   попадают никогда, и это сказано в тексте справки флага и в документации.

Рекомендуемый безопасный набор — инструменты, принимающие **настоящий путь**, а не строку shell: `Read`,
`Grep`, `Glob`. Для них у гварда есть поле `file_path`/`path`/`pattern`, обойти кавычками нечего.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| `setting_sources=["project"]` и `permissions` в `.claude/settings.json` | самоавторизация агента, утечка пользовательской области, задвоение `CLAUDE.md` — см. «Контекст» |
| Список в `aqven.yaml` | тот же файл проекта, который правит агент: самоавторизация возвращается |
| `permission_mode="bypassPermissions"` | SDK прямо предупреждает, что `can_use_tool` не вызывается совсем; остаётся только хук, эвристика которого пробиваема |
| Настройка в Studio через SQLite | человеческое решение, но требует UI и живёт между запусками; флаг запуска даёт то же, а область действия — один процесс |
| Ничего не менять, только промтом уводить агента на MCP-тулы | помогает, но не даёт управления: агент всё равно волен взять `Bash`. Может быть сделано дополнительно |

## Последствия

- Для всех, кто не передал флаг, ничего не изменилось: список пуст, спрашивается всё как раньше.
- Укрепление гварда действует **всегда**, а не только при автоодобрении: `cat .e''nv` теперь запрещён и в
  ручном режиме.
- Правила `Bash(...)` матчатся по префиксу команды, а shell позволяет композицию через `;`, `&&`, пайпы и
  подстановку. Префикс — слабая граница, и это цена флага; она приемлема ровно потому, что дефолт пуст и
  решение принимает человек.
- `--chat-allow-tool` относится только к бэкенду Claude. У Codex своя модель — профиль файловой системы с
  `deny` на `.env` ([codex_policy.py](../../packages/aqven/src/aqven/chat/codex_policy.py)), его флаг не трогает.

## Пересмотр

Запись пересматривается, если SDK начнёт пропускать `PreToolUse` при автоодобрении (тогда флаг придётся
снять), если появится разбор shell вместо эвристики по тексту, или если Claude-бэкенд получит песочницу
файловой системы наподобие той, что уже есть у Codex.

## Открытые вопросы

1. **Эвристика вместо разбора shell.** `SecretFileGuard` ищет имена `.env` в тексте команды. Надёжный путь —
   разбирать команду как shell и отклонять всё, где путь вычисляется, а не записан буквально. Закрыть:
   отдельная работа, после неё `Bash(cat:*)` станет безопасным кандидатом на автоодобрение.
2. **Промт в пользу MCP-тулов.** Агент берёт `Bash` там, где хватило бы типизированного тула сервера `aqven`.
   Закрыть: правка системного промта и шаблонного `AGENTS.md`, замер доли вызовов `Bash` до и после.
3. **`.claude/settings.json` не защищён от записи агентом.** Сейчас это безвредно, потому что файл не
   читается. Закрыть: добавить его в `disallowed_tools`, чтобы включение источников настроек в будущем не
   открыло дыру задним числом.

# ADR-0035. Диапазон этапов при запуске Dataset

> Статус: принято
> Дата: 2026-09-18
> Частично меняет: [ADR-0033](0033-flow-datasets-and-scoped-runs.md) для запуска Dataset из Studio

## Контекст

`selected_nodes` выбирает целевые узлы, после чего движок автоматически исполняет все их зависимости. Поэтому проверка одного среднего этапа всё равно запускает начало flow. Инженеру нужно проверять отдельный этап или непрерывный участок на данных Dataset, не повторяя подготовительные узлы. Доступные границы должны быть видны до запуска.

## Решение

1. На странице Datasets запуск задаётся двумя границами на шкале верхнеуровневых узлов в `flow.order`. Обе границы привязаны к узлам и включены в диапазон. Движок исполняет только узлы диапазона в порядке flow; дочерние узлы выбранного контейнера исполняются по его обычной логике.
2. Кейс Dataset может содержать `node_outputs`: значения выходов ранее выполненных верхнеуровневых узлов, индексированные по ID узла. Вход `inputs` и `context` могут содержать только данные, нужные выбранному диапазону. Эти значения служат фикстурой на границе; предоставленные узлы не становятся исполнениями в Runs.
3. Доступность каждой пары границ вычисляет backend для всех кейсов, которые будут запущены. Пара доступна, если ссылки внутри диапазона разрешаются из `inputs`, `context`, выходов узлов диапазона и предоставленных `node_outputs`. Причины недоступности включают кейс и отсутствующую ссылку. Studio показывает недоступные границы серым цветом, а запуск неактивен, пока выбранный диапазон недоступен.
4. API запуска run и группы run принимает пару `start_node`/`end_node`. Передача только одной границы, неизвестного или вложенного узла, либо диапазона с недостающими данными отвергается до запуска. Без границ сохраняется полный flow; прежний `selected_nodes` и его транзитивные зависимости остаются совместимыми для других клиентов.
5. Для одиночного run проверяется открытый кейс. Для группового запуска проверяются все выбранные кейсы. У каждого действия в Studio собственный результат проверки, чтобы доступность одного кейса не разрешала ошибочный групповой запуск.

## Альтернативы

| Вариант | Почему не взят |
|---|---|
| Расширить `selected_nodes` | Его существующий смысл включает зависимости; изменение сломало бы прежние запуски |
| Выбирать произвольные узлы чекбоксами | Результат сложнее понять; запрос пользователя — непрерывный участок процесса |
| Вычислять доступность только в браузере | У браузера нет гарантированно той же семантики ссылок, что у движка |

## Последствия

- Dataset может одновременно хранить вход полного flow и значения для проверки этапов в середине.
- Диапазон с серой начальной точкой требует дополнительных данных в кейсах; Studio показывает, каких именно.
- Частичный run описывает результат выбранных этапов, а не итог всего flow.
- Предварительная доступность проверяет наличие ссылок и полей в фикстуре. Полная совместимость значений с типами входа проверяется при исполнении узла.

## Проверка

- Запуск одного среднего узла с выходом предшественника в `node_outputs` создаёт исполнение только этого узла.
- Пропущенная фикстура даёт одинаковый отказ в предварительной проверке и при попытке запуска через API.
- Полный запуск и старый `selected_nodes` сохраняют прежний порядок исполнения.
- В Studio две границы перемещаются только между узлами; групповой запуск блокируется, если хотя бы одному выбранному кейсу не хватает данных.

## Пересмотр

Если понадобится запускать вложенный узел отдельно от контейнера, определить явную форму его локального контекста (`$item`, `$case`, `$acc`, ветка и итерация), прежде чем показывать его как независимую отметку шкалы.

# ADR-0032. Маршруты студии и словарь домена — зеркало сущностей движка

> Статус: **принято** (2026-09-18)
> Дата: 2026-09-18
>
> Зависит от: [ADR-0026](0026-yaml-spec-and-code-refs.md), [ADR-0028](0028-studio-api-contract.md), [ADR-0030](0030-local-browser-backend.md)
> Меняет в части маршрутов и словаря: [ADR-0024](0024-studio-on-vite.md), [15. Studio](../15-studio-frontend.md)
> Контракт маршрутов и событий API: [23. Studio API](../23-studio-api.md)

## Контекст

`apps/studio` собирался как прототип поверх мок-бэкенда, у которого сущности были придуманы
до движка: `workspace`, `workflow`, `stage`, реестр `signature`/`profile`/`adapter`, нумерованные
ревизии, `NodeKind = tool|llm|fn|human|image|audio|video`, трёхзначный `Outcome = ok|degraded|failed`.
Ни одна из этих сущностей не существует в движке ADR-0030: сервер отдаёт один проект на процесс
(`ProjectInfo.root`, `ProjectInfo.package`), `FlowSummary.flow_id`, десять видов узла, шесть статусов
прогона и семь статусов исполнения, вложенность узлов через `parent`, а не через ступени.

URL повторял выдумку: `/$locale/$workspaceId/$workflowId/<mode>`, где первый сегмент — идентификатор,
которого у движка нет. Параллельно в дереве успел появиться второй шелл на `/$locale/$flowId/*` —
две оболочки, два пикера, два набора вкладок на одни и те же данные.

Динамический сегмент первого уровня несёт ещё и ловушку. По [ADR-0026](0026-yaml-spec-and-code-refs.md) §2
воркфлоу — это каталог `flows/<flow_id>/`, имя которого ограничено только `^[a-z][a-z0-9_]{0,62}$`.
Каталог `flows/project/` или `flows/settings/` законен, а в маршрутизаторе статический сегмент
ранжируется выше динамического — такой воркфлоу оказался бы недостижим, молча, без ошибки.

## Решение

**Один шелл, один URL, словарь — зеркало `packages/api-types`.**

### 1. Форма URL

```
/                                     → редирект на воркфлоу из lib/landing.ts
/flows/$flowId                        → оболочка: чат слева, рамка воркфлоу справа
/flows/$flowId/{canvas|nodes|runs|datasets|review|evals}
/project  /settings  /setup
```

Английский — язык студии по умолчанию; сегмента локали в URL нет. Провайдер переводов
устанавливается в корневом маршруте. Прежние ссылки с `/en/` перенаправляются на адрес без
языкового сегмента с сохранением поисковых параметров.

Статический сегмент `flows` — не украшение. Он повторяет раскладку на диске (`flows/<flow_id>/`)
и снимает конфликт статических маршрутов с динамическим: воркфлоу с именем `project` открывается
как `/flows/project/canvas`, а обзор проекта остаётся на `/project`. Альтернатива — список
зарезервированных имён — требовала бы второй формы URL для зарезервированного имени, то есть
того же сегмента, только неявно.

Сегменты `workspaceId` и `workflowId` исчезают: у сервера один проект на процесс, переключателя
рабочих пространств нет, заголовок пикера рисует `ProjectInfo.package` и `FlowSummary.flow_id`.

### 2. Набор вкладок

| Вкладка | Чем закрыта |
|---|---|
| `canvas` | `GET /api/flows/{id}/nodes`, `/nodes/{node_id}` |
| `nodes` | то же, плюс `/nodes/{node_id}/prompt` |
| `runs` | `GET /api/runs?flow_id`, `/api/runs/{id}`, `/executions`, `/executions/detail` |
| `review` | `GET /api/runs?flow_id&status=suspended` → `RunSummary.waits[]`, `POST /api/runs/{id}/resume` |
| `evals` | `GET /api/files?kind=Eval`, `?kind=Dataset`, `GET /api/raw/{path}` |

`schema` и `dataflow` прототипа схлопываются в `canvas` и `runs`. Ступеней (`stage`) в наборе нет:
вложенность узла — `NodeSummary.parent`, контейнер — вид узла `parallel|map|loop|switch|call`.

**Вкладка `evals` остаётся и переводится на реальные сущности.** Выделенного REST-ресурса для
эвалов и датасетов среди маршрутов API сегодня нет, но сами сущности реальны: по
[DECISIONS.md](../DECISIONS.md) датасет живёт файлом `datasets/<name>.yaml` в формате pydantic-evals,
а витрина `lumen` содержит `evals/support_case/reply_quality.yaml` вида `Eval` и
`evals/support_case/reply_cases.yaml` вида `Dataset` — оба проиндексированы и читаются через индекс
файлов. Экран не выдумка прототипа и не удаляется; он читает индекс `GET /api/files?kind=`,
фильтруя по префиксу пути `evals/<flow_id>/`, пока не появится собственный ресурс.

### 3. Словарь домена

`src/domain/vocabulary.ts` перестаёт быть авторским: каждый набор объявлен кортежем `as const`
и сверен с `components["schemas"][...]` из `@aqven/api-types` через нулевой по рантайму
`Verified<SameSet<...>>`. Регенерация типов движка, добавившая или убравшая член, ломает сборку,
а не расходится молча. Ветки прототипа (`Outcome`, `StageKind`, `RegistryKind`, `RevisionStatus`,
`GatewayMode`, `TestHealth`) удаляются вместе с экранами, которые их рисовали.

Тон статуса в `src/components/studio/presets.ts` раскладывается по реальным перечислениям:
`RUN_STATUS_TONE`, `EXECUTION_STATUS_TONE`, `COMPILE_STATUS_TONE`, `INDEX_STATUS_TONE`,
`WAIT_STATE_TONE`, `SEVERITY_TONE`. `degraded` больше не статус прогона — это флаг исполнения
`NodeExecution.degraded`, поэтому значок прогона его не показывает.

### 4. Ссылка на прогон

Идентификаторы прогона — UUIDv7, у соседних прогонов совпадает вся первая группа
(`01a0b104-4658-…`, `01a0b104-41b6-…`). Короткая ссылка — последние шесть шестнадцатеричных
(`#b56d92`), полный идентификатор — в `title` и в поисковом параметре `?run=`.

## Альтернативы

- **Оставить `/$locale/$flowId/*` с охраной зарезервированных имён.** Охрана требует при коллизии
  увести воркфлоу на другой путь — то есть завести вторую форму URL. Сегмент `flows` делает то же
  самое явно и один раз.
- **Оставить вкладку `tests` прототипа как есть.** Её данные (наборы строк, вердикты, гейты)
  придуманы; но сама тема реальна, поэтому вкладка не удаляется, а переводится на `Eval`/`Dataset`.
- **Не показывать `evals`, пока нет REST-ресурса.** Отвергнуто владельцем: эвалы и датасеты —
  первоклассные сущности продукта, индекс файлов их уже отдаёт, и скрывать работающее чтение
  ради будущего маршрута незачем.
- **Держать словарь руками, сверяя глазами.** Прототип так и жил и разошёлся с движком по всем
  перечислениям сразу.

## Последствия

- Все закладки и ссылки прототипа перестают работать. Редиректа со старой формы нет: прототип
  не выпускался, совместимость стоила бы маршрута-призрака в дереве.
- `src/features/workspace` (второй шелл) удалён; из него перенесены ряд статус-чипов
  `вход → выход · проблемы · последний прогон`, вывод буквы проекта и реальные пункты пикера.
- Экраны вкладок переезжают волнами. Пока волна не приземлилась, файл маршрута уже существует
  и импортирует прежний компонент — дерево маршрутов остаётся целым, ошибки локализованы в экране.
- Пространства сообщений `workspace`, `callSheet`, `dataflow`, `schema`, `trace` удалены;
  `runs` заведено; `domain` переписано под перечисления движка.

## Проверка

- `src/features/shell/presenters.test.ts` — строки пикера и чипы рамки считаются на записанных
  ответах `lumen` (`30 nodes · run #bf2e9a · 1h ago`, `CaseRequest → CaseOutcome`).
- `src/features/shell/shell.test.tsx` — рендер `/flows/support_case/review` даёт вкладки
  вкладок, значок прогона ведёт на `runs?run=<полный uuid>`, `judge_panel` без прогонов значка
  не рисует, неизвестный воркфлоу даёт «Page not found».
- `src/i18n/messages.test.ts` — состав пространств и форматируемость каждого сообщения ICU.
- `EngineVocabularyIsCurrent` в `src/domain/vocabulary.ts` — сверка словаря с типами движка на `tsc`.

## Пересмотр

Возвращаемся к решению, когда у эвалов и датасетов появится собственный ресурс API
(тогда вкладка `evals` перестаёт читать индекс файлов) или когда у сервера появится
несколько проектов на процесс (тогда над `flows` возникает сегмент проекта).

## Открытые вопросы

1. `RunSummary.cost_usd` приходит строкой-Decimal (`"0"`, `"0E-17"`). Нормализовать на границе
   ввода-вывода или форматировать строку — решает владелец экрана прогонов.
2. Нужен ли отдельный маршрут прогона (`runs/$runId`) вместо поискового параметра `?run=`.
   Закрывается замером: если экран прогона получает собственный заголовок и историю — нужен.
3. Где живёт реестр типов: `GET /api/types` без фильтра по воркфлоу, поэтому он на `/project`;
   если типы понадобятся в контексте воркфлоу, появится шестая вкладка.
4. Область видимости датасета. [DECISIONS.md](../DECISIONS.md) кладёт его в `datasets/<name>.yaml`
   (проектный уровень), витрина `lumen` — в `evals/<flow_id>/` (уровень воркфлоу). Вкладка сейчас
   фильтрует по префиксу `evals/<flow_id>/`, то есть видит только второй случай. Закрывается
   решением владельца: датасет привязан к воркфлоу или к проекту.

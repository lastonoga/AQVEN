# ADR-0034. Codex CLI и треды проекта в чате Studio

> Статус: принято
> Дата: 2026-09-18
> Меняет: [ADR-0030](0030-local-browser-backend.md) §6 и `A14` только в части «чат — только Claude»
> Основание: [согласованное решение](../superpowers/specs/2026-09-18-codex-studio-chat-design.md)

## Контекст

Порт `AgentBackend`, журнал `.aqven/aqven.sqlite` и SSE-контракт уже отделяют чат Studio от Claude SDK. Владелец
хочет выбирать Claude Code или Codex CLI и вести несколько разговоров в одном проекте. Переключение агента не должно
менять исполнение воркфлоу и не должно переписывать старую историю.

## Решение

| Часть | Выбор |
|---|---|
| Адаптер Codex | `openai-codex==0.147.0` (Apache-2.0), низкоуровневый `CodexClient` к поставляемому `codex app-server` |
| Выбор агента | значение `chat.backend` в проектных настройках, `claude` по умолчанию; `GET/PUT /api/chat/backend` |
| Маршрутизация | новый тред — выбранный агент; продолжение и возобновление — `backend` сохранённого треда |
| История | один журнал проекта, отдельные сессии и события каждого треда; список показывает Claude и Codex вместе |
| Контекст | тот же корень проекта, файловая система, ярлык `flow_id` и AQVEN MCP; транскрипты не смешиваются |
| Одобрения | SDK-обработчик всегда задан явно; неизвестные запросы и расширения прав отклоняются |

Версия 0.154.0 SDK требует `packaging>=26.2`, а текущая ось `pydantic-ai-slim[xai]` — `packaging<26`. Поэтому
пин 0.147.0 и поставляемый с ним `openai-codex-cli-bin==0.147.0` фиксируются в `uv.lock`. Встроенный бинарник
избавляет от требования к отдельно установленному `codex`, но пользователь должен войти через `codex login`.

Codex запускается с проектным профилем разрешений: запись только в проекте (`plan` — без записи), запрет чтения
`.env` и `.aqven/server.json`, очищенное окружение shell. Токен обязательного HTTP MCP-сервера передаётся через
переменную процесса, не через аргументы или проектные файлы. Секреты Claude по-прежнему защищены тремя механизмами
`A14`; это решение их не ослабляет. Если Codex, вход или MCP недоступны, ход завершается ошибкой без автоматического
перехода на Claude.

Оба адаптера получают текущие проектные инструкции из `AGENTS.md` и `CLAUDE.md`; Codex передаёт их как
`developerInstructions` при создании и возобновлении нативного thread. Привязка к одному проекту не означает
общую память разговоров: предыдущие сообщения остаются только в исходном треде.

## Альтернативы

| Вариант | Почему не взят |
|---|---|
| Собственный JSON-RPC транспорт | Потребовалось бы сопровождать протокол, типы и запуск процесса |
| `codex exec --json` | Пакетный режим не даёт нужного интерактивного маршрута одобрений |
| Одна общая история Claude и Codex | Нативные id и контекст моделей несовместимы; безопаснее сохранять отдельные треды |
| Перенос старой сессии при выборе другого агента | Подменяет бэкенд уже созданного треда и нарушает воспроизводимость истории |

## Последствия

- Настройка действует только на новые треды; старые Claude и Codex разговоры доступны после переключения.
- API и типы Studio сохраняют общий `ChatEvent`; нативный Codex thread id хранится в `backend_session_id`.
- Второй SDK и встроенный CLI увеличивают размер Python-установки; несовместимость зависимостей требует точного пина.

## Проверка

- Тесты проверяют маршрутизацию, продолжение после рестарта, одобрения, прерывание и sandbox-профиль.
- Интеграционный тест по умолчанию проверяет реальный app-server и обязательный AQVEN MCP без вызова модели.
  При `AQVEN_CODEX_LIVE=1` он дополнительно проверяет потоковый ход через адаптер и продолжение того же треда
  после закрытия клиента; этот прогон выполнен с подготовленным входом 2026-09-18.

## Пересмотр

Если SDK поднимет нижнюю границу `packaging` после снятия конфликта в оси провайдеров, обновить точный пин и
повторить проверки профиля и одобрений. Если app-server изменит протокол запроса прав, отклонять новые варианты
до добавления явного отображения в Studio.

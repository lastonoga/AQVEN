# ADR-0016. Git — граница релиза, база — граница редактирования

> Статус: **частично заменено [ADR-0017](0017-files-as-source-of-truth.md)** (2026-09-14)
> Дата: 2026-09-12
>
> Заменена строка «база — источник истины для определений»: заказчик решил хранить определения
> файлами. Остаются верными и действуют: вся фактура исследования, аргумент «у git нет точки, где
> слияние можно отклонить» (поэтому инварианты проверяет валидатор, а не merge), урок оркестраторов
> о пине версии в прогоне, требование канонической сериализации без дефолтных значений и решение
> о раскладке канваса вне определения.
> Контекст-документы: [16. Модель данных](../16-data-model.md), [04. Формат IR](../04-ir-schema.md), [18. Экспорт](../18-export-and-conformance.md), [ADR-0009](0009-op-log-not-crdt.md)

## Контекст

Предложение заказчика: хранить воркфлоу файлами и положить сверху git — «workflow as code».
Мотив здравый: версии, патчи, диффы, откат и масштабирование получаются готовыми, вместо того чтобы
изобретать их в базе. Мы действительно наполовину написали свой git поверх Postgres — op-log
с ревизиями, `flow_revert`, семантический дифф, lineage.

Проверили на живых продуктах и инструментах, а не на рассуждениях.

**Никто из семи продуктов с визуальным редактором не сделал git источником истины для спеки.**
Файлы первичны только у Strapi — ценой того, что редактор схемы работает лишь в dev-режиме.
Windmill, Appsmith, n8n, Retool, Budibase, Directus держат базу авторитетной, а git используют как
аудит-лог, канал доставки между окружениями и поверхность для ревью.

| Факт | Источник |
|---|---|
| Windmill: синк — это `rsync --delete`, а не merge: «Syncing is a one-off operation with no state maintained… remove those that are in the target and not in the source» | docs/advanced/git_sync |
| Цена этого измерима: issue #8468 (открыт 21.03.2026, без фикса) — синк увидел флоу удалённым, применил удаление локально, закоммитил и запушил. Флоу потерян в обе стороны | github.com/windmill-labs/windmill/issues/8468 |
| n8n прямым текстом: «n8n can't detect conflicts on workflows». Единственный исход расхождения — «Pull and override» | docs.n8n.io, Source Control |
| Appsmith: «The Appsmith server, not a user's web client, stores the local repository» — git это серверное зеркало базы; конфликты чинятся руками в JSON (issue #14498) | инженерный блог Appsmith |
| Retool: ручные правки файлов в репозитории запрещены — «All changes must be done through the Retool interface» | docs.retool.com, Source Control |
| Argo CD (модель «git единственный источник»): `selfHeal` автоматически откатывает ручные правки через 5 секунд | argo-cd.readthedocs.io |
| Kestra сделала источник истины параметром: `sourceOfTruth: GIT \| KESTRA`, merge не изображает — «overwriting any conflicting UI edits with the Git version» | kestra.io/docs/version-control-cicd |
| Ревизии флоу у Kestra живут в базе (вкладка Revisions, сравнение любых двух, Restore), git — sync-канал | kestra.io |

**Механическая причина, по которой у всех одинаково.** Git умеет трёхстороннее слияние по строкам,
а спека воркфлоу — типизированный граф с инвариантами: DAG без циклов вне `loop`, совместимость типов
портов, полнота `switch` по enum, доминирование источника привязки. Строковое слияние даёт
синтаксически валидный файл с мёртвой семантикой. Это ровно аргумент [ADR-0009](0009-op-log-not-crdt.md)
против CRDT, и здесь git даже хуже: **у него нет точки, где слияние можно отклонить**. Отсюда в отрасли
наблюдаются ровно три исхода — перезапись, запрет ручных правок, ручная починка JSON. Четвёртого нет.

**Оркестраторы дают тот же урок с другой стороны.** Ни один из семи (Airflow, Dagster, Prefect, Argo
Workflows, Temporal, Flyte, GitHub Actions) не исполняет файл из git напрямую: между репозиторием и
прогоном всегда стоит слой материализации. И все пинят версию в записи прогона — Airflow 3 завёл
`DagRun.created_dag_version_id`, Argo вкапывает `status.storedWorkflowSpec` в объект прогона,
Flyte делает регистрацию неизменяемой. Temporal, который вкопировать определение не может (оно =
произвольный код), платит самую дорогую цену: nondeterminism error на живых прогонах.

**Альтернативы в базе тоже проверены.** Dolt 2.0 (Apache-2.0) перестал быть игрушкой, но версионирует
базу целиком — коммит это снимок всех таблиц, тогда как нам надо версионировать одну сущность и
держать прогоны, трассы и кассеты вне версионирования. Doltgres стоит 2.7× к PostgreSQL.
В PostgreSQL 18 появилась только application-time темпоральность; системное версионирование живёт
в расширениях, которые не развиваются.

## Решение

**Граница проходит по назначению данных, а не по технологии.**

| Слой | Где живёт | Почему |
|---|---|---|
| Редактирование | Postgres, op-log с `base_rev` (ADR-0009) | Здесь нужны инварианты, транзакции и точка, где правку можно отклонить |
| Релиз | Git: коммит на `version_propose`, не на каждый `flow_patch` | Это граница, на которой изменение становится предметом ревью и отката |
| Прогоны, трассы, чекпоинты, датасеты, кассеты | Postgres | Их миллионы, они не ревьюятся и не сливаются |
| Раскладка канваса | Отдельный ui-канал, LWW по полю | Вне спеки, вне хеша, вне git — иначе драг мышью был бы коммитом |

Так «workflow as code» получает всё, ради чего его хотели: файлы в репозитории, читаемый дифф,
ревью изменения воркфлоу пул-реквестом, откат релиза, работа в редакторе кода рядом с UI. И не
получает того, из-за чего ломаются остальные: перезаписи, потери и ручной починки JSON.

Момент коммита совпадает с фактическим поведением Windmill (коммит при деплое) и n8n (пушится
saved-версия), а не с их декларациями.

### Что берём у разобранных продуктов

| Приём | Откуда | Зачем нам |
|---|---|---|
| `sourceOfTruth: GIT \| DB` как режим проекта, дефолт DB | Kestra | Команде с CI-дисциплиной можно отдать git; архитектуру это не меняет |
| `whenMissingInSource: DELETE \| KEEP \| FAIL`, дефолт **FAIL** | Kestra | Явная политика расхождения множеств вместо неявного `rsync --delete`. Прямой ответ на баг Windmill #8468 |
| Префикс в коммитах синка, который синк игнорирует | Windmill | Дешёвая защита от петли push → pull → push |
| Разделение stub/secret: в git — id, имя, тип; значение — в базе | n8n | Совпадает с нашим правилом трёх зон и с исключением секретов из `spec_hash` |
| `fieldManager` владеет полями, а не документом; изменение чужого поля даёт конфликт | Kubernetes Server-Side Apply | Готовая семантика для трёх писателей: человек, агент, git |
| Дифф на канвасе бейджами «новые / изменённые / удалённые» | n8n | Наш дифф патча агента (гипотеза Г2) |
| Прогон пинит версию определения | Airflow 3, Argo, Flyte | Подтверждает наш `release_hash`; правка спеки не влияет на идущий прогон |

### Чего git нам не даст

- **Откат не бесплатный.** `git revert` восстановит текст, но не пересоберёт `release_hash` с пинами
  промтов, профилей моделей и компонентов. `flow_revert` откатывает то, чего git не видит.
- **Запросов по содержимому нет.** «Где используется тип X» (требование R14) git не отвечает —
  нужен индекс в базе. Значит `type_usages` и `type_impact` остаются нашими операциями.
- **Транзакций между репозиторием и базой нет.** Релиз, затрагивающий несколько воркфлоу и датасет,
  атомарным не будет — это принимается осознанно, потому что релиз редкий и подтверждается человеком.
- **Частые мелкие коммиты от агента превращают историю в мусор**, а `packed-refs.lock` — в узкое место
  (хронический класс отказов у Gitaly). Коммит на релиз, а не на операцию, снимает и это.

### Формат файлов

Каноническая сериализация YAML из [04. Формат IR](../04-ir-schema.md) §6 остаётся, её ценность —
читаемость диффа в пул-реквесте. Одно уточнение по итогам исследования: **дефолтные значения
печатать нельзя**. Retool выкинул YAML ради своего DSL именно из-за нечитаемых диффов, забитых
умолчаниями. Гранулярность — каталог на воркфлоу, файл на узел не дробим: прецеденты есть оба
(Kestra — один файл, Windmill — каталог), но идентичность у нас даёт `spec_hash`, а не путь в ФС.

## Альтернативы

| Альтернатива | Почему отвергнута | Когда вернёмся |
|---|---|---|
| Git — единственный источник истины | Ломает визуальный редактор: модель Argo CD автоматически откатывает ручные правки, модель Strapi отключает редактор в проде | Если продукт превратится в чисто кодовый без канваса |
| Двусторонний синк как ядро | Ни у кого не работает без дисклеймера: Grafana Git Sync помечен experimental, Windmill теряет флоу, n8n не детектирует конфликты | Если появится структурный merge графа с отклонением невалидных слияний |
| Dolt / Doltgres | Версионирует базу целиком, а нам нужно версионировать одну сущность; Doltgres 2.7× медленнее PostgreSQL | Если понадобятся ветки данных, а не только спек |
| Системное версионирование в PostgreSQL | В PG 18 его нет; расширения не развиваются; даёт «строку во времени», а нам нужна именованная версия с автором и доказательствами | Если появится в ядре PostgreSQL |
| Event sourcing как единственный источник | Op-log уже даёт историю; полный ES добавляет стоимость чтения и миграции схемы событий без нового свойства | Нет |

## Последствия

**Положительные.** Ревью изменений воркфлоу пул-реквестом. Откат релиза штатными средствами.
Работа в редакторе кода рядом с UI. История релизов, независимая от базы. Экспорт бандла
(§18) и git-синк становятся одним механизмом, а не двумя.

**Отрицательные.** Два хранилища вместо одного. Нужна защита от петли синка. Релиз не атомарен
с базой. Появляется класс расхождений «в базе одно, в репозитории другое» — лечится политикой
`FAIL` и явным экраном дрейфа.

**Обязательства.** Коммит только на `version_propose`. Секреты и значения в git не попадают.
Каноническая сериализация без дефолтных значений. Индекс содержимого спек в базе для `type_usages`
и `type_impact`. Прогон пинит `release_hash` и не зависит от последующих правок.

## Проверка

- Kill-критерий 13 (round-trip: экспорт → импорт → экспорт даёт идентичный бандл) распространяется
  на git-синк: коммит → чтение → коммит не порождает диффа.
- Тест на петлю: синк не реагирует на собственные коммиты.
- Тест на дрейф: правка файла в репозитории при `sourceOfTruth: DB` даёт видимый дрейф и **не**
  применяется молча.
- Проверка сериализации: в выводе нет полей со значениями по умолчанию.

## Пересмотр

Появление структурного трёхстороннего слияния графа, которое умеет отклонять семантически невалидный
результат, — тогда двусторонний синк становится возможен и решение пересматривается.

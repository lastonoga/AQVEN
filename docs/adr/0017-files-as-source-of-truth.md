# ADR-0017. Файлы — источник истины для определений, база — индекс

> Статус: принято
> Дата: 2026-09-14
> Заменяет частично: [ADR-0016](0016-git-as-release-boundary.md)
> Изменяет в части носителя: [ADR-0009](0009-op-log-not-crdt.md)
> Детали: [files-first/](../files-first/)

## Контекст

[ADR-0016](0016-git-as-release-boundary.md) поставил базу источником истины для определений,
опираясь на то, что **ни один из семи продуктов с визуальным редактором** не сделал иначе.
Заказчик, увидев это, решение подтвердил в обратную сторону: хранить определения файлами.

Аргумент заказчика переигрывает исследование, и вот почему. Разобранные продукты — Windmill,
Retool, Appsmith, n8n — делались для пользователя, у которого **единственный вход это UI**;
файлы там лишняя сущность, отсюда и перезаписи. У нас основной пользователь — инженер,
работающий в Claude Code. Для него файлы означают, что проект грепается, диффается, правится
в редакторе, а агент работает с определениями **напрямую нативными инструментами**, без MCP.
Это не удобство, это другой способ работы с продуктом.

Что из исследования остаётся верным и учтено ниже: у git нет точки, где слияние можно отклонить,
поэтому инварианты обязан проверять валидатор, а не merge.

## Решение

**Определения — файлы. База — перестраиваемый индекс. Прогоны — база.**

| Сущность | Где | Почему |
|---|---|---|
| Воркфлоу, узлы, промты, типы, компоненты, профили моделей, агенты, тулы | Файлы в репозитории проекта | Их читают, ревьюят, правят в редакторе и диффают |
| Индекс определений (схема `idx`) | Postgres, производная проекция | Файлы не отвечают на «где используется тип X» (R14) |
| Прогоны, трассы, чекпоинты, кассеты, строки датасетов, метрики, разметка | Postgres | События, их миллионы |
| Раскладка канваса (позиции, зум) | Postgres, LWW-канал | Не часть определения; по этой строке ADR-0016 не заменяется |
| Секреты | Хранилище секретов; в файлах только `ref:` | Никогда не в git |

### Раскладка на диске

Каталог на воркфлоу, **файл на узел**: `flows/<flow_id>/flow.yaml` + `nodes/<node_id>.yaml`.
Мотив — узел несёт промт и схему, а параллельные правки разных узлов git сливает сам.
Прецедент Windmill (`<path>__flow/`), а не Kestra: у них флоу это 50 строк декларации без прозы.

**Промт всегда отдельным файлом** — `<node_id>.prompt.md` рядом с узлом или `prompts/<key>.md` для
общего. Многострочный текст в YAML-строке нечитаем в диффе, а правят его чаще всего остального.

**Идентичность — путь в файловой системе.** Поля `id` внутри файлов нет: файловая система физически
запрещает дубликат ключа, дерево грепается, `git mv` даёт rename-детект. Цена — переименование меняет
идентификатор; закрывается append-only журналом `renames` в `project.yaml`, через который резолвится
lineage прогонов и кассет.

Имена только `^[a-z][a-z0-9_]{0,62}$`: на APFS и NTFS `Score.yaml` и `score.yaml` — один файл,
без правила это тихая потеря узла. В `.gitattributes` — `eol=lf`, иначе CRLF молча ломает хеш.

**Версий в именах файлов нет.** `egypt_rules.md`, не `egypt_rules@3.md`; пин версии живёт
в `wf.lock.yaml` и в `release_hash`. Иначе правка фрагмента заставляет править прозу всех шаблонов,
которые его включают, и топит содержательный дифф.

### Запись

`base_rev` из базы заменяется **compare-and-swap по хешу байтов файла**. Клиент присылает
`expects[{path, file_hash}]` на каждый затрагиваемый путь; `file_hash: null` означает «файла быть
не должно». Коды отказа: `STALE_FILE`, `FILE_VANISHED`, `FILE_EXISTS`, `LOCK_BUSY`, `TREE_DIRTY`.

**Транзакция на несколько файлов** — переименовал узел, поменялась ссылка в промте:
блокировка → проверка `expects` → staging-каталог `.wf/txn/<ulid>` с полными новыми версиями и `fsync`
→ `intent.json` и `fsync` (точка невозврата) → серия атомарных `rename(2)` → снятие. Падение после
точки невозврата доигрывается при следующем старте.

Межпроцессная блокировка `.wf/lock` (`O_EXCL`, pid + ttl 30 с + heartbeat) — Studio и Claude Code
в одном каталоге это реальный сценарий, а не гипотеза.

**Валидатор стоит до сериализации** и работает на всём дереве проекта в памяти: межфайловые инварианты
одним файлом не проверить. Две категории диагностик: `blocking` (цикл вне `loop`, несовместимость типов
портов, неполный `switch`, висячая ссылка, дубль имени) — не пишется вовсе; `advisory` — пишется
с пометкой.

**Промт коммитится явно.** Черновик живёт в `.wf/drafts/<путь>.draft` с `base_file_hash`,
в `.gitignore`, вне дерева определений и мимо компилятора.

### Два уровня редактирования на одних байтах

| Уровень | Кто | Валидация | Когда |
|---|---|---|---|
| Файловый | Claude Code нативными Read/Edit/Write и git | **После** записи, хуком `flow_check` на `PostToolUse` | Точечная правка текста промта, массовые замены |
| Доменный | Studio и MCP через `flow_patch` | **До** записи | Структурные и кросс-файловые правки |

Файловых операций `file_read`/`file_write` в MCP **не заводим**: у Claude Code уже есть свои
инструменты, дублирование дало бы вторую схему CAS. Правило приоритета: структурные правки — через
`flow_patch`; прямая запись законна, но отчёт постфактум. Невалидное дерево закоммитить можно,
**релизнуть нельзя**.

### История

Коммит на **эпизод правки**: один ход агента целиком либо серия правок человека, закрытая затиханием
30 секунд. Не на запись (история превратится в мусор) и не на релиз (потеряем промежуточные состояния).
`git author` — инициатор (человек или `Claude Code <agent+…@wf.local>`), `git committer` — всегда
`wf-engine`, актор дублируется трейлером.

Откат всегда **движением вперёд**: `reset --hard` и force-push запрещены, потому что прогоны
ссылаются на коммиты. Библиотека — `isomorphic-git@1.42.2` (MIT) за интерфейсом `GitPort`.

### Прогон

Авторитетен **хеш содержимого, а не commit sha**. Старт материализует план в снимок в базе
(`origin: 'working_copy'`), прогон исполняет снимок и файлы больше не читает. Правка файла во время
прогона на него не влияет — тот же приём, что `storedWorkflowSpec` у Argo и
`created_dag_version_id` у Airflow 3.

Запуск из рабочей копии битого файла запрещён, из опубликованного релиза — разрешён всегда.
Поломка одного файла — карантин файла, а не проекта.

### Human-in-the-loop

Подсистема задач отменяется: шесть операций `human_task_*` не нужны. Приостановленный прогон — это
состояние, «что ждёт меня» — `run_list({status: 'suspended'})`, ответ — `run_resume` с payload.
Форма ввода приходит из `run_get_node` как `form_schema`, развёрнутая из типа. Таймаут — не операция,
он объявлен в узле и исполняется планировщиком.

## Альтернативы

| Альтернатива | Почему отвергнута |
|---|---|
| База как истина (ADR-0016) | Отменено решением заказчика: закрывает прямую работу Claude Code с определениями |
| Файловые операции в MCP | Дублируют нативные инструменты Claude Code и вторую схему CAS |
| Коммит на каждую запись | История нечитаема после часа работы агента |
| `commit sha` как идентичность версии | Один и тот же контент в разных коммитах даст разные идентичности; ломает replay-кэш |
| Зеркало дерева на сервере (модель Appsmith) | Для локального инструмента лишний слой; оставлено как вариант для SaaS |

## Последствия

**Положительные.** Проект грепается и диффается. Claude Code правит определения напрямую.
Ревью изменений воркфлоу пул-реквестом. Экспортный бандл и рабочее дерево почти совпадают.
Индекс можно снести и перестроить: `DROP SCHEMA idx CASCADE` не теряет ничего.

**Отрицательные и честные.** Инвариант «невалидная ревизия не может попасть в историю» перестаёт
быть свойством системы и становится свойством дисциплины: прямую запись в файл держат только хук
и CI. Это прямая цена решения. Появляется класс «индекс отстал от дерева». Переименование как смена
идентификатора требует журнала, который обязаны читать все резолверы lineage.

**Обязательства.** Хук `flow_check` на `PostToolUse` и в pre-commit. `wf check` в CI.
Канонизация при записи, а не при чтении. Журнал `renames` читают все резолверы.

## Проверка

- Kill-критерий 13 усиливается: `write(spec) → read → write` даёт **байтовый фикспойнт** в рабочем
  дереве, а не только идентичный бандл.
- `DROP SCHEMA idx CASCADE` с последующей переиндексацией не меняет ни одного ответа продукта.
- Тест на падение в транзакции: убить процесс после `intent.json` — дерево доигрывается при старте.
- Тест на две записи: Studio и Claude Code пишут одновременно, вторая получает `STALE_FILE`.

## Пересмотр

Переход в мультитенантный SaaS, где рабочее дерево на машине пользователя невозможно, — тогда
возвращается модель зеркала на сервере.

# ADR-0008. Имена MCP-тулов в snake_case и фазовое раскрытие поверхности

> Статус: **частично изменено [ADR-0025](0025-python-engine.md)** (2026-09-16)
> Дата: 2026-09-11
>
> Изменены имя сервера и MCP SDK (ADR-0025 §8): сервер `volt` → `aqven`, схема ресурсов `volt://` → `aqven://`,
> префикс `mcp__aqven__` занимает 12 символов вместо 11, проверка длины — `len("mcp__aqven__") + name <= 128`;
> `@modelcontextprotocol/sdk` заменён на `mcp` 2.2.0 `MCPServer`, у которого нет `RegisteredTool.enable()/disable()`,
> поэтому механизм фазового раскрытия открыт (открытый вопрос 18 ADR-0025). Остаются верными и действуют: имена
> тулов в `snake_case` с префиксом группы, регулярка `^[a-z][a-z0-9_]*$`, фазовое раскрытие поверхности как принцип.
> Контекст-документы: [14. MCP-контракт для агентов](../14-mcp-contract.md), [21. Дорожная карта и критерии остановки](../21-roadmap.md), [ADR-0007](0007-single-operation-contract.md), спека §13.1

## Контекст

Спека §13.1 называет тулы через точку: `flow.create`, `run.start`, `catalog.list`, `run.replay_node`,
`experiment.compare`. Это невалидно для нашего основного клиента:

| Ограничение | Значение |
|---|---|
| Имя тула в Anthropic Messages API | допустимый набор символов не включает точку; длина до 128 символов |
| Claude Code | префиксует MCP-тулы как `mcp__<server>__<tool>`, то есть 11 символов при имени сервера `volt` |
| Проверка длины | `mcp__volt__project_verify_migration` = 34 символа, в лимит укладывается с большим запасом |

Второе ограничение — цена контекста. Поверхность контракта — около 50 тулов в 15 группах.
Реалистично 250–600 токенов на тул с нетривиальной схемой, то есть **12k–30k токенов только на
определения тулов, до первого действия агента**. Это бюджет, который нужен на трейсы прогонов.
Anthropic на своём материале показывает тот же порядок: загрузка всех определений может съедать
~150k токенов до первого сообщения пользователя.

Сверх этого сам факт наличия хотя бы одного тула добавляет системный промт: Claude Opus 5 —
286 токенов при `tool_choice: auto|none` и 406 при `any|tool`; Sonnet 5 — 354 и 474 соответственно.

Механизм для динамики в SDK штатный: `RegisteredTool` из `@modelcontextprotocol/sdk@1.30.0` имеет
`enable() / disable() / update() / remove()`, которые сами рассылают `notifications/tools/list_changed`;
capability `{ tools: { listChanged: true } }`. Клиентские лимиты ответа: `MAX_MCP_OUTPUT_TOKENS`
по умолчанию 25 000 токенов на ответ тула с предупреждением на 10 000; пер-тульный override —
`_meta["anthropic/maxResultSizeChars"]` до 500 000 символов.

## Решение

**Имена.** Только `snake_case`, форма `<группа>_<глагол>_<объект>`, префикс группы обязателен:
`flow_*`, `run_*`, `trace_*`, `eval_*`, `dataset_*`, `secret_*`, `provider_*`, `export_*`,
`studio_*`. Точки из §13.1 запрещены. **§13.1 спеки настоящим переименована**: `flow.create` →
`flow_create`, `run.replay_node` → `run_replay_node`, `experiment.compare` → `experiment_compare`,
`catalog.list` → `catalog_list`. Имя сервера — короткое `volt`, не `ai-workflows-automate`:
префикс Claude Code входит в 128 символов. Группа спеки воркфлоу называется `flow_`, а не
`workflow_`, чтобы имена оставались короткими и совпадали с переименованной §13.1. Синонимичных
тулов (`run_get` и `run_fetch` одновременно) не существует — это прямой антипаттерн из руководства
Anthropic по написанию тулов и главная причина ошибок выбора у агента.

**Фазовое раскрытие.** Поверхность делится на ядро и фазовые группы. Ядро из 8–10 тулов включено
всегда и самодостаточно: `flow_list`, `flow_get`, `run_start`, `run_get`, `run_get_trace`,
`studio_open`, `mode_set`, `help_contract`. Остальные группы включаются через `mode_set({ phase })`
или автоматически по контексту (открыт прогон с ошибкой → включается группа отладки). Фазы:
`discover → author → run → debug → evaluate → ship`. Одновременно включено **не более 20–25 тулов**,
а не 50.

Дополнительно поверхность сокращается консолидацией: вместо шести CRUD-тулов на шаг — один
`flow_patch` с массивом операций (он же решает конкурентность, см. [ADR-0009](0009-op-log-not-crdt.md)).
Консолидация даёт 50 → ~30 статически, фазовость снижает одномоментное число до ≤25.

**Риск и страховка.** Не все MCP-клиенты корректно перечитывают список по
`notifications/tools/list_changed`; поведение Claude Code при смене списка в середине сессии
на живом сервере не проверено. Страховка двухслойная:
1. Ядро самодостаточно: любой сценарий можно начать и довести до `studio_open` только ядром.
2. Вызов выключенного тула возвращает **не** «unknown tool», а доменную ошибку конверта:
   `problems[{ code: "TOOL_PHASE_DISABLED" }]` с текстом «тул доступен в фазе `debug`» и готовым
   `candidates[0].apply = { tool: "mode_set", arguments: { phase: "debug" } }`. Агент делает ровно
   один следующий вызов вместо гадания.

**Сопутствующие обязательные атрибуты тула.** `annotations` заполняются всегда (`readOnlyHint`,
`destructiveHint`, `idempotentHint`, `openWorldHint`); все листинги отдают `{ items, next_cursor,
total_estimate }` с дефолтным `limit: 20`; «толстые» тулы имеют `view: summary|detailed|raw` с
дефолтом `summary` и явный `_meta: { "anthropic/maxResultSizeChars": N }`.

## Альтернативы

| Альтернатива | Почему отвергнута | При каких условиях вернёмся к ней |
|---|---|---|
| Оставить имена из §13.1 через точку | Точка не входит в допустимый набор символов имени тула в Messages API; гарантированный источник отказов | Никогда |
| Держать все ~50 тулов включёнными всегда | 12k–30k токенов на определения до первого действия; этот бюджет нужен трейсам | Если клиент начнёт грузить определения лениво сам |
| Пагинация `tools/list` (`params.cursor` / `result.nextCursor`) вместо выключения | Пагинация уменьшает один ответ, а не контекст: клиент всё равно дочитывает страницы и держит все определения | Как дополнение, если тулов станет реально больше 50 |
| Tool Search Tool от Anthropic («работа с тысячами тулов, загрузка по требованию») | Это фича Messages API, а не MCP-сервера: мы как сервер её не включаем. Доступность внутри Claude Code для MCP-тулов не проверена | Если наш агент-раннер пойдёт напрямую в Messages API — там включаем его вместе со `strict: true` |
| Code execution over MCP (определения как код, -98.7% токенов по данным Anthropic) | Меняет модель взаимодействия целиком и требует песочницы исполнения; несоразмерно текущей фазе | Если поверхность вырастет на порядок или фазовость окажется недостаточной |
| Только консолидация, без фазовости (50 → ~30) | 30 тулов с нетривиальными схемами — всё ещё около 7k–18k токенов; и часть операций не консолидируется без потери смысла | Если проверка `tools/list_changed` в Claude Code покажет, что клиент список не перечитывает |
| `namespace.tool` как суффикс вместо префикса (`search_asana` против `asana_search`) | Выбор префикс/суффикс даёт нетривиальную разницу в eval, но префикс группы даёт предсказуемую сортировку и совпадает с рекомендацией Anthropic | После eval-замера на нашей поверхности |

## Последствия

Положительные:
- Контекст до первого действия — ядро (8–10 тулов), а не вся поверхность.
- Префикс группы даёт агенту навигацию без описаний: по имени видно область и обратимость.
- `enable()/disable()` — штатный механизм SDK, своих костылей с перерегистрацией сервера нет.
- Ошибка «тул выключен» несёт готовый вызов `mode_set` — агент не теряет ход.

Отрицательные:
- Состояние фазы — это состояние сервера на сессию; при stateful StreamableHTTP оно живёт в памяти
  транспорта, значит при нескольких нодах нужен sticky routing или общий store.
- Расхождение с §13.1 исходной спеки: все ссылки на имена тулов в документации и примерах надо
  править разом.
- Зависимость от поведения клиента при `tools/list_changed` — непроверенная точка.

Обязаны делать:
1. Реестр тулов — единая таблица `Record<ToolName, { phase, group, annotations }>` (паттерн Registry);
   имя тула порождается из `operationId` операции ([ADR-0007](0007-single-operation-contract.md)), а не пишется руками.
2. Валидатор имени на старте сервера: `^[a-z][a-z0-9_]*$`, длина `len("mcp__volt__") + name <= 128`,
   обязательный префикс из закрытого списка групп.
3. Хендлер выключенного тула регистрируется всегда (тул не `remove()`, а `disable()`), чтобы вернуть
   `TOOL_PHASE_DISABLED` вместо «unknown tool».
4. Ядро держать в границах 8–10: добавление тула в ядро требует вынести другой.
5. Каждый «толстый» тул объявляет `_meta["anthropic/maxResultSizeChars"]` и параметры сужения
   (`view`, `limit`, `include_payloads`), иначе он упрётся в 25 000 токенов клиента.

## Проверка

| Что проверяем | Как |
|---|---|
| Форма имён | Юнит-тест по реестру: регулярка `^[a-z][a-z0-9_]*$`, префикс из списка групп, длина с `mcp__volt__` ≤ 128. Падает на любой точке и любом CamelCase |
| Точная регулярка Messages API | Отдельный контрактный тест против документации define-tools: пока не подтверждён, считаем ограничение действующим (точка запрещена), но тест обязателен до релиза |
| Нет синонимов | Тест на пересечение: ни у двух тулов не совпадает пара (группа, глагол-синоним) по словарю синонимов |
| Одновременная поверхность | Тест по каждой фазе: число включённых тулов ≤ 25; ядро включено во всех фазах |
| Бюджет определений | Замер `gpt-tokenizer` по `tools/list` в каждой фазе; порог — суммарно ≤ 8 000 токенов на фазу, превышение валит CI |
| Поведение выключенного тула | Интеграционный тест: вызов тула чужой фазы → `isError: true`, `problems[0].code == "TOOL_PHASE_DISABLED"`, `candidates[0].apply.tool == "mode_set"` |
| Реакция клиента на `tools/list_changed` | Живой прогон против Claude Code: `mode_set` в середине сессии, затем вызов тула новой фазы. Kill-критерий: если клиент список не перечитывает и страховка из п. 2 не спасает сценарий отладки — фазовость отключается, остаётся консолидация |
| §13.1 переименована | grep по `docs/` на шаблон `\b(flow\|run\|eval\|export\|catalog\|experiment)\.[a-z_]+\b` в контексте имён тулов — ноль совпадений |

## Пересмотр

Пересматриваем, если: Claude Code окажется неспособен перечитывать список тулов в середине сессии;
Tool Search Tool станет доступен для MCP-тулов внутри Claude Code; поверхность вырастет настолько,
что даже ядро перестанет укладываться в бюджет; Anthropic изменит допустимый набор символов или
схему префиксования имён MCP-тулов.

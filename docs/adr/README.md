# Записи архитектурных решений (ADR)

Каждая запись фиксирует одно решение: чем оно вызвано, что именно решено, какие альтернативы
отвергнуты и почему, чем проверяется соблюдение и по какому триггеру решение пересматривается.

Решения уже сведены в [../DECISIONS.md](../DECISIONS.md) — этот каталог объясняет, **почему**
они такие. Если документ комплекта противоречит ADR — ошибка в документе.

| ADR | Решение | Ключевой аргумент |
|---|---|---|
| [0001](0001-execution-core-on-voltagent.md) | Своё ядро исполнения поверх VoltAgent | 19 из 20 конструкций IR ложатся на готовые примитивы; нашим остаётся только периметр гарантий |
| [0002](0002-ai-sdk-v6-axis.md) | Ось AI SDK v6, провайдеры изолированы в `@wf/llm` | Опасно не столкновение версий, а его отсутствие: у `@ai-sdk/*` нет peer на `ai`, поэтому npm молча ставит линию v7 и ломается уже в рантайме |
| [0003](0003-model-middleware.md) | Гарантии живут в middleware уровня модели | `Agent.generateObject` помечен deprecated; кассеты, бюджеты и PII-редакция нужны на каждом вызове, а не в обёртке одного метода |
| [0004](0004-schema-profiles.md) | Профиль схемы — свойство пары (IR-схема × провайдер) | Требования OpenAI и Anthropic взаимно противоречивы; Zod 4 даёт пять проверенных поломок strict-вывода |
| [0005](0005-three-call-outcomes.md) | Три исхода вызова, обрезанный ответ чинить запрещено | `jsonrepair` на обрыве дописывает `null` и отдаёт валидный, но ложный объект |
| [0006](0006-dynamic-allowed-sets.md) | Потолок allowed-set и индексный выбор | Ёмкость упирается в формат ID: UUID v4 — 416 значений, nanoid — 714; выше падает и точность |
| [0007](0007-single-operation-contract.md) | Один контракт операций: Zod → OpenAPI → MCP и клиент UI | `@voltagent/server-hono` уже вендорит `@hono/zod-openapi`; tRPC был бы вторым транспортом рядом |
| [0008](0008-mcp-tool-naming-and-phasing.md) | `snake_case` имена тулов и фазовое раскрытие | Точка в имени невалидна; 50 тулов стоят 12–30 тыс. токенов до первого действия |
| [0009](0009-op-log-not-crdt.md) | Server-authoritative op-log вместо CRDT | CRDT гарантирует сходимость, но не инварианты графа: реплики сойдутся к привязке на удалённый узел |
| [0010](0010-pg-boss-scheduler.md) | pg-boss как планировщик и единственная очередь | Postgres уже есть; транзакционная постановка задачи вместе с бизнес-транзакцией снимает свой outbox |
| [0011](0011-two-schemas-and-tenancy.md) | Две схемы в базе, мультитенантность в данных с первого дня | VoltAgent создаёт свои таблицы в рантайме; добавить `tenant_id` позже дороже, чем завести сразу |
| [0012](0012-langfuse-as-store.md) | Langfuse — хранилище, отладчик — свой | Отладчик показывает наш IR, а не спаны; всё, от чего зависит поведение, дублируется в наш Postgres |
| [0013](0013-liquidjs-template-engine.md) | liquidjs как движок шаблонов | Встроенный статический анализ и типизированный AST условий; `{% switch %}` из спеки не нужен — есть `{% case %}` |
| [0014](0014-ir-mutation-testing.md) | Доменный IR-мутатор для kill-критерия «100% мутантов» | Stryker мутирует исходники, а ловить надо типовые ошибки агента в IR |
| [0015](0015-gate-statistics.md) | Своя статистика гейтов на `@stdlib`, без Python | Трёх пакетов и ~150 строк хватает на McNemar, бутстрап BCa и поправки на множественность |
| [0016](0016-git-as-release-boundary.md) ⚠️ частично заменено 0017 | Git — граница релиза | Исследование: ни один из семи продуктов с визуальным редактором не сделал git источником истины; у git нет точки, где слияние можно отклонить |
| [0017](0017-files-as-source-of-truth.md) | Файлы — источник истины для определений, база — индекс | Основной пользователь работает в Claude Code: определения должны правиться напрямую, а не только через UI |

| [0019](0019-escape-hatch-rules.md) | Escape hatch даёт значение, но не форму | Cube держит гарантии фазовым разделением: код влияет на значения, не на структуру модели |
| [0020](0020-llm-function-and-adapters.md) | LLM-функция как единица; адаптация под модель — работа платформы | 17 осей адаптации выводятся из каталога и проб; слово «JSON» вставляет адаптер, а не автор |
| [0021](0021-prompt-dependency-model.md) | Промт собирается в рантайме; идентичность — по факту отправки | Предвычисление влияния отвергнуто как переусложнение: отрисованный промт в трассе даёт те же свойства |
| [0022](0022-hash-as-version.md) | Версия — хеш содержимого, а не поле в исходнике | Ручной номер не проверяем машиной; идентичность и метка релиза — разные вещи |
| [0023](0023-lexical-references.md) | Узлы связываются лексическими ссылками, а не строками | Вдвое дешевле по типам, спеллчек в ошибках, ацикличность становится невыразимой, кодмод точнее |

## Как добавлять новую запись

1. Следующий свободный номер, имя файла `NNNN-краткое-имя-латиницей.md`.
2. Структура: Контекст → Решение → Альтернативы → Последствия → Проверка → Пересмотр.
3. Если решение меняет [../DECISIONS.md](../DECISIONS.md) — правьте оба файла одним изменением.
4. Отменённая запись не удаляется: статус меняется на «заменено ADR-NNNN», со ссылкой.

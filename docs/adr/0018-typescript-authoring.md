# ADR-0018. TypeScript — единственный язык авторинга, канвас правит через кодмод

> Статус: принято
> Дата: 2026-09-14
> Зависит от: [ADR-0017](0017-files-as-source-of-truth.md)
> Исследование: [research/ts-*.md](../research/), проба в scratchpad/probe-ts

## Контекст

YAML не умеет выражать код: экстракцию, слияние, кастомное преобразование, запрос к API.
Заказчик предложил взять TypeScript «аля Cube.js».

Проверка показала, что образец опровергает часть замысла.

| Факт | Источник |
|---|---|
| **Визуальный редактор Cube работает только с YAML:** «Visual Modeler only allows editing of cubes and views that are defined using the YAML syntax (not JavaScript)»; на динамических моделях и Jinja отключается | docs.cube.dev/data-modeling/visual-modeler |
| Поддержку `cube.ts` в конфиге удалили 2026-09-04 | cube-js/cube PR #11763 |
| Типобезопасности у JS-модели нет: `cube()` — глобаль в `vm`, без импортов; инференс типов результата открыт с 2022 | cube-js/cube issue #4202 |
| YAML у Cube транспилируется **в** JS, то есть JS — низ стека, а не альтернатива | DataSchemaCompiler.ts |
| Синхронизация валидатора, транспайлера и YAML-ветки ручная: в исходнике капслок-комментарий «ATTENTION: … update CubePropContextTranspiler» | CubeValidator.ts |
| Единственный доказанный прод-прецедент «мышь меняет структуру в настоящем исходнике» — WinForms Designer (2002, CodeDom над `InitializeComponent`) | срез 4 |
| На TypeScript прецеденты (Onlook, Lovable) правят атрибуты JSX, а не структуру программы | срез 4 |

Замеры на пробе (`scratchpad/probe-ts`, node 20.19.0, tsx 4.23.13, esbuild 0.28.2):

- синтез графа на 200 узлов — 27,6 мс вхолодную, 1,9–2,3 мс прогретый; весь `tsx synth.ts` — 0,80 с;
- тайпчек 50 воркфлоу × 20 шагов — 0,82 с, рост линейный (~69 типов на шаг цепочки);
- полнота `switch` ловится типами (`TS2322: … not assignable to type 'never'`), доминирование и
  ацикличность — нет;
- ts-morph 28.0.0: кодмод по объектным литералам сохранил тело `code`-узла байт в байт вместе
  с комментарием и пустой строкой.

## Решение

**Код строит граф, а не исполняет его.** TypeScript — единственный язык авторинга; YAML как формат
авторинга не вводится вовсе. Синтез односторонний: TS → IR.

Заказчик подтвердил выбор после предъявления доказательств выше. Отказ от второго формата снимает
главный налог модели Cube: у них валидатор, транспайлер и YAML-ветка синхронизируются руками
(капслок-комментарий «ATTENTION» в `CubeValidator.ts`). У нас один язык авторинга и один машинный
артефакт.

**Артефакт синтеза — канонический JSON, а не YAML.** Раз его никто не пишет руками, читаемость
уступает строгости: JSON канонизируется по RFC 8785 без ловушек YAML (якоря, типы-сюрпризы, отступы).
YAML остаётся только в экспортном бандле, где его читает человек и чужой LLM.

**Канвас правит структуру кодмодом по TypeScript, на декларативном подмножестве.**
Проба ts-morph 28.0.0 подтвердила механику: кодмод по объектным литералам сохранил тело `code`-узла
байт в байт вместе с комментарием и пустой строкой. Прецеденты — Onlook и Lovable, правящие JSX
через AST.

**Почему подмножество, а не весь TypeScript.** Синтез — функция многие-к-одному: разные программы
дают один и тот же IR, поэтому обратить её в общем случае нельзя. Пример: цикл
`for (const lang of ['ru','en','de']) flow.llm(...)` порождает три узла; удаление одного узла на
канвасе требует понять, что узел породил этот цикл, что им управляет этот массив, и переписать
массив. Где соответствие один-к-одному (узел = объектный литерал), обращение механическое.

**Три состояния воркфлоу вместо двух режимов:**

| Состояние | Что в проекте | Канвас |
|---|---|---|
| Декларативный TS | TS из литералов, 1:1 с узлами | правит через кодмод — полноценно |
| Генеративный TS | циклы, условия, композиция кодом | только чтение, явная плашка |
| Без исходника | только IR-файл | правит напрямую, TS-файла нет |

**Переход между состояниями — явная операция.** «Развернуть в IR»: синтезированный JSON
материализуется в явные узлы, циклы разворачиваются, TS-файл удаляется; после этого воркфлоу
правится мышью целиком. Обратно — «собрать в TS». Аналог `eject` в create-react-app:
генеративность теряется по кнопке и осознанно, а не втихую.

Прямая правка IR при существующем TS-файле **запрещена**: следующий синтез затёр бы её. Это класс
отказов Windmill (issue #8468, потеря флоу в обе стороны).

**Подмножество определяется синтаксически:** воркфлоу собран последовательностью вызовов фабрик
с объектными литералами, без циклов, условий и динамической композиции на уровне графа.
Тела `code`-узлов в подмножество не входят и кодмодом не трогаются никогда.

Как только анализатор видит конструкцию вне подмножества, канвас для этого воркфлоу переходит
в режим чтения с явной плашкой «собран кодом, правьте в редакторе». Деградация видимая, а не тихая:
пользователь не должен гадать, почему узел не тащится.

### Синтез

- Билдер вызывается **ровно один раз** и возвращает `Ref<T>`, а не значения. Замыкание
  `map(over, item => …)` вызывается с символическим `$item`.
- Синтез — **чистая функция**: сеть, файловая система, `Date.now`, `Math.random` и чтение окружения
  запрещены и подменяются в изоляте. Иначе `plan_hash` перестаёт быть воспроизводимым.
  Это осознанное расхождение с Cube (`asyncModule` ходит в API) и с Pulumi (исполняет программу
  на каждом preview).
- **Синтезированный IR коммитится** — расхождение с CDK, где `cdk.out` в `.gitignore`. Без
  закоммиченного IR теряют вход семантический дифф версий, канвас, `spec_hash`, кассеты, бандл
  и kill-критерий 14.
- Ошибка синтеза показывается в терминах кода (файл, строка), ошибка компилятора — в терминах IR
  со ссылкой обратно в исходник.

### Что остаётся файлами-данными

Промты (`*.prompt.md`), профили моделей, политики, формы, метаданные датасетов, `wf.lock.yaml`.
Типы — `zod` в `types/*.ts`, потому что нужны и тайпчекеру, и рантайму.

## Альтернативы

| Альтернатива | Почему отвергнута |
|---|---|
| YAML как второй язык авторинга | Отвергнуто заказчиком: два формата — постоянный налог на каждый примитив языка (у Cube синхронизируются руками) |
| Полный двусторонний круговорот TS ↔ канвас | Прецедент только WinForms 2002; берём ограниченный вариант — кодмод на подмножестве |
| Обратная кодогенерация IR → TS | Теряет рукописный код и структуру; 18 §9 это прямо запрещает |
| Синтез без материализации артефакта (модель Cube: объект в памяти) | Нечего диффать, нечего хешировать, нечего экспортировать |
| Многофазный реэкзекьют исходника (4 прохода Cube) | У нас ссылки между узлами — данные (`Binding`), а не свободные идентификаторы: граф читается из IR без исполнения |

## Последствия

**Положительные.** Кастомная логика пишется настоящим кодом с типами и автодополнением.
Claude Code правит определения напрямую. Синтез быстрый — канвас пересобирается на сохранение.
Полнота `switch` ловится тайпчекером до компилятора.

**Отрицательные.** Канвас теряет правку мышью на всём, что вне декларативного подмножества, и это
станет заметно ровно на сложных воркфлоу, где визуальная правка нужнее всего. Кодмод — код, который
надо поддерживать под каждый новый примитив языка. Статический анализ рвётся там, где начинается
динамика кода.

**Обязательства.** Изолят синтеза с подменёнными глобалями. Материализация IR при синтезе.
Явная отметка режима авторинга на канвасе, чтобы «не могу перетащить узел» не выглядело багом.
Урок CDK: идентичность узла не выводить из пути в дереве конструктов — переименование там
8 лет читалось как delete+create.

## Проверка

- Синтез дважды из одного исходника даёт побайтово идентичный IR.
- Попытка `Date.now()` в файле определения — ошибка синтеза, а не тихое расхождение.
- Кодмод ts-morph по DSL сохраняет тела `code`-узлов и комментарии байт в байт.
- Кодмод не меняет ни одного байта вне целевого узла (проверяется побайтовым сравнением файла).
- Воркфлоу с циклом в билдере определяется как вне подмножества и показывает плашку, а не молча
  игнорирует перетаскивание.

## Пересмотр

Устойчивая доля воркфлоу вне подмножества выше половины означает, что кодмод не окупается:
тогда канвас честно становится только смотрелкой, а правка уходит целиком в редактор.

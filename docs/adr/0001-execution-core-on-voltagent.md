# ADR-0001. Своё ядро исполнения поверх VoltAgent

> Статус: **заменено [ADR-0025](0025-python-engine.md)** (2026-09-16)
> Дата: 2026-09-11
>
> Заменено целиком: ядро исполнения больше не строится на VoltAgent 2.10.0. Движок — на Python, надёжное
> исполнение даёт DBOS 2.31.1 (чекпоинт шага, восстановление, `fork_workflow`), исполнитель IR — наша функция
> DBOS-workflow, узел — DBOS-шаг; компиляция IR в `WorkflowChain`, `timeTravel`, `WorkflowRegistry` и схема
> `voltagent` уходят. Остаются верными и действуют: суженный периметр — свой планировщик, хранилище чекпоинтов
> и движок реплея не пишем; наш слой — семантика и гарантии (`switch` с first-match, `quorum(k)`, `any`,
> `first_success`, лимиты циклов, `map` с `on_item_error`, ключи идемпотентности, три исхода, кассеты); на
> границе шага — JSON-совместимые значения, модель восстанавливает проверка Pydantic (ADR-0025 §3–§4).

## Контекст

Спека §4 ставит три варианта фундамента: **A** — собрать продукт из готового движка воркфлоу,
**B** — тонкий слой поверх Mastra, **C** — своё ядро исполнения.

Продукт продаёт четыре гарантии: провенанс каждого выхода узла, видимость входов узла,
join-политики (`quorum(k)`, `any`, `first_success`, `on_item_error`) и воспроизводимость прогона.
Все четыре реализуются там, где данные подаются на вход узла и снимаются с выхода, — то есть
в **исполнителе**, а не в настройках фреймворка. Вариант A отпадает по этой причине.

Одновременно проверено чтением `@voltagent/core@2.10.0` (MIT, `dist/index.d.ts` + встроенные docs,
346 md-файлов), что **движок долговечности писать не надо** — он есть и работает:

| Возможность | Механизм 2.10.0 |
|---|---|
| Чекпоинты | `checkpointInterval` (@default 1), `disableCheckpointing` (@default false); running-чекпоинт пишется после каждого завершённого шага в `metadata.__voltagent_restart_checkpoint` |
| Crash-recovery | `workflow.restart(executionId)`, `restartAllActive()`, `WorkflowRegistry.restartAllActiveWorkflowRuns({workflowId?})` |
| Replay и fork | `timeTravel({executionId, stepId, inputData?, resumeData?, workflowStateOverride?, memory?})`, `timeTravelStream` |
| Человек в цикле | `suspend(reason, suspendData)` + `suspendSchema`/`resumeSchema` на шаге (перекрывают воркфлоу-уровневые), типизированный `resumeData` |
| Состояние прогона | `workflowState` + `setWorkflowState`, сохраняется в чекпоинт и восстанавливается на resume/restart |
| Доступ к выходам узлов | `getStepData(stepId) → {input, output}`, `getStepResult<T>(stepId)`; после restart восстанавливается из `checkpoint.stepData` |
| Горячая регистрация версий | `WorkflowRegistry.registerWorkflow/unregisterWorkflow`, `VoltAgent.registerWorkflows` — без рестарта процесса |
| Прогресс | `WorkflowStreamEvent {from, stepIndex, stepType, input, output, status}`, `writer`, SSE-эндпоинты |
| Политики контента | `createPIIInputGuardrail`, `createPromptInjectionGuardrail`, `createDefaultSafetyGuardrails` и ещё шесть готовых |
| HTTP, MCP, трассы, evals | `@voltagent/server-hono@2.0.14`, `@voltagent/mcp-server@2.2.0`, `VoltAgentObservability({spanProcessors})`, `@voltagent/evals@2.0.5` |

Из 20 конструкций нашего IR **19 имеют прямой примитив** VoltAgent (`andThen`, `andMap`, `andAll`,
`andForEach`, `andBranch`, `andWhen`, `andDoWhile/andDoUntil`, `andRace`, `andGuardrail`,
`andWorkflow`, `andAgent`, `andSleep/andSleepUntil`, `suspend`, `timeTravel`, `bail/abort`,
`input`/`result`-схемы). Прямого аналога нет только у `try/catch/finally`.
Это закрывает и блокер спеки §20.4 (регистрация воркфлоу в рантайме подтверждена),
и делает вариант «свой планировщик» покупкой того, что уже лежит на полке.

## Решение

Берём **вариант C, но с явно суженным периметром**: наша — семантика (IR, компилятор, исполнители
узлов, гарантии), VoltAgent — исполнение (планировщик шагов и весь слой долговечности).
Собственного планировщика, собственного хранилища чекпоинтов и собственного движка реплея не пишем.

Компилятор IR транслирует граф в **цепочку VoltAgent** (`createWorkflowChain(...).and*()`), один
стабильный `Workflow`-инстанс на версию графа (`.toWorkflow()` вызывается один раз), который
регистрируется в `WorkflowRegistry`. Рёбра графа компилируются в декларативные `andMap`
(`{source: "value"|"data"|"input"|"context"|"step"|"fn", path/key/stepId}`), а не в JS-замыкания —
граф остаётся сериализуемым и инспектируемым, а компилятор остаётся компилятором, а не интерпретатором.

### Точная граница

| Наше (`@aqven/*`) | VoltAgent 2.10.0 |
|---|---|
| IR: схема, версионирование, валидация, JSON-сериализуемость | — |
| Компилятор IR → `WorkflowChain`: генерация id шагов, мапперов рёбер, взаимоисключающих предикатов `switch`, условий цикла, шагов сведения | Исполнение цепочки, протекание типов, `retries` на шаге |
| Исполнители узлов (`Record<nodeKind, NodeExecutor>`, Strategy) и контракт вход/выход узла | `andThen`/`andAgent` как оболочка вызова исполнителя |
| Провенанс: `writer.write({metadata: {nodeId, parentNodeId, branchIndex}})`, происхождение каждого значения | `WorkflowStreamEvent`, хуки `onStart/onStepStart/onStepEnd/onSuspend/onError/onFinish` |
| Join-политики: обёртка ветки в `Result<T,E>` + явные ключи + шаг сведения (`quorum(k)`, `any`, `first_success`, `on_item_error`) | `andAll` (merge в один объект, падает целиком), `andForEach` (порядок сохраняется), `andRace` (Promise.any-семантика) |
| Лимиты итераций: `max_iter`, бюджет, стагнация, best-of — счётчики в `workflowState`, условие генерирует компилятор | `andDoWhile`/`andDoUntil` (тело минимум один раз, лимита нет) |
| Backoff с джиттером, отмена проигравших в `race` (свой `AbortController`), таймауты приостановки (pg-boss `sendAfter` + сверяющий cron, [ADR-0010](0010-pg-boss-scheduler.md)), ключи идемпотентности | `retryConfig {attempts, delayMs}` (только фиксированная задержка), `abortSignal` на агенте |
| Детерминизм реплея: кассеты как `LanguageModelMiddleware` (см. [ADR-0003](0003-model-middleware.md)) | `timeTravel` переисполняет вызовы моделей |
| Lineage форков: своя таблица + чтение `metadata.replayedFromExecutionId` | `timeTravel` пишет lineage в `metadata` (типизированные поля адаптеры теряют) |
| Реестры моделей/компонентов/политик, MCP-контракт, схема `app` в БД, RLS, мультитенантность | Схема `voltagent` (6 таблиц, `CREATE TABLE IF NOT EXISTS` в рантайме) |
| Гейты качества узла (обёртка шага), типизированный `PolicyViolation` | Guardrails как механизм (бросают голый throw) |

Границы применимости: решение действует, пока класс наших воркфлоу выражается **цепочкой шагов**,
известной на момент компиляции. Граф, перестраивающийся по ходу прогона, этой границей не покрыт.

## Альтернативы

| Альтернатива | Почему отвергнута | При каких условиях вернёмся |
|---|---|---|
| **A. Собрать из готового движка воркфлоу + LLM-узлы** | Гарантии живут в исполнителе; чужой исполнитель не даёт провенанса на уровне узла, join-политик и типизированных выходов. `switch` по enum, лимиты итераций, `quorum(k)` всё равно пришлось бы дописывать — но уже без контроля над исполнителем | Если появится рантайм, где провенанс на уровне узла — часть контракта, а не надстройка |
| **B. Тонкий слой поверх Mastra** | Mastra у нас — **вторая цель миграции** для kill-критерия 14, то есть мишень экспорта, а не фундамент. Фундаментом она даст те же пробелы, но без проверенной семантики `timeTravel`/`restart`/чекпоинтов 2.10 | Если `@voltagent/core` перестанет развиваться (нет релизов 6 месяцев) или сменит лицензию с MIT |
| **C1. Своё ядро целиком: планировщик поверх pg-boss** | Пришлось бы написать чекпоинты, crash-recovery, replay/fork, suspend/resume и хранилище истории — всё это уже есть и проверено чтением `dist` | Если понадобится исполнение, не выражаемое цепочкой шагов: граф, меняющийся в ходе прогона |
| **C2. Форк VoltAgent** | Все четыре пробела (backoff, отмена в race, лимиты итераций, таймауты приостановки) закрываются сверху, без правки ядра. Стоимость поддержки форка выше стоимости обёрток | Если пробел обнаружится внутри планировщика шагов и не будет закрываться сверху |
| **Свой раннер графа поверх примитивов (интерпретация IR в рантайме)** | `andMap` + `getStepData`/`getStepResult` снимают нужду в раннере: доступ к любому прошлому выходу — по `stepId` | Никогда при текущем IR |

## Последствия

**Положительные**
- Replay/fork/checkpoint/HITL получены готовыми под MIT; «Claude отлаживает и чинит» закрывается штатным `timeTravel`, а не нашим кодом.
- Горячая (пере)регистрация версий воркфлоу без рестарта процесса; запасной вариант «воркер на проект» из §20.4 не нужен.
- Граф остаётся данными: рёбра — `andMap`, а не замыкания, значит IR инспектируется, диффается и экспортируется.
- Периметр «ядра доверия» сузился до четырёх пробелов + IR/компилятор/реестры/MCP — это измеримый объём.

**Отрицательные**
- Мажор `ai` диктуется peer-зависимостью VoltAgent — см. [ADR-0002](0002-ai-sdk-v6-axis.md).
- `WorkflowRegistry` — глобальный синглтон (`globalThis.___voltagent_workflow_registry`): изоляция тенантов и тестов на нас.
- Цена чекпоинтов: каждый завершённый шаг = один UPSERT всей строки исполнения (`events` целиком + `metadata` с чекпоинтом). Для циклов на сотни итераций это заметная нагрузка и рост строки.
- `checkpointInterval: N` управляет не только стоимостью записи, но и тем, с каких шагов доступен `timeTravel`: при большом интервале часть шагов становится недоступной для реплея.
- Lineage реплея в типизированные поля `WorkflowStateEntry` не пишут ни `@voltagent/postgres@2.1.3`, ни `@voltagent/libsql` — только `metadata`.
- Сериализация состояния — голый `JSON.stringify`: `Date` → строка, `Map`/`Set` → `{}`, `BigInt` портит запись.

**Обязаны делать**
1. Компилятор отдаёт **один стабильный `Workflow`-инстанс на версию графа** и регистрирует его в `WorkflowRegistry`; работа с builder-ом напрямую запрещена — иначе suspend/resume не видит сохранённого состояния.
2. Для каждого `andAgent` компилятор **всегда** генерирует 4-й аргумент `map`: `(output, {data}) => ({...data, [nodeId]: output})`. Без него выход агента затирает данные воркфлоу.
3. Ветки `andAll`/`andBranch` получают уникальные ключи, обёртку в `Result<T,E>` и шаг сведения; для `andBranch` компилятор доказывает взаимоисключаемость предикатов и полноту enum, `default` = отрицание объединения.
4. Валидатор JSON-сериализуемости выходов узлов и `workflowState` — на этапе компиляции, а не в рантайме.
5. Свои ключи в `metadata` мержатся, а не перезаписывают её целиком; имя `__voltagent_restart_checkpoint` зарезервировано.
6. `restartAllActiveWorkflowRuns()` вызывается на bootstrap процесса.
7. Политика `checkpointInterval` задаётся классом воркфлоу (дешёвый/дорогой шаг) и документируется вместе с потерей доступности реплея.
8. Своё: экспоненциальный backoff с джиттером, `AbortController` для отмены проигравших в `race`, счётчики итераций в `workflowState`, дедлайны приостановки через pg-boss `sendAfter` ([ADR-0010](0010-pg-boss-scheduler.md)), ключи идемпотентности для узлов с внешними эффектами (шаг после resume/restart выполняется заново с начала).

## Проверка

| Что проверяем | Как |
|---|---|
| Компилятор не теряет данные на `andAgent` | Снапшот-тест сгенерированной цепочки: у каждого шага `stepType: "agent"` присутствует mapper; правило генератора + тест на снапшоте IR→chain |
| Сериализуемость | Тест: выход каждого исполнителя узла проходит `canonicalize` без потерь; `Date`/`Map`/`Set`/`BigInt` в выходе — ошибка компиляции |
| Долговечность | Интеграционный тест на testcontainers + PostgreSQL 18: убить процесс в середине прогона → `restartAllActiveWorkflowRuns()` → `getStepData(stepId)` возвращает те же выходы |
| Детерминизм реплея | Два `timeTravel` с одного `stepId` на кассетах дают побайтово равные выходы узлов |
| Периметр гарантий | conformance-прогон: 100% кейсов проходят при отключённой сети (вызовы только через кассеты) |
| Kill-критерий | Доменный IR-мутатор: компилятор ловит 100% мутантов IR |

## Пересмотр

- `@voltagent/core` выпускает мажор с несовместимой семантикой шагов, чекпоинтов или `timeTravel`.
- Ядро перестаёт быть MIT либо не имеет релизов 6 месяцев подряд → альтернатива B.
- Появляется класс воркфлоу, не выражаемый цепочкой шагов, известной на момент компиляции (граф меняется в ходе прогона) → альтернатива C1 для этого класса.
- Обнаружен пробел внутри планировщика шагов, не закрываемый обёрткой сверху → альтернатива C2.

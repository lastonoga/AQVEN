# ADR-0041. Модель и усилие рассуждения чата: асимметричный каталог, одна шкала

> Статус: принято
> Дата: 2026-09-21
> Зависит от: [ADR-0028](0028-studio-api-contract.md), [ADR-0030](0030-local-browser-backend.md) §6, [ADR-0034](0034-codex-and-project-chat-threads.md), [ADR-0040](0040-chat-agent-allowed-tools.md)
> Источники: `CodexClient.model_list()` вызван вживую 2026-09-21 против локального `codex app-server`; отсутствие перечисления у Claude проверено по `claude --help` и по исходникам `claude_agent_sdk` 0.2.154; поля `V2ThreadStartParams` и `V2TurnStartParams` прочитаны из установленного `openai_codex`

## Контекст

`ChatSessionOptions.model` существовал с самого начала, и оба бэкенда его честно применяли: Claude —
`ClaudeAgentOptions(model=...)`, Codex — `thread_start.model`. Но Studio жёстко отправляла `model: null` и
`permission_mode: "default"`, поэтому **выбрать было нечем**. Усилие рассуждения не выражалось вовсе: у Claude
бюджет размышления стоял константой 8000, Codex про усилие не узнавал никогда.

**Перечисление моделей у бэкендов устроено по-разному, и это не выравнивается.**

| | Codex | Claude |
|---|---|---|
| Список моделей | `CodexClient.model_list()` — метод JSON-RPC, отдаёт `id`, `display_name`, `description`, `is_default` | **нет ничего**: у CLI нет подкоманды, в SDK нет вызова |
| Уровни усилия | в том же ответе, **на каждую модель**, с описаниями и `default_reasoning_effort` | понятия нет; есть `thinking.budget_tokens` |
| Куда передаётся | `thread_start.model`, `turn_start.effort` | `ClaudeAgentOptions.model`, `ClaudeAgentOptions.thinking` |

Единственный машинный след моделей Claude — текст справки `--model`, где названы алиасы `fable`, `opus`,
`sonnet`. Разбирать справку нельзя: формат вывода не контракт.

## Решение

**1. Маршрут `GET /api/chat/models?backend=` отвечает тем, что бэкенд может сказать честно.** Codex вызывает
`model_list()` и отдаёт живой список; Claude отдаёт реестр из трёх документированных алиасов
([chat/models.py](../../packages/aqven/src/aqven/chat/models.py)). Оба ставят `accepts_any_model = true`, и у
Claude заполнено поле `detail` — строка, объясняющая, почему список короткий. Это видно в интерфейсе, а не
спрятано в коде.

Падение `model_list()` не роняет маршрут: каталог возвращается пустым с `detail`, и остаётся свободный ввод.

**2. Усилие — одна шкала порта на оба бэкенда:** `low`, `medium`, `high`, `xhigh`, `max`. Значения взяты из
ответа Codex, чтобы для него отображение было тождественным. Для Claude шкала переводится в
`thinking.budget_tokens` таблицей; монотонность роста закреплена тестом, потому что немонотонная таблица —
тихая ошибка, которую никто не заметит.

Из ответа Codex берутся **только те уровни, которые знает порт**: незнакомое значение отбрасывается, а не
протекает в контракт. Это проверено тестом на записи с посторонним уровнем.

**3. Значения по умолчанию задаёт запуск:** `--chat-model`, `--chat-effort`, `--chat-permission-mode`. Правило
подстановки — запрос главнее: что пришло в теле, то и применяется, флаг заполняет остальное. Именно это
позволило выпустить движок отдельным шагом, пока Studio ещё слала `null`.

Тот же принцип, что в [ADR-0040](0040-chat-agent-allowed-tools.md): настройку даёт человек при старте, а не
файл внутри проекта, который правит агент.

**4. Поле `effort` у сессии** добавлено колонкой через существующий механизм `ADDED_COLUMNS`, поэтому открытые
журналы продолжают читаться.

**5. Интерфейс использует идиом репозитория,** а не новый контрол: `PickerTrigger` с `Popover` и `Command` —
тот же комбобокс, что у полосы прогонов и экрана датасетов. Уровни усилия берутся у выбранной модели, а при
её отсутствии — объединением по каталогу; выбор модели, не поддерживающей текущий уровень, **сбрасывает
уровень**, а не отправляет то, что бэкенд отвергнет.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| Разбирать `claude --help` ради списка моделей | формат текста справки не контракт, сломается на первом релизе CLI |
| Только свободное поле для обоих | не пришлось бы сопровождать реестр, но опечатка выясняется лишь на первом ходе, ошибкой от бэкенда; у Codex при этом есть живой список, и прятать его расточительно |
| Отдельные шкалы усилия на бэкенд | честнее к их различиям, но переносит асимметрию в контракт API и в интерфейс, где пользователю она не нужна |
| Хранить выбор в `aqven.yaml` или настройках Studio | файл проекта правит агент ([ADR-0040](0040-chat-agent-allowed-tools.md)); настройки Studio — отдельная работа с UI и миграцией |
| Сбрасывать каталог в состояние загрузки при смене бэкенда | прямолинейно, но это синхронный `setState` в эффекте, запрещённый правилом React Compiler; состояние ключуется бэкендом |

## Последствия

- Реестр алиасов Claude **устаревает** и требует обновления с релизами CLI. Цена принята: свободный ввод
  всегда рядом, и `accepts_any_model` говорит об этом интерфейсу.
- Отображение усилия в бюджет токенов Claude — **наша выдумка**, а не документированное соответствие.
  Числа подобраны монотонными; менять их можно без изменения контракта.
- Настройки применяются к **новой** сессии: модель и режим фиксируются при её создании. Сменить их у
  открытого треда нельзя — это следует из модели сессии, а не из интерфейса.

## Пересмотр

Запись пересматривается, если Claude CLI научится перечислять модели (реестр удаляется), если у Codex
изменится форма ответа `model_list`, или если понадобится менять модель у уже открытого треда.

## Открытые вопросы

1. **Реестр алиасов Claude сопровождается вручную.** Закрыть: следить за `--model` в справке CLI при
   обновлении оси версий, либо удалить реестр, если появится перечисление.
2. **Русская и прочие локали.** Строки добавлены только в `en`. Закрыть: при следующем проходе по локалям.
3. **Смена модели у открытого треда.** Сейчас невозможна. Закрыть: решение владельца — нужна ли она, и
   создавать ли при этом новый тред с переносом истории.

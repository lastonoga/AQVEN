## Контекст

Заказчик сформулировал два требования. Первое: промт, вход и выход — **единая сущность**, их нельзя
рассматривать порознь. Второе: промты должны быть составными и адаптироваться под модель и язык,
потому что разные модели требуют разного.

Второе подтвердилось фактами жёстче, чем ожидалось.

| Факт | Источник |
|---|---|
| У OpenAI `json_object` и у Qwen `json_object` **дословно одна и та же ошибка**: `'messages' must contain the word 'json' in some form, to use 'response_format' of type 'json_object'.` | developers.openai.com, alibabacloud.com/help/model-studio |
| У reasoning-моделей OpenAI роль `system` заменена на `developer`; sampling-параметры не поддерживаются | developers.openai.com/api/docs/guides/reasoning |
| У Anthropic роли `system` нет вовсе — это top-level параметр; подряд идущие одинаковые роли склеиваются; пустой text-блок запрещён | platform.claude.com/docs/api/messages |
| Prefill у Anthropic несовместим с thinking: при включённом thinking последний assistant-turn обязан начинаться с thinking-блока | platform.claude.com/docs/extended-thinking |
| Кэш Anthropic: максимум 4 breakpoints, минимум 512–4096 токенов по модели, **короткий префикс не кэшируется молча, без ошибки**; смена `tool_choice` инвалидирует кэш сообщений | platform.claude.com/docs/prompt-caching |
| Prefill у Qwen — через флаг `"partial": true` на последнем assistant-сообщении, что нарушает общее правило «последним идёт user» | alibabacloud.com/help/model-studio/partial-mode |
| Cohere урезает JSON Schema сильнее всех: нет `allOf`/`oneOf`/`not`, `minItems`, `minLength`, почти нет regex — невыразимое приходится переносить **текстом в промт** | docs.cohere.com/docs/structured-outputs |
| У vLLM допустимые роли определяет chat template конкретной модели, а не сервер — из вендора не выводится | docs.vllm.ai |

## Решение

### Единица — LLM-функция

Промт, входной тип и выходной тип объявляются одним целым: `{ in, body, out }`. У функции одна версия,
один хеш, один тест. Отдельной «версии текста» не существует, потому что блок формата вывода
генерируется из выходного типа: смена `out` физически меняет отправляемый текст.

Следствия: промт перестаёт быть самостоятельным файлом-данными; единица версии, теста, датасета
и переиспользования — функция; архетипы (§7.5) становятся библиотекой типизированных функций.
Prompt management Langfuse под это не подходит (там промт — текст с переменными, версионируемый
отдельно) — промтами управляет код, Langfuse получает собранный промт атрибутом трассы.

### Адаптация — работа платформы, а не автора

Между отрисовкой шаблона и телом запроса стоит слой **адаптеров**: вход — нейтральный
`RenderedPrompt` (блоки с ролями и метками кэша), выход — тело запроса провайдера.
Один адаптер на `provider_kind`, поведение задаётся **осями**, а не именем модели.

Исследование выделило **17 осей**: `system_placement`, `json_keyword`, `schema_enforcement`,
`schema_dialect`, `enum_case_fidelity`, `key_order_fidelity`, `prefill`, `last_message_role`,
`role_merge`, `empty_block_policy`, `cache_breakpoints`, `cache_min_prefix`, `cache_invalidated_by`,
`reasoning_prompt_style`, `sampling_params`, `tool_forcing`, `output_budget_coupling`,
`lang_adherence`.

Каждая ось выводится из объявленных возможностей каталога или из пробы (§5 [11-providers](../11-providers.md)).
**Имя модели в компоновщик не попадает никогда** — даже временно: внутри одного вендора ось имеет
разные значения (schema-режим Qwen доступен только части линейки).

**Слово «JSON» вставляет адаптер, а не автор шаблона.** Это разрешает конфликт правил: R-T6 запрещает
описывать формат вывода руками, а OpenAI требует слова «JSON» в сообщениях. Требование провайдера —
свойство канала доставки, а не текста автора.

### Язык — покомпонентный выбор, а не перевод целиком

Вопрос «переводить промт или нет» поставлен неверно. Данные:

| Компонент и задача | Что лучше | Источник |
|---|---|---|
| Извлечение (QA, NER): контекст | исходный язык (корреляция +0.33 QA, +0.32 NER) | arXiv 2502.09331, 35 языков, 4 задачи |
| Классификация: инструкция | английский (macro-F1 spam 0.881 против 0.787) | arXiv 2409.07054, 197 конфигураций, 12 датасетов |
| Культурно укоренённые задачи | нативный (английский даёт −8,08%) | там же |

Поэтому язык объявляется **на компонент функции** (инструкция, контекст, рубрика, few-shot, формат
вывода), а не на промт целиком.

Токенизация измерена на нашем стеке (gpt-tokenizer 4.0.0, o200k_base, ×к английскому):
ru 1.30, de 1.52, zh 1.13, ja 1.73, ko 1.32, ar 1.27, hi 1.38. Множители «2–4×» из блогов в бюджеты
класть нельзя — цифра «до 15×» относится к cl100k и старше. Anthropic через gpt-tokenizer оценивать
нельзя вовсе: публичного токенизатора нет, есть бесплатный `POST /v1/messages/count_tokens`.

### Что берём у прототипов

| Источник | Берём | Не берём |
|---|---|---|
| Priompt (@anysphere/priompt 0.2.1, MIT) | топологию: дерево, слоты, изоляты бюджета как границы кэш-точек, деградации | рантайм-бинпоиск приоритетов — недетерминирован относительно `behavior_hash` |
| dotprompt (1.1.2, ISC) | состав метаданных: модель, конфиг, схемы входа и выхода рядом с текстом | механизм вариантов: вариант = копия файла, а язык × модель даст N×M копий |
| BAML (0.226.2, MIT) | функция = сигнатура + шаблон + тип; тесты рядом с функцией; упорядоченные фолбэки | отдельный язык вне TypeScript |

## Последствия

**Положительные.** Автор пишет один текст, платформа доставляет его на любую модель. Смена профиля
модели не требует правки промта. Требования вендоров живут в одном месте и покрыты пробами.

**Отрицательные.** Слой адаптеров — новый код с 17 осями, каждую надо проверять пробой и поддерживать.
Оценка длины префикса для кэша опирается на приближённый токенизатор, а промах молчаливый.

**Обязательства.** Три новые пробы: `json_keyword` (ожидаемая ошибка 400 = успех пробы), `prefill`,
`lang_echo`. Правило компиляции: профиль с кэш-точками предупреждает, если оценка префикса ниже
`cache_min_prefix` модели. Оценка токенов для Anthropic — через их эндпоинт, не через gpt-tokenizer.

## Проверка

- Один и тот же промт компилируется под OpenAI, Anthropic, Qwen и vLLM и проходит вызов на каждом.
- Grep по компоновщику не находит ни одного имени модели.
- Проба `json_keyword` на модели без слова «JSON» получает 400 — и это засчитывается как успех.
- Смена профиля модели меняет отправляемый текст и не меняет авторский исходник.

# ADR-0015. Статистика гейтов выпуска — своя, на @stdlib, без Python-сайдкара

> Статус: принято
> Дата: 2026-09-11
> Контекст-документы: [13. Evals и гейты](../13-evals-and-gates.md), [12. Наблюдаемость](../12-observability.md), [16. Модель данных](../16-data-model.md), [20. Репозиторий и инструменты](../20-repo-and-tooling.md); спека §12, §18

## Контекст

Спека §12: «Эксперименты: версия спеки × датасет × скореры → дельты по узлам с доверительными интервалами», плюс
требование «нет регрессии на детерминированных скорерах» и «прирост по LLM-метрикам значим». Отсюда четыре
жёстких следствия, каждое из которых определяет выбор инструмента:

1. **Данные спарены по `case_id`** — датасет один и тот же. Непарные тесты (Mann-Whitney, two-sample t) выбрасывают
   корреляцию между A и B на одном элементе и раздувают дисперсию в 2–5 раз. Это главная причина «на глаз видно
   улучшение, а тест не значим».
2. **LLM не детерминированы даже при `temperature = 0`** (батчинг, роутинг MoE, апдейты провайдера). Наблюдаемая
   разница содержит и эффект правки, и run-to-run шум; их надо разделять, а не надеяться на p-value.
3. **Тестов десятки**: 15+ узлов × 3–5 скореров = 45–75 сравнений. При alpha = 0.05 и 60 тестах ожидаемо 3 ложных
   «значимых» результата, даже когда B идентична A.
4. **Улучшение и отсутствие регрессии — разные задачи**: superiority (`H0: delta <= 0`) и non-inferiority
   (`H0: delta <= -margin`). «p > 0.05, значит регрессии нет» — логическая ошибка, на малом n так проезжает любая
   регрессия.

Инвентаризация TS-экосистемы (npm view + установка + рантайм-вызовы, 2026-09-11): парных тестов нет почти нигде.
`simple-statistics@7.12.0` — ни один его тест не парный (`tTest` одновыборочный и без p, `wilcoxonRankSum` — это
Mann-Whitney, `permutationTest` непарный). Бутстрапа в нём нет вообще. `jstat@1.9.6` — 3.8 года без релиза, поле
license в манифесте пустое, типов нет и `@types/jstat` не существует. `jerzy`, `ml-stat`, `statsmodels-js` — мёртвые
с 2022 года. Живы и проверены вызовом: `@stdlib/stats-wilcoxon@0.2.3`, `@stdlib/stats-ttest@0.2.3`,
`@stdlib/stats-binomial-test@0.2.3` (все Apache-2.0, релиз 2026-02-08).

## Решение

Статистика гейта — **собственный пакет `@wf/stats`: атомарные пакеты @stdlib + ~150 строк своего кода. Python в
рантайме нет.**

Пакет — чистые функции: вход — массивы чисел и конфиг, выход — типизированный результат. Ноль зависимостей от
VoltAgent, Langfuse и БД, поэтому тестируется в вакууме и переиспользуется воркером evals, MCP-тулом
`experiment_compare` и Studio через API (10 000 реплик бутстрапа на 60 тестах — серверная работа, не браузерная).

### Что берём готовым, а что пишем

| Нужно гейту | Источник |
|---|---|
| Wilcoxon signed-rank (парный) | `@stdlib/stats-wilcoxon@0.2.3` |
| Парный t-тест + CI | `@stdlib/stats-ttest@0.2.3` |
| Exact binomial (ядро exact McNemar) и Clopper-Pearson CI | `@stdlib/stats-binomial-test@0.2.3` |
| chi2 CDF (McNemar при `n_disc >= 25`) | `@stdlib/stats-base-dists-chisquare-cdf@0.3.1` |
| Нормальный квантиль (power, MDE) | `@stdlib/stats-base-dists-normal-quantile@0.3.1` |
| Квантили, ресемплинг, probit | `simple-statistics@7.12.0` (ISC) — как числовые утилиты, не как тесты |
| **McNemar** | наш, ~25 строк поверх двух пакетов выше |
| **Парный бутстрап (percentile)** | наш, ~30 строк |
| **BCa-бутстрап** (`z0` + jackknife-ускорение) | наш, ~70 строк |
| **Holm и Benjamini-Hochberg** | наш, ~20 строк каждый |
| **Power / MDE** | наш, закрытая форма через normal-quantile + MC-симулятор |
| **Seeded RNG** (xorshift/PCG) | наш, ~10 строк |

Метапакет `@stdlib/stats@0.4.1` целиком не берём — тянет всё; только атомарные пакеты.

### Механика гейта

- **Три семейства тестов, объявленные до прогона**: `primary` (1–3 теста: целевая метрика изменённого узла +
  end-to-end) — Holm-Bonferroni, alpha = 0.05, FWER; `secondary` (40–70 тестов) — Benjamini-Hochberg, q = 0.10, FDR;
  `safety` (non-inferiority по детерминированным скорерам, стоимости, латентности) — **без поправки**, alpha = 0.05,
  решение по границе CI. Поправка в non-inferiority делает выпуск **легче**, а обнаружение регрессии — труднее,
  поэтому её отсутствие здесь не оплошность, а требование.
- **Три процедуры по типу метрики**: binary → exact McNemar (`n_disc < 25`) либо chi2 с поправкой Йейтса;
  ordinal → Wilcoxon signed-rank с `zeroMethod: 'pratt'` и `exact: n <= 50`; continuous → парный бутстрап,
  парный t как сверка. CI **всегда** парный бутстрап BCa, `B = 10 000`, фиксированный seed. Ресемплим элементы
  датасета (пара переносится целиком), внутри страт при размеченных срезах и по кластерам, если из одного документа
  нарезано несколько кейсов.
- **A/A-прогон обязателен** до сравнения A/B: та же версия спеки, другие seed-ы, тот же датасет и пайплайн. Истинный
  эффект там 0, поэтому любое отвержение в `primary` означает сломанный пайплайн или нестабильную метрику, а ширина
  CI на A/A — эмпирический **пол шума**, который показывается в Studio рядом с delta. Результат кэшируется по ключу
  `(spec_version_A, dataset_version, scorers_version, R)`.
- **Четыре исхода**: `PASS` / `WARN` (выпуск с аппрувом человека) / `BLOCK` / `GATE_UNAVAILABLE`. Последний — не
  `PASS` ни при каких обстоятельствах.

| Условие | Исход |
|---|---|
| датасет < 200, дискордантов < 25, test-сплит загрязнён, судья не допущен, дрейф провайдера, A/A даёт отвержение в primary, отброшено > 5% кейсов | `GATE_UNAVAILABLE` |
| `ci_lo < -ni_margin` на safety-скорере; выход за бюджет стоимости/латентности; нет значимого прироста на целевой метрике; прирост ниже пола шума A/A | `BLOCK` |
| BH-значимая деградация вторичной метрики; `ICC < 0.5`; расхождение t-теста и бутстрапа по ширине CI > 30%; достигнутая мощность < 0.80 | `WARN` |
| всё выше пройдено | `PASS` |

- **Пороги по умолчанию**: `alpha_primary 0.05`, `q_secondary 0.10`, `alpha_safety 0.05`, `bootstrap_B 10 000`,
  `bootstrap_method 'BCa'`, `min_dataset 200` (`strict` 500), `min_discordant 25`, `min_runs_R 3`,
  `mpe_proportion 0.02`, `mpe_rubric_1_5 0.10`, `mpe_cost -0.05`, `ni_margin 0.02`, `min_icc 0.50`, `mode 'normal'`.
- **Минимальные размеры выборки** (Monte-Carlo, 4000 итераций на клетку, seeded xorshift):
  n = 30–50 даёт мощность 0.01–0.20 на реалистичных эффектах и не годится ни для чего, кроме «не сломалось совсем».
  Блокирующий гейт — от **n = 200** (MDE ≈ +8 pp binary / `dz` 0.20), **n = 500** для смены модели или провайдера и
  критичных узлов. Прирост меньше +3 pp на бинарной метрике на разумных n не доказывается. Контринтуитивный факт,
  который надо показывать пользователю: чем больше версии расходятся (`pd` выше), тем **больше** нужен n при том же
  delta — при `pd = 0.10` и +5 pp нужно ~500 кейсов, при `pd = 0.30` — ~1000. Операционный критерий для Studio —
  число дискордантных пар: при `psi = 0.70` нужно 42 пары, при `psi = 0.60` — 189.
- **Повторы R** режут только `sigma2_run`, не `sigma2_item`: детерминированный скорер над стохастическим выходом —
  R = 3, LLM-судья по рубрике — 3–5, панель из K судей — R = 2, extractor со строгой схемой при temperature = 0 —
  R = 2. Seed-ы у A и B одинаковые: это дополнительный слой спаривания.
- **Допуск судьи к блокировке выпуска**: судья участвует в блокирующем решении только при weighted kappa ≥ 0.7 и
  Krippendorff alpha ≥ 0.8 относительно человеческой разметки и неустаревшей калибровке. Иначе —
  `GATE_UNAVAILABLE('judge_not_calibrated')`, а не тихое исключение метрики. Для рубрик 1..5 согласие считается
  **quadratic weighted kappa**, плоская kappa на порядковой шкале занижает согласие.

### Почему не тянем Python

Всё перечисленное закрывается тремя пакетами stdlib и ~150 строками своего кода. Это ровно то, что спека называет
«ядро доверия строим сами»: код маленький, детерминированный, целиком юнит-тестируемый, без внешнего процесса в
пути принятия решения о выпуске. Корректность при этом проверяется **против** Python: golden-фикстуры генерируются
один раз оффлайн (`scipy.stats.wilcoxon`, `statsmodels.stats.contingency_tables.mcnemar`,
`statsmodels.stats.multitest.multipletests`, `scipy.stats.bootstrap`), коммитятся как JSON и сверяются в vitest с
допуском 1e-9. Python остаётся инструментом разработки, а не зависимостью рантайма.

| Альтернатива | Почему отвергнута | При каких условиях вернёмся к ней |
|---|---|---|
| **Python-сайдкар со scipy/statsmodels** | Для гейта в описанном объёме не нужен: даёт ноль функциональности сверх ~150 строк, но добавляет контейнер, деплой, наблюдаемость и отдельный режим отказа прямо в решении о выпуске | Смешанные модели (`MixedLM`), GEE/кластерно-робастные оценки, байесовская отчётность «вероятность того, что B лучше A, = 0.93». См. раздел «Пересмотр» |
| **jstat 1.9.6** | 3.8 года без релиза, пустое поле license в манифесте (юридический риск), нет типов и нет `@types/jstat` — на строгом TS мы всё равно пишем `.d.ts` руками, только непроверенный | Не вернёмся |
| **simple-statistics как основа тестов** | Ни один его тест не парный; бутстрапа нет. Берём только как набор числовых утилит | — |
| **Непарные тесты (Mann-Whitney, two-sample t)** | Выбрасывают спаривание по `case_id`, раздувают дисперсию в 2–5 раз — гейт перестаёт видеть реальные приросты | Только если датасеты A и B перестанут совпадать (тогда это уже другой продукт) |
| **Метапакет `@stdlib/stats@0.4.1`** | Тянет всю библиотеку ради пяти функций | — |
| **`@danielsimonjr/mathts-statistics@0.3.48`** | Живой и пинится к SciPy, но одиночный мейнтейнер и версия 0.x — не для ядра доверия | Если станет 1.x с несколькими мейнтейнерами |
| **Percentile-бутстрап вместо BCa** | Смещён на ограниченных и скошенных метриках (accuracy у потолка 0.95+, стоимость с тяжёлым хвостом): на n = 100 и accuracy 0.9 граница CI уезжает на 1–2 pp | Percentile допустим для интерактивного превью в Studio при `B = 2000` |
| **Bonferroni вместо Holm** | Holm контролирует тот же FWER и равномерно мощнее; у голого Bonferroni нет преимуществ, кроме простоты объяснения | — |
| **Benjamini-Yekutieli вместо BH** | Тесты по узлам положительно коррелированы (PRDS), BH валиден; BY при m = 60 даёт делитель ~4.5× — избыточный консерватизм | Флаг `gate.fdr_method: 'BY'` для проектов с произвольной зависимостью тестов |

## Последствия

**Положительные**

- Гейт детерминирован и воспроизводим: seed бутстрапа, состав семьи, версии датасета и скореров попадают в
  иммутабельный `GateReport`, адресуемый хешем; выпуск ссылается на него.
- Ни одного сетевого вызова и ни одного внешнего процесса в пути принятия решения — исчезает целый класс отказов
  «сайдкар недоступен на релизе».
- `@wf/stats` без зависимостей тестируется в вакууме и переиспользуется воркером evals, MCP-тулом
  `experiment_compare` и Studio.
- Понятные человеку величины считаются из тех же данных: delta в единицах метрики, win/loss/tie, число дискордантных
  пар, пол шума, достигнутая мощность — они объясняют, **что делать дальше** («добавь кейсов», «добавь повторов»,
  «стабилизируй судью»), в отличие от p-value.

**Отрицательные**

- Корректность BCa, McNemar, Holm и BH — наша ответственность; защищаемся golden-фикстурами из scipy/statsmodels.
- Недоступны смешанные модели, GEE и байесовские иерархические модели: при нескольких судьях развести случайные
  эффекты кейса, судьи и прогона мы не можем.
- A/A-прогон стоит денег: это ещё один полный прогон датасета (кэшируется, но первый раз платим).
- BCa при 60 тестах × 10 000 реплик × n = 500 на Node не замерен; если прогон превысит порог интерактивности,
  jackknife придётся кэшировать и выносить расчёт в воркер с прогрессом.
- Порог допуска судьи назначен по аналогии и требует проверки на собственной калибровочной разметке.

**Обязаны делать**

1. Семья тестов, `mpe` и `ni_margin` объявлены **до** прогона в политике узла (`NodeGatePolicy`). Подбор метрики
   после просмотра цифр — p-hacking; при 60 метриках «значимая» найдётся всегда.
2. `test`-сплит недоступен оптимизатору промтов; загрязнение — `GATE_UNAVAILABLE`, не `WARN`.
3. Обёртка над `@stdlib/stats-ttest` наружу отдаёт только `delta = B − A`. Проверено: `ttest(x, y)` даёт CI для
   `mean(x) − mean(y)`, то есть **A − B**; знак обязан быть покрыт тестом.
4. Множества `case_id` у A и B идентичны; любой пропуск выбрасывается из обеих версий и логируется в
   `dropped_cases`. Тихая непарность ломает всю статистику молча.
5. A и B прогоняются в одном окне, `provider_snapshot` пишется в запись эксперимента — иначе «прирост» это дрейф
   провайдера.
6. Non-inferiority проверяется границей CI, никогда `p > 0.05`.
7. `GATE_UNAVAILABLE` никогда не деградирует в `PASS` — ни по таймауту, ни при падении зависимости, ни на пустом
   датасете.
8. В отчёте по каждой строке обязательны: `node_id`, `scorer_id`, `n_pairs`, `n_discordant`/`n_ties`, `delta`,
   `CI95`, `p_raw`, `p_adj`/`q_adj`, `method`, `family`, `decision`; в шапке — `m` каждой семьи, `B`, `seed`, `R`,
   `dropped_cases`, `dataset_version`, `judge_calibration_id`.

## Проверка

- Юнит-тесты против golden-фикстур scipy/statsmodels с допуском **1e-9**: Wilcoxon (`zeroMethod` pratt/wilcox),
  exact и chi2-McNemar, percentile и BCa-бутстрап, Holm, BH.
- Тест на классическую ошибку BH: ищется **наибольшее** k с `p_(k) <= k/m*q`, отвергаются все гипотезы с 1 по k,
  включая те, чей собственный p порог не прошёл. Наивная реализация «отвергай каждую, чья `p <= k/m*q`» обязана
  валить тест.
- Тест знака: обёртка возвращает `delta > 0`, когда B действительно лучше (ловит готчу `ttest`).
- MC-тест калибровки: на синтетике с истинным эффектом 0 доля отвержений в `primary` не превышает alpha, в
  `secondary` — около q.
- A/A как runtime-проверка самого пайплайна: отвержение в `primary` на A/A → `GATE_UNAVAILABLE('pipeline_unstable')`;
  доля отвержений в `secondary` выше `2 × q` → `GATE_UNAVAILABLE('dependence_underestimated')`.
- Правило границ импорта: `@wf/stats` не импортирует `@voltagent/*`, Langfuse, drizzle и `@wf/llm` — проверяется
  `no-restricted-imports`, как и изоляция LLM-слоя.
- CI: gate-репорт сериализуется и перечитывается без потерь; два прогона гейта на одних данных и одном seed дают
  идентичное решение и идентичные границы CI.
- Kill-критерий: если A/A-прогон систематически даёт отвержения в `primary` либо гейт не отличает A/A от A/B,
  статистика гейта считается непригодной и блокирующие решения по ней не принимаются до починки.

## Пересмотр

Пересматриваем при появлении любого из требований, которых нет в TS:

1. **Смешанные модели** — несколько судей, надо развести случайные эффекты кейса, судьи и прогона
   (`statsmodels.MixedLM`, `lme4`); эквивалента в TS нет.
2. **Кластерно-робастные оценки / GEE** при сильно вложенных датасетах.
3. **Байесовская отчётность** («вероятность того, что B лучше A, = 0.93» вместо p-value) — язык понятнее для
   продукта, но это отдельная фаза.

Способ возврата зафиксирован заранее, чтобы решение не принималось в спешке: **stateless HTTP-сайдкар**
(FastAPI + uvicorn) в собственном контейнере с пиннутыми `scipy`/`statsmodels`, вызывается **только воркером
evals** и никогда в пути запроса, вход и выход — JSON, валидируемые zod на нашей стороне; при недоступности
сайдкара гейт отдаёт `GATE_UNAVAILABLE`, а не `PASS`. Прямой запрет: не тащить Python в монорепу Node через
`child_process` — это ломает деплой и наблюдаемость.

Отдельные триггеры на ревизию порогов: замер BCa на реальном объёме (60 тестов × 10 000 реплик × n = 500) свыше
порога интерактивности — выносим в воркер и кэшируем jackknife; накопленная калибровочная разметка судьи —
перепроверяем пороги weighted kappa и Krippendorff alpha на своих данных; узлы с метрикой у потолка
(accuracy 0.98) — абсолютный `mpe` в pp там бессмыслен, нужен относительный порог по доле оставшихся ошибок
(error reduction), и это правка политики узла, а не кода `@wf/stats`.

# 31. Редактирование канваса: человек и агент

> Статус: draft
> Зависит от: [15. Studio](15-studio-frontend.md), [14. MCP-контракт](14-mcp-contract.md), [ADR-0017](adr/0017-files-as-source-of-truth.md), [ADR-0009](adr/0009-op-log-not-crdt.md)
> Детали: [frontend/edit-gestures.md](frontend/edit-gestures.md) и соседние edit-*.md

## Постановка

Канвас редактируемый руками с самого начала; тот же воркфлоу параллельно правит агент через MCP;
обе правки видны и различимы. Это отменяет режим «только чтение» в фазе 0.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Чем человек правит граф | тот же `flow_patch(expects[{path, file_hash}], ops[])`, что у агента; UI ходит REST `PATCH /api/specs/:id` с `If-Match: "<file_hash>"` в тот же use-case | один валидатор, одна точка записи файла, один источник конфликтов; `If-Match` и `expects` выражают одно условие CAS |
| Гранула записи | жест = патч = запись файла = строка в ленте | жест — единица намерения человека и единица отката |
| Позиции узлов и свёрнутость | не операции графа: хранилище раскладки в базе, LWW по полю, своя ось `layout_rev`, вне файлов и вне `content_hash`; это единственное состояние канваса, которое остаётся в базе — по этой строке ADR-0016 не заменяется | иначе драг мышью отбивал бы CAS агента десятки раз в минуту и рождал коммит на каждое движение |
| Модель клиентского состояния | `serverDoc(file_hash)` + `pendingIntents[]`, рендер = `project(serverDoc, intents)`; в полёте намерение, не готовый патч | намерение переигрывается на новой базе, патч — нет; клиентской истории и клиентского ребейза не заводим |
| Оптимистичность | применяем локально сразу, откатываем целиком по отказу сервера | агент занимает документ секундами; round-trip на каждый клик невозможен |
| Сопоставление своего патча с ответом | обязательный `client_op_id` (ULID) в `flow_patch`, возвращается в конверте и в событии | иначе UI не знает, чей патч прилетел по SSE: свой откатывать нельзя, чужой надо подсветить |
| Канал живых изменений | SSE `GET /api/specs/:id/events`, `Last-Event-ID` = монотонный `seq` индексатора, не хеш: хеш не упорядочен; **транспорт, а не операция контракта** | у клиента агента нет server-initiated push и есть idle timeout 5 мин; агент добирает пропуск через `flow_history({since})` по git-логу |
| Undo | обратные операции новым патчем, записываемым в файл; личный стек жеста | git-история файла линейна и содержит чужие коммиты; откат до коммита молча снёс бы работу агента |
| Откат правки агента | отдельный явный жест, инверсный `flow_patch` поверх текущего `file_hash`; инверсию считает сервер, результат — новый коммит | единственная точка записи остаётся одна, откат всегда движением вперёд |
| Advisory-lock | мягкий, берётся на сессию структурной правки, а не на драг; перехват — только человеком и только REST | drag конфликтов не имеет; лок сокращает частоту диалогов, а не корректность |
| Применение потока агента | по умолчанию `batched`: сервер применил, канвас показывает по кнопке, дифф доступен до применения | доверие строится на «увидел дифф → принял», а не на дёргающемся графе |
| Атрибуция | `actor` из git-коммита, для ещё не закоммиченного — из `write_intents`; UI ничего не вычисляет сам; носитель — триада форма обводки + бейдж + текст, цвет четвёртым слоем | второй реестр авторства = рассинхрон; цвет не может быть единственным носителем (§8.3) |

## Жесты и операции

`op` — элемент `ops[]` внутри `flow_patch`. Полная таблица — [frontend/edit-gestures.md](frontend/edit-gestures.md) §1.

| Жест | Операция | Канал |
|---|---|---|
| Перетащить архетип из палитры, `⌘K` → выбрать | `add_node{type, name}` | `flow_patch` |
| Delete на узле | `remove{kind:'node'}` + каскад `remove{kind:'binding'}` одним патчем | `flow_patch` |
| Двойной клик по заголовку → ввод | `set{path:'nodes/<name>/name'}`, ссылки каскадит сервер | `flow_patch` |
| Протянуть от выхода к слоту либо обратно | `bind{target, source}` | `flow_patch` |
| Оторвать конец ребра: в пустоту — `remove{kind:'binding'}`, на другой выход — одна `bind` | по месту отпускания | `flow_patch` |
| Правка поля в инспекторе, коммит по blur/Enter | `set{path:'nodes/<name>/<field>'}` | `flow_patch` |
| Рамочное выделение → Delete | один патч, `ops[]` = удаления + каскад рёбер, лимит 50 | `flow_patch` |
| Перетащить узел, свернуть группу, зум | `flow_layout_set`, LWW | раскладка |

Три класса: **свободно** (позиция, свёрнутость, зум, выделение) — локально и сразу; **с валидацией до
применения** (`bind`, отцепление обязательного слота, `remove` узла с потребителями, `set` на поле,
меняющее сигнатуру) — клиент проверяет синхронным предикатом по локальной копии реестра типов, сервер
проверяет заново и авторитетен только он; **без прямого жеста** — пять случаев ниже.

| Не пускаем прямой манипуляцией | Почему | Как всё-таки сделать |
|---|---|---|
| Привязка к узлу, не доминирующему над потребителем | доминирование считает компилятор, на клиенте в момент жеста недоказуемо | патч через диалог, кандидат «вставить `join`» |
| Ребро, замыкающее цикл вне `loop` | то же | обернуть в `loop` |
| Удаление узла, на который ссылается активный прогон или датасет | ссылка живёт вне спеки | диалог с подтверждением каскада |
| Правка узла внутри компонента из общей библиотеки | правка затронула бы чужие воркфлоу | форк компонента |
| Редактирование `uses`-пинов (версии, хеши) | пин — граница доверия | `registry_propose` |

«Запрещено» здесь значит **нет прямого жеста**, а не «невозможно». Никакой жест не обходит валидатор.

## Два канала записи

Главное решение документа: **граф пишется в файл, геометрия — в базу; носители разные и семантика разная.**

| Свойство | Канал графа (файл) | Канал раскладки (база) |
|---|---|---|
| Операция | `flow_patch({expects[{path, file_hash}], ops[1..50], client_op_id})` | `flow_layout_set({layout_rev, entries[{path,value,at}]})` |
| Носитель | `flows/<flow_id>/flow.yaml` и `nodes/<node_id>.yaml`; пишет компилятор транзакцией `.aqven/txn/<ulid>` под `.aqven/lock` | таблицы раскладки в Postgres |
| Ось версий | sha256 байтов файла плюс git-история | `layout_rev`, `updated_at` на запись |
| Оптимистичная блокировка | CAS по `file_hash` (`If-Match`), отказ `STALE_FILE`, `FILE_VANISHED`, `FILE_EXISTS` | нет: хеш не проверяется, 409 невозможен |
| Семантика конфликта | отказ валидатора либо ребейз либо вопрос человеку | LWW по полю, проигравшие возвращаются в `dropped[]` |
| Влияние на `content_hash` | входит | не входит; `ir.ui` — снимок, запекаемый при публикации и экспорте |
| Атрибуция | автор git-коммита, видна в ленте и на канвасе | `actor` только для отладки, в историю не попадает |
| Доступ агента | полный, включая прямую правку файла нативными Read/Edit/Write | нет ни записи, ни чтения: позицию новому узлу ставит сервер, `actor: system` |

Почему не один канал: позиции внутри `nodes/<node_id>.yaml` ломают `release_hash` и дают коммит
с девятью изменёнными файлами на один драг; вынести их в файл рядом — тот же шум в `git status`
и лишняя сущность в диффе; отказ от позиций (всегда ELK) делает руку бессильной. Раскладка остаётся
в базе именно потому, что она не часть определения и её незачем ревьюить. Разбор целиком —
[frontend/edit-layout.md](frontend/edit-layout.md) §1.

ELK не запускается на каждое изменение: холодная раскладка (позиций нет вовсе), инкрементальная
вставка узла чистым правилом за O(соседей), явная перекладка кнопкой со снятием закреплений.
Автоматической полной перекладки нет ни при одном изменении графа — вместо неё подсказка при
`overlap_ratio > 5 %`.

## Одновременность

Событие SSE и тело ответа-конфликта несут одни и те же кадры `{seq, blob_before, blob_after, actor, client_op_id, ops[], summary}` — путь обработки один, а не два. Порядок держит `seq` индексатора, тождество состояния — хеш.

| Условие | Что делает клиент |
|---|---|
| `ev.blob_before === localBlob` | fast-forward: применить `ops` к `serverDoc`, локальный хеш становится `blob_after` |
| `ev.blob_before !== localBlob` либо `truncated` | полный `flow_get`, `pendingIntents` сохраняются, батч сбрасывается |
| Есть `pendingIntents` | каждое намерение переигрывается на новом `serverDoc`; пересечение путей → `conflicted`, не отправляется |
| Человек держит мышь | применение отложено в буфер, `serverDoc` обновлён, проекция — нет |
| Обрыв SSE | переподключение с `Last-Event-ID`; после 3 неудач — поллинг `flow_get` раз в 10 с и плашка |

Ребейз автоматический ⇔ множества путей не пересекаются **и** все id, которые читает операция, живы
после дельты. Иначе отказ с кандидатами либо вопрос человеку.

| Моя операция | Операция агента | Результат |
|---|---|---|
| Тащу узел | `remove_node` того же узла | позиция отбрасывается, узел становится призраком, тост «вернуть» |
| `bind` слота | сменил `schemaId` выхода источника | отказ `TYPE_MISMATCH` + `candidates[]` |
| Правлю скаляр | правит тот же путь | вопрос человеку: два значения на выбор, `rebase:'manual'` |
| Оборачиваю в компонент | любая правка внутри выделения | эксклюзивная операция: побеждает первый, второй повторяет на новом `file_hash` |

**Advisory-lock мягкий.** На драг лок не берётся: конфликтов у драга нет, а лок на перетаскивание —
ложное чувство защищённости. Лок берётся на сессию структурной правки, `ttl_s: 60`, heartbeat 20 с;
лок агента — `ttl_s: 300` на ход целиком. Перехват — кнопка человека, `flow_lock_takeover` в
MCP-поверхности отсутствует; агент узнаёт о выселении предупреждением `LOCK_TAKEN`, и патч всё равно
применяется. Если оба игнорируют лок, работает CAS по `file_hash`: **невалидное дерево физически не пишется**.

**Поток агента.** Сервер применяет всё немедленно, буферизация только визуальная — поэтому бейдж
«показан `a1b2c3d` · на сервере `9f4e2a1`» висит всё время отставания. Режимы: `live`, `batched`
(по умолчанию), `paused`. Батч = кадры с одним `lock_id`, ELK пересчитывается один раз на батч,
> 200 операций либо > 10 коммитов → полный `flow_get`. Эксклюзивные операции (`component_define`,
записывающий `component_expand`, `architecture_instantiate`, `flow_import`, смена архетипа) идут как
`flow_patch({exclusive: true})`: UI на секунды становится read-only с сохранением черновиков.

## Атрибуция

Различимость без цвета: сплошная обводка — человек, штриховая — агент, призрак — удаление, двойной
контур — конфликт. Цвет и бейдж (`User` / `Sparkles` из §8.3) — слои сверху. Гранула — узел и путь
операции. Позиции атрибуции не получают вовсе.

| Состояние узла | Кодировка | Снимается |
|---|---|---|
| Изменено мной в этой сессии | 2px сплошная, бейдж `User` | конец рабочей сессии |
| Изменено агентом, не просмотрено | 2px штриховая + точка на бейдже | узел открыт, либо закрыт слой диффа, либо «всё просмотрено» |
| Изменено агентом, просмотрено | 1px штриховая, приглушённый бейдж | конец сессии; дальше только лента и провенанс поля |
| Удалён агентом | призрак 50 %, не перетаскивается | вместе с меткой «просмотрено» |

Затухание — **по событию, а не по таймеру**: таймер гасит метку до того, как её увидели.

**Дифф патча агента** — слой поверх графа (клавиша `D`, состояние в URL). Незатронутые узлы
приглушены до 40 %, но остаются на месте; добавленные — бейдж `Plus`; удалённые — призраки на прежних
координатах; изменённые поля — счётчик с раскрытием `path: было → стало`; перемещения не показаны.
Раскладка заморожена, пока слой открыт. Сводка над канвасом: `Claude · a1b2c3d → 9f4e2a1 · 12 операций ·
+3 узла · −1 · 6 полей · 2 связи`, клик по счётчику фильтрует слой, `[по шагам]` проигрывает коммиты эпизода.

**Лента ревизий** читает git, а не таблицу операций: горизонтальная шкала под канвасом, засечка =
коммит эпизода, форма засечки повторяет кодировку, серии одного автора группируются. Что изменилось
берётся из `flow_history` поверх git-лога файла, «зачем» — из `intent`-трейлера и `journal_read` по тому
же коммиту (нет записи — не выдумываем), валидность состояния — `flow_compile({at})`. Незакоммиченная
правка показана хвостовой засечкой «черновик» из `write_intents`. Просмотр прошлого коммита переводит
канвас в явный режим истории с запретом правки.

**Откат правки агента** — `flow_history({invert: true})` отдаёт инверсию как готовый
`candidates[].apply`, кнопка сначала шлёт `dry_run`; серия из 12 операций откатывается одним патчем.
Формулировка в UI честная: откатить можно то, поверх чего никто не писал. Лгать про «undo как в
редакторе» нельзя — git-история линейна и вперёд-направлена, откат сам становится коммитом.

## Undo

Undo — `flow_patch(expects = текущие хеши затронутых путей, ops = inverse_ops)`, а не
`flow_revert` до коммита: откат до коммита снял бы все правки агента, случившиеся после. Пишется undo
туда же, куда и обычный патч, — в файл. `inverse_ops` считаются в момент применения из снимка
затронутых путей (для `set` нужно прежнее значение, для `remove` — удалённое тело). Стек **личный**:
undo человека никогда не отменяет операцию агента. Undo проходит тот же валидатор и может быть
отклонён — это нормально и должно быть видно.

| Что случилось между правкой и undo | Исход |
|---|---|
| Ничего либо агент правил другие файлы и пути | применяется, при нужде авто-ребейз, подсказка «поверх 3 правок Claude» |
| Агент правил тот же путь | диалог: инверсия вернула бы значение, которое агент заменил осознанно |
| Правка человека — предпосылка правки агента | отклонён валидатором, кандидат «отменить обе» одним патчем |

Redo — прямой повтор `ops` тем же механизмом. У канала раскладки свой undo, мгновенный и без сервера.

## Внешние правки

Файл меняется мимо Studio: человек сохранил из редактора, Claude Code записал через Write/Edit,
приехал `git pull`. Это штатный путь работы, а не авария. Детали —
[files-first/external-edits.md](files-first/external-edits.md).

| Вопрос | Решение |
|---|---|
| Обнаружение | fs-watcher с дебаунсом и сверкой `file_hash`; git-операции ловятся по `.git/HEAD` и `ORIG_HEAD` и дают один батч, а не N событий на файл |
| Как попадает на канвас | импортом в виде патча от актора `fs:<hash>` либо `git:<sha>`: тот же валидатор и та же единственная точка записи |
| Защита от петли | writer кладёт ожидаемый `file_hash` в outbox; событие с совпавшим хешем — no-op |
| Битый файл | карантин файла, а не проекта: в индексе живёт `last_good`, соседние воркфлоу и прогоны работают |
| Раскладка | из файлов не импортируется вовсе: она в базе и на `file_hash` не влияет |

Канвас реагирует по состоянию клиента, а не по источнику события:

| Состояние клиента | Что делает канвас |
|---|---|
| Нет `pendingIntents`, пути не пересекаются | молчаливое применение, штриховая обводка, бейдж `fs` либо `git` |
| Есть `pendingIntents`, пути не пересекаются | авто-ребейз, ничего не спрашиваем |
| Пересечение путей | плашка «в git — X, у вас — Y», три исхода: принять чужое, оставить своё, разобрать по путям |
| Батч > 200 операций либо > 10 коммитов | полный `flow_get`, плашка «проект обновлён из git (47 файлов)» |
| Импорт отклонён валидатором | канвас не меняется вовсе, плашка «файл `X` не принят», список `problems[]` |

Блокировки канваса на внешнюю правку нет никогда: чужой коммит не имеет права отнять у человека
несохранённый жест. Пока кнопка мыши нажата, применение отложено — `serverDoc` обновлён, проекция нет.

## Изменения контракта

| Операция | Новая или изменение | Зачем | Приоритет |
|---|---|---|---|
| `flow_list` | новая | стартовый экран: человек начинает со списка, а не с известного `spec_id` | BLOCKER P0 |
| `flow_history` | новая, читает git-лог файла; `spec_ops_read` отменяется | лента ревизий, дифф патча агента, шаг по истории; агент ею же добирает пропуск | BLOCKER P0 |
| `flow_revert` | новая; пишет восстановленное содержимое новым коммитом, не переписывает историю | откат патча агента; агенту доступна только для коммитов с его же `actor` | BLOCKER P0 |
| `flow_layout_get`, `flow_layout_set` | новые | канал раскладки: драг не пишет файл, не рождает коммит и не отбивает CAS агента | BLOCKER P0 |

## Открытые вопросы

1. **`flow_revert` — обратный патч или запись содержимого коммита?** Обратный патч существует не всегда
   (удалённый узел с вложенными биндингами). Что сделать: выбрать до реализации — от этого зависит `reverted[]`.
2. **Ревизирует ли раскладка — закрыт.** Раскладка живёт в базе, своя ось `layout_rev`, файлов
   и `file_hash` не касается ([ADR-0017](adr/0017-files-as-source-of-truth.md)).
3. **Слияние текста промта.** Стало острее: промт лежит отдельным файлом, и его правят в редакторе
   напрямую. Без библиотеки трёхстороннего слияния любая параллельная правка уходит в диалог.
   Что сделать: замерить частоту коллизии на моках, затем решать про CRDT.
4. **Мультиагентность.** `actor` — это «Claude» или конкретная сессия? Двух штриховых обводок не
   различить. Что сделать: решить кодировку §Атрибуция до первой реализации, а не после.
5. **Гранулярность подсветки и `seen_seq` без аккаунта.** Помечать узел или поле; куда писать курсор,
   пока пользователь один. Что сделать: `local-user` в прототипе с явным долгом на миграцию.

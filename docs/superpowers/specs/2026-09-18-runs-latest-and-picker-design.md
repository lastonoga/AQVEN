# Выбор последнего прогона и понятный список Runs

> Статус: согласовано владельцем 2026-09-18.
> Область: локальная Studio, `GET /api/runs`, страница одного flow.

## Цель

Переход по верхней вкладке Runs должен сразу показывать последний начатый прогон этого flow. Список прогонов должен помогать отличать их по содержанию, а не только по короткому ID. Ссылки с явным `?run=` сохраняют точный выбор.

## Подход

| Вариант | Итог |
|---|---|
| Добавить `run` к ссылке верхней вкладки из `last_run` flow | Отклонён: прямой `/runs` остаётся пустым; источник выбора зависит от места перехода. |
| Разрешать отсутствие `run` в загрузчике Runs как последний элемент списка | Выбран: одинаковое поведение вкладки, прямого URL и обновления страницы без второго перехода. |
| Загружать снимок каждого прогона при открытии списка | Отклонён: запрос на каждый пункт и задержка перед показом списка. |

Последний прогон — первый элемент `run_list` с сортировкой по `started_at` от новых к старым. При пустом списке остаётся существующее пустое состояние. Явный `?run=<id>` всегда имеет приоритет и не заменяется последним прогоном. Выбранный ID, снимок и события загружаются одним маршрутом, как сейчас.

## Данные и представление

`RunSummary` в Python и OpenAPI получает `dataset_item_id: string | null` и `selected_nodes: string[] | null`. Эти значения уже находятся в `RunCall.spec` при построении сводки; дополнительных запросов к хранилищу на пункт списка не требуется. `RunSnapshot` наследует поля из `RunSummary`. В документации API эти поля добавляются к контракту `run_list`.

Закрытый селектор и каждый пункт раскрытого списка показывают короткий ID, статус, относительное время, датасет и область запуска. Для `dataset_item_id` показываются датасет и case; при `null` — «Без датасета». Для `selected_nodes === null` — «Весь flow»; иначе — «Выбранные узлы: …». Это **область выбора**, а не обещание, что каждый узел успешно исполнился: зависимости и пропуски отражены в деталях прогона. Длинные наборы узлов визуально сокращаются, но полное значение остаётся доступным в имени пункта и поиске.

Пункты становятся выше и шире для двух-трёх строк метаданных, с ограничением по ширине окна. Первый пункт помечается «Последний». Поиск находит прогон по ID, статусу, датасету, case и имени выбранного узла. Существующий выбор пункта сохраняет явный `?run=` и закрывает список.

## Состояния и проверка

Загрузка и ошибка страницы используют существующие состояния маршрута; новые запросы при открытии списка не нужны. Отсутствующий датасет и полный flow получают явные подписи вместо пустых полей. Некорректный или недоступный явный ID не подменяется последним прогоном и проходит через существующую ошибку снимка.

Тесты проверяют: вход на `/runs` выбирает последний прогон; явный ID остаётся выбранным; flow без прогонов показывает пустое состояние; `RunSummary` отдаёт оба поля; раскрытый и закрытый селектор показывают контекст и позволяют искать по нему. После изменения OpenAPI обновляются генерируемые типы Studio; проходят тесты Python и Studio, типизация, линт и сборка.

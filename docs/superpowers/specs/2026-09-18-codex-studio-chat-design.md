# Codex CLI в чате Studio: проектное решение

> Статус: согласовано владельцем 2026-09-18; дополнено общим списком тредов проекта.
> Заменяет решение «только Claude» в [ADR-0030](../../adr/0030-local-browser-backend.md) §6, `A14` и [DECISIONS.md](../../DECISIONS.md) после принятия нового ADR.

## Цель и граница

Studio предлагает выбрать Claude Code или Codex для встроенного чата. Выбор не меняет исполнение узлов `llm`, провайдеров моделей воркфлоу и внешний MCP-контракт. Оба агента используют существующие маршруты чата, журнал сессий и поток `ChatEvent`; пользователь видит одинаковые операции: новое сообщение, поток ответа, инструменты, одобрение, прерывание, история и возобновление.

## Рассмотренные подходы

| Подход | Плюсы | Минусы | Решение |
|---|---|---|---|
| `openai-codex` для `codex app-server` | Официальный Python SDK и типизированные сообщения; собственный CLI-рантайм закреплён версией | Требуется нормализация событий и явный обработчик одобрений | Выбран |
| Свой клиент JSON-RPC к `codex app-server` | Полный контроль над протоколом | Сопровождение транспорта, схем и совместимости своими силами | Отклонён |
| `codex exec --json` | Простая пакетная интеграция | Не предназначен для интерактивного управления одобрениями Studio | Отклонён |

Официальная документация: [Python SDK](https://learn.chatgpt.com/docs/codex-sdk), [app-server](https://learn.chatgpt.com/docs/app-server), [неинтерактивный режим](https://learn.chatgpt.com/docs/non-interactive-mode). Метаданные PyPI на 2026-09-18: `openai-codex==0.147.0`, Apache-2.0, Python `>=3.10`, зависимости `pydantic>=2.12`, `openai-codex-cli-bin==0.147.0`. Релиз 0.154.0 не подходит существующей оси зависимостей: он требует `packaging>=26.2`, тогда как `pydantic-ai-slim[xai]==2.43.0` через `xai-sdk` требует `packaging<26`. Низкоуровневый API и поведение обработчика одобрений версии 0.147.0 проверены по wheel. Точный пин попадает в `aqven` и общий `uv.lock`; проверка версии и зависимостей записывается в `docs/98-version-audit.md`.

## Настройка и совместимость

- Проект хранит `chat.backend: "claude" | "codex"` как обычное значение в проектной SQLite-базе. При отсутствии записи действует `claude`, поэтому существующие установки не меняют поведение.
- Экран Settings → Agents показывает выбранный CLI, обе опции и статус входа выбранного агента. Изменение подтверждается типизированным REST-запросом и отражается в Studio без перезапуска сервера. Если Codex недоступен или пользователь не вошёл, выбор сохраняется, но новый ход сообщает причину и инструкцию входа; автоматического отката на Claude нет.
- Выбор определяет бэкенд **новых** сессий. Каждая созданная сессия уже хранит `backend`; старые сессии Claude остаются Claude, новые Codex остаются Codex при дальнейших переключениях. Возобновление использует бэкенд сохранённой сессии, а не текущее значение настройки. Миграции истории между агентами нет.
- Панель чата показывает треды **всего проекта** одним списком, с отметкой Claude/Codex и привязкой к flow, если она есть. Действия «Новый тред» и «Открыть тред» позволяют создать сколько угодно разговоров под одним проектом и переключаться между ними; новый тред использует текущий выбор агента и контекст проекта. Переключение агента не скрывает и не переписывает старые треды. Контекст проекта (файлы, выбранный flow и AQVEN MCP) общий, но история сообщений одного треда не переносится автоматически в другой или между агентами.
- Существующий HTTP-контракт чата и SSE остаётся основным. Тип `AgentBackendKind` расширяется до `claude | codex`, OpenAPI и генерируемые TypeScript-типы обновляются от Python-моделей. API выбора бэкенда валидирует оба значения, не доверяя произвольному JSON в хранилище.

## Адаптеры и маршрутизация

- `AgentBackend` остаётся портом. Реестр двух адаптеров выбирает агент по `ChatSession.backend` для сообщений, событий, одобрений, прерываний и закрытия. Создание новой сессии читает `chat.backend`. Код Claude не перенаправляется через Codex и его существующий журнал сохраняется.
- Адаптер Codex владеет процессом app-server через низкоуровневый `CodexClient` из `openai-codex`, запускаемый без блокировки event loop. Высокоуровневый `AsyncCodex` **не используется для одобрений**: у SDK 0.147.0 обработчик по умолчанию принимает запросы одобрения, тогда как Studio обязана ждать явного ответа пользователя. Адаптер регистрирует собственный обработчик с отказом при неизвестном виде запроса, таймауте, закрытии или прерывании.
- При первом ходе создаётся Codex thread с `cwd` проекта; его id хранится в `backend_session_id`. При возобновлении вызывается `thread/resume`. Уведомления app-server переводятся в существующие события текста, рассуждений, вызовов инструментов, команд, изменений файлов, использования токенов, ошибок и завершения хода. SSE читает тот же журнал Studio, поэтому реконнект клиента идёт по `seq`, а не по истории app-server.
- `GET /api/chat/status` отражает выбранный агент; статус Codex читается через `account/read` из app-server. AQVEN не читает и не сохраняет токены Codex. В интерфейсе для отсутствующего входа показывается команда входа в Codex CLI.
- Codex получает MCP-сервер AQVEN по локальному HTTP URL. Конфигурация передачи токена не записывает его в argv или файлы проекта; сервер AQVEN должен быть доступен до начала хода. Ошибка инициализации обязательного MCP-сервера останавливает ход с диагностикой, а не запускает агента без инструментов AQVEN.

## Безопасность

- Процесс Codex получает очищенное окружение без ключей провайдеров из `.env`. Его разрешения ограничены рабочим проектом; профиль файловой системы запрещает чтение `.env` и производных секретных файлов, а также прямое чтение служебных файлов с токенами. Запрет применяется к командам и изменению файлов независимо от режима одобрений. Переменная для MCP-токена не наследуется исполняемыми агентом shell-командами.
- Режим `plan` не пишет файлы. Режимы `default` и `accept_edits` сопоставляются с разрешениями Codex так, чтобы опасные операции проходили существующий маршрут одобрения Studio. Неизвестный запрос app-server отклоняется; без доказанного ограничения секретов Codex-сессия не стартует.
- Проверки включают попытку прочитать `.env` и вывести ключ через окружение в каждом режиме, проверку отсутствия токена MCP в событиях, ошибках, аргументах процесса и журнале, а также сценарии разрешения и отказа для команд и правок.

## Ошибки и проверка

- Неустановленный или не запускающийся CLI, отсутствие входа, ошибка MCP, отказ sandbox-профиля, авария процесса и потеря связи дают типизированный `chat_error` без молчаливого переключения провайдера. Повторная отправка с тем же `client_op_id` остаётся идемпотентной.
- Тесты Python проверяют настройку, маршрутизацию смешанных сессий, воспроизведение событий Codex, каждое решение об одобрении, прерывание, восстановление и защиту секретов. Тесты Studio проверяют выбор агента, статусы, сохранение настройки, общий список тредов проекта, создание нового треда выбранным агентом и продолжение старой Claude-сессии после выбора Codex. Интеграционная проба использует установленный CLI и отдельный временный проект; сетевой модельный вызов выполняется только при явно подготовленном тестовом входе.
- Новый ADR отменяет Claude-only пункты ADR-0030. Обновляются `docs/DECISIONS.md`, `docs/23-studio-api.md`, версии, установка и инструкции пользователя. Чужие незакоммиченные правки в текущем рабочем дереве остаются нетронутыми.

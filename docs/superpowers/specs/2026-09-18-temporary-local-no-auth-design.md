# Временное отключение токена локальной Studio

> Статус: согласовано владельцем 2026-09-18; реализовано для локального CLI-сервера.
> Зависит от: [ADR-0030](../../adr/0030-local-browser-backend.md) §3, [DECISIONS](../../DECISIONS.md) «Локальный режим».

## Цель

Локальные `aqven studio`, `aqven dev` и `aqven serve` по умолчанию принимают запросы Studio, API и MCP без Bearer-токена, cookie или `access_token`. Это временное исключение из ADR-0030 §3. Привязка сокета к loopback и проверки `Host` и `Origin` остаются обязательными. Уже запущенный процесс нужно перезапустить: изменение кода не меняет его настройки.

## Границы и поведение

| Поверхность | Решение |
|---|---|
| Локальный CLI-сервер | `ServerOptions.require_auth=False` по умолчанию; `--require-auth` возвращает токеновый режим на время исключения. |
| `AccessGuard` | Проверки `Host` и `Origin` работают в обоих режимах. При `require_token=False` пропускается только проверка учётных данных; URL-токен не обменивается на cookie. |
| MCP | В локальном режиме без токена отключается и внутренняя Bearer-проверка `/mcp/`. В режиме `--require-auth` текущая проверка сохраняется. |
| Браузер | Без токена открывается обычный URL Studio или `--dev-origin`; с `--require-auth` остаётся существующий URL с `access_token`. |
| `server.json` | Формат и случайный токен сохраняются для совместимости с CLI, пробой живости сервера и чатом; при локальном режиме без auth они не обязательны для запросов. |
| Встраиваемое приложение | `create_local_app` и прямой `create_app` не меняют своих значений по умолчанию; `LocalAppOptions(access=None)` продолжает работать отдельно. |

При повторном запуске CLI уже работающий сервер проекта переиспользуется с его прежней настройкой и открывается по URL с токеном для совместимости; для смены режима пользователь останавливает и запускает сервер заново. Отключение токена повышает доступность API и инструментов MCP для других локальных процессов, поэтому оно не должно расширять привязку сокета или допустимые `Host`/`Origin`.

## Проверка

- На свежем локальном сервере без auth анонимные `/api/project`, `/api/health` и `/mcp/` проходят, а чужие `Host` и `Origin` отклоняются.
- `--require-auth` воспроизводит прежние ответы 401 и доступ по Bearer/cookie, включая внутреннюю проверку MCP.
- Браузер получает URL без токена в режиме по умолчанию и с токеном при `--require-auth`.
- Программное встраивание и прямой сервер сохраняют текущие тесты безопасности.

## За пределами изменения

Пересборка IR, ускорение сканирования проекта и обновление Vite proxy при перезапуске бэкенда — отдельные задачи. Отсутствие токена не исправит `502`, когда Python-сервер не запущен, или устаревший адрес прокси.

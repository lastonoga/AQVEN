# Inference Presentation Formatters Implementation Plan

> Historical plan. The implemented interface uses typed Liquid component tags and the **Formatted/Raw** Runs switch.
> See [the current flow guide](../../../aqven-py/docs/building-flows.md#5-presenting-inference-values-in-studio).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an inference declare one reusable Python formatter for input, output, or both, and let Runs switch between the existing Default value view and a safe Formatted view without losing any recorded data.

**Architecture:** An inference stores optional formatter references in its compiled plan. Execution events capture bound and normalized input, selected variants, and inference identity; a read-only batch API loads the run's plan snapshot and full values, calls each formatter, and validates a versioned display document. Studio renders only approved elements, appends unrepresented value leaves, and keeps its existing Flat/JSON Default renderer.

**Tech Stack:** Python 3.14, Pydantic 2, FastAPI, DBOS run events; React 19, TypeScript, TanStack Router, openapi-fetch, Vitest, Testing Library.

The exact display contract for version 1 is: `DisplayDocument(version=1, root=section)`; children are `section`, `text`, `field`, `list`, `badge`, or `media`. Scalar elements have **exactly one** of `path` (JSON Pointer into the focused value) or `value` (literal). `media` requires a `path` to an existing media value. `section` and `list` contain children and do not themselves mark data as represented. `tone` accepts only `neutral`, `positive`, `warning`, or `critical`. No HTML, URL, class name, component name, or handler field is accepted. This is the shared contract for the tasks below.

The exact REST contract is `POST /api/runs/{run_id}/presentation` with a JSON body `{ "locale": "en", "targets": [{ "address": { "node_id": "reply", "branch_key": null, "iteration": null, "item_index": null }, "side": "input" }] }`. It returns `{ "results": [{ "address": { ... }, "side": "input", "status": "formatted", "formatter": { "ref": "lumen.views:render", "fingerprint": "sha256-..." }, "document": { "version": 1, "root": { "kind": "section", "children": [] } }, "error": null }] }`. For `unavailable` or `error`, `document` is null, `formatter` may be null, and `error` is a short diagnostic string. Results preserve target order. The Python facade owns plan lookup: `DbosEngineFacade.present()` reads `view.call.ir_hash` through `self.runtime.plans.find()`. `ServerContext` needs no runtime field; the route calls the new `EngineFacade.present()` protocol method. A missing whole run remains HTTP 404; one bad target remains isolated in the 200 batch response.

## Completion criteria

The formatter is optional and reusable for both sides. A failed or missing formatter never changes run status and never hides Default. Python records complete inference input before validation and normalized input after preparation; old runs still load. The API uses the run's compiled plan snapshot and returns one isolated result per address/side. Formatted shows all represented content plus every unrepresented leaf, while Default retains Flat/JSON and flow-level output behavior.

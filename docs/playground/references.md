# Срез 1: образцы — что копировать

Что строим: локальный dev-плейграунд для воркфлоу. Один человек, свой каталог, `npx` команда, браузер.
Ниже — разбор образцов и решения, что взять.

## 1. Cube Playground — эталон, названный заказчиком

Факты из docs.cube.dev/docs/explore-analyze/playground:

- **Что это.** Веб-инструмент, чтобы *валидировать модель данных*: выполнить запрос и посмотреть
  результат. Аудитория — инженер, который прямо сейчас правит файлы модели. Не BI, не продукт.
- **Запуск.** Отдельной команды нет: поднимается сам вместе с сервером на `localhost:4000`, если
  `CUBEJS_DEV_MODE=true`. Dev-режим = `NODE_ENV=development` + выключенная проверка JWT.
- **Dev vs прод.** Прод-режима нет вообще. Документация прямо называет dev-режим «authentication
  bypass»: кто дошёл до порта — читает файлы модели, перезаписывает конфиг и делает запросы без
  ключей. «Use it only on a local development machine, never in production.»
- **Первый экран.** Сайдбар со списком кубов/вью и их членами (меры, измерения, иерархии, папки),
  раскрашенными по типу. Не дашборд, не «добро пожаловать» — сразу дерево того, что есть в проекте.
- **Навигация.** Один экран, вкладки результата: Results (строки + пагинация), Chart, Generated SQL,
  и вкладки API (SQL / REST JSON / GraphQL) — та же выборка в виде готового запроса для копипаста.
- **Связь с файлами.** Работает поверх тех же файлов модели, что и рантайм; отдельного хранилища у
  плейграунда нет. UNVERIFIED: моментальность подхвата правок и запись файлов из UI в этой странице
  документации не описаны — проверять экспериментом, не закладываться.
- **Что генерирует.** Эквивалент текущего запроса на трёх API. То есть UI — это способ *собрать
  корректный запрос руками и унести его в код*.

**Решение.** Копируем целиком форму: один порт, dev-only, без аутентификации, первый экран — дерево
того, что нашли в каталоге проекта, справа вкладки результата одного прогона, включая вкладку
«исходник» (у нас — DSL и IR вместо SQL).

## 2. Остальные образцы: одна сильная идея, одна ошибка

**Prisma Studio** (`npx prisma studio` → :5555). Сильное: запускается одной командой без своего
конфига — берёт `schema.prisma`, который в проекте уже есть, и сразу показывает сайдбар таблиц.
Ошибка: умеет работать и по голому `--url`, без схемы. Инструмент, оторванный от проекта, перестаёт
знать смысл данных и вырождается в грид. Мы так не делаем: без каталога проекта плейграунд не стартует.

**Drizzle Studio** (`drizzle-kit studio` → 127.0.0.1:4983). Сильное: локальный процесс отдаёт только
данные, вся конфигурация — существующий `drizzle.config.ts`, ничего нового заводить не надо.
Ошибка: сам UI хостится на `local.drizzle.studio` и ходит на localhost. Отсюда сертификаты, mkcert
и отвалы в Safari/Brave. Тот же дефект, за который заказчик отверг консоль VoltAgent. UI — локальный.

**GraphiQL**. Сильное: интроспекция схемы кормит автодополнение и панель Docs — исследуешь API, не
читая документацию; курсор в запросе всегда знает, что тут допустимо. У нас аналог — слоты и
лексические ссылки: клик по слоту показывает, откуда он резолвится. Ошибка: клиент без проекта —
он не знает, из каких файлов схема собрана, и не покажет провенанс. Нам провенанс обязателен.

**Storybook**. Сильное: единица работы — изолированный случай с зафиксированным входом, адресуемый
по URL. Переиспользуем: узел + зафиксированный вход = адрес вида `/node/:id`, перезагрузка не теряет
место. Ошибка: отдельный каталог конфигурации и свой билд. Старт секундами, конфиг живёт своей
жизнью и протухает. У нас конфигурации нет вообще: аргумент команды — путь к каталогу проекта.

**LangGraph Studio** (`langgraph dev` → :2024). Сильное: горячая перезагрузка — правишь промт или
сигнатуру тула в коде, UI показывает новое без рестарта; плюс возврат к узлу и повторный прогон.
Ошибка: требует аккаунт LangSmith и `LANGSMITH_API_KEY` до первого запуска, а UI живёт на
smith.langchain.com с `?baseUrl=localhost` — Safari это блокирует, лечится флагом `--tunnel`.
Регистрация ради дебага локального файла — запрещено.

**Mastra playground** (`mastra dev` → :4111). Сильное: воркфлоу рисуется графом и прогоняется
по шагам с произвольным входом, активный шаг подсвечивается; отдельный тул зовётся в одиночку.
Ошибка: расползание — туда же въехали чат с переключением моделей, MCP-браузер, скореры, датасеты
и эксперименты. Дебаг-панель стала продуктом. Наш список «чего НЕТ» существует именно против этого.

**Temporal Web UI**. Сильное: главный объект — история событий прогона, типизированный список с
payload входа и выхода на каждом шаге; это читается как факт, а не как лог. Ошибка: события описаны
в терминах движка (task queue, activity task scheduled), а не твоего кода — чтобы прочитать экран,
надо знать внутренности. Мы называем узлы именами из DSL, а не именами стадий компилятора.

**Inngest dev server** (`npx inngest-cli dev` → :8288). Сильное: ноль setup — ключи не проверяются,
подойдёт любая строка; сервер сам опрашивает приложение и подхватывает новые и изменённые функции.
Ошибка: автообнаружение сканирует порты 3000–3010, 5173, 8080 и прочие наугад; когда угадало не то,
это молчаливая пустая страница. Явный путь надёжнее магии — у нас путь к проекту передаётся всегда.

## 3. Что берём: приём → откуда → зачем нам

| Приём | Откуда | Зачем нам |
|---|---|---|
| Одна команда, без конфига плейграунда | Prisma Studio, Inngest | `npx wf dev ./project` и браузер — всё |
| Аргумент — каталог проекта, не БД | Prisma Studio (от обратного) | смысл узлов живёт в файлах, читаем настоящие |
| Dev-only, без аутентификации, один порт | Cube Playground | нет входа, нет пользователей, нет ролей |
| Первый экран — дерево найденного | Cube Playground | сразу видно, что компилятор увидел в каталоге |
| UI хостится локально | Drizzle, LangGraph (от обратного) | нет чужого домена, сертификатов и блокировок |
| Вкладка «сгенерированный исходник» | Cube (Generated SQL) | вкладки DSL и IR рядом с результатом прогона |
| Горячая перезагрузка при правке файла | LangGraph Studio | сохранил `flow.ts` — граф перерисовался сам |
| Узел + вход = адрес в URL | Storybook | F5 не теряет место; ссылку можно передать |
| Граф с подсветкой активного шага | Mastra playground | канвас показывает прогон, править им нельзя |
| Прогон = список событий с вход/выход | Temporal Web UI | тройка «промт + вход + выход» на каждом узле |
| Имена узлов из DSL, не из компилятора | Temporal (от обратного) | экран читается без знания внутренностей |
| Явный путь вместо автообнаружения | Inngest (от обратного) | не угадал — пустой экран без объяснения |

## 4. Антипаттерны dev-инструментов и как их не повторить

**Настройка до первого запуска.** LangGraph Studio требует аккаунт LangSmith и ключ ещё до того,
как ты увидел свой граф; Storybook требует каталог конфигурации. Правило: обязательных переменных
окружения ноль. Ключей моделей не просим — вызовы моделей и внешних тулов замоканы. Файл SQLite
создаётся сам при первом старте, рядом с проектом, и удаляется как обычный файл.

```
npx wf dev ./examples/hotel_pitch
```

**Медленный старт.** Билд-шаг перед первым экраном — главный источник раздражения. Правило:
Vite в middleware-режиме внутри того же сервера, без отдельной сборки; синтез — в том же процессе.
Синтезируем лениво: только открытый флоу, остальные — имя и статус из индекса каталога.
Цель — от команды до дерева в браузере меньше двух секунд. UNVERIFIED: цифру подтвердить замером.

**Потеря состояния при перезагрузке.** Перезагрузил вкладку — выбор узла, вход и последний прогон
исчезли. Правило: выбранное живёт в URL (`/flow/:flow/node/:node`), прогоны — строки в SQLite, не
объекты в памяти процесса. Рестарт сервера не стирает историю; F5 возвращает тот же экран.
Ссылку на конкретный узел можно передать другому человеку.

**Пустой экран вместо ошибки.** Inngest не нашёл приложение — пустая страница; компилятор упал —
белый экран. Правило: диагностика компилятора и синтеза — это контент первого экрана, наравне с
деревом. Не тост, не консоль браузера. Каталог без флоу показывает, где искали и что не подошло.
Флоу, который не компилируется, остаётся в дереве со статусом и текстом ошибки.

**Внешний хост и расползание.** Drizzle и LangGraph отдают UI с чужого домена — сертификаты и
блокировки браузера; Mastra доросла до чата, датасетов и экспериментов. Правило: один локальный
порт отдаёт и UI, и API. Список экранов зафиксирован в `scope.md` и растёт только через отдельное
решение заказчика — «раз уж есть панель, добавим сюда ещё» не аргумент.

## 5. Чеклист приёмки образцовости

1. Команда одна, аргументов кроме пути к каталогу нет, переменных окружения нет.
2. Ни один запрос страницы не уходит за пределы localhost.
3. Правка `flow.ts` перерисовывает граф без рестарта сервера.
4. F5 на любом экране возвращает тот же экран с тем же выбором.
5. Сломанный DSL даёт читаемую диагностику в интерфейсе, а не пустоту.
6. Ни один экран не даёт править граф мышью.

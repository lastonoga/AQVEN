# Срез 3. Визуальные конвенции воркфлоу-редакторов

Что копировать у n8n / Airflow / Step Functions / BPMN и как это ложится на наши 8 правил
(`01-graph-rendering-rules.md`).

## 0. Главный принцип, который чинит дефекты 1 и 2

AWS Step Functions требует от `Parallel`/`Map` структурного инварианта: **ветвь
самодостаточна** — «A state in one branch of a Parallel state must not have a `Next` field
that targets a field outside of that branch, nor can any other state outside the branch
transition into that branch» ([docs](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html)).
То же в BPMN (правило 0202, раздел 4).

Рёбра сквозь группу — не баг маршрутизации, а баг модели. Лечение: у группы ровно **один порт
входа и один выхода**, любое ребро «снаружи → внутрь» переадресуется на порт.

```ts
const boundary = (e: Edge, s = ownerFrame(e.source), t = ownerFrame(e.target)): Edge =>
  s === t ? e : { ...e, source: s ? exitPortOf(s) : e.source, target: t ? entryPortOf(t) : e.target }
```

Это убирает и дефект 1: транзитная линия не может пройти «мимо» `deduped` — вне группы её конец
теперь порт, а не внутренний узел.

## 1. n8n — ближайший аналог

| Приём | Как у них | Берём? |
|---|---|---|
| Поток слева направо, узлы выстроены по одной горизонтали | да, ветви расходятся **по вертикали от точки ветвления** | да: `rankdir: 'LR'`, ветви — соседние `rank` одного родителя |
| Порт-центричность: у узла явные кружки-хендлы, ребро всегда входит в хендл | да | да, у нас уже `@xyflow/react` handles — но зафиксировать `sourcePosition: Position.Right`, `targetPosition: Position.Left` на всех узлах |
| Слияние — **отдельный явный узел** `Merge`, а не «стрелки сошлись» | да, Merge ждёт оба входа | да: наш `merge` должен быть узлом-ромбом/плашкой, а не подписью на ребре (дефект 4) |
| Порядок ветвей задаётся геометрией: «orders the branches based on their position on the canvas, from topmost to bottommost» ([docs](https://docs.n8n.io/flow-logic/execution-order/)) | да | да: сортируй ветви в детерминированном порядке и не давай dagre их тасовать между рендерами |
| **Не** копировать | зависимость порядка исполнения от Y-координаты; «sticky notes» как группировку без семантики | нет |

Плотность n8n держит узкой карточкой: иконка + подпись **под** узлом; параметры на канвасе не
показываются вовсе, только в правой панели
([Node UI design](https://docs.n8n.io/integrations/creating-nodes/plan/node-ui-design/)).

## 2. Оркестраторы: стадии, статусы, вложенность

**Airflow Graph View** — прямой аналог наших групп ([`TaskGroup`, вложенность без
предела](https://www.astronomer.io/docs/learn/task-groups)). Берём: рамка с шапкой сверху и
кликабельная целиком; подсветка upstream/downstream по наведению — дешёвая замена распутыванию
рёбер; миникарта ([UI](https://airflow.apache.org/docs/apache-airflow/stable/ui.html)).
**Не** берём: у них известный баг ровно с нашим дефектом 1-2 —
«task-to-task dependencies between tasks buried into nested task groups … draws relationships
and node spacing in unusual ways» ([#35301](https://github.com/apache/airflow/issues/35301)).
Причина та же — рёбра адресуют внутренние узлы чужой группы.

**Dagster** — единственные, кто публично описал масштабирование: ranker `network-simplex` →
**`tight-tree`**, ребро рисуется только при видимом конце (порог **>50 рёбер в кадре**),
раскладка кэшируется в IndexedDB по SHA-1 графа
([blog](https://dagster.io/blog/scaling-dag-visualization)).
У нас: `ranker: nodeCount > 150 ? 'tight-tree' : 'network-simplex'`.

**Temporal Web UI** сознательно **не** рисует DAG: только Timeline с Event Groups (Scheduled +
Started + Completed = одна строка, [блог](https://temporal.io/blog/lets-visualize-a-workflow)).
Вывод: длительность и статус — не канвас, а `StageRail.tsx`; канвас показывает структуру.

**Argo / Prefect** — статус кодируется цветом **обводки** и бейджем в углу, не заливкой
(заливка занята типом узла). Копируем: `ring`, не `bg`.

## 3. AWS Step Functions Workflow Studio — наши `parallel` и `map`

| Состояние | Как отрисовано у AWS | Что копируем |
|---|---|---|
| `Parallel` | контейнер с заголовком, внутри **колонки-ветви**, все ветви начинаются на одной высоте и заканчиваются на одной; вход и выход контейнера — по одной точке | наш `parallel`: выравнивать первые узлы всех ветвей по одному `rank` и последние — тоже (`align: 'UL'` в dagre) |
| `Map` | **та же рамка, но со сдвоенным/штрихованным контуром** — «стопка карточек», означающая «то же самое ×N», внутри рисуется **один** экземпляр итерации | наш `map`: рисовать одну итерацию + бейдж `×N`, обводка `double`/offset-тень — ровно то, что правило 1 разрешает для рантайм-веера |
| ветвь | самодостаточна, связи наружу запрещены | инвариант из раздела 0 |

Дефект 5: `map` внутри `call` не «оторвана», если её порт входа соединён с портом родителя
коротким ребром, а рамка стоит по общему `padding`.

## 4. BPMN — источник условных обозначений (главный)

Правило **BPMN 0202**: sequence flow не пересекает границу под-процесса — поток родителя
**заканчивается на границе**, внутри начинается новый ([Basic
Rules](https://www.bpmnquickguide.com/quickguide/bpmn-quick-guide/bpmn-basic-rules),
[Flowable](https://documentation.flowable.com/latest/reactmodel/bpmn/reference/subprocess)).
Это наш инвариант из раздела 0, названный отраслевым стандартом.
Глоссарий берём целиком ([Camunda](https://camunda.com/bpmn/reference/)):

| Смысл | Знак BPMN | Наш узел / стиль |
|---|---|---|
| развилка «все ветви сразу» | ромб с **`+`** (parallel gateway) | `FanNode` для `diverge` / `parallel`: ромб 32×32, `+` |
| развилка «ровно одна ветвь» | ромб с **`×`** (exclusive) | `switch`: тот же ромб, глиф `×` |
| слияние | **тот же ромб, что и развилка**, входящих рёбер много | `merge` / `aggregate` / `judge` — ромб `+`, не прямоугольник (правило 3: конвергенция видна так же, как дивергенция) |
| повтор | **круговая стрелка** снизу по центру карточки | `loop`: глиф в нижнем центре `FlowNode`, плюс обратное ребро (правило 7) |
| «то же самое для каждого элемента» | **три полосы** снизу по центру: вертикальные = параллельно, горизонтальные = последовательно | `map` параллельный — ‖‖‖ вертикально; `map` последовательный — ≡ |
| развёрнутый под-процесс | скруглённая рамка со своими start/end внутри | `GroupNode` — так и есть |
| свёрнутый под-процесс | рамка с **`+`** в нижнем центре | **не используем** — правило 2 запрещает сворачивание |
| вызов внешнего компонента | **утолщённая рамка** (call activity) | `call` — `border-width: 3px` вместо `1px`. Единственный способ отличить «наш компонент» от «встроенной группы» без сворачивания |

Подписи веток (`best_of`, `merge`, `rank`, `vote`) в BPMN — **имена исходящих потоков gateway**:
текст у начала ребра, рядом с ромбом, а не в отдельной колонке.
Дефект 4: `EdgeLabelRenderer` с позицией **не в середине ребра**, а
`translate(${sx + 28}px, ${sy - 10}px)`, подложка `bg-background/90`, 11px,
`pointer-events-none`. Вертикальный пунктирный столбец подписей убрать.

## 5. Правила отрисовки, дающие максимум за минимум

Purchase, *Effective information visualisation*: «reducing the number of edge crosses is by far
the most important aesthetic»; изгибы и симметрия слабее; **ортогональность и угловое разрешение
статистически незначимы** ([1](https://www.sciencedirect.com/science/article/abs/pii/S0953543800000321),
[2](https://eprints.gla.ac.uk/227646/1/227646.pdf)). Порядок работ:

1. **Пересечения.** Раздел 0 убирает их структурно: dagre их и так минимизирует, мешают только транзитные рёбра.
2. **Рёбра сквозь узлы (дефект 1).** Сначала инвариант портов. Остаток — точечно
   `@tisoap/react-flow-smart-edge` 5.0.0 (A* вокруг узлов) только для рёбер, чей отрезок
   пересекает чужой узел; глобально не включать — он строит сетку на каждое ребро.
3. **Один тип ребра:** `type: 'smoothstep'`, `pathOptions: { borderRadius: 12, offset: 20 }` —
   выходит горизонтально из порта, совпадая с `LR`. Исключение — обратное ребро цикла:
   `type: 'default'` (bezier), `zIndex: 0`.
4. **Сетка** 8px (`snapGrid={[8,8]}`) — дёшево; полную ортогональную маршрутизацию исследование не оправдывает.
5. **Направление одно на весь канвас**: LR внутри группы и TB снаружи смешивать нельзя.

## 6. Плотность (дефект 3) при запрете сворачивания

Пустота у `merged` — следствие того, что группа растянута до габарита самого широкого ранга.
Меры по убыванию эффекта:

- **`rankdir: 'LR'` внутри линейных групп, `'TB'` только для веера** — цепочка занимает высоту
  одной карточки вместо колонки.
- **Разделители:** `nodesep: 24`, `ranksep: 56`, `edgesep: 12`; внутри группы — минус 25%.
- **Отступ рамки один на всех уровнях:** `padding = { top: 34, x: 16, bottom: 16 }` (34 — шапка
  с именем). Тогда `map` в `call` читается как вложенная, а не оторванная (дефект 5).
- **LOD вместо сворачивания** (правило 2 цело): `zoom < 0.55` → иконка + имя; иначе полная
  карточка. Читать `useStore(s => s.transform[2])` в `FlowNode`. **Габарит карточки при этом
  не меняется** — иначе поедет измеренная раскладка (правило 6).
- **Виртуализация и `tight-tree`** по порогам Dagster (>50 рёбер в кадре, >150 узлов).
- **Не** уменьшать шрифт: n8n держит 12px и прячет детали в панель.

## 7. Итоговая таблица конвенций

| Что показываем | Как принято обозначать | Откуда взято |
|---|---|---|
| развилка на N ветвей | ромб с `+`, ветви расходятся по вертикали | BPMN parallel gateway; n8n |
| выбор одной ветви | ромб с `×`, подпись условия у начала ребра | BPMN exclusive gateway |
| слияние | тот же ромб, что развилка; отдельный узел, а не «сошлись стрелки» | BPMN; n8n Merge |
| имя ветви | текст у источника ребра, 24-32px от ромба | BPMN flow name |
| цикл | круговая стрелка внизу карточки + обратное ребро bezier | BPMN loop marker |
| `map` ×N | три полосы внизу (вертикальные = параллельно, горизонтальные = последовательно), рамка «стопкой», бейдж `×N` | BPMN multi-instance; SFN Map |
| вызов компонента | утолщённая рамка группы (3px) | BPMN call activity |
| граница группы | шапка с именем и видом; **ни одно ребро её не пересекает** | BPMN 0202; SFN self-contained branch |
| вход/выход группы | по одному порту на сторону | SFN Parallel/Map |
| статус прогона | цвет обводки + бейдж в углу | Argo, Prefect |
| длительность | не на канвасе — на таймлайне/рельсе | Temporal Timeline |
| связи узла | подсветка upstream/downstream по наведению; обзор — миникарта + LOD по зуму, **без сворачивания** | Airflow; Dagster |

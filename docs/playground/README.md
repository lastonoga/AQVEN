# Плейграунд: сведённый план

> Пять срезов проектирования лежат рядом. Этот файл — арбитраж расхождений между ними
> и единая точка входа. При конфликте с любым срезом верен этот файл.

## Что строим

Dev-панель в стиле Cube Playground: открыл каталог проекта — увидел воркфлоу, запустил, разобрал
по узлам, нашёл причину, поправил файл, увидел обновление. Не продукт.

Чего нет: авторизации, пользователей, мультитенантности, правки на канвасе, реестров, версий,
экспорта, evals, датасетов, ленты агента, деплоя.

## Арбитраж расхождений

Срезы писались параллельно и разошлись в четырёх местах. Решено так:

| Вопрос | Варианты в срезах | Решение | Почему |
|---|---|---|---|
| Команда и порт | `wf playground` :5173 / `wf dev` :4000 / `wf dev` :5180 | **`wf dev`, порт 5180** | 5173 занят самим Vite, 4000 у Cube, 4983 у Drizzle, 3141 у VoltAgent |
| Сервер | Hono против голого `node:http` | **Hono 4.13.7 + @hono/node-server 2.1.1** | MIT, ноль зависимостей, есть `streamSSE`. Свой роутер — это ручной SSE-фрейминг, keep-alive, `Last-Event-ID` и backpressure. И бэкенд всё равно будет на Hono: VoltAgent на нём построен |
| Рантайм | Node 20.19.0 из пробы | **Node 24 LTS** | Node 20 EOL 24.03.2026, Node 22 EOL 28.07.2026 — оба без обновлений безопасности |
| Хранилище | better-sqlite3 12.x против 13.x | **`node:sqlite`, встроенный** | На Node 24 статус Release Candidate (`Stability: 1.2`, проверено по docs). Убирает нативный модуль, требующий `npm rebuild` при смене Node |
| Раскладка | elkjs против dagre | **@dagrejs/dagre@3.1.1** | Решение заказчика: [00-canvas-decision.md](00-canvas-decision.md). elkjs — 7,7 МБ и EPL/GPL, нужен только для вложенных графов, которых в плейграунде нет |

## Состав

Шесть экранов, физически две страницы:

| Экран | Маршрут | Что показывает |
|---|---|---|
| Список воркфлоу | `/` | найденное в каталоге, статус синтеза, строки FAIL не прячутся |
| Граф | `/flow/:id` | канвас, полоса диагностики над ним |
| Форма входа | правая панель | схема входа воркфлоу |
| Прогон | правая панель | статусы узлов по мере исполнения |
| Инспектор узла | правая панель | пять вкладок, см. ниже |
| Отчёт скана | `/` на пустом каталоге | путь, маска, сколько просмотрено и найдено |

**Инспектор узла — главный экран.** Пять вкладок: Вход (слоты с лексической ссылкой),
Промт (блоки по ролям, кэш-префикс, отдельно `output_format`, переключатель шаблон/отрисовка),
Ответ (сырой текст), Выход (распарсенный объект и результаты проверок с путём до поля),
Цена (время, токены). У не-llm узлов вкладок Промт и Ответ нет вовсе — вместо них Исходник.

Провенанс — не экран, а поведение: клик по слоту уводит на узел-источник и подсвечивает поле.

## Данные

Синтез настоящий, из настоящих файлов. Замерено на пробе: `hotel_pitch` синтезируется за 0,9 с
процессом с нуля, IR 5 КБ. Синтез идёт дочерним процессом на файл — битый файл не роняет сервер.

Модели заменяются цепочкой: кассеты (JSON в репозитории) → фиктивный провайдер по схеме выхода.
Настоящие вызовы позже, за флагом. Плейграунд запускается без ключей.

Исполнитель упрощённый: топологический обход, статусы, время, настоящий промт, провенанс.
**Каждое упрощение получает бейдж на узле** — «последовательно · в IR concurrency: 8»,
«ретраи выключены», «компонент не раскрыт». Молчаливое упрощение запрещено, иначе экран врёт.

Хранилище: SQLite, три таблицы — `runs`, `events`, `renders`. IR и граф в базу не пишутся,
пересчитываются из файлов за миллисекунды.

## Порядок работ

12 шагов по полдня. Первый работающий результат — конец второго дня: `wf dev --once` печатает
список воркфлоу из настоящего каталога. Проходит весь путь чтения, не требует ни React, ни HTTP,
ни базы, и сразу даёт негативный сценарий с путём и строкой ошибки.

Критический путь: скелет монорепо → `@wf/dsl` + `@wf/ir` → `@wf/synth` → `wf dev` → сервер и SSE →
Vite → канвас → инспектор → исполнитель и база. Шаги watcher, форма входа и раскрытие компонентов
параллельны и откладываются без вреда.

Детали — [build-order.md](build-order.md).

## Что этот прототип проверяет, а что нет

Честно: из восьми гипотез [30-frontend-plan](../30-frontend-plan.md) закрывается меньше половины.

| Гипотеза | Статус |
|---|---|
| Г3 «почему узел выдал это» быстрее логов | закрывается целиком |
| Г1 читаемость графа | частично: 9 узлов вместо 15, цикла нет |
| Г5 раскрытие компонента | частично |
| Г4 починка ошибки в один клик | наполовину: ошибка есть, кандидата нет |
| Г2 прозрачность агента | не проверяется |
| Г6 совместная правка | не проверяется — прямая цена read-only |
| Г7 деградация и фолбэк | **не проверяется в принципе на моках** |
| Г8 плотность на 40 узлах | не проверяется |

Г7 — самая неприятная: тихие деградации по определению не воспроизводятся на фиктивных моделях.
Её проверка откладывается до настоящего рантайма.

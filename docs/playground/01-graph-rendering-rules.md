# Правила отрисовки графа

> Требования заказчика после живого просмотра, 2026-09-14. Обязательны для всех правок канваса.

## 1. Один шаг — один вызов модели

Дословно: «по сути, на один шаг один LLM-вызов». Если узел делает четыре вызова модели,
на канвасе должно быть **четыре узла**, а не один с подписью.

Сейчас нарушено: `diverge` с `n: 4` рисуется одним прямоугольником, и по нему непонятно,
дивергенция это или обычный вызов.

### Веер известен статически

Если количество веток выводится при синтезе — `n: { const: 4 }`, литеральный
`vary: { persona: [...] }`, литеральный список в `map.over` — ветки **материализуются
в развёрнутом IR** как отдельные узлы. У каждого виден свой отличающий параметр
(персона, температура, модель).

Это не работа отрисовки: развёрнутый IR обязан содержать N узлов, иначе канвас додумывает.

### Веер зависит от данных прогона

Если количество известно только в рантайме (`map` по выходу тула) — статически рисуется
один узел с явной пометкой `×N` и указанием источника количества. Во время прогона
показываются фактические экземпляры с их номерами.

Молчаливое «один прямоугольник» запрещено в обоих случаях.

## 2. Группы не сворачиваются

Решение заказчика: без сворачивания. Тело компонента и вложенные узлы видны всегда.
Не делать кнопок «развернуть», не хранить состояние свёрнутости.

Следствие: раскладка обязана справляться с полным графом. Если он не помещается —
решается зумом и полосой этапов, а не прятанием содержимого.

## 3. Конвергенция видна так же, как дивергенция

Узел, сводящий N результатов в один (`aggregate`, `judge`, свёртка `map`), должен показывать,
что в него входит несколько ветвей. Рёбра от всех ветвей — к нему, а не одно обобщённое.

## 4. Ссылки интерактивны

Слот показывает, что значение пришло по ссылке, от какого узла и какого типа. По наведению —
фактическое значение из открытого прогона. Ссылка остаётся видимой как ссылка: значение
показывается рядом, а не вместо.

## 5. Стрелки и типы связей

Маркер на конце ребра обязателен. Разные стили: поток данных, переход ветки `switch`,
вход в цикл, граница компонента.

## 6. Узлы не наслаиваются

Программный критерий приёмки: после раскладки ни одна пара прямоугольников узлов не пересекается.
Проверяется тестом, а не глазами. Размеры для раскладки берутся **измеренные после рендера**,
а не оценочные.

## 7. Произвольная вложенность и композиция

Дословно: «дивергенция произошла, дальше идёт джадж с доработкой дивергенции, это может быть в луп;
разные штуки можно смешивать, разные архитектуры, разную логику — в этом вся суть».

Значит вложенность произвольной глубины и в любом сочетании:

```
loop (до порога)
  └─ diverge ×4          четыре узла llm с разными персонами
  └─ judge               сводит четыре в один вердикт
  └─ revise              доработка по вердикту
```

Требования:
- **Глубина не ограничена.** Компонент внутри цикла внутри компонента — нормальный случай.
- **Смешение видов.** Группой может быть `call` компонента, `map`, `loop`, `parallel`, ветка `switch`.
- **Границы групп видны.** Рамка с именем и видом: понятно, где кончается цикл и начинается
  дивергенция внутри него.
- **Обратное ребро цикла рисуется как цикл**, а не как прямая связь вперёд.

### Следствие для раскладки

Произвольная вложенность — это compound-граф. dagre его не умеет напрямую: он раскладывает
плоский граф.

Решение — **рекурсивная раскладка**: каждая группа раскладывается своим прогоном dagre, у неё
берётся габаритный прямоугольник, и в родительской раскладке группа участвует как один узел
этого размера. Обход снизу вверх, координаты детей сдвигаются на позицию группы.

Это сохраняет dagre (MIT, 1,3 МБ) и не требует elkjs (7,7 МБ, EPL-2.0 OR GPL-3.0) —
см. [00-canvas-decision.md](00-canvas-decision.md). Триггер пересмотра: если рекурсивная раскладка
даст неприемлемое качество на реальных графах, elkjs с `hierarchyHandling: INCLUDE_CHILDREN`
возвращается вместе с лицензионным вопросом.

### Следствие для DSL

Комбинаторы обязаны вкладываться друг в друга без ограничений: тело `loop` содержит `parallel`,
ветка `parallel` содержит `call` компонента, тело компонента содержит `map`. Если какая-то
комбинация невыразима — это дыра в ядре, а не особенность примера.

## 8. Дивергенция — это разные семейства моделей

Замечание заказчика: «дивергенция подразумевает использование моделей из разных семейств,
поэтому бред, что модель одна».

Разнообразие внутри одного семейства — слабая форма: при варьировании только температуры выходы
коррелированы, потому что модель та же. Настоящее разнообразие даёт смена семейства.

Подтверждение из исследования по судьям (уже зафиксировано в [ADR-0020](../adr/0020-llm-function-and-adapters.md)):
панель из нескольких меньших моделей **разных семейств** обошла одного большого судью и показала
меньше внутримодельного смещения. Для генерации действует та же логика.

### Что требуется

| Ось `vary` | Сила разнообразия | Когда уместна |
|---|---|---|
| `model` (разные семейства) | **основная** | по умолчанию для `diverge` и `judge_panel` |
| `persona`, `prompt_variant` | средняя | когда нужен разный угол зрения при одной модели |
| `temperature`, `seed` | слабая | только как добавка к смене семейства |

- Примеры в `examples/patterns` обязаны использовать `vary: { model: [...] }` как основную ось.
  Сейчас там `temperature` и `persona` — слабая форма, подлежит замене.
- Компилятор: `diverge` без источника разнообразия — ошибка (§7.2 спеки). Дополнительно —
  предупреждение, если все ветки из одного семейства.
- `judge_panel` — правило R-J2 уже требует минимум два семейства и запрещает судье быть
  из семейства генератора. Для `diverge` требование симметричное.

### Следствие: у каждой ветки своя эффективная конфигурация

Разные семейства означают разные профили схем (Cohere не выражает `oneOf`, OpenAI требует все поля
обязательными), разную адаптацию промта по 17 осям и разные точки кэширования.

При этом **автор пишет один промт**: адаптацию выполняет платформа
([ADR-0020](../adr/0020-llm-function-and-adapters.md)). Поэтому `vary: { model: [...] }` остаётся
честной записью — три семейства, один текст, платформа доставляет каждому в его форме.

На канвасе у каждой ветки видно, какая модель и какое семейство — иначе непонятно, чем ветки
отличаются, и дивергенция снова выглядит как непрозрачный прямоугольник.

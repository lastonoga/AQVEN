# Плейграунд: состав

Срез 2. Что входит в локальный dev-плейграунд и что явно не входит.

Опора: реальный `hotel_pitch` из пробы синтеза — 9 верхнеуровневых узлов
(`tool`, `map`, `code`, `call`×3, `llm`, `render`), компонент `pitch_gen`, ссылки вида
`$in.hotels[*]`, `$gen.out`. Граф, инспектор и провенанс строятся из этого IR, не из фикстур.

## 1. Экраны: шесть, не больше

| # | Экран | Зачем | Что на нём | Данные |
|---|---|---|---|---|
| S1 | Список воркфлоу | Единственная точка входа; заменяет оболочку, палитру, индикатор | Таблица: имя, версия IR, вердикт синтеза, путь к файлу, время последнего прогона | Скан каталога проекта + результат синтеза каждого файла |
| S2 | Канвас графа | Главная гипотеза: читается ли граф без объяснений | Узлы по `kind`, рёбра из лексических ссылок, полоса ошибок синтеза сверху, раскрытие `call`/`map` | `ir.json`: `nodes`, `components`, `in`/`out`, `budget` |
| S3 | Инспектор узла (статика) | Что узел делает и на чём держится | `kind`, `description`, вход по полям со ссылкой-источником, выход, модельная роль, `outputContract`, бюджет, кнопка «открыть в файле» | Узел IR + позиция в исходнике |
| S4 | Форма запуска | Дать вход, не собирая JSON руками | Поля из входного типа (`TourRequest`), пресет-примеры, кнопка «Запустить» | JSON Schema входного типа из синтеза |
| S5 | Прогон на канвасе | Видно, где идёт и где встало | Тот же канвас: статусы узлов, потраченный бюджет, время; список прогонов слева | Поток событий от локального исполнителя |
| S6 | Инспектор узла прогона | Главный выигрыш: «почему узел выдал это» | Вход (с провенансом до узла-источника), выход, отрендеренный промт, ответ модели, ошибка/повтор | Событие узла + IR-ссылки |

Три экрана — один маршрут `/(flow)/[id]`: S2/S3 — канвас с панелью, S5/S6 — тот же канвас в режиме
прогона. Физически страниц две: список и воркфлоу. Роутинг закрывает четыре из шести таблицы.

Панель ошибок синтеза — не экран, а полоса над канвасом: текст ошибки, путь и строка. Битый файл
показывается в S1 строкой со статусом FAIL, а не пустым экраном.

## 2. Не входит

| Что | Почему не сейчас | Когда вернётся |
|---|---|---|
| Правка на канвасе, drag, инспектор как форма | решение заказчика: канвас только показывает | вместе с кодмодом ADR-0018, после Studio |
| Кодмод «IR → правка исходника» | требует печатника TS и сверки хешей | там же |
| Оболочка, палитра команд, глобальный поиск | две страницы не нуждаются в навигации | при третьем кластере экранов |
| Редактор шаблона промта | правка идёт в файле, плейграунд показывает результат | со Studio и правкой |
| Лента ревизий, дифф патча, blame | нет второго актора: правит только человек в редакторе | с встроенным агентом |
| Лента действий агента, бриф, чат, кандидаты исправления | агента в плейграунде нет | фаза агента |
| Реестры типов, промтов, моделей, тулов; анализ влияния | нужен индекс в базе, а не скан каталога | с бэкендом и `type_usages` |
| Версии, семантический дифф, экспорт | версионирование делает git, не UI | со Studio |
| Датасеты, evals, эксперименты, матрица моделей, гейт | другая задача: качество, не отладка | после плейграунда |
| Водопад, дифф прогонов, таймлайн цикла | сравнение прогонов требует хранилища прогонов | когда прогонов станет больше десятка |
| Человеческие задачи, приостановленные прогоны | `human` в демо-воркфлоу мокается автоответом | с настоящим исполнителем |
| Стриминг токенов в инспекторе | ответ мока приходит целиком | когда подключим настоящие модели |

Граница простая: плейграунд читает файлы и показывает. Всё, что пишет файлы, меняет состояние
проекта или требует второго актора, — за границей.

## 3. Первый экран: два состояния

**Каталог без воркфлоу.** Не «добро пожаловать» и не туториал. Показываем, что именно сканировали
и почему пусто: путь каталога, маску поиска (`**/*.flow.ts`), число просмотренных файлов, ноль
найденных. Одна кнопка — «Создать демо-проект»: кладёт `hotel_pitch` из пробы в каталог и
перечитывает. Второй строкой — команда, которой это делается руками. Ошибка «каталог не
существует» и «нет прав» показываются тем же экраном с другим текстом, без модалок.

**Каталог с воркфлоу.** Сразу таблица, без промежуточного дашборда — как дерево кубов в Cube.
Строка: имя флоу, `version`, путь к файлу, вердикт синтеза (`OK` / `FAIL: <первая ошибка>`),
число узлов, время последнего прогона. Строки с `FAIL` не прячутся и не уезжают вниз: битый файл —
это то, ради чего человек открыл плейграунд. Клик по строке `OK` ведёт на канвас, клик по `FAIL` —
на тот же канвас с развёрнутой полосой ошибки и подсвеченным местом в исходнике.

Общее для обоих состояний: сверху путь проекта и кнопка «Перечитать». Нет пустого экрана, у
которого нельзя спросить, что он видел.

## 4. Сквозной сценарий

| # | Шаг | Что делает система | Что видит человек |
|---|---|---|---|
| 1 | `npx wf playground` в каталоге проекта | сканирует `**/*.flow.ts`, синтезирует каждый, поднимает порт | ссылку `localhost:5173` в терминале |
| 2 | Открыл | отдаёт список из шага 1 | таблицу: `hotel_pitch`, `v7`, `OK`, 9 узлов |
| 3 | Клик по строке | грузит `ir.json` этого флоу | канвас: 9 узлов по `kind`, рёбра из лексических ссылок, `map` и `call` со значком раскрытия |
| 4 | Клик по узлу `gen` | открывает S3 справа | `kind: llm`, описание, слоты входа с их ссылками, тип выхода, `modelRole: writer`, `outputContract.mode: strict` |
| 5 | «Запустить» | строит форму из JSON Schema входного типа | поля `TourRequest`, пресет «3 отеля, Крит» одним кликом |
| 6 | «Поехали» | локальный исполнитель идёт по IR, модели отвечают моком | узлы меняют цвет по ходу: ждёт → идёт → готов; счётчик потраченного бюджета |
| 7 | Элемент `map` упал | у `score_hotels` стоит `onItemError: skip` — граф доехал, но 1 из 3 пропущен | `map` жёлтый, счётчик `2/3`, полосу «пропущен элемент» с кнопкой «открыть узел» |
| 8 | Клик по пропущенному элементу | открывает S6 (см. §5) | в слоте `hotel` поле `price` пустое; провенанс ведёт к `load_hotels`; сырой ответ не прошёл `strict` |
| 9 | Правка в редакторе: ссылка в `flow.ts` меняется на существующее поле | watcher ловит запись, пересинтезирует, шлёт новый IR | канвас перерисовался за секунду, полоса ошибок пуста, прогон помечен «устарел» |
| 10 | «Перезапустить» | прогон с той же формой входа | `map` зелёный целиком, `render` отдал текст питча |

Шаги 8→9→10 — это и есть петля, ради которой всё делается: причина, правка в файле, подтверждение.
Плейграунд не пишет файлы ни на одном шаге; запись делает редактор человека.

## 5. Инспектор узла прогона (S6) — состав

Панель справа, вкладки. Открывается по клику на узел канваса, адресуется URL
`/flow/hotel_pitch/run/:runId/node/:nodeId` — F5 не теряет место.

Шапка, всегда видна: `id` узла, `kind`, статус, попытка `2/2` при повторе, `modelRole` и
фактическая модель, к которой роль разрешилась. Для узла внутри `map` — индекс элемента.

| Вкладка | Что показывает | Откуда |
|---|---|---|
| **Вход** | таблица слотов: имя, лексическая ссылка (`hotel ← $score_hotels.item`), тип по IR, значение | `node.in` из IR + payload события |
| **Промт** | отрисованный текст, разбитый по сообщениям с ролями | рендер шаблона на тех же значениях |
| **Ответ** | сырой текст от модели байт в байт, до парсинга | событие исполнителя |
| **Выход** | распарсенный объект и результат проверок | парсер + `outputContract` |
| **Цена** | время и токены | таймеры исполнителя + учёт мока |

**Вход.** Каждый слот кликабелен: клик уводит на узел-источник ссылки и подсвечивает там поле
выхода. Это и есть провенанс — не отдельный экран, а поведение таблицы. Значение `null` в слоте
помечается явно и отличается от «слот не заполнен».

**Промт.** Блоки по `{% message %}` с ролью каждого. Кэшируемый префикс — статический начальный
отрезок сообщений — отчёркнут; блок `output_format`, сгенерированный из типа выхода, показан
отдельной секцией, потому что в шаблоне его текста нет. Переключатель «шаблон / отрисовка»:
слева исходный liquid, справа результат. Рядом — счётчик символов и оценка токенов.

**Выход.** Что именно проверяли и чем кончилось: соответствие схеме выхода, режим
`outputContract.mode: strict`, израсходованные `maxRepairs` (`1/1`), сработал ли `onTruncated`
или `onRefusal`. Провал показывается путём до поля: `.hotels[1].score: expected number, got null`.

**Цена.** Время до первого токена и полное; токены входа и выхода; из них — доля кэш-префикса.
Стоимость считается по тарифу роли, а не приходит от провайдера: UNVERIFIED до подключения
настоящих моделей, и на экране помечена как расчётная. Рядом — остаток бюджета узла и флоу.

Для не-`llm` узлов (`tool`, `code`, `call`, `render`) вкладки «Промт» и «Ответ» не показываются —
не серыми, а отсутствующими. Их место занимает «Исходник»: фрагмент `flow.ts` для этого узла.

## 6. Гипотезы: что закрываем и что нет

| # | Гипотеза | Вердикт | Почему |
|---|---|---|---|
| Г1 | Граф читается без объяснений | частично | 9 узлов с `map`, `call` и дивергенцией — но не 15, и цикла в `hotel_pitch` нет |
| Г2 | Понятно, что сделал агент | нет | агента в плейграунде нет вообще |
| Г3 | «Почему узел выдал это» быстрее логов | **да, целиком** | §5 — ровно этот замер; ради него плейграунд и строится |
| Г4 | Ошибка компилятора чинится в один клик | наполовину | ошибка с путём и строкой есть, кандидата исправления нет |
| Г5 | Раскрытие компонента не ломает ориентацию | да | `pitch_gen` и `map` раскрываются на канвасе |
| Г6 | Правки человека и агента не мешают | нет | канвас только показывает, второго актора нет |
| Г7 | Деградация и фолбэк заметны | нет | модели мокаются, настоящего фолбэка не происходит |
| Г8 | Плотный интерфейс не перегружает | нет | 9 узлов вместо 40; на таком объёме вопрос не ставится |

Из восьми гипотез плейграунд закрывает полторы с половиной: Г3 полностью, Г1 и Г5 частично,
Г4 наполовину. Это честная цена решения «канвас только показывает»: убрав правку, мы убрали
четыре гипотезы из восьми. Взамен получили инструмент за шесть дней вместо трёх фаз.

Отдельно: Г3 — самая дорогая из списка и единственная, ради которой продукт вообще существует.
Проверять её на моках можно: замеряется время до нахождения причины, а не качество ответа модели.
Подсаженный провал в `score` (§4, шаг 7) даёт ровно тот же поиск, что и настоящий.

# Данные плейграунда: настоящий синтез, моки только на моделях

Срез 3. Откуда берутся данные на экранах. Не мокаем ничего, кроме модели и внешнего тула:
граф, IR, диагностика и отрисованный промт — настоящие.

## 1. Путь файл → граф

| Шаг | Кто запускает | Выход | Время | При ошибке |
|---|---|---|---|---|
| Скан каталога | сервер при старте + `chokidar` на `workflows/**/*.flow.ts` | список абсолютных путей | ~10 мс, UNVERIFIED | пустой каталог → S1 с текстом «нет файлов», не падение |
| Синтез | сервер, дочерний процесс `tsx harness.ts <file>` | IR-JSON в stdout (5 КБ для `hotel_pitch`) | **0,9 с** на файл, процесс с нуля (замерено: 930/900/950 мс) | `exit != 0` → stderr в поле `error` строки S1, статус FAIL |
| Диагностика | сервер, чистая функция над IR | список `{code, nodeId, path, message}` | < 5 мс | диагностика — не ошибка: граф строится, полоса над канвасом краснеет |
| Граф | браузер, из IR | узлы по `kind`, рёбра из строковых ссылок | < 50 мс, UNVERIFIED | нерезолвимая ссылка → висячее ребро с меткой, не исключение |

Синтез — **отдельный процесс на файл**, не `jiti` в том же: битый flow-файл уронит сервер, а кеш
модулей придётся чистить руками. `src/synth.ts` из пробы жёстко импортирует `./flow.js` и печатает в
stdout — делим на чистую функцию и обёртку, один раз, без переписывания логики:

```ts
const url = pathToFileURL(process.argv[2]).href;
process.stdout.write(JSON.stringify(synthesize((await import(url)).default)));
```

`synthesize(flow): Ir` — нынешнее тело `synth.ts` без верхнеуровневого `import flow` и `console.log`.

Кеш по `sha256(содержимое)`; правка → chokidar → синтез → SSE-пуш в браузер, без правки — 0 мс.

**Три класса ошибок, три места на экране.** Ошибка компиляции TS (`tsx` не разобрал файл) и ошибка
синтеза (`throw` в `idOf`: `unregistered node` — воспроизведено на `src/orphan.ts`, где `isRef` = true,
а `ids.has(target)` = false) дают в S1 строку FAIL со stderr и прячут граф. Диагностика IR
(недостижимый узел, ссылка вперёд, `call` на неизвестный компонент) — только полоса над канвасом,
граф при этом рисуется. Правило: чем позже класс, тем мягче реакция.

## 2. Чем заменяем модели

Ключей нет, интернета может не быть, `npx` — и работает. Три источника ответа, один интерфейс:

```ts
interface ModelSource { tryAnswer(call: LlmCall): Promise<LlmAnswer | null>; }
const chain: ModelSource[] = [cassettes, schemaFake];
```

| Источник | Что делает | Когда | Стоимость сборки |
|---|---|---|---|
| **Кассеты** | JSON-файлы `cassettes/<flow>/<preset>/<nodeId>.json` рядом с демо-проектом, в гите | **со старта**, основной | ~80 строк: чтение, ключ, запись |
| **Фиктивный провайдер** | генерирует значение по `out:`-типу через zod 4 | **со старта**, подстраховка | ~90 строк генератора по `z.toJSONSchema()` |
| **Настоящие вызовы** | реальный провайдер | потом, по `PLAYGROUND_LIVE=1` + ключ | отдельный срез, не сейчас |

Порядок: кассета → фейк; промах кассеты не ошибка, узел помечается «сгенерировано по схеме».
Ключ кассеты — `sha256(nodeId + canonicalJson(in))`: тот же вход даёт тот же ответ, отладчик честен
при перезапуске. Фейк детерминирован тем же ключом как seed — иначе «прогони ещё раз» врёт.

zod 4.6.5 умеет `z.toJSONSchema()` из коробки — `zod-to-json-schema` не нужен, `json-schema-faker`
тоже: нам нужны правдоподобные значения, а не случайные. Генератор берёт `.meta({ example })` из
реестра типов, если он есть, иначе даёт `"<Pitch.title>"`, `0`, первый вариант enum.

**Чего в пробе нет:** `types.ts` объявляет типы заглушками `ty<T>(name)` — ни схем, ни примеров.
Демо-проект обязан привезти настоящие zod-схемы `Hotel`, `Pitch`, `HotelScore`, `PitchVerdict`: без
них фейк нечем питать, а блок формата вывода (§4) нечем собирать. Сами кассеты пишутся из реального
прогона (`PLAYGROUND_LIVE=1 --record`) один раз и коммитятся — сочинённый руками JSON врёт формой.

## 3. Упрощённый исполнитель

Полного рантайма на этом этапе нет. Минимум, чтобы экран отладчика не врал: обход графа —
топологический по ссылкам IR, строго последовательно; статус узла `pending` → `running` →
`ok` / `failed` / `skipped` потоком SSE, время — `performance.now()` вокруг узла и отдельно вокруг
модели. Промт настоящий (§4), провенанс входа — строка ссылки IR (`$top3.out`) в узел-источник.
Бюджет считается оценкой `chars/4` и показывается, но **не применяется**.

**Чего НЕ делает — и как это видно на экране.** Молчаливое упрощение хуже отсутствия функции,
поэтому каждое отклонение получает бейдж на узле, а не прячется:

| Не делает | Бейдж на узле | Почему так |
|---|---|---|
| Параллелизм `map` | `последовательно · в IR concurrency: 8` | порядок событий важнее скорости в дебаг-панели |
| Ретраи и бэкофф `defaults.retry` | `ретраи выключены` | без сети ретраить нечего, имитация — ложь |
| Тело `loop`/`call` без определения | `компонент не раскрыт` + выход по схеме | `diverge`, `judge`, `critic_loop` в проекте только именами; `pitch_gen` раскрывается — он в `components` |
| `human` | `ожидание человека` + форма из `form:` | в автопрогоне подставляется из кассеты, факт подстановки виден |
| Изоляция веток, `policies.visibility` | `политики не применены` | это свойство рантайма, не обходчика |

Исполнитель — тот же дочерний процесс, что и синтез, с другим аргументом; сервер проксирует события
в SSE, прогоны пишутся в SQLite (`runs`, `node_events` — двух таблиц хватает).

## 4. Отрисованный промт по-настоящему

Фиктивная модель не мешает промту быть настоящим: текст собирается из шаблона и данных прогона, а не
из ответа. Минимум из `docs/08-prompts.md`, остальное оттуда — не сейчас.

| Берём | Строк | Зачем без этого нельзя |
|---|---|---|
| `liquidjs@10.29.0` с `strictVariables`/`strictFilters` и снятыми тегами `assign`, `capture`, `increment`, `decrement`, `cycle`, `echo`, `liquid`, `raw`, `render`, `tablerow`, `layout`, `block` | 8 | иначе `{{ nope }}` тихо отрендерится пустотой; шаблон обязан быть чистой функцией слотов, иначе провенанс не сходится |
| Тег `{% message %}` | ~25 | без ролей нет того, что реально уходит в модель |
| Блок `{{ output_format }}` из `out:`-типа | ~70 | половина промта; один эмиттер вместо таблицы профилей §6.1 |
| `fs`-loader для `{% include 'role_scorer@3' %}` плюс контекст рендера строго из `in:` узла IR | ~35 | фрагменты есть в записях §3; контекст из слотов — и есть проверка «данные мимо слотов не проходят» |

Связка узел ↔ запись промта уже сходится: узел `score` несёт `fn: scoreHotel` с `name: "score_hotel"`,
а запись в §3 — `prompt: score_hotel`; ищем `prompts/score_hotel@*.yaml`, берём старшую версию.

**Не берём:** view реестра типов (в контекст идёт объект целиком), R-T3..R-T13, профили провайдеров,
кэш-префикс — метки `cache` парсим и показываем, но ни на что не влияют. R-T1 и R-T2 берём: они
бесплатны, `globalFullVariablesSync(ast)` даёт их разностью множеств.

## 5. Демо-проект

Три файла в `examples/`, чтобы на первом открытии было что смотреть:

| Воркфлоу | Узлов | Роль |
|---|---|---|
| `hotel_pitch` | 9 + компонент | главный: все `kind`, вложенный `map`, три `call`, `human`, `switch` |
| `quick_quote` | 3 (`tool` → `llm` → `code`) | быстрый прогон за пару секунд, чтобы форма запуска не пугала |
| `orphan` | 2 | заведомо битый: ссылка на узел вне `nodes`, S1 показывает FAIL со stderr |

Пресеты кассет к `hotel_pitch` — переключатель в форме запуска, каждый ведёт по своей ветке.
Важнее прочих два последних: именно они проверяют, что канвас не врёт при неудаче.

| Пресет | Что показывает |
|---|---|
| `accept` | счастливый путь, `switch` в `pick.out.best`, `human` не трогается |
| `revise` | ветка `fix`: `critic_loop` как нераскрытый компонент, бейдж на узле |
| `escalate` | `human` встаёт в `ожидание человека`, прогон висит до ответа в форме |
| `degraded` | `map` с `onItemError: "skip"`: два отеля из десяти падают, узел `ok`, но с пометкой «2 пропущено» |
| `tool_fail` | `load_hotels` бросает: узел `failed`, всё ниже по графу — `skipped`, не пустой экран |

## 6. Граница с настоящим рантаймом

| Судьба | Что |
|---|---|
| **Останется** | `synthesize()`, формат IR, диагностика, компилятор и рендер промта, канвас, реестр типов, схема SQLite `runs`/`node_events`, кассеты (станут фикстурами тестов) |
| **Перепишется** | поток событий → спаны VoltAgent/OTel; модель статусов узла; семантика `map`/`loop`/`human` |
| **Выбросим** | сам обходчик, оценка бюджета по символам, фиктивный провайдер (уедет в тестовую обвязку), бейджи упрощений |

Чтобы выброс был дешёвым, UI не знает про обходчик — он читает один интерфейс:

```ts
interface RunSource { start(input: unknown): Promise<RunId>; events(id: RunId): AsyncIterable<NodeEvent>; }
```

Замена рантайма = вторая реализация `RunSource`; всё выше интерфейса её переживает. Обратное правило:
**не класть в `NodeEvent` полей, которых VoltAgent дать не сможет** — иначе экран, построенный на
них, придётся разбирать вместе с обходчиком.

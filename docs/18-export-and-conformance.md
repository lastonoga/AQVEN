## Зачем этот слой

Платформа продаётся как конструктор production-воркфлоу без lock-in (R21, боль §8 №87). Значит уход
с платформы обязан быть дешёвой механической операцией, а не переписыванием. Этот слой делает
«воссоздано 1:1» проверяемым утверждением: бандл несёт нормативную семантику ядра, эталонный
интерпретатор и корпус записанных прогонов, а совпадение доказывается прогоном корпуса, а не
чтением глазами. Три kill-критерия закрываются здесь целиком: 13 (round-trip байт-в-байт),
14 (LLM воссоздаёт воркфлоу в чужом фреймворке и проходит конформанс на 100%),
15 (сгенерированный VoltAgent-проект собирается и проходит конформанс без правок).

## Решения

| Решение | Что берём | Версия | Лицензия | Почему |
|---|---|---|---|---|
| Канонический JSON | `canonicalize` (RFC 8785 JCS) | 5.0.0 | Apache-2.0 | автор — соавтор RFC; JCS — единственная спецификация, которую чужая реализация воспроизведёт по тексту |
| Хеш | `@noble/hashes` sha256 | 2.4.0 | MIT | аудированная, без нативных зависимостей, одинакова в Node и браузере |
| YAML-транспорт | `yaml` | 2.9.0 | ISC | единственный живой парсер с настраиваемым `ToStringOptions`; round-trip проверен пробой |
| Упаковка бандла | `tar-stream` | 3.2.1 | MIT | пишет ровно заданные поля заголовка, детерминизм достижим без борьбы с форматом |
| Печать кода | `prettier` | 3.9.6 | MIT | идемпотентность печати проверена (`format(format(x)) === format(x)`) |
| Отладочная HTTP-запись | `msw` / `@mswjs/interceptors` | 2.15.0 / 0.42.5 | MIT | второй слой вне контракта: «что реально ушло провайдеру» |

**Не берём:** `fast-json-patch` (2022, мёртв), `deep-object-diff` (2022, мёртв), `@pollyjs/core`
(2023, мёртв, HTTP-уровень), `safe-stable-stringify` и `fast-json-stable-stringify` для хешей
(молча коэрсят BigInt/NaN/циклы, `NaN → null`), `nock` (HTTP-уровень, SSE-стримы — боль),
`ts-morph` и `@babel/generator` для codegen (вес без выигрыша на генерации с нуля).

## 1. Канонизация и хеширование

Один модуль `@aqven/canon` — единственное место в монорепо, где вызывается `canonicalize` и `sha256`.
Всё остальное ходит через `hashOf(domain, value)`. Доменная сепарация обязательна: без неё хеш
спеки и хеш тела узла с одинаковым содержимым совпадут, и кеш одного домена отравит другой.

```ts
import canonicalize from "canonicalize";
import { sha256 } from "@noble/hashes/sha2";
import { bytesToHex, concatBytes, utf8ToBytes } from "@noble/hashes/utils";

export type HashDomain =
  | "spec/v1"
  | "node-body/v1"
  | "prompt/v1"
  | "cassette-req/v1"
  | "schema/v1"
  | "value/v1"
  | "idem/v1"
  | "pii/v1";

export type Sha256 = `sha256-${string}`;

const DOMAIN_SEPARATOR = new Uint8Array([0x00]);

export const canonicalBytes = (value: unknown): Uint8Array => {
  assertCanonicalizable(value);
  const text = canonicalize(value);
  if (text === undefined) throw new CanonError("E_CANON_UNSUPPORTED");
  return utf8ToBytes(text);
};

export const hashOf = (domain: HashDomain, value: unknown): Sha256 =>
  `sha256-${bytesToHex(sha256(concatBytes(utf8ToBytes(domain), DOMAIN_SEPARATOR, canonicalBytes(value))))}`;

export const hashBytes = (domain: HashDomain, bytes: Uint8Array): Sha256 =>
  `sha256-${bytesToHex(sha256(concatBytes(utf8ToBytes(domain), DOMAIN_SEPARATOR, bytes)))}`;
```

### Что именно хешируем

| Домен | Вход | Где используется |
|---|---|---|
| `spec/v1` | канонический JSON версии спеки воркфлоу (IR, развёрнутый до примитивов) | `manifest.specVersions[].specHash`, заголовок сгенерированного кода, `case.specRef.specHash` |
| `node-body/v1` | тело узла без поля `id` | детект переименования узла в семантическом диффе (rename vs delete+add) |
| `prompt/v1` | нормализованный текст отрисованного промта (см. §6, правило 2) | `expect.renderedPrompts[*].valueHash` |
| `cassette-req/v1` | `NormalizedModelRequest` / `NormalizedToolRequest` | ключ кассеты и имя её файла |
| `schema/v1` | JSON Schema тула или схемы структурированного выхода | `tools[].schemaHash`, `outputSchemaHash` внутри ключа кассеты |
| `value/v1` | канонический JSON выхода узла или финального выхода | `expect.nodeOutputs[*].valueHash`, `expect.finalOutput.valueHash` |
| `idem/v1` | `{executionId, nodeId, iteration, itemKey}` | ключ идемпотентности узла с побочным эффектом (§4) |
| `pii/v1` | `{caseId, kind, value}` | стабильный псевдоним при обезличивании кейса (§8) |

`idem/v1` намеренно **не включает номер попытки** — иначе ретрай сгенерирует новый ключ и продублирует
эффект, ради защиты от которого ключ и заведён.

### Ловушки и как они закрыты

| Ловушка | Что происходит без правила | Правило |
|---|---|---|
| Большие числа | `canonicalize` печатает числа по ECMAScript; `BigInt` не сериализуется, `2^53` теряет точность | в IR запрещены `BigInt`, `NaN`, `Infinity`, `-0`; целые вне безопасного диапазона хранятся строкой с типом `int64` из реестра типов; `assertCanonicalizable` бросает `E_CANON_BIGINT` / `E_CANON_NONFINITE` |
| `undefined` | JCS выбрасывает `undefined`-поля объектов и превращает их в `null` в массивах — два разных значения дают один хеш | `assertCanonicalizable` обходит значение и бросает `E_CANON_UNDEFINED`; опциональность в IR выражается **только явным `null`** (совпадает с профилем схем: все поля required, `additionalProperties: false`) |
| Unicode | JCS сортирует ключи по UTF-16 code units и экранирует по правилам JSON, но **не нормализует** текст: «é» в NFC и NFD дадут разные хеши | `NFC` применяется на границе ввода к текстам, которые участвуют в сравнении (промты, тексты кассет), и **не применяется** к данным, уходящим в модель; ключи IR ограничены `[a-z0-9_]` и это проверяется JSON Schema на импорте |
| Ключи вне ASCII | порядок JCS (UTF-16 code units) и порядок `sortMapEntries` у `yaml` (`Array.prototype.sort`) совпадают только на ASCII | то же правило `[a-z0-9_]`: вопрос закрыт навсегда, а не «обычно совпадает» |
| Циклы и классы | `safe-stable-stringify` молча чинит цикл, `fast-json-stable-stringify` молча делает `NaN → null` | обе библиотеки запрещены на пути хеширования; `canonicalize` на цикле бросает, и это желаемое поведение |
| Порядок ключей в БД | Postgres `jsonb` не хранит порядок ключей и схлопывает дубликаты | истина — байты файла в рабочем дереве, `jsonb` только индекс; порядок в нём восстанавливается канонизацией, а авторский текст из него не восстанавливают — он и не терялся |

Порядок полей внутри узла IR при этом сохраняется как в IR и не сортируется — сортирует только
канонизатор, и только для хеша; человекочитаемый экспорт печатает поля в порядке IR.

Бандл и рабочее дерево проекта ([04. Формат IR](04-ir-schema.md) §1.5) теперь почти совпадают:
определения в бандл **не генерируются, а копируются**.

| Часть бандла | Откуда берётся |
|---|---|
| `types/`, `components/`, `flows/` (модульный вид), `prompts/`, `agents/`, `tools/`, `context/`, `datasets/` | побайтовая копия рабочего дерева; экспортёр их не сериализует заново |
| `manifest.json`, развёрнутый вид и план в `flows/`, `semantics/`, `reference/`, `schema/`, `conformance/`, `evals/`, `providers/`, `targets/` | генерируются: производное, в рабочем дереве его нет |

Что упрощается: у определений исчезает второй сериализатор, а с ним и класс расхождений «в дереве
одни байты, в бандле другие»; дифф двух бандлов на определениях равен `git diff` двух ревизий.

Разница остаётся ровно одна, и она в именах. Бандл — снимок **опубликованных** версий, поэтому
несёт `@<version>`; рабочее дерево держит черновик и версий в именах не знает (§4.5 [04](04-ir-schema.md)).
Суффикс ставится на имя каталога воркфлоу и файла промта, внутренняя раскладка каталога при копировании
не меняется: `flows/hotel_pitch/flow.yaml` → `flows/hotel_pitch@7/flow.yaml`.

Правила, без которых round-trip не держится:

1. **Имена детерминированы и содержательны.** Для копируемых каталогов это требование
   к рабочему дереву ([04](04-ir-schema.md) §1.5, [20. Репозиторий и тулинг](20-repo-and-tooling.md)),
   экспортёр добавляет только `@<version>`: `flows/<flowId>@<specVersion>/flow.yaml`,
   `prompts/<promptId>@<version>.md`. Никаких временных меток, uuid и порядковых номеров экспорта.
2. **Ровно один файл на сущность.** Индексы и перечни — вычисляемый артефакт, живут в `manifest.json`;
   дублирование содержимого в «индексном» файле запрещено.
3. **YAML — только человекочитаемые спеки** (`flows/`, `components/`, `agents/`), промты — Markdown.
   `manifest.json`, `schema/`, `conformance/` — строго JSON: хеши считаются по JSON, не по YAML.
4. **`reference/` самодостаточен:** в `dependencies` только `zod` и `canonicalize`, никаких ссылок на
   наш монорепо, чтобы `npm i && npm test` в распакованном бандле работал у любого.
5. **Кассета адресуется хешем запроса**, поэтому одна запись переиспользуется несколькими кейсами.

### manifest.json

```jsonc
{
  "formatVersion": "1.0.0",
  "generator": { "name": "aiwf", "version": "0.4.2" },
  "project": { "id": "01J...", "slug": "hotel-pitch" },
  "specVersions": [{ "flowId": "hotel_pitch", "version": 7, "specHash": "sha256-..." }],
  "hashAlgorithm": "sha256",
  "files": [
    { "path": "README.md", "size": 4211, "hash": "sha256-..." },
    { "path": "flows/hotel_pitch@7/flow.yaml", "size": 8130, "hash": "sha256-..." }
  ],
  "merkleRoot": "sha256-...",
  "capabilities": { "hasCassettes": true, "hasDatasets": true, "piiMasked": true },
  "signatures": []
}
```

| Поле | Правило |
|---|---|
| `formatVersion` | semver формата бандла; мажор = несовместимость импорта, импорт отказывает с внятным текстом |
| `generator` | информационно, **не входит** в `merkleRoot` — иначе смена версии CLI ломает kill 13 |
| `files[]` | отсортирован по `path` (UTF-16 code units), пути POSIX, без `./`, `manifest.json` в список не входит |
| `merkleRoot` | считается по `files[]`, алгоритм ниже, описан в `semantics/07-hashing.md` |
| `signatures` | зарезервировано под sigstore, **не входит** в `merkleRoot`; подпись добавляется без смены `formatVersion` |

### Merkle-корень

```
leaf_i = sha256(0x00 || utf8(path_i) || 0x00 || fileBytes_i)
листья отсортированы по path (UTF-16 code units)
node   = sha256(0x01 || left || right)
нечётный остаток поднимается на уровень выше КАК ЕСТЬ (не дублируется — защита от CVE-2012-2459)
merkleRoot для пустого набора = sha256(0x02)
```

Путь входит в лист, поэтому перестановка файлов ломает корень. Дерево, а не хеш конкатенации, — чтобы
при расхождении round-trip спуск по дереву сразу показывал **какой файл** разошёлся, и чтобы можно было
проверить один файл, не выкачивая бандл целиком (актуально для `targets/` в десятки МБ).

### Детерминированная упаковка

`tar-stream@3.2.1`, фиксированные поля заголовка каждой записи:

| Поле | Значение | Зачем |
|---|---|---|
| `mtime` | `new Date(0)` | время сборки не должно попадать в байты |
| `uid`/`gid`/`uname`/`gname` | `0` / `0` / `""` / `""` | байты не зависят от машины сборки |
| `mode` | `0o644` | одинаково на всех ОС |
| `type` | `"file"` | записи директорий не пишем вовсе |
| порядок записей | сортировка по `path` | единственный детерминированный порядок |
| pax-заголовки | запрещены | требует путей ≤ 100 байт и размеров < 8 ГБ; более длинный путь — баг именования, не повод включать pax |

Сжатие — вне хеша: **kill-критерий 13 проверяется на `.tar`**, `.tar.gz` отдаётся для удобства
(gzip недетерминирован между версиями zlib; при необходимости `zlib.gzipSync(buf, { level: 9, mtime: 0 })`).
В git бандл кладётся распакованным — tar только для передачи.

### Проверка на импорте (порядок строгий, любой шаг = отказ)

1. Мажор `formatVersion` совместим.
2. Пересчёт хеша каждого файла из `manifest.files` и `merkleRoot`; **лишний файл, не перечисленный в
   манифесте, — ошибка** (защита от «подложили кассету»).
3. JSON Schema-валидация каждого файла по `schema/` (схемы лежат в бандле и тоже в манифесте —
   самоописываемость); на границах — ajv, не zod.
4. Zod-парсинг IR и проверка ссылочной целостности: каждая привязка указывает на существующий
   узел и порт, каждый `componentRef@version` присутствует в `components/`.
5. Пересчёт `specHash` каждой спеки из содержимого и сверка с `manifest.specVersions` — ловит правку
   файла с обновлением манифеста, но без пересборки.
6. Прогон `conformance/` на `reference/`: бандл, не проходящий собственный конформанс, битый
   до всякого импорта.
7. Только после этого — запись в рабочее дерево одной транзакцией (staging `.aqven/txn/<ulid>` плюс атомарные `rename(2)`) и индексация; `merkleRoot` сохраняется вместе с проектом,
   чтобы «этот прод собран из вот этого бандла» доказывалось без криптоинфраструктуры.

## 3. Нормативная семантика ядра

Урок из четырёх образцов (WebAssembly spec, JSON Schema Test Suite, CommonMark, sqllogictest):
**корпус тестов и есть спецификация**. Текст нужен людям, эталонный интерпретатор — чтобы корпус
дёшево расширялся, но арбитр — корпус. Поэтому `conformance/` важнее `semantics/`, а kill 14
формулируется через корпус, а не через «LLM понял текст».

### Состав `semantics/`

| Файл | Что нормирует |
|---|---|
| `00-model.md` | модель исполнения: спека, узел, порты, привязки, прогон, итерация, попытка |
| `01-bindings.md` | порядок вычисления привязок и видимость выходов |
| `02-join.md` | `parallel`, `quorum(k)`, `any`, `first_success`, политики ошибок веток, `on_item_error` |
| `03-loops.md` | момент проверки условия, счёт итераций, лимиты и предохранители |
| `04-errors-retries.md` | коды ошибок, сложение уровней ретраев, идемпотентность, resume |
| `05-provenance.md` | что считается источником каждого куска контекста и как это переносится |
| `06-comparison.md` | правила сравнения прогонов (§7 этого документа — его краткая версия) |
| `07-hashing.md` | канонизация, доменная сепарация, Merkle — чтобы чужая реализация воспроизвела хеши |

Каждый нормативный абзац несёт рядом пример в блоке ` ```example `, как в CommonMark.
`scripts/extract-spec-tests.ts` извлекает примеры в `conformance/cases/semantics/<file>-<n>.json`,
и CI гоняет их на `reference/`. Текст физически не может разойтись с тестами: расхождение падает
в CI как обычный тест.

### Что именно описываем

**Порядок вычисления привязок.** Узлы исполняются в топологическом порядке спеки; при равенстве —
в порядке объявления в IR. Внутри узла привязки вычисляются в порядке объявления полей IR (порядок
полей IR сохраняется и не сортируется). Привязка читает выход узла-источника целиком, по `jsonpath`
из спецификации привязки; чтение выхода узла, который в этом прогоне не исполнялся, — ошибка
`E_BINDING_UNRESOLVED`, а не `null`. Выходы узлов доступны через `getStepData(stepId) → {input, output}` —
ядро хранит и вход, и выход каждого шага, дублировать их в состоянии не нужно.

**`quorum(k)` при сбоях.** `andAll` у VoltAgent сливает результаты веток в один объект и падает целиком,
если упала любая ветка, — поэтому нормативная семантика задаётся нашей обёрткой, а не поведением
библиотеки:

1. каждая ветка оборачивается в `Result` (`{ok: true, value} | {ok: false, error}`) и пишется под
   **явным ключом ветки** — иначе слияние в один объект затрёт поля;
2. узел ждёт завершения **всех** веток, даже когда `k` уже набрано. Досрочная отмена запрещена
   нормативно: иначе реализация на `Promise.any` даст другой набор побочных эффектов и другой
   бюджет токенов;
3. `ok`-веток `≥ k` → узел успешен, его выход — объект из `ok`-веток в порядке объявления веток;
   упавшие ветки присутствуют как `null` и перечислены в `failures[]`;
4. `ok`-веток `< k` → узел падает с `E_QUORUM_NOT_MET`, в ошибке — коды ошибок всех упавших веток;
5. `any` / `first_success` — отдельный примитив (`race`), а не `quorum(1)`: он **отменяет**
   остальные ветки. Тип результата у `andRace` — union, а не кортеж;
6. `on_item_error` для `map`: элемент оборачивается в `Result`, политика применяется к списку —
   `fail_fast` (первая ошибка валит узел), `skip` (ошибочные элементы выпадают, порядок остальных
   сохраняется), `collect` (ошибки едут в выход отдельным списком). Порядок результатов `andForEach`
   сохраняет исходный порядок элементов — на это можно опираться.

**Момент проверки условия цикла.** Тело выполняется **минимум один раз**, условие проверяется
**после** итерации (post-condition; `andDoWhile`/`andDoUntil` именно так и работают). Счётчик
итераций инкрементируется **до** вычисления условия, поэтому `loopIterations` в конформансе равно
числу выполненных тел. Лимита итераций у VoltAgent нет — компилятор синтезирует условие как
конъюнкцию: `userCondition && iteration < maxIter && budgetLeft > 0 && !stagnation`. Исчерпание
`maxIter` — это не тихий выход, а исход `E_LOOP_LIMIT`, если политика цикла не объявлена как
`best_of` (тогда возвращается лучший кандидат из состояния).

**Ретраи и идемпотентность.**

| Уровень | Механизм | Семантика |
|---|---|---|
| Шаг | `retries?: number` на шаге, `retryConfig: {attempts, delayMs}` на воркфлоу | total attempts = `retries + 1` (подтверждено: `retryCount` = 0, 1, 2 при `retries: 2`); конфиг воркфлоу — дефолт, поле шага переопределяет |
| Модель | `maxRetries` у `andAgent` | total attempts = `maxRetries + 1`, ретраит AI SDK на уровне провайдера |
| Middleware | `maxMiddlewareRetries` | ретраи, вызванные `abort({retry: true})` |

Уровни **перемножаются**, поэтому нормативно: у узла ровно один эффективный ретрай-бюджет, объявленный
в IR; компилятор обязан обнулить нижние уровни (`maxRetries: 0`, `maxMiddlewareRetries: 0`) и
реализовать backoff и предикат «ретраить ли эту ошибку» собственным циклом внутри `execute` — у
VoltAgent ни backoff, ни предиката по коду ошибки нет. Ретраи на `andTap` бессмысленны: он глотает
ошибки по контракту.

Идемпотентность: при resume **шаг исполняется заново с начала** с доступным `resumeData`. Значит
каждый узел с побочным эффектом обязан нести ключ `hashOf('idem/v1', {executionId, nodeId, iteration, itemKey})`,
и ключ не зависит от номера попытки. Узлы без эффектов идемпотентны по построению — их повтор
обслуживается replay-кэшом по хешу нормализованного запроса.

**Провенанс.** У каждого куска контекста, попавшего в промт, хранится источник: узел, привязка,
версия документа или фрагмента, момент получения. Точка записи — `andTap`: он не может сломать поток
(ошибки внутри ловятся и логируются), поэтому провенанс, метрики и запись кассет живут именно там,
а не в `andThen`. Провенанс не выражается нативно **ни в одном** целевом фреймворке (см. §11) —
он переносится как рантайм-обвязка, и это фиксируется в отчёте потерь.

### Связь текста и эталонного интерпретатора

`reference/` — **тот же код, что в проде**, а не вторая реализация: изолированная сборка ядра, где
модель, тул, часы, случайность и человек — порты (Port/Adapter), реализованные кассетой и секцией
`env` кейса. Это бесплатно даёт: воспроизводимость прод-сбоя (kill 5), генерацию секции `expect`
прогоном (кейс записывается, а не пишется руками) и проверку бандла на импорте (§2, шаг 6).
Риск назван честно: баг ядра попадёт и в текст, и в тесты. Противовесы — доменный мутационный тест
компилятора (kill 1) и вторая реализация на Mastra (kill 14), которая ловит расхождение между
текстом семантики и кодом ядра.

## 4. Формат конформанс-кейса

Формат заимствован у JSON Schema Test Suite: реализация-агностичный JSON, разделение
`required` / `optional`, харнесс на стороне реализации. `conformance/cases/<caseId>.json`:

```jsonc
{
  "caseId": "hotel_pitch/basic-3-hotels",
  "specRef": { "flowId": "hotel_pitch", "version": 7, "specHash": "sha256-..." },
  "tier": "required",
  "features": ["map", "diverge", "judge_panel", "loop"],
  "env": {
    "now": "2026-03-01T12:00:00.000Z",
    "seed": 42,
    "humanInputs": [{ "atNode": "approve", "iteration": 0, "value": { "approved": true } }]
  },
  "input": {},
  "cassetteKeys": ["sha256-...", "sha256-..."],
  "expect": {
    "nodeOutputs": {
      "load_hotels": { "mode": "exact", "valueHash": "sha256-..." },
      "score": { "mode": "unordered-by-key", "keyPath": "$.hotelId", "valueHash": "sha256-..." },
      "pitches": { "mode": "exact", "value": {} }
    },
    "renderedPrompts": { "pitch_gen#0": { "mode": "normalized-text", "valueHash": "sha256-..." } },
    "toolCalls": [{ "node": "load_hotels", "name": "db_hotels", "argsHash": "sha256-..." }],
    "controlFlow": {
      "branchesTaken": [{ "node": "route", "branch": "premium" }],
      "loopIterations": { "verify_fix": 2 },
      "nodesSkipped": ["fallback_cheap"]
    },
    "finalOutput": { "mode": "exact", "valueHash": "sha256-..." }
  }
}
```

| Поле | Тип | Правило |
|---|---|---|
| `caseId` | `string` | `<flowId>/<slug>`, только `[a-z0-9_/-]`; совпадает с путём файла |
| `specRef.specHash` | `Sha256` | сверяется с `manifest.specVersions` перед прогоном; расхождение = `E_CASE_STALE` |
| `tier` | `"required" \| "optional"` | `optional` реализация вправе честно пропустить, если не поддерживает его `features` |
| `features[]` | `string[]` | имена примитивов и комбинаторов ядра; ранер печатает пропуски отдельным списком |
| `env.now` | ISO-8601 UTC, мс | **единственный** источник времени; прямой `Date.now()` в реализации = провал кейса |
| `env.seed` | `number` | сид детерминированного PRNG; алгоритм назван в `semantics/00-model.md` |
| `env.humanInputs[]` | `{atNode, iteration, value}` | ответы человека для `suspend`/`resume`; `iteration` нужен для узлов внутри циклов |
| `input` | канонизируемый JSON | вход воркфлоу |
| `cassetteKeys[]` | `Sha256[]` | подмножество кассет, нужное кейсу; позволяет выгружать кейс отдельно от всего бандла |
| `expect.nodeOutputs` | `Record<nodeId, Expectation>` | ожидание по каждому узлу, исполненному в прогоне |
| `expect.renderedPrompts` | `Record<"<nodeId>#<callIndex>", Expectation>` | `callIndex` — порядковый номер вызова модели в этом узле, с нуля |
| `expect.toolCalls[]` | `{node, name, argsHash}` | порядок — как в прогоне; сравниваются аргументы, не результат |
| `expect.controlFlow` | см. пример | «те же ветки, то же число итераций» из критерия 1:1 |
| `expect.finalOutput` | `Expectation` | выход воркфлоу |

```ts
type Expectation =
  | { mode: "exact"; value: JsonValue }
  | { mode: "exact"; valueHash: Sha256 }
  | { mode: "unordered-by-key"; keyPath: string; valueHash: Sha256 }
  | { mode: "unordered-canonical"; valueHash: Sha256 }
  | { mode: "normalized-text"; valueHash: Sha256 }
  | { mode: "error"; code: ErrorCode };
```

Мелкие ожидания кладутся значением (`value`), крупные — хешем (`valueHash`): урок sqllogictest,
где для тяжёлых выдач хранится хеш, а не сама выдача. Порог — 2 КБ канонического JSON, фиксирован
в конфигурации записи, чтобы кейсы не различались по машине записи. Значение читаемо человеком и
LLM, поэтому по умолчанию предпочитается `value`, а `valueHash` — вынужденная мера.

Секция `expect` — **единственная**, которую харнесс не получает (§5, требование 5).

## 5. Контракт адаптера для чужой реализации

Чужая реализация поставляет **один исполняемый файл-харнесс**, общающийся построчным JSON (NDJSON)
через stdin/stdout. Язык и фреймворк неважны — это и есть смысл kill 14.

Команды ранера в stdin харнесса:

```jsonc
{"op":"load","specPath":"flows/hotel_pitch@7/flow.yaml"}
{"op":"run","caseId":"hotel_pitch/basic-3-hotels","input":{},"env":{},"cassetteDir":"conformance/cassettes"}
{"op":"shutdown"}
```

События харнесса в stdout, по одной строке на событие:

```jsonc
{"ev":"ready","features":["map","loop","diverge"]}
{"ev":"node.end","node":"load_hotels","output":{}}
{"ev":"prompt.rendered","node":"pitch_gen","index":0,"messages":[{"role":"user","content":"..."}]}
{"ev":"tool.call","node":"load_hotels","name":"db_hotels","args":{}}
{"ev":"branch","node":"route","branch":"premium"}
{"ev":"loop.iteration","node":"verify_fix","n":2}
{"ev":"node.skipped","node":"fallback_cheap"}
{"ev":"run.end","output":{}}
{"ev":"error","node":"score","code":"E_SCHEMA_INVALID"}
```

Требования к харнессу — ровно пять, и каждое проверяемо автоматически:

1. модели и тулы вызываются **только** через кассету; прогон идёт с отключённым сетевым доступом
   (проверка автоматическая — попытка сети завершает прогон провалом);
2. время и случайность берутся **только** из `env`;
3. каждое событие выдаётся **до** того, как его результат использован, — иначе расхождение
   невозможно локализовать;
4. падение — это событие `{"ev":"error", ...}`, а не молчание и не ненулевой код возврата посреди прогона;
5. харнесс **не читает `expect`**: файл кейса передаётся ему без этой секции, сравнивает наш ранер.

Запуск:

```
aqven conformance run \
  --bundle ./project-export \
  --harness "node ./my-mastra-impl/harness.mjs" \
  --tier required \
  --strict-cassette \
  --report ./conformance-report.json
```

Ранер поднимает харнесс один раз на прогон, шлёт `load` на каждую спеку, затем `run` на каждый кейс,
собирает события и сравнивает по правилам §6. Отчёт — `{passed, failed, skipped[], firstDivergence}`
по каждому кейсу. **Kill 14 засчитывается только при `--strict-cassette`** и только на
`tier: required`; `optional` отчитывается отдельной строкой и выпуск не блокирует.

## 6. Правила сравнения

Нормативная версия — `semantics/06-comparison.md`, реализация — один модуль `@aqven/conformance`.

1. **Выходы узлов** сравниваются как `canonicalize(output)` байт-в-байт. Никакого «примерно равно»
   для не-LLM узлов.
2. **Промты** нормализуются `NFC → \r\n|\r → \n → rtrim каждой строки → 3+ пустых строки → 2 →
   trim документа`, затем сравниваются точно. Роли и порядок сообщений — точно. Порядок тулов в
   запросе — отсортирован по `name`; мы сортируем, и это записано в семантике как обязанность
   реализации. Нормализация применяется **только к сравнению и к ключу кассеты**, но не к тому,
   что уходит в модель: иначе тесты меняют поведение прода.
3. **Параллельные ветки** (`parallel`, `map`, `diverge`) сравниваются **как мультимножество по
   ключу**, не по порядку. Ключ объявлен в спеке узла (`keyPath`, например `$.hotelId`; для
   `diverge` — индекс варианта, потому что варианты различимы по `vary`-параметрам). Ключ не
   объявлен — сравниваем как мультимножество канонических строк элементов (сортируем строки).
   **Сравнение параллельных результатов по индексу массива запрещено** — это встроенный
   ложноположительный провал.
4. **Числа** сравниваются после канонизации, то есть по представлению ECMAScript: `1.0` и `1` равны,
   `0.1 + 0.2` и `0.3` — нет. Для агрегатов (`avg`, `score`) семантика узла обязана задавать
   округление явно (`round(x, 4)`), иначе реализация на Python разойдётся в последнем бите.
5. **Решения потока**: `branchesTaken` сравнивается как последовательность пар `(node, branch)` в
   порядке исполнения; `loopIterations` — точное совпадение числа выполненных тел по каждому узлу
   цикла; `nodesSkipped` — как множество. У VoltAgent пропущенные ветки видны штатно: статус
   `"skipped"` есть в типе события потока.
6. **Ошибки** сравниваются по нашему коду (`E_SCHEMA_INVALID`, `E_BUDGET_EXCEEDED`,
   `E_QUORUM_NOT_MET`, `E_LOOP_LIMIT`), а не по тексту сообщения.
7. **Usage, стоимость и латентность не сравниваются** — они не часть семантики.
8. **Расхождение локализуется на первом различии в топологическом порядке.** Отчёт печатает узел,
   режим сравнения и канонический дифф значения. Без этого LLM, чинящий свою реализацию, не сойдётся
   за разумное число итераций.

## 7. Кассеты

HTTP-уровень (`nock`, `msw`, HAR, Polly) как контракт **не годится**, и каждой из трёх причин
достаточно по отдельности:

1. ключ обязан быть семантическим: тот же логический вызов к OpenRouter и к Anthropic — разные URL
   и разные тела, а кассета, записанная на одном провайдере, обязана проигрываться на другом;
2. цель конформанса — чужая реализация в чужом фреймворке; она не обязана ходить теми же HTTP-запросами,
   она обязана сделать логически тот же вызов;
3. тулы и MCP — вообще не HTTP (stdio-транспорт).

Поэтому формат свой, на уровне порта модели и тула. `msw`/`@mswjs/interceptors` остаётся вторым,
**отладочным** слоем: пишет сырой HTTP в `conformance/raw-http/` вне `merkleRoot` и вне контракта —
для разбора «провайдер ответил не то».

### Ключ

```ts
type NormalizedModelRequest = {
  kind: "model";
  modelProfile: string;
  messages: Array<{ role: "system" | "user" | "assistant" | "tool"; content: NormalizedContent[] }>;
  tools?: Array<{ name: string; schemaHash: Sha256 }>;
  outputSchemaHash?: Sha256;
  params: { temperature?: number; topP?: number; maxTokens?: number; seed?: number; stop?: string[] };
};

const key = hashOf("cassette-req/v1", normalizeRequest(request));
```

`modelProfile` — **наш логический профиль** (`strong-json`), а не `gpt-4o-2024-11-20`: иначе смена
модели под профилем обнуляет весь корпус. В ключ **не входят**: ключ API, `baseUrl`, request-id,
`user`, метаданные трассировки, временные метки. Тексты нормализуются той же функцией, что в §6,
правило 2.

**Вторичный ключ (fallback):** при промахе точного ключа кассета может ответить по
`(modelProfile, nodeId, callIndex)` — «N-й вызов модели в этом узле». Это спасает чужую реализацию,
у которой промт разошёлся на пробел, не покрытый нашей нормализацией. Режим включается только
`--no-strict-cassette` и только для отладки; **kill 14 засчитывается исключительно в strict**.

### Формат записи

```jsonc
{
  "key": "sha256-...",
  "kind": "model",
  "request": { },
  "response": {
    "finishReason": "tool-calls",
    "text": "...",
    "object": { },
    "toolCalls": [{ "id": "call_1", "name": "db_hotels", "args": {} }],
    "usage": { "inputTokens": 812, "outputTokens": 140, "reasoningTokens": 0 },
    "chunks": [
      { "t": 0, "type": "text-delta", "delta": "Hel" },
      { "t": 120, "type": "tool-call-delta", "id": "call_1", "argsDelta": "{\"ci" },
      { "t": 300, "type": "finish" }
    ]
  },
  "recordedAt": "2026-09-11T00:00:00.000Z",
  "provider": { "id": "openrouter", "model": "anthropic/claude-sonnet-4.5" }
}
```

`request` пишется целиком, а не только его хеш: кассета должна читаться человеком и LLM, который
чинит свою реализацию. `object` при структурированном выходе хранится уже распарсенным и
канонизированным.

**Стриминг.** `chunks[]` хранит относительные `t` в миллисекундах от начала ответа, округлённые до
10 мс, — иначе байты записи меняются от прогона к прогону. При воспроизведении `t` по умолчанию
игнорируется (мгновенная отдача); `--realtime` нужен только для отладки UI. Конформанс сравнивает
**склеенный результат и последовательность типов чанков, но не тайминги**.

**Тулы.** `kind: "tool"`, `request: {toolName, toolSchemaHash, args}`, `response: {result | error}`.
Недетерминированные источники (`now()`, `random()`, обращения к БД за живыми данными) — **не тулы, а
окружение**: они живут в `env` кейса (`now`, `seed`, `humanInputs`), и эталонный интерпретатор обязан
брать время и случайность только оттуда, иначе нет воспроизводимости (kill 5).

**Коллизии.** Один ключ — один ответ. Если узел в цикле дважды вызывает модель с одинаковым
нормализованным запросом и ожидает разные ответы, значит либо промты на самом деле различаются
(в них входит история итераций), либо это баг спеки. Кассета обязана упасть с `AMBIGUOUS_REPLAY`,
а не молча вернуть тот же ответ: иначе маскируется бесконечный цикл.

### PII

Правило спеки — «секретов нет, только ссылки; PII маскирована» — исполняется **детерминированной
псевдонимизацией на этапе построения кейса, а не при записи кассеты**. Порядок:

1. прод-прогон отбирается в кейс;
2. детекция PII — `createPIIInputGuardrail` / `createDefaultPIIGuardrails` из VoltAgent;
3. каждое найденное значение заменяется стабильным псевдонимом `PERSON_1`, `EMAIL_3`, вычисляемым
   как позиция в отсортированном списке `hashOf('pii/v1', {caseId, kind, value})` — одно и то же
   значение получает один и тот же псевдоним по всему кейсу;
4. псевдонимизируются **вход кейса, `env.humanInputs` и датасеты одновременно**;
5. кейс переигрывается на `reference/` уже на псевдонимах, и кассеты записываются заново — поэтому
   ключ кассеты считается по псевдонимизированному запросу и сходится;
6. `manifest.capabilities.piiMasked = true` выставляется только после шага 5.

Обратная таблица «псевдоним → исходное значение» **в бандл не попадает** ни при каких условиях.

### Размер и чистка

| Правило | Значение |
|---|---|
| Тело ответа в кассете | > 256 КБ канонического JSON — выносится в `conformance/blobs/<sha256>.bin`, в кассете остаётся `{"$blob": "sha256-..."}` |
| Перезапись | только по явной команде `aqven cassette record --refresh`: `recordedAt` и `provider` входят в содержимое файла, значит и в `merkleRoot`, и перезапись меняет бандл |
| Сборка мусора | достижимость из `cases[].cassetteKeys`; недостижимые удаляются `aqven cassette gc`, он же падает, если кейс ссылается на отсутствующий ключ |
| Дедупликация | адресация по ключу даёт её бесплатно: один запрос — одна запись на весь бандл |

## 8. Round-trip (kill 13)

Процедура, которая гоняется в CI:

```
export(projectId)  -> bundleA (детерминированный .tar)
import(bundleA)    -> projectId2   (полная JSON Schema + Zod валидация, §2)
export(projectId2) -> bundleB
assert sha256(bundleA) === sha256(bundleB)
assert merkleRoot(bundleA) === merkleRoot(bundleB)
```

Проверяются оба равенства: байтовое доказывает критерий, по-файловое показывает, **где** разошлось.
Сверх этого — property-тест на `fast-check`: генерим случайный валидный IR, гоняем
`export → import → export` три раза и требуем стабилизации со второго прохода. Первый проход вправе
нормализовать авторский ввод — это законно; дальше обязан быть фикспойнт.

После переноса истины в файлы этот тест слабее фикспойнта рабочего дерева ([04](04-ir-schema.md) §6.4):
каталоги определений в бандл копируются, поэтому их байтовое равенство тривиально и про сериализатор
ничего не доказывает. Вес теста сместился на `import`: он обязан воссоздать рабочее дерево байт-в-байт —
те же пути минус `@<version>`, те же байты файлов, тот же журнал `renames` в `project.yaml`.
Для генерируемой части бандла (`manifest.json`, развёрнутый вид, `schema/`, `conformance/`, `targets/`)
kill 13 остаётся полноценной проверкой детерминизма экспортёра.

### Канонический YAML

Опции, при которых round-trip байт-в-байт подтверждён пробой (`c1 === c2 === c3`):

```ts
export const YAML_CANON: YAML.ToStringOptions & YAML.DocumentOptions & YAML.SchemaOptions = {
  version: "1.2",
  indent: 2,
  indentSeq: false,
  lineWidth: 0,
  minContentWidth: 0,
  defaultStringType: "QUOTE_DOUBLE",
  defaultKeyType: "PLAIN",
  doubleQuotedAsJSON: true,
  singleQuote: false,
  blockQuote: false,
  collectionStyle: "block",
  flowCollectionPadding: false,
  nullStr: "null",
  simpleKeys: true,
  sortMapEntries: true,
  directives: false,
};
```

`lineWidth: 0` — чтобы ширина терминала не влияла на байты. `doubleQuotedAsJSON: true` — чтобы
экранирование совпало с JCS. `blockQuote: false` — многострочные строки едут как `"a\nb"`, а не
через `|`/`>`.

### Что запрещено в авторском YAML

Список запретов и способ ловли каждого — [04. Формат IR](04-ir-schema.md) §6.3, одна копия на весь
комплект. Здесь он проверяется дважды: валидатором на импорте бандла и `aqven check` над рабочим деревом.

Отдельно: **`.tar.gz` не участвует в kill 13** — это записано в формулировке критерия, иначе он
будет ложно падать на смене версии zlib.

## 9. Codegen в VoltAgent (kill 15)

Инструмент — **шаблонные строки плюс `prettier`**. AST-инструменты не берём: сгенерированный файл —
артефакт, а не исходник. Он помечен `GENERATED … DO NOT EDIT`, несёт `specHash` и перегенерируется
целиком. `ts-morph` был бы нужен для правки написанного человеком кода, а мы этого не делаем именно
потому, что kill 15 требует «собирается и запускается без ручных правок». Идемпотентность печати
проверена: `prettier.format(x) === prettier.format(prettier.format(x))`.

Фиксированный конфиг печати кладётся в бандл (`targets/voltagent/.prettierrc`), иначе байты зависят
от машины:
`{ parser: "typescript", printWidth: 100, semi: true, singleQuote: false, trailingComma: "all", arrowParens: "always", endOfLine: "lf" }`.

Ядро генератора — диспетчеризация по `kind` через таблицу эмиттеров (Strategy; никаких `if/else`
и `switch`-лестниц):

```ts
type Emitter = (node: IRNode, ctx: EmitCtx) => string;

const EMITTERS: Record<IRNode["kind"], Emitter> = {
  const: emitConst,
  code: emitCode,
  tool: emitTool,
  llm: emitAgent,
  map: emitForEach,
  parallel: emitAll,
  switch: emitWhenChain,
  loop: emitLoop,
  race: emitRace,
  try: emitTry,
  subflow: emitSubflow,
};

const emitChain = (ir: IRFlow, ctx: EmitCtx): string =>
  ir.nodes.map((node) => EMITTERS[node.kind](node, ctx)).join("");
```

Живой результат генерации цепочки из узлов IR (`tool → andThen`, `map → andForEach`, `llm → andAgent`):

```ts
import { createWorkflowChain } from "@voltagent/core";
import { z } from "zod";

export const hotel_pitch = createWorkflowChain({
  id: "hotel_pitch",
  name: "Hotel Pitch",
  purpose: "pitch hotels",
  input: z.object({ filters: z.record(z.string(), z.unknown()) }),
  result: z.object({ pitch: z.string() }),
})
  .andThen({
    id: "load_hotels",
    execute: async ({ data }) => ({
      ...data,
      load_hotels: await tools.hotelsByFilters(data.filters),
    }),
  })
  .andForEach({
    id: "score",
    items: ({ data }) => data.hotels,
    concurrency: 8,
    step: scoreStep,
  })
  .andAgent(async ({ data }) => `Pitch these: ${JSON.stringify(data.top)}`, pitchAgent, {
    schema: z.object({ pitch: z.string() }),
  });
```

Шапка `GENERATED from spec hotel_pitch@7 sha256-… — DO NOT EDIT` эмитится как первая строка файла;
в примере выше она опущена только потому, что в этом документе комментарии в коде запрещены.

### Что генератор обязан делать сверх перевода узлов

1. **Zod-схемы из реестра типов** генерятся в отдельный `schemas.ts`, шаги ссылаются на `S.HotelScore`.
   Инлайн схем размазывает один enum по 15 местам и ломает kill 6 (распространение enum).
2. **Стабильный порядок всего:** узлы — в топологическом порядке спеки, импорты отсортированы, ключи
   объектных литералов — в фиксированном порядке эмиттера. Тогда дифф сгенерированного кода между
   версиями спеки читается человеком.
3. **Проверка `specHash` на старте** сгенерированного проекта против `manifest.json` — защита от
   «поправили спеку, забыли перегенерить».
4. **`switch` → цепочка `andWhen`** с взаимоисключающими предикатами: родного `switch` у VoltAgent
   нет, а `andBranch` запускает **все** истинные ветки (нет first-match и нет `else`). Ветка `else`
   эмитится отдельным `andWhen` с отрицанием конъюнкции всех предыдущих условий — выписывается явно,
   а не подразумевается порядком.
5. **Ручной вызов агента внутри `andThen` вместо `andAgent`**, когда узлу нужен стриминг или
   инспекция tool-calls. Выбор делает генератор по флагам узла, человек в этом не участвует.
6. **Явный учёт токенов** для узлов, ушедших в `andThen`: `state.usage` копится только по `andAgent`,
   иначе бюджет врёт.
7. **`harness.ts`** — тот же NDJSON-контракт (§5), с кассетой вместо провайдера. Запись и сверка
   вешаются на `andTap`: он ловит свои ошибки и не ломает поток.

### Проверка сгенерированного — четыре уровня, все в CI

| Уровень | Команда | Что доказывает |
|---|---|---|
| 1 | `tsc --noEmit` (`typescript@7.0.2`) | биндинги IR типо-корректны в целевом коде — самая ценная статическая проверка |
| 2 | `npm i && npm run build` в распакованном бандле из чистого кэша | `targets/voltagent/package.json` самодостаточен; пин `ai@6` обязателен (peer `ai: ^6.0.0` у `@voltagent/core@2.10.0`) |
| 3 | `aqven conformance run --harness "node targets/voltagent/harness.js"` | 100% кейсов `tier: required` — это и есть kill 15 |
| 4 | `codegen(spec) === codegen(spec)` на 100 прогонах | детерминизм самого генератора |

## 10. Другие цели миграции

Легенда: **N** — ложится нативно, **E** — эмулируется нашей обвязкой поверх, **L** — теряется и идёт
в отчёт потерь.

| Наш примитив | VoltAgent 2.10 | Mastra 1.66 | LangGraph JS 1.4 | Temporal TS 1.23 |
|---|---|---|---|---|
| `llm` (structured output) | **N** `andAgent(prompt, agent, {schema})` | **N** `createStep` + `agent.generate({structuredOutput})` | **E** узел с ручным вызовом модели | **E** только как activity |
| `tool` | **N** тул агента / `andThen` | **N** `.tool()` / step | **E** узел | **N** `proxyActivities` |
| `code` | **N** `andThen` | **N** `.then(createStep)` | **N** узел | **N** activity (в воркфлоу — только детерминированный код) |
| `const` | **N** | **N** | **N** | **N** |
| `map` (fan-out по коллекции) | **N** `andForEach` | **N** `.foreach()` с `concurrency` | **N** `Send` — родной динамический fan-out | **N** `Promise.all(items.map(...))` |
| `parallel` (фиксированные ветки) | **N** `andAll` | **N** `.parallel([...])` | **N** рёбра из одного узла + барьерный канал | **N** `Promise.all` |
| `switch` / `gate` | **E** цепочка `andWhen` | **N** `.branch([[cond, step], ...])` | **N** `addConditionalEdges` | **N** обычный `if` |
| `loop` (while/until) | **N** `andDoWhile`/`andDoUntil` | **N** `.dowhile()`/`.dountil()` | **E** условное ребро назад + `GraphRecursionError` как предохранитель | **N** `while` + `condition()` |
| `race` / timeout | **N** `andRace` (результат — union, не кортеж) | **E** `.parallel` + своё «первый победил» | **E** | **N** `Promise.race` + `sleep` |
| `try` / retry | **N** `retries` на шаге (без backoff и предиката) | **N** retry на step | **N** `RetryPolicy` на узле | **N** самый богатый: backoff, non-retryable types, heartbeat |
| подворкфлоу по версии | **N** воркфлоу как шаг | **N** вложенный workflow | **N** субграф | **N** `executeChild` |
| ожидание человека | **N** `suspend`/`resume` | **N** `.waitForEvent()`/`.sendEvent()`, `.resume()` | **N** `interrupt()` + `Command({resume})` | **N** `defineSignal`/`defineUpdate` + `condition()` |
| чекпоинты и durability | **N** чекпоинт после каждого шага | **N** + `.timeTravel()` | **N** checkpointer | **N** event sourcing — эталон отрасли |
| типизированный контракт шага | **N** Zod на каждом шаге | **N** Standard Schema | **E** канал состояния типизирован, контракт узла — нет | **L** только TS-типы, без рантайм-схем |
| **провенанс контекста** | **L** | **L** | **L** | **L** |
| **статические гарантии компилятора** | **L** | **L** | **L** | **L** |
| **replay-кэш по нашему ключу** | **E** | **E** | **E** (`CachePolicy` — не наш ключ) | **E** |
| **бюджет по стоимости и токенам** | **E** | **E** | **E** | **E** |
| **эффективная конфигурация вызова** | **N** | **N** | **E** | **E** |

**Mastra — обязательная вторая цель** для kill 14: у неё есть ровно наши комбинаторы
(`branch`, `parallel`, `foreach`, `dowhile`/`dountil`, `waitForEvent`, `stateSchema`), карта
соответствия почти 1:1, и LLM воссоздаёт механически.

**LangGraph — стресс-тест семантики.** Граф с каналами вместо чейна: именно на нём видно, честно ли
дописаны join-политики, потому что барьер там — канал, а порядок слияния задаётся reducer'ом, который
надо вывести из нашей join-политики, а не скопировать из VoltAgent-API.

**Temporal — валидатор чистоты IR, а не цель для LLM-семантики.** Все LLM- и тул-вызовы обязаны стать
activity, внутри воркфлоу — только детерминированный код. Если `code`-узел не переживает
`overrideGlobals` (дёргает `Date.now`/`Math.random` напрямую), значит у нас дырка в детерминизме.

### Отчёт потерь

Обязателен для каждой цели: `targets/<target>/loss-report.md` (для человека) плюс
`targets/<target>/loss-report.json` (для CI):

```jsonc
{
  "target": "@mastra/core@1.66.0",
  "mapping": [{ "primitive": "switch", "verdict": "native", "construct": ".branch([...])" }],
  "emulated": [{ "primitive": "race", "cost": "своя обвязка «первый победил» поверх .parallel" }],
  "lost": [
    { "capability": "provenance", "impact": "контекст не отслеживается до источника", "mitigation": "рантайм-обвязка в state" },
    { "capability": "compiler_guarantees", "impact": "гарантии L0/L1 становятся рантайм-ассертами" }
  ],
  "conformance": { "tier": "required", "total": 48, "passed": 48, "skipped": [] }
}
```

Постоянно теряются во всех целях одни и те же четыре вещи: провенанс, статические гарантии
компилятора, наш replay-ключ и бюджеты. Они переносятся рантайм-обвязкой, и конформанс проверяет их
только косвенно — это записано в отчёте прямым текстом, а не умалчивается.

## 11. Скилл воссоздания для LLM

Упакован по стандарту Agent Skills и лежит в бандле (`README.md` ссылается на него первым абзацем).
Протокол — тот же цикл «реализовать → прогнать → починить», что и в architecture-implementation-loop,
но тесты даны заранее.

| Шаг | Действие | Проверка выхода шага |
|---|---|---|
| 1 | Прочитать `README.md`, `semantics/` целиком, `types/` | назвать все примитивы из `features` кейсов и их семантику своими словами |
| 2 | Выбрать цель и открыть `targets/<target>/mapping.json`; для цели без карты — построить её из таблицы §10 и сохранить | каждая строка карты — `native` / `emulated` / `lost` |
| 3 | Реализовать ядро или отобразить его на примитивы цели | `tsc --noEmit` или аналог для языка цели зелёный |
| 4 | Перенести компоненты, воркфлоу, шаблоны, агентов и тулы из `flows/`, `components/`, `prompts/`, `agents/`, `tools/`; брать **развёрнутую до примитивов** версию воркфлоу и **эффективную конфигурацию** каждого вызова, переопределения не пересчитывать | все `specHash` из `manifest.specVersions` сверены |
| 5 | Подключить кассету вместо моделей и тулов, время и случайность — из `env`; реализовать харнесс по контракту §5 | прогон с отключённой сетью не падает на сетевой ошибке |
| 6 | `aqven conformance run --tier required --strict-cassette` и чинить до 100%; расхождение читать по первому различию в топологическом порядке | 0 failed |
| 7 | Прогнать `tier: optional`, честно записать пропуски | список `skipped[]` с причинами |
| 8 | Зафиксировать `loss-report.json` и `loss-report.md` | схема отчёта валидна по `schema/loss-report.schema.json` |

Порядок шагов не переставляется: шаг 5 до шага 6 — потому что без кассеты конформанс измеряет
недетерминизм модели, а не семантику; шаг 2 до шага 3 — потому что без карты соответствия LLM
воспроизводит VoltAgent-API вместо семантики ядра.

## Открытые вопросы

1. **Подпуть импорта `@noble/hashes@2.4.0`.** В заметках зафиксирована версия и алгоритм, но не
   имя подмодуля (`@noble/hashes/sha2` против `@noble/hashes/sha256`, менявшееся между мажорами).
   *Закрыть:* поставить пакет в probe, прочитать `exports` из `package.json`, зафиксировать импорт
   в `@aqven/canon` и здесь.
2. **Противоречие внутри исследования: состав `env`.** В разделе о кассетах `env` описан как
   отдельный файл `conformance/env/<caseId>.json` с полями `now`, `seed`, `randomStream`,
   `humanInputs`; в формате кейса `env` лежит **внутри** файла кейса и содержит только `now`, `seed`,
   `humanInputs` — без `randomStream`. В документе принят второй вариант (env внутри кейса, seed
   вместо потока). *Закрыть:* решить, достаточно ли `seed` плюс именованный PRNG, или нужен явный
   поток чисел для реализаций на других языках, где алгоритм PRNG не совпадёт; зафиксировать
   алгоритм PRNG в `semantics/00-model.md`.
3. **UNVERIFIED в заметках: prior art.** Точные пути файлов и имена полей в WebAssembly spec,
   JSON Schema Test Suite, CommonMark и sqllogictest взяты по памяти и в этот заход не проверялись.
   *Закрыть:* сверить формат кейса и механику извлечения примеров из текста с репозиториями этих
   проектов до фиксации `formatVersion: 1.0.0`.
4. **Целостность полей манифеста вне `merkleRoot`.** `generator` и `signatures` намеренно не входят
   в корень, а сам `manifest.json` не входит в `files[]`. Значит поля `project`, `capabilities`,
   `formatVersion` ничем не защищены от правки без пересборки. *Закрыть:* решить, вводить ли
   `manifestHash` (хеш манифеста без `signatures`), печатаемый CLI и сохраняемый при импорте, или
   считать это зоной ответственности подписи из v2.
5. **Пороги размера не подтверждены замерами:** 2 КБ для `value` против `valueHash` в ожиданиях и
   256 КБ для выноса тела кассеты в `blobs/`. *Закрыть:* замерить бандл эталонного 15-шагового
   воркфлоу, подобрать пороги так, чтобы кейсы оставались читаемыми, а бандл не выходил за разумный
   размер для git.

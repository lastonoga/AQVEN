# Миграция комплекта документации на files-first

> Решает: точный список правок в уже написанных документах после переноса источника истины в файлы.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Удалять ли таблицы определений | Нет: `specs`, `spec_versions`, `components`, `registry_entries` остаются как **индекс**, перестраиваемый из файлов | запросы «где используется тип», «что сломает правка» на файлах не живут; но истина — файл |
| Признак индекса в DDL | Каждая индексная таблица получает `source_path text NOT NULL`, `source_blob bytea` (sha256 файла), `indexed_at`, и `TRUNCATE` + переиндексация обязаны давать тот же результат | иначе через полгода никто не скажет, какая таблица авторитетна |
| Что удаляется совсем | `app.op_log` / `app.spec_ops`, `specs.rev`, `spec_versions.parent_id`, `spec_versions.author/message` | это git: история, родитель, автор, сообщение |
| Чем заменяется `base_rev` | CAS по sha256 **байтов файла** (`If-Match`), не по нормализованному контенту | база больше не владеет счётчиком; хеш байтов — единственное, что обе стороны видят одинаково |
| Нумерация версий | номер живёт в имени файла (`flows/x@7.yaml`) и в git-теге, `max(version)+1` в транзакции удаляется | транзакционный счётчик без владельца данных даёт дыры и гонки |
| Аппрув реестров | `status`/`approved_by` переезжают **в файл**, БД хранит только проекцию; факт аппрува — строка в `app.audit_log` | аппрув — свойство определения, его ревьюят диффом |
| Раскладка канваса | остаётся в базе, отдельный канал, `layout_rev` — своя ось; в файлы **не** идёт | ADR-0016 по этой строке не заменяется: драг не должен быть коммитом |
| Прогоны, трассы, чекпоинты, датасеты, кассеты | не трогаются ни одним из документов ниже | их миллионы, они события |
| Порядок правок | ADR → 04 (формат) → 16 (модель) → 31 (запись) → 18 → остальные | нижние документы ссылаются на верхние; обратный порядок даёт два переписывания |

## 16. Модель данных — самая большая правка

| Раздел | Что стало неверно | На что менять | Объём |
|---|---|---|---|
| §2.2 `specs` | `rev bigint` (счётчик op-log), `head_version` как указатель истины | `rev` удалить; `head_blob bytea` (sha256 файла) + `source_path` вместо `head_version`; таблица описывается как индекс | средняя |

| §8 порт `SpecStore` | адаптер пишет в Postgres | порт остаётся, адаптер становится `FileSpecStore` (fs + git) + `IndexProjector`; DIP не нарушается, меняется только реализация | средняя |
| §9 сиды и `docker-compose.dev.yml` | сиды вставляют спеки SQL-ом | сиды — файлы в `fixtures/`, локальный старт = индексация каталога; compose без правок | малая |

| §5.2 развёрнутый вид | «запись в БД перестраиваемая, руками не редактируется» — верно | добавить: в рабочем дереве развёрнутый вид не лежит (или лежит в `.gitignore`), иначе два файла на одну сущность в диффе | малая |
| §7 семантический дифф | подаётся как замена диффа git | остаётся и становится **надстройкой** над `git diff`: git показывает строки, `ir_diff` — классы влияния; добавить абзац про связку `git diff --ext-diff` | малая |

## ADR-0016 — заменяется частично, не удаляется

Шапка: `> Статус: частично заменено [ADR-0017](../adr/0017-files-as-source-of-truth.md)`. Ниже — врезка «почему это
не противоречие»: исследование велось по визуальным редакторам для непрограммистов, а наш пользователь —
инженер в Claude Code, для которого файл есть рабочая поверхность, а не канал доставки. Тело не переписывается.

| Часть ADR-0016 | Судьба |
|---|---|
| Все факты из research (Windmill #8468, n8n «can't detect conflicts», Retool, Argo `selfHeal`, Kestra `sourceOfTruth`) | **остаются**, это доказательства, а не решения |
| «У git нет точки, где слияние можно отклонить» | **остаётся и становится центральным**: поэтому запись идёт через валидатор, а не через `git merge` |
| Урок оркестраторов: между репозиторием и прогоном всегда слой материализации; прогон пинит версию | **остаётся целиком**, это ровно наша схема «файл → компилятор → прогон с пином» |
| Таблица решения, строка «Редактирование — Postgres, op-log с `base_rev`» | **заменено**: файл + CAS по хешу файла |
| Строка «Релиз — коммит на `version_propose`, не на каждый `flow_patch`» | **заменено**: коммит на каждую принятую правку; релиз — тег/ветка, а не первый коммит |
| Строки «Прогоны… — Postgres» и «Раскладка — ui-канал, LWW» | **остаются** |
| «Что берём у продуктов»: `whenMissingInSource: FAIL`, префикс синка, stub/secret, `fieldManager`, дифф бейджами | **остаются**; `sourceOfTruth: GIT \| DB` теряет смысл — режим один | 
| Dolt / Doltgres / темпоральность PG18 | **остаются** как отвергнутые альтернативы | 

## ADR-0009 — меняется носитель, не аргумент

Шапка: `> Статус: принято; изменено ADR-0017 (отдельный ADR-0018 не заводился: CAS по хешу файла вошёл в 0017) в части носителя истории`.

| Часть ADR-0009 | Судьба |
|---|---|
| «CRDT гарантирует сходимость, но не гарантирует валидность»; пример с `parse_pdf`; пример с двумя рёбрами в цикл | **остаётся целиком, это главное в ADR** |
| «Одновременных редакторов единицы, конфликтов мало» | **остаётся** |
| «Серверный op-log нужен в любом случае: на нём стоят `version_propose(evidence)`, дифф версий, `run_lineage`, аудит» | **меняется**: эти четыре потребителя переезжают на git-историю плюс индекс; аргумент «история нужна» верен, вывод «значит таблица» — нет |
| `PatchInput.base_rev: z.number()` | → `base_blob: Sha256`; остальные поля (`ops[1..50]`, `idempotency_key`, `dry_run`) **без правок** |
| Серверная транзакция, шаги 1–6 | шаг 1 `SELECT … FOR UPDATE` → блокировка файла + сверка хеша; шаги 3–4 (валидатор, отказ) **без правок**; шаг 5 `INSERT INTO spec_ops` → `write file + git commit + index` |
| «Большинство конфликтов ребейзится автоматически» | **остаётся**: ребейз считается на уровне операций IR, не строк |

## Крайние случаи

| Ситуация | Поведение системы | Что видит человек |
|---|---|---|
| Инженер правит YAML в редакторе, файл ломает инвариант | индексатор отклоняет: строка индекса остаётся прежней, файл помечен `invalid` | красный маркер на воркфлоу, диагностика компилятора; файл никто не переписывает |
| Тот же файл правят агент через MCP и человек в редакторе одновременно | CAS по `blob_sha256` отбивает второго | `stale_blob` с текущим хешем и диффом; агент перечитывает и переигрывает намерение |
| `git checkout` другой ветки под работающим Studio | watcher видит смену хешей пачкой, индексатор перестраивает, SSE шлёт `reindexed` | канвас перезагружается, плашка «ветка изменилась»; раскладка сохраняется (она в базе, привязана к `node_id`) |
| Индекс отстал или повреждён | запросы `type_usages` / `type_impact` отдают `problems[{code:'index_stale'}]`, прогон и компиляция работают | предупреждение «поиск по проекту неполон», кнопка переиндексации |
| Файл переименован снаружи (`git mv`) | индексатор видит тот же `content_hash` на новом пути → переименование, а не удаление+создание | история не рвётся |
| Два файла с одним `flow.id` | индексатор отказывает обоим и не индексирует ни один | ошибка «дубликат id», оба пути названы |

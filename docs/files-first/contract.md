# Контракт операций после перехода на файлы

> Решает: какие MCP-операции остаются, меняются и исчезают, когда определения лежат файлами, а база — индекс.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| `base_rev` | умирает; CAS по содержимому: `base{commit, files[{path, sha256}]}` | нет глобального счётчика ревизий — есть коммит и хеши файлов; правка мимо MCP не отбивает ось версий |
| Op-log `app.spec_ops` | умирает как источник истины; git-коммиты + `intent`-трейлеры | ADR-0009 требовал линейной истории — git её даёт; op-log остаётся кэшем-проекцией в индексе |
| Уровни операций | оба: файловый — нативные Read/Write/Edit агента, доменный — `flow_patch` поверх файлов | новых `file_read`/`file_write` в MCP не заводим: Claude Code уже умеет файлы, дублирование даёт две несогласованные CAS-схемы |
| Кто держит инварианты | валидатор на записи (`flow_patch`) + `flow_check` по хуку после прямой правки файла | нет «пишем что попало»: прямая правка допустима, но незакоммиченный невалидный файл не релизится |
| `human_task_*` (6 операций) | **отменены полностью**; вместо них `run_list(status='suspended', assignee)` + `run_resume(payload)` | подсистемы задач нет: приостановленный прогон — это статус, «что ждёт меня» — фильтр |
| `app.human_tasks` | не источник истины; индекс-проекция над приостановленными прогонами | дедлайн исполняет pg-boss (17 §6), сверка остаётся, отдельная сущность — нет |
| Коммит промта | явный `flow_commit`; запись в файл — черновик, прогон пинится к `sha` | редактирование файла не должно менять то, что уже исполняется |
| `flow_history`/`flow_revert`/`flow_diff` | поверх git; `flow_revert` — новый коммит, не переписывание истории | откат — событие, которое само подлежит ревью |
| Раскладка канваса и лок | раскладка — LWW-канал вне git и вне хеша ([31](../31-canvas-editing.md)); лок — advisory-lockfile `.volt/locks/<flow>.lock`, TTL 300 с | драг мышью не рождает коммит; лок виден в `git status` и переживает рестарт сервера |

## 1. Реестр §2 после перехода

Затронуто 15 операций из 57 (14 меняются, одна отмирает); остальные 42 не трогаем — прогон, evals, провайдеры, каталог.

| Операция | Судьба | Что именно |
|---|---|---|
| `flow_patch` | **меняется** | `base_rev` → `base{commit, files[{path,sha256}]}`; `ops[]` те же; пишет в файлы, не в JSONB; `conflict` сравнивает хеши, а не номера |
| `flow_get` | **меняется** | `rev?` → `at?: commit \| 'working'`; в выходе `version{commit, files[{path,sha256}]}`, `dirty`, `layout_rev` |
| `flow_create`, `flow_lock` | **меняются** | `flow_create` создаёт файлы по [layout.md](layout.md) и возвращает `paths[]`; `flow_lock` пишет lockfile, добавляет `holder_kind`, `reason`, `takeover_allowed` |
| `flow_compile` | **меняется** | вход `at?`; по умолчанию читает рабочую копию, не последнюю ревизию БД |
| `component_define` | **отмирает** | локальный компонент — файл, пишется `flow_patch` или прямой правкой |
| `flow_import`, `project_import` | **меняются** | результат — файлы в рабочем дереве, не запись в БД |
| `project_export`, `version_propose` | **меняются** | `rev` → `commit`; требуют чистого дерева, иначе `DIRTY_WORKTREE` |
| `brief_submit`, `context_bind`, `architecture_instantiate`, `component_propose_to_library` | **меняются** | у первых трёх `base_rev` → `base{...}`; у четвёртой `id` → `path` |
| `journal_append` | **меняется** | пишет в `journal/*.md`, а не в таблицу; коммитится вместе с правкой |
| `catalog_*`, `mode_set`, `help_contract`, `studio_open`, весь `run`/`eval`/`provider` | **остаются** | события и внешние каталоги в файлы не переезжают; каталог читает индекс и несёт `stale` |

## 2. Два уровня операций

Файловый уровень **не оформляется в MCP-тулы**: у Claude Code уже есть Read/Edit/Write и git.
`file_read`/`file_write` завели бы вторую CAS-схему и способ записать невалидный граф мимо валидатора.

| | Файловый уровень | Доменный уровень |
|---|---|---|
| Кто | нативные тулы агента, редактор, git | `flow_patch` и его родня по MCP/REST |
| Единица и CAS | файл, байты; конфликт ловит git | операция над IR, атомарно по набору файлов; `base{commit, files[]}` |
| Валидация | **после** записи: хук `flow_check` на `PostToolUse`, файл остаётся на диске | **до** записи: невалидное не пишется, `problems[]` + `candidates[]` |
| Атомарность и охват | один файл: текст промта, правка поля, чтение, грепы | весь набор (переименование типа в 40 файлах — один вызов): структурное и кросс-файловое |

**Как сосуществуют.** Источник истины один — байты на диске, поэтому уровни не расходятся.

| Правило | Формулировка |
|---|---|
| Приоритет | структурную правку делаем `flow_patch`; прямая запись законна, но её отчёт приходит постфактум |
| Дрейф | `flow_patch` сверяет `files[].sha256` перед записью; расхождение → `STALE_FILE` с текущим хешем и дельтой, а не молчаливая перезапись |
| Граница коммита | невалидное дерево коммитить можно, релизить — нет: `version_propose` требует `flow_compile(ok)` |
| Индекс | оба уровня переиндексируются одинаково — watcher на дереве, не хук внутри `flow_patch` ([index.md](index.md)) |

## 3. Человек в цикле без подсистемы задач

Узел `human` (03 §2.5) остаётся как есть: `form`, `resume`, `timeout`, `on_timeout`, `assignee`.
Меняется только то, что вокруг него нет отдельной сущности «задача».

| Операция | Вход | Выход |
|---|---|---|
| `run_list` | `status?: 'running' \| 'suspended' \| 'failed' \| 'done'`, `assignee?`, `spec_id?`, `overdue?`, `limit=20`, `cursor?` | `items[{run_id, spec_id, node_id, status, assignee, waiting_since, deadline_at, form_ref, title}]`, `next_cursor` |
| `run_resume` | `run_id`, `node_id`, `payload`, `idempotency_key?` | `status`, `next_node_id?`, `problems[]` при несоответствии `resumeSchema` |
| `run_cancel` | `run_id`, `reason` | `status='cancelled'` |

- **«Что ждёт меня»** — `run_list({status:'suspended', assignee:'me'})`: инбокса как сущности нет, есть сохранённый фильтр; просроченные — `overdue: true`, сортировка по `deadline_at`.
- **Форма ввода.** `run_get_node` добавляет `form_schema` (JSON Schema, развёрнутая из `form: TypeRef`
  по файлу типа) и `suspend_data`; рендер — RJSF, как в 15 §10. `form_kind` как отдельного справочника
  нет: kind — это id типа. `payload` проверяется против `resumeSchema` **шага**, а не воркфлоу (03 §2.5);
  ошибка — конверт с `problems[]`, прогон остаётся приостановленным.
- **Таймаут — не операция.** Объявлен в узле, исполняется планировщиком: `sendAfter` на `suspend`,
  сверяющий cron добирает потерянные (17 §6); по срабатыванию применяется `on_timeout`
  (`fail | default(value) | escalate(role)`), прогон меняет статус сам.
- **Идемпотентность.** Повтор с тем же `idempotency_key` возвращает результат первого ответа,
  с другим — `ALREADY_RESUMED` и текущий статус.

**Отменяется:** `human_task_list/get/answer/reassign/escalate/cancel`. Таблица `app.human_tasks` (17 §6) остаётся как индекс
приостановленных прогонов для сверки и дедлайнов, но перестаёт быть отдельной доменной сущностью:
`resolved_by`/`resolution` переезжают в трассу прогона, `form_kind` — это `TypeRef` из файла.

## 4. Явный коммит

Запись в файл — черновик. Коммит — момент, когда определение становится тем, к чему можно пинить
прогон и релиз. Промт здесь не исключение, а типовой случай: он лежит файлом, как и всё остальное.

```
flow_commit({ paths: string[], message, intent? })
  -> { commit, files: [{path, sha256, status}], compile: {ok, problems[]} }
```

| Правило | Как выражено |
|---|---|
| Коммит явный | автокоммита на `flow_patch` нет; дерево может быть грязным сколько угодно |
| Что исполняется | `run_start({at: commit \| 'working'})`, по умолчанию `'working'` в dev и `commit` в проде; запись прогона хранит `commit` + `content_hash`, изменение файла на живой прогон не влияет |
| Релиз | `version_propose({commit, evidence[]})`; грязное дерево → `DIRTY_WORKTREE` |
| Автор | `actor_kind` + `actor_id` — трейлеры коммита, не отдельная таблица ([history.md](history.md)) |
| Невалидный коммит | разрешён (черновик в ветке), `compile.ok=false` в ответе, гейт релиза его не пропустит |

## 5. Операции истории поверх git

```
flow_history({ path?, spec_id?, since?, until?, actor_kind?, limit=20, cursor?, view='summary' })
  -> { items: [{commit, parent, actor_kind, actor_id, at, message, intent,
                files: [{path, status}], summary: {added, removed, changed}}], next_cursor }

flow_diff({ from: commit|'working', to: commit|'working', path?, scope='semantic'|'text', view })
  -> { deltas: [{path, node_id?, kind, before, after}], layout_changed, problems[] }

flow_revert({ to: commit, paths?, message, base: {commit}, dry_run=false })
  -> { commit, reverted: [{commit, files[]}], compile: {ok, problems[], candidates[]}, conflicts[] }
```

- `flow_diff` по умолчанию **семантический**: сравниваются нормализованные IR (04 §3), а не строки; `scope: 'text'` даёт обычный git-дифф для промтов и markdown.
- `flow_revert` создаёт новый коммит (`git revert`, не `reset`) и прогоняет валидатор: ломающий
  компиляцию откат отдаёт `compile.ok=false`. Права из
  [frontend/edit-contract.md](../frontend/edit-contract.md) сохраняются: агент откатывает свои коммиты
  (по трейлеру `actor_id`), чужие — `FORBIDDEN` + `next[] = studio_open(elicit)`.
- `spec_ops_read` и `version_diff` отменяются: первый — это `flow_history`, второй — `flow_diff`.

## Крайние случаи

| Ситуация | Поведение системы | Что видит человек |
|---|---|---|
| Файл изменён мимо MCP между чтением и `flow_patch` | `STALE_FILE`: текущий `sha256`, дельта, `candidates[]` «перечитать» / «применить поверх» | «Файл изменился, пока Claude работал» |
| Правка руками ломает инвариант | файл остаётся на диске, `flow_check` отдаёт `problems[]`, индекс метит спеку `invalid` | красная плашка, список ошибок, «откатить файл» |
| Одновременная правка узла человеком и агентом | сравнение хешей: непересекающиеся файлы проходят оба, пересечение — отказ агенту | «Claude не смог применить правку: вы редактируете тот же узел» |
| `run_resume` на прогоне, упавшем по таймауту | `RUN_TIMED_OUT` + фактический исход `on_timeout` | «Срок истёк 2 часа назад, сработало `escalate(reviewer)`» |
| `payload` не проходит `resumeSchema` | прогон остаётся `suspended`, `problems[]` с путями полей | подсветка полей в форме, ничего не отправлено |
| Релиз при грязном дереве | `DIRTY_WORKTREE` со списком незакоммиченных путей | «Сначала зафиксируйте 3 изменения» + дифф |
| Индекс отстал от файлов | ответы каталога и поиска несут `stale: {since, reason}` | «Индекс перестраивается», данные показываются с возрастом |
| Файл изменили в середине прогона | прогон идёт на запиненном `content_hash`, новый файл подхватит следующий запуск | «Определение изменилось после старта» на карточке прогона |

## Открытые вопросы

1. **Построчная сверка с исходными 56.** Категорийный пересчёт даёт 40; список надо восстановить построчно, иначе расхождение всплывёт на реализации.
2. **Продление дедлайна.** «Дай мне ещё сутки» операции не имеет: `run_extend_deadline` или правка определения?
3. **Нужен ли `flow_patch`, если агент — Claude Code.** Возможно, доменный уровень стоит свести к `flow_check` + `flow_commit`, а правку отдать нативным тулам. Мера — сколько кросс-файловых правок агент делает за сессию на прототипе.
4. **Ребейз `ops[]` на изменившиеся файлы.** Таблицы коммутативности операций нет (ADR-0009); без неё `STALE_FILE` всегда честный отказ, а не авто-ребейз.
5. **82 тула и лимит 25.** Фазы §5.3 собирались под 57 и требуют пересборки целиком.

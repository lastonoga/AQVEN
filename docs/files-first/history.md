# История, дифф и откат на git

> Решает: как файловый источник истины версионируется, кто автор правки, как откатить и чем прогон привязан к версии определения навсегда.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Когда коммит | **На эпизод правки**: ход агента = коммит; правка человека = коммит по затиханию 30 с или смене файла. Плюс явный коммит и коммит на `version_propose` | Коммит на запись даёт 2000 коммитов в неделю и мёртвый `log`; коммит на релиз лишает undo и «вернуть к вчера» |
| Кто в истории автор | `author` = инициатор (человек или агент-identity), `committer` = `aqven-engine`, `Aqven-Actor:` трейлером | `git log --author` и `--grep` работают без нашего UI; префикс в subject не машиночитаемее трейлера |
| Ветка агента | По умолчанию `main`; ветка `aqven/agent/<session>` включается правилом радиуса (см. §3) | Один пользователь: ветка ради ветки — ритуал. Ветка нужна там, где патч реально смотрят |
| Слияние | Только fast-forward или squash. Трёхстороннего слияния графа нет | ADR-0016: строковый merge даёт валидный текст с мёртвой семантикой |
| Разрешение расхождения | Переигровка операций эпизода на новом base через op-log, не `git rebase` | Отклонение невалидного результата возможно только в компиляторе |
| Откат | Всегда движение вперёд: `revert` / восстановительный коммит. Никогда `reset --hard`, никогда force-push | История прогонов ссылается на коммиты; переписать историю = осиротить ссылки |
| Чем прогон пинит версию | `release_hash` авторитетен, снимок скомпилированного плана в базе, `source_commit` — провенанс | Airflow пинит свой `created_dag_version_id`, Argo вкапывает `storedWorkflowSpec`; git sha меняется от косметики и умирает при rewrite |
| Библиотека | `isomorphic-git@1.42.2` за портом `GitPort`, CLI через `simple-git@3.36.0` вторым эшелоном | Нужны commit, log по пути, checkout дерева, CAS ref — всё есть; rebase и merge нам не нужны по конструкции |
| Дифф | Семантический по канонизированному IR — основной; текстовый YAML — вкладка «исходник» | `spec_hash` равен ⇒ определение не менялось, что бы ни показал текст |

## 1. Когда возникает коммит

**Эпизод** — непрерывная последовательность валидных записей одного актора: ход агента целиком либо
серия правок человека, закрытая затиханием 30 с, сменой воркфлоу, запуском прогона или уходом со
страницы. Незакоммиченные записи уже прошли валидатор — коммит только фиксирует границу.

| Вариант | Коммитов за неделю (агент ~200 правок/день, человек ~100) | Как выглядит история |
|---|---|---|
| На каждую валидную запись | 1500–2100 | `log` нечитаем, `blame` показывает промежуточные состояния, loose-объекты растут между `gc`, contention на `packed-refs.lock`. Ровно грабли Flux image-automation #482 |
| **На эпизод (взято)** | 150–250 | Лента читается: «агент: расширил switch по каналу оплаты», «человек: поправил промт». Один эпизод = одна отменяемая единица |
| На сессию правки | 20–40 | Коммит склеивает несвязанные изменения; откат одной правки агента требует ручного patch-выделения |
| На релиз | 3–10 | Git перестаёт быть историей работы: между релизами неделя правок без следов, «вернуть к вчера» невозможен |

Порог защиты: больше 40 эпизодов на воркфлоу за час — backpressure, движок просит человека
подтвердить продолжение. Это же граница цикла самоправки агента.

## 2. Автор коммита

`author` — кто произвёл изменение, `committer` — кто его записал: исходная семантика git про нашу
пару «агент написал — движок применил».

| Поле | Правка человека | Правка агента |
|---|---|---|
| `author` | `Кирилл <lastonoga@gmail.com>` из профиля | `Claude Code <agent+claude-opus-5@aqven.local>` |
| `committer` | `aqven-engine <engine@aqven.local>` | `aqven-engine <engine@aqven.local>` |
| Трейлер актора | `Aqven-Actor: human` | `Aqven-Actor: agent` |
| Ответственный | он же author | `Aqven-On-Behalf-Of: Кирилл <lastonoga@gmail.com>` |

```
flow(checkout): добавить ветку SEPA в switch по каналу оплаты

Aqven-Actor: agent
Aqven-Agent: claude-code/opus-5
Aqven-Session: 01J9K3M2T7QН
Aqven-On-Behalf-Of: Кирилл <lastonoga@gmail.com>
Aqven-Prompt: добавь оплату SEPA
Aqven-Spec-Hash: 9f2c4ab1e0d7
Aqven-Nodes: +2 ~1 -0
```

Правка человека — тот же формат без `Aqven-Agent`, `Aqven-Prompt` и `Aqven-On-Behalf-Of`, с `Aqven-Actor: human`.

Запросы, которые это даёт бесплатно: `git log --grep='Aqven-Actor: agent' -- flows/checkout.yaml`,
`git log --author='Claude Code'`, `git log --grep='Aqven-Session: 01J9K3M2T7QН'` — весь патч одной
сессии агента. Subject — Conventional-подобный `<область>(<flowId>): <что>`, область берётся из
раскладки (`flow`, `type`, `prompt`, `model`, `tool`), не из угадывания по тексту.

## 3. Ветки для агента

Оба режима существуют, переключает не человек, а **правило радиуса влияния** — оно считается
компилятором до записи, по тем же `type_usages` и `type_impact`.

| Условие патча | Куда пишет агент | Как завершается |
|---|---|---|
| Один воркфлоу, узлы и параметры, публичные контракты не тронуты | `main` напрямую | Коммит эпизода сразу в ленте, откат — `revert` одного коммита |
| Затронуто >1 воркфлоу, или изменён общий тип/порт, или удалены узлы, или тронуты пины моделей и промтов | `aqven/agent/<session>` | Экран ревью с семантическим диффом → **ff-only merge** или squash-коммит; отказ = удаление ветки, следов в `main` нет |

Почему не «всегда ветка»: пользователь один, ревью лёгкое, ветка добавляет два клика к мелкой правке
и отдаляет момент, когда правку видно на канвасе. Почему не «всегда main»: удаление узлов и смена
общего типа — класс изменений, где `revert` постфактум дороже, чем взгляд до применения.

Если `main` ушёл вперёд, пока жила ветка, `git rebase` не применяется: операции эпизода из op-log
переигрываются на новом base через компилятор, каждая валидируется заново. Неприменимая операция
останавливает переигровку и показывается как конфликт с именем узла, а не как маркеры `<<<<<<<`
в YAML. Это та самая точка отклонения, которой у git нет (ADR-0016).

## 4. Откат: три уровня

| Уровень | Механизм | Что видит человек |
|---|---|---|
| **Undo последней правки** | Эпизод ещё открыт: обратная операция из op-log применяется к рабочему дереву, коммита не было. Эпизод закрыт: `revert` его коммита | Ctrl+Z, узел возвращается на канвасе мгновенно; в ленте либо ничего (эпизод не закрыт), либо строка «отменено» |
| **Откат патча агента** | Ветка — удаление ветки. `main` — `revert --no-commit` по диапазону коммитов сессии, один результирующий коммит с `Aqven-Revert-Of: <sha>…` и `Aqven-Actor: human` | Кнопка «Отменить правку агента» на карточке сессии в ленте, предпросмотр семантического диффа до применения |
| **Проект на вчера** | Дерево коммита на момент T читается в индекс и пишется **новым** коммитом поверх `main` с `Aqven-Restore-From: <sha>`, `Aqven-Restore-At: <ts>` | Слайдер времени в ленте, дифф «сейчас → 13.09 18:00», подтверждение. История не переписывается, вернуться обратно можно тем же жестом |

- **Восстановление проходит через валидатор.** Дерево из прошлого компилируется перед записью; если
  текущее состояние ушло несовместимо вперёд, откат отклоняется со списком конфликтующих узлов.
- **`release_hash` пересобирается, а не берётся из прошлого**: пины промтов, моделей и компонентов
  могут разрешиться иначе. Дифф пинов показывается перед подтверждением — это и есть цена, о которой
  предупреждал ADR-0016 («`git revert` не бесплатен»).
- **Ни `reset --hard`, ни force-push**: прогоны ссылаются на коммиты, осиротевшая ссылка недопустима.
- Раскладка канваса не откатывается: LWW-канал вне git (см. [31](../31-canvas-editing.md)).

## 5. Связь прогона с версией определения

Прогон **не читает файл** ни при старте, ни в процессе: компилятор материализует план, кладёт снимок
в базу, прогон исполняет снимок. Это модель Argo (`status.storedWorkflowSpec`) и Airflow 3
(`DagRun.created_dag_version_id` — собственный id версии, не git sha).

| Поле в `app.runs` | Значение | Роль |
|---|---|---|
| `release_hash` | Как было: `hash(spec_hash, prompt_pins, model_profile_pins, component_lock, env_overlay_hash)` | **Авторитетная идентичность исполненного.** По ней сравнивают прогоны и воспроизводят |
| `spec_version_id` | Строка индекса со снимком IR | Физическое тело плана, читается вечно, не зависит от репозитория |
| `source_commit` | sha коммита эпизода, nullable | Провенанс: blame, «покажи, что за правка это была», дифф между двумя прогонами в git |
| `source_ref` | `refs/heads/main` или `aqven/agent/<session>` | Откуда пришло: прогон с ветки агента видно сразу |
| `source_dirty` | `true`, если эпизод ещё не закоммичен | Честный признак «запуск из-под руки»; воспроизводимость не страдает — снимок уже в базе |

Почему не «commit sha вместо хеша содержимого»: sha меняется от косметики (переезд файла, правка
соседнего воркфлоу в том же коммите) — два идентичных прогона выглядели бы разными; sha исчезает при
пересоздании репозитория, а прогоны живут дольше репозитория. Обратное направление тоже неверно —
хеша мало для вопроса «кто и зачем это сделал», поэтому пишем оба: хеш для равенства, sha для истории.

## 6. Библиотека

`isomorphic-git@1.42.2` (MIT, 2026-09-11) — основной путь записи и чтения, за интерфейсом `GitPort`.
`simple-git@3.36.0` (MIT, 2026-04-12) — та же реализация порта для редких тяжёлых операций.

| Нужно нам | isomorphic-git | Комментарий |
|---|---|---|
| commit без рабочей копии | `writeBlob` / `writeTree` / `writeCommit` / `writeRef` | Пишем в bare, worktree не держим |
| CAS на ref | `writeRef` с проверкой прежнего значения | Тот же примитив, что `UPDATE specs SET rev=rev+1 WHERE rev=$expected` |
| log по пути | `log({ filepath })` | Лента ревизий одного воркфлоу |
| checkout версии | `readBlob` / `readTree` по oid | Откат уровня «на вчера» и предпросмотр |
| ветки, ff-merge | `branch`, `fastForward` | Полный `merge` с конфликтами не реализован — **и не нужен**: у нас ff-only |
| rebase | **нет** | Не нужен: переигровка эпизода через op-log (§3) |
| текстовый дифф | нет | `diff@9.0.0` (MIT) поверх двух blob'ов |
| `gc`, `repack`, `log --follow` | нет / медленно | Через `simple-git`, вне горячего пути |

Обязательное условие производительности: единый объект `cache` между вызовами (issue #291) — иначе
packfile переразбирается на каждую команду. `nodegit` не берём: нативная сборка под каждую ABI при
нулевой выгоде. `dugite@3.2.3` — запасной вариант, если системного git в образе не окажется.

## 7. Дифф для человека

| Поверхность | Что показываем | Почему так |
|---|---|---|
| Лента ревизий | Семантический дифф по канонизированному IR: узлы `+2 ~1 −0`, рёбра, типы портов, изменения пинов промтов и профилей моделей | Текстовый дифф YAML шумит переездами якорей и порядком ключей; читать «что стало с воркфлоу» по нему нельзя |
| Канвас | Бейджи на узлах «новый / изменённый / удалённый» (приём n8n) + панель «что изменилось» по клику на узел | Правку смотрят там, где её применяют |
| Вкладка «исходник» | Обычный текстовый дифф файла | Нужен для PR на GitHub, для правок вне определения (комментарии, форматирование) и как последняя инстанция доверия |

Правило приоритета: совпал `spec_hash` — определение не менялось, лента пишет «только форматирование».
Обратный случай (хеш изменился, текст нет) означает смену пинов промта или профиля модели; такой
коммит помечается отдельно, потому что на канвасе он невидим.

## Крайние случаи

| Ситуация | Поведение системы | Что видит человек |
|---|---|---|
| Процесс упал с открытым эпизодом | При старте незакоммиченное рабочее дерево фиксируется коммитом с `Aqven-Recovered: true` | Строка в ленте «восстановлено после перезапуска» |
| Человек правит файл в редакторе, пока агент пишет тот же воркфлоу | CAS на ref не сходится, запись агента отклонена, эпизод переигрывается на новом base | Уведомление «правка агента переигрывается поверх вашей» |
| Определение откатили во время прогона | Прогон исполняет снимок, откат его не касается | Ничего; в карточке прогона отметка «определение изменилось после старта» |
| Откат «на вчера» ломает сегодняшние зависимости | Валидатор отклоняет восстановление целиком | Список конфликтующих узлов, кнопка «откатить только этот воркфлоу» |
| Force-push в `main` извне | Расхождение с последним известным sha, автоподстройки нет | Экран дрейфа, выбор «принять извне» / «восстановить наше» |
| Цикл самоправки агента, 40+ эпизодов за час | Backpressure, новые эпизоды не открываются | «Агент внёс 40 правок за час, продолжить?» |
| Репозиторий повреждён | Определения восстанавливаются из снимков индекса, история теряется | «Восстановлено текущее состояние, история недоступна» |
| Правка вне определения (README, .gitignore) | Коммитится обычным путём, семантического диффа нет | Только текстовый дифф |

## Открытые вопросы

- `reftable` (Git ≥ 2.45) снимает contention на рефах, но `isomorphic-git` его не читает — проверить на стенде до введения ветки на воркфлоу.
- Сворачивать ли эпизоды старше 90 дней: экономит обход истории, но рвёт `source_commit` у старых прогонов.
- Подписывать ли коммиты агента SSH-ключом движка, и что делать с `source_commit` при переносе проекта в другой репозиторий (пара `(repo_id, sha)` или провенанс потерян).
- Кто автор автоматического коммита без человека (плановый прогон, миграция): `aqven-system` или `aqven-engine`.

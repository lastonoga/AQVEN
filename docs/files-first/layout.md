# Файловая раскладка проекта

> Решает: что именно лежит на диске, с какой гранулярностью, в каком формате и как файлы ссылаются друг на друга.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Гранулярность воркфлоу | каталог `flows/<flow_id>/` + **файл на узел** | узел несёт промт и схему типа; параллельные правки разных узлов git сливает сам, без драйвера. Прецедент — Windmill, у которого инлайн-скрипты вынуждают то же. Kestra-вариант (один YAML) закрыт: у них флоу — 50 строк декларации без прозы |
| Два режима (маленький флоу — одним файлом) | нет, всегда каталог | два режима = два пути в компиляторе, два формата диффа и вопрос «когда мигрировать». Каталог из двух файлов не дороже одного |
| Промты | всегда отдельный файл, `.md` с Liquid | многострочный текст в YAML-строке нечитаем в диффе, не проверяется спеллчекером и ломает канонический YAML (`blockQuote: false`, §6.2 [04](../04-ir-schema.md)) |
| Идентичность | **путь = идентификатор**, поля `id` внутри файлов нет | одна истина. ФС физически запрещает дубликат ключа, грепается, `git mv` даёт rename-детект. Совпадает с §4.1 IR: тело узла не содержит своего `id` — идентичность это ключ записи, а ключ это имя файла |
| Версии в именах файлов | нет: `egypt_rules.md`, не `egypt_rules@3.md` | рабочее дерево = черновик, версии даёт git и лок релиза. `@version` в именах остаётся только в экспортном бандле ([18](../18-export-and-conformance.md) §2), где снимки неизменяемы |
| Ссылки внутри проекта | относительный путь | грепается, чинится редактором, битая ссылка видна `ls`. Логическое имя нужно только там, где цель вне проекта |
| Ссылки на внешнее (библиотека, реестр) | логический ключ + пин в `wf.lock.yaml` | пин обязан быть хешем содержимого, а не путём: путь не говорит «то же ли это» |
| Раскладка канваса | **не файл** | LWW-канал с своей осью `layout_rev` ([31](../31-canvas-editing.md)); драг мышью даёт десятки записей в минуту — в git это шум и конфликты |
| Формат структуры | YAML, канонический по §6.2 [04](../04-ir-schema.md) | уже решено; запись форматирует канонизатор, руками формат не ставится |

## 1. Дерево проекта

```
project/

  tools/
    crm_search.yaml
  context/

  datasets/

  .wf/

```

| Путь | Что внутри | Соответствие IR |
|---|---|---|
| `project.yaml` | `project_id`, `ir_version`, политики по умолчанию, журнал переименований | корень проекта |
| `flows/<id>/flow.yaml` | всё, кроме `nodes`: `input`, `output`, `returns`, `context`, `budget`, `order`, `uses`, `policies`, `defaults` | корень документа IR минус `nodes`, минус `ui`, минус `meta` |
| `flows/<id>/nodes/<node_id>.yaml` | тело узла `Node` без поля `id` | одна запись `nodes` |
| `flows/<id>/nodes/<node_id>/<inner>.yaml` | тела вложенных подграфов `map.do`, `loop.body`, ветки | своё пространство имён §4.1; вложенность каталога = вложенность namespace |
| `<node_id>.prompt.md` | Liquid-шаблон узла, все роли в одном файле через `{% message %}` | `prompt` узла |
| `components/<name>/component.yaml` | контракт входа/выхода, `order`, `uses` | `contract` + корень компонента |
| `wf.lock.yaml` | разрешённые пины: ключ → путь + `content_hash` + версия | материализация `uses` |
| `.wf/cache/` | развёрнутый вид, план компиляции, AST промтов — **в `.gitignore`** | производное (§5 IR), из файлов восстановимо |

`order` живёт в `flow.yaml`, а не в именах файлов: числовые префиксы (`01_fetch.yaml`) сделали бы перестановку узлов переименованием и убили lineage. Порядок узлов — `COSMETIC`-правка одной строки, перестановка файлов её не стоит.

## 2. Промты: связь узла и шаблона

Две формы ссылки, как импорт в коде: `prompt: ./write_pitch.prompt.md` для соседнего шаблона узла, `prompt: pitch_system` для общего из `prompts/`.

| Правило | Формулировка | Кто проверяет |
|---|---|---|
| Соседство | локальный шаблон узла обязан лежать рядом и называться `<node_id>.prompt.md` | валидатор записи: другое имя — `E_PROMPT_MISPLACED` |
| Сиротство | `.prompt.md` без одноимённого узла — ошибка, не предупреждение | валидатор: иначе мусор копится вечно |
| Переименование узла | `git mv` обоих файлов одной операцией `flow_rename` | атомарная операция компилятора, не две ручные |
| Общий шаблон | `prompts/<key>.md`, ссылка ключом, разрешение через `wf.lock.yaml` | лок хранит `content_hash`, расхождение — `E_LOCK_STALE` |
| Фрагменты | `{% include "fragments/egypt_rules" %}`, **без `@v` в тексте** | версия фрагмента — пин в локе и в `release_hash`, не суффикс в прозе |

Почему версия фрагмента не пишется в текст: `include fragment@v3` означает, что правка фрагмента требует править прозу всех шаблонов, которые его включают. Это ровно тот дифф, в котором ревьюер перестаёт видеть содержательные изменения. Вместо этого `wf.lock.yaml` держит `prompts/fragments/egypt_rules: sha256-...`, релиз пинит хеш (§4.3 IR, `release_hash`), а обратный индекс «какие шаблоны перекомпилировать» остаётся запросом к базе (`prompt_fragment_uses`, [16](../16-data-model.md) §2.5) — теперь база строит его, обходя файлы при индексации, а не владея ими.

## 3. Формат

| Файл | Формат | Почему |
|---|---|---|
| `flow.yaml`, `nodes/*.yaml`, `types/**`, `agents/*`, `models/*`, `tools/*`, `context/*`, `project.yaml`, `environments/*` | YAML | правит человек и агент; канонический вывод §6.2 [04](../04-ir-schema.md), якоря, комментарии и блочные скаляры запрещены линтером |
| `*.prompt.md`, `prompts/**/*.md` | Markdown + Liquid, plain text | построчный дифф прозы, спеллчек, ревью без экранирования |
| `wf.lock.yaml` | YAML | машина пишет, **человек читает в дифф-ревью** — это его единственное назначение |
| `datasets/*.yaml` | YAML | метаданные: сплиты, ссылка на тип, политика PII |
| `.wf/cache/*.json` | JSON | машинный артефакт, никто не ревьюит, скорость парсинга |
| экспортный `manifest.json`, `schema/`, `conformance/` | JSON | хеши считаются по JSON, [18](../18-export-and-conformance.md) §2 |
| `.gitattributes` | `* text eol=lf`, `*.md diff` | CRLF на Windows ломает `content_hash` молча |

## 4. Идентичность и переименование

Идентификатор — путь. Поля `id` внутри файла нет ни у узла, ни у типа, ни у промта: дубликат поля означал бы состояние «ключ ≠ id», которое кто-то обязан чинить. ФС такого состояния не допускает.

Цена решения одна: переименование меняет идентификатор, а прогоны и кассеты ссылаются на старый. Закрывается append-only журналом `renames: [{kind, from, to, at}]` в `project.yaml`.

| Следствие | Поведение |
|---|---|
| Lineage прогона | резолвер идёт по журналу: старый путь → текущий; дальше §4.1 IR («удалённый id не переиспользуется») держится |
| Переиспользование имени после удаления | запрещено: журнал видит, что путь занят историей |
| Регистр в именах | только `^[a-z][a-z0-9_]{0,62}$` (§1.4 IR) — на APFS и NTFS `Score.yaml` и `score.yaml` это один файл, и без правила это тихая потеря узла |
| Символические ссылки, вложенность глубже namespace, пробелы | запрещены валидатором записи |

## 5. Ссылки между файлами

| Цель ссылки | Форма | Пример |
|---|---|---|
| Промт узла | относительный путь | `./write_pitch.prompt.md` |
| Тип, enum, view | ключ реестра проекта | `type: hotel`, резолв в `types/entities/hotel.yaml` |
| Компонент проекта | ключ | `use: enrich_lead` → `components/enrich_lead/component.yaml` |
| Компонент библиотеки, тул, профиль модели | ключ + пин в `wf.lock.yaml` | `uses.enrich: {key: lib/enrich_lead, version: 4, hash: sha256-...}` |
| Фрагмент промта | ключ Liquid-include | `{% include "fragments/egypt_rules" %}` |

Битая ссылка ловится в трёх точках, и все три обязательны:

| Точка | Что ловит | Код ошибки |
|---|---|---|
| Запись через компилятор (`flow_patch`, запись файла агентом) | ссылку на несуществующий путь или ключ — правка отклоняется до записи на диск | `E_REF_MISSING` |
| `wf check` в pre-commit и CI | ручную правку в редакторе в обход компилятора, оборванный `git mv`, удалённый файл-цель | `E_REF_MISSING`, `E_ORPHAN_FILE` |
| Индексация в базу | расхождение лока и содержимого, циклический include | `E_LOCK_STALE`, `E_INCLUDE_CYCLE` |

Обратные вопросы («где используется тип `hotel`», «что перекомпилировать после правки фрагмента») отвечает база как индекс: обход дерева на каждый запрос не масштабируется, а индекс перестраивается инкрементально по событиям ФС и git-хукам.

## 6. Что НЕ файл

| Сущность | Где | Почему |
|---|---|---|
| Прогоны, `run_nodes`, трассы, чекпоинты | база | миллионы строк в день, партиционированы, ретеншн; в дереве это не дифф, а свалка |
| Кассеты, блобы ответов | база и объектное хранилище | адресуются хешем запроса, переиспользуются кейсами; в git это бинарный балласт |
| Строки датасетов, результаты evals и калибровок | база, JSONL в экспорте | данные, а не определения; правятся разметкой, а не редактором |
| Раскладка канваса, свёрнутые группы | база, LWW, ось `layout_rev` | не часть определения (§4.4 IR), десятки записей в минуту |
| `op_log`, черновиковые `rev` | база | точка отказа валидатора; в файлах нет места, где правку можно отклонить (ADR-0016) |
| Секреты, ключи провайдеров | секрет-хранилище, в файлах только имя ссылки | `environments/*.yaml` пинит `api_key: ref:vault/openai` |
| Каталог моделей, результаты проб возможностей | база | снимок внешнего мира, обновляется без участия человека |

## Крайние случаи

| Ситуация | Поведение системы | Что видит человек |
|---|---|---|
| Файл узла есть, в `order` его нет | запись отклонена | `E_NODE_UNORDERED` с путём файла и предложением добавить в конец `order` |
| Узел удалён руками, на него есть привязка | `wf check` падает до коммита | `E_REF_MISSING`, список узлов-потребителей |
| Руками правленый YAML: якорь, комментарий, блочный скаляр | импорт линтера отклоняет по AST | «формат ставит канонизатор», кнопка `wf fmt` |
| Git-merge оставил маркеры конфликта в `nodes/*.yaml` | парсер падает на первом файле, дальше не идёт | `E_MERGE_MARKERS` с путём и строкой |
| Оба параллельно поправили разные узлы | git сливает, валидатор проверяет результат целиком | обычный merge без вмешательства |
| Оба поправили один узел | конфликт git по строкам, слияние не изображается | конфликт в редакторе, `wf check` перед коммитом |
| `git mv` узла без правки привязок | коммит проходит, `wf check` в CI падает | `E_REF_MISSING`; починка — `flow_rename`, а не ручной `mv` |
| `Score.yaml` рядом со `score.yaml` | невозможно: правило имён `[a-z0-9_]` | `E_BAD_NAME` при записи |
| Промт-файл есть, узла нет | сирота — ошибка, не предупреждение | `E_ORPHAN_FILE` |
| Лок разошёлся с содержимым фрагмента | компиляция и релиз отказывают | `E_LOCK_STALE`, команда `wf lock` |

## Открытые вопросы

1. Один репозиторий на проект или монорепо на тенанта — от этого зависит, где живёт общая библиотека компонентов и как её пинить: путём или пакетом.
2. Зеркалятся ли опубликованные версии в файлы (`flows/<id>/.versions/`) или существуют только в базе и в экспортном бандле.
3. Порог болезненности: флоу на 200 узлов — это 200 файлов; нужен ли генерируемый обзорный файл и не станет ли он третьей копией истины.
4. Инкрементальная индексация: watcher ФС, git-хук или обход по запросу — и что делать при `git checkout` ветки с сотней изменений.
5. Формат `wf.lock.yaml`: пины на уровне проекта или на уровне воркфлоу (второе даёт независимые обновления, первое — один дифф на ревью).

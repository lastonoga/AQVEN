# Конвенции документации (обязательны для всех авторов)

## Язык и стиль
- Текст — русский. Идентификаторы, имена пакетов, коды правил, поля схем — английские.
- Пишем для инженера, который будет это реализовывать, и для Claude, который будет по этому кодить.
- Плотно. Таблицы вместо абзацев там, где это таблица. Никакой воды, никаких «важно отметить, что».
- Не пересказывай спеку — спека лежит рядом. Документ отвечает на «как именно мы это делаем»:
  конкретные библиотеки, версии, сигнатуры, схемы, DDL, алгоритмы, пороги.

## Правила заказчика, которые действуют и на примеры кода
1. Не изобретаем велосипед: есть живая библиотека — берём её. Своё пишем только там, где
   в исследовании явно сказано «нет готового» (ядро доверия, IR, компилятор, исполнители узлов).
2. **Никаких комментариев в коде.** Примеры кода идут без `//` и `/* */`. Всё объяснение — в тексте
   до или после сниппета. Имена должны объяснять сами себя.
3. Плоский код: ранние возвраты, guard clauses, таблицы/словари вместо вложенных if/else и switch-лестниц.
4. SOLID и явные паттерны, названные по имени (Strategy, Adapter, Port/Adapter, Registry, Visitor,
   Builder, Chain of Responsibility). Если паттерн применён — называем его в тексте.
5. TypeScript строгий: без `any`, без `as` кроме границ ввода-вывода, branded types для идентификаторов.

## Структура каждого документа
```
# NN. Название

> Статус: draft | ready
> Зависит от: [ссылки на другие документы]
> Источники: [research/<файл>.md, разделы спеки]

## Зачем этот слой            (2-5 предложений: какую проблему из §8 он закрывает)
## Решения                     (таблица: решение | что берём | версия | лицензия | почему)
## <содержательные разделы>
## Открытые вопросы            (нумерованный список, каждый с «что сделать, чтобы закрыть»)
```

## Факты
- Любое утверждение о библиотеке — с точной версией и лицензией.
- Источник факта — заметки в `scratchpad/research/*.md` и исходная спека. Чего там нет — не пишем.
  Если знание нужно, а его нет, это строка в «Открытые вопросы», а не выдумка.
- Маркеры `UNVERIFIED:` из заметок НЕ переносим в документ как факт: либо проверяем, либо
  формулируем как открытый вопрос с пометкой, что требуется проверка.
- Заметки исследования могут противоречить друг другу. Заметил противоречие — вынеси его
  в «Открытые вопросы» с обеими позициями, не заметай.

# Кластер: Слой моков

> Экраны: обслуживает все 18 экранов §5 [15-studio-frontend.md](../15-studio-frontend.md); свои экраны — `/dev/scenarios` (панель мира), `/dev/gallery` (галерея состояний §12.4), `/dev/tape` (плеер SSE-ленты)
> Приоритет кластера: **P0** — без него ни один экран прототипа не запускается

## Что проверяем прототипом

1. Контракт `@wf/contracts` пригоден как источник правды **до** бэкенда: UI и мок пишутся против него, расхождение ловится тестом, а не глазами.
2. Zod 4.6.2 совместим с `@hono/zod-openapi@1.6.3` — это непроверенная точка ADR-0007; мок-сервер закрывает её за 200 строк вместо спайка.
3. UI спроектирован под **асинхронный** бэкенд: `flow_compile` 2–4 с, `experiment_run` минуты. Мок с честными задержками убивает дизайн «нажал — получил».
4. Отладчик прогона играбелен на ленте событий: если он не читается на 15 узлах и 120 событиях — проблема не в бэкенде.
5. Конверт §3.1 (`problems[]`, `candidates[]`, `next[]`, `truncated`) реально рендерится: гипотеза «человек видит, что сделал агент и почему» проверяется на моках, а не после ядра.

## 1. Чем мокаем

| Вариант | Версия / лицензия | За | Против | Вердикт |
|---|---|---|---|---|
| MSW | `msw@2.15.0` MIT, обновлён 2026-07-08, peer только `typescript >= 4.8` | перехват на уровне `fetch`/SW: один и тот же мок в браузере, Vitest, Playwright, Storybook; стримы через `ReadableStream` | сам по себе схему не знает — хендлер врёт что угодно | **берём как транспорт** |
| `@stoplight/prism-cli` | 5.16.0 Apache-2.0, `engines.node >= 24.18.0` | генерирует ответы прямо из OpenAPI, валидирует запрос | ответы из `examples`/типов — бессвязны между вызовами; нет состояния (`rev` не растёт, форк прогона не связан с родителем); отдельный процесс; SSE не умеет | нет |
| `openapi-backend@5.20.1` MIT | | роутер + валидация по OpenAPI, состояние своё | дублирует роутинг, которого у нас уже есть свой (Hono) | нет |
| Модуль фикстур за клиентом | — | ноль зависимостей | нет сети → нет задержек, кодов ошибок, обрывов, пагинации; UI спроектируем под идеальный мир | нет |
| **Наш `@wf/mock-server` на `OpenAPIHono` + MSW** | `hono@4.13.7`, `@hono/zod-openapi@1.6.3` | тот же `createRoute`, та же валидация входа, те же `operationId` | пишем сами ~300 строк каркаса | **выбор** |

**Решение.** Мок — не хендлеры, а **реализация тех же роутов на фикстурных адаптерах** (Port/Adapter):
`@wf/mock-server` монтирует схемы `@wf/contracts` в `new OpenAPIHono()` и подставляет `FixtureRepository`
вместо будущего `PgRepository`. Тело мока — `app.fetch(Request): Response`, поэтому он работает всюду:

```ts
export const createMockControlPlane = (world: World) =>
  mountContractRoutes(new OpenAPIHono(), fixtureAdapters(world));

export const handlers = [http.all("/api/v1/*", ({ request }) => mockApp.fetch(request))];
```

Три режима подъёма одного `mockApp`: MSW service worker в браузере; `setupServer(...handlers)` из `msw/node`
в `instrumentation.ts` для серверной оболочки Next; `@hono/node-server@2.1.1` на `:8787` для Playwright.

Если понадобится обычный MSW-хендлер мимо Hono — `openapi-msw@2.0.0` (MIT, peer `msw ^2.10.5`): те же `paths` из `@wf/api-types`, что у `openapi-fetch@0.17.0`.

**Валидация ответа — наша.** `createRoute` валидирует вход; описание ответа в нём — документация.
Оборачиваем хендлер декоратором `respondValidated(Schema, handler)`: мок, врущий мимо схемы, падает
в dev с 500 и кодом `contract_violation` — в этом весь смысл упражнения.

## 2. Где живёт контракт до бэкенда

`@wf/contracts` создаётся **первым пакетом монорепо**, раньше рантайма и раньше БД. Он не импортирует
ничего, кроме `zod@4.6.2` (правило no-restricted-imports из ADR-0007 действует с первого дня).

`packages/contracts/src/`: `envelope.ts` (Envelope, Problem, Candidate, Version §3.1 — один на все 57 операций),
`problem-codes.ts` (`ProblemCode` == `ErrorCode` компилятора), `domain/`, `operations/` (по файлу на группу:
input/output-схемы + `createRoute`). Рядом: `packages/api-types/schema.d.ts` (кодоген, коммитится) и
`packages/mock-server/` (фикстурные адаптеры, удаляется при появлении бэкенда).

Порядок неизменен: схема → `createRoute` → `openapi.json` (`app.doc31()`) → `schema.d.ts` → клиент и мок.
Мок **не имеет** своих типов ответа, только `z.infer` из `@wf/contracts`: намокать поле вне контракта
невозможно — не скомпилируется. CI фазы 0 держит три гейта ADR-0007 без строчки бэкенда (diff
`openapi.json`, diff `schema.d.ts`, снапшот `z.toJSONSchema(input, { io: "input" })` по `operationId`)
плюс наш четвёртый: **каждая фикстура парсится своей выходной схемой** (`describe.each(fixtures)`).

## 3. Фикстуры

JSON-файлы, **коммитятся**, генерируются скриптом, а не на лету: `@faker-js/faker@10.6.0` с фиксированным
`faker.seed()` и `zocker@3.0.0` (MIT, peer `zod ^3.25 || ^4.0.0` — единственный генератор из zod-схем,
совместимый с zod 4; `@anatine/zod-mock@3.14.0` держит peer `zod ^3.21.4` и отпадает) заполняют только
скучные поля, смысловые пишем руками. Раскладка: `fixtures/world/<scenario>.json` (состав мира),
`flows/wf_invoice@43.json`, `runs/<id>/snapshot.json` (ответы `run_get` и `run_get_node`),
`runs/<id>/tape.jsonl` (лента SSE, кадр на строку), `datasets/`, `experiments/`.

| Набор | Что внутри | Крайние случаи, ради которых он существует |
|---|---|---|
| `wf_invoice@43` — эталон | 15 узлов: `llm.structured`, `switch` на 4 ветки, `foreach`, цикл, панель судей, human-задача, компонент | узел с 60-символьным id, кириллица и эмодзи в названии, два узла с одинаковым именем в разных компонентах |
| `run_ok` | 15 узлов зелёных, 118 кадров ленты | кэш-хит на узле (`cached`), узел пропущен веткой `switch` (`skipped`) |
| `run_node_failed` | падение на `validate_totals`, ниже — `skipped` | `refusal` и `truncated` как отдельные исходы вызова (ADR-0005), не как «ошибка» |
| `run_degraded` | фолбэк модели на узле, два ретрая, деградация качества | провенанс показывает **другую** модель, чем эффективная конфигурация; стоимость выросла, статус зелёный |
| `run_loop_3` | цикл 3 итерации, остановка по стагнации | итерация 2 хуже итерации 1; best-of выбирает не последнюю |
| `ds_invoice_200` | 200 строк, сплиты `train/dev/test` | 3 строки-дубликата, одна строка 400 КБ, одна с пустым входом, покрытие `switch` 3 из 4 (дырка видна на экране покрытия) |
| `exp_significant` / `exp_flat` | +8.4 п.п. при n=200 и +0.9 п.п. с перекрывающимися CI | второй набор обязателен: UI не должен рисовать зелёную стрелку на шуме |
| `gate_pass` / `gate_warn` / `gate_block` / `gate_unavailable` | 4 исхода `G-release` (§5 этап 12) | `GATE_UNAVAILABLE` — не ошибка и не отказ: отдельное состояние экрана версий |
| `run_blame_partial` | `verdict: 'partial'` при исчерпании бюджета | экран blame обязан показывать «бюджет кончился», а не пустой список |

Мир (`world/*.json`) — это ссылки на наборы плюс объём: `empty`, `normal` (1 спека, 4 прогона),
`large` (40 спек, 300 прогонов, лента 4000 кадров — проверка виртуализации §12).

## 4. Стриминг прогона на моках

Лента (`tape.jsonl`) — список кадров с **виртуальным** временем; реальные задержки считаются из него,
а не записаны в него. Поэтому одна лента играется мгновенно в тестах и в реальном темпе в демо.

```ts
type TapeFrame = { seq: number; at_ms: number; event: RunEvent };

const playTape = (tape: TapeFrame[], { from, speed }: PlayOptions) =>
  new ReadableStream({ async start(controller) {
    let clock = tape[from]?.at_ms ?? 0;
    for (const frame of tape.slice(from)) {
      if (speed > 0) await delay((frame.at_ms - clock) / speed);
      clock = frame.at_ms;
      controller.enqueue(encodeSse(frame));
    }
    controller.close();
  } });
```

| Требование | Как выполнено |
|---|---|
| Детерминизм | порядок и содержимое — из файла; `speed: 0` даёт мгновенную ленту для Vitest и Playwright |
| «Перемотать» | повтор `POST /v1/runs/:id/stream` с `Last-Event-ID: <seq>` → `from = seq + 1`. Тот же путь, что реальный реконнект §4.3 — прототип отлаживает реконнект бесплатно |
| Пауза, шаг | `/dev/tape`: `speed` 0.25×/1×/8×, кнопка «кадр вперёд», слайдер по `seq` |
| Обрыв | сценарий `sse_drop_at=40`: `controller.error()` на 40-м кадре. UI обязан переподключиться сам |
| Грязный поток | лента содержит один дубль `seq` и одну пару в обратном порядке — идемпотентность по `(executionId, seq)` проверяется, а не декларируется |
| Финал | последним кадром `workflow-result`, затем `invalidateQueries(['run', runId])` на клиенте |

Кадры несут типы `WorkflowStreamEvent` VoltAgent и парсятся на клиенте схемой `RunEvent`; мок
**намеренно** шлёт один кадр с лишним полем и один без `stepIndex` — граница доверия §4.2 не украшение.

## 5. Сценарные переключатели

Состояние мира передаётся **заголовком запроса**, а не глобальной переменной: параллельные
Playwright-воркеры не мешают друг другу, а мок остаётся stateless по сценарию.

```ts
api.use({ onRequest: ({ request }) => { request.headers.set("x-mock-scenario", encodeScenario(readScenario())); return request; } });
```

| Ось | Значения | Что ломает в UI |
|---|---|---|
| `world` | `empty` / `normal` / `large` | пустые состояния и виртуализация |
| `latency` | `instant` / `real` / `slow` (×6) / `hang` (60 с) | скелетоны, отмена, «идёт компиляция» |
| `fault` | `none` / `node_failed` / `degraded` / `conflict_409` / `contract_violation_422` / `rate_limit_429` / `server_500` / `sse_drop` | ветки ошибок, откат оптимистичной правки |
| `scope` | `owner` / `editor` / `viewer` / `expired` | «нет прав» как состояние экрана, а не редирект на 403 |
| `truncation` | `off` / `on` | конверт `truncated` и кнопка «показать полностью» |

Панель `/dev/scenarios` — `Sheet` по `Ctrl+Shift+D`, состояние в zustand + `localStorage`, плюс
`?scenario=` в URL: сценарий отправляется ссылкой. Playwright ставит заголовок через
`page.setExtraHTTPHeaders`, UI не трогая. Панель под `NEXT_PUBLIC_MOCK`, вырезается из прод-бандла.

## 6. Storybook — нет

`storybook@10.6.0` и `@storybook/nextjs-vite@10.6.0` **поддерживают** Next 16 (peer `next: ^14.1 || ^15 || ^16`) —
ОВ-7 в части версий закрыт фактом. И всё равно не берём в фазе 0.

Даёт: галерею состояний §12.4 и изоляцию компонента; `msw-storybook-addon@3.0.0` (peer `msw>=2`,
`storybook>=9`) переиспользует наши хендлеры. Платим: второй сборкой (Vite-билдер рядом с Turbopack),
второй конфигурацией Tailwind v4, третьей точкой инициализации моков — и всё равно не покрываем RSC-экраны.

**Решение:** `/dev/gallery` внутри приложения — все состояния узла
(`idle/running/ok/failed/skipped/cached/retrying/needs-approval`), инспектора и водопада на одной фикстуре,
ноль зависимостей, тот же роутер и токены. Скриншот — Playwright по одному узлу (§12.3). Возвращаемся,
когда у реестра `@wf` (§9) появится второй потребитель или придёт дизайнер.

## 7. Переход на реальный бэкенд

Меняется **одна строка окружения**. Ни один экран, ни один запрос, ни один тип не трогается.

| Файл | Фаза 0 | С бэкендом |
|---|---|---|
| `apps/studio/.env` | `NEXT_PUBLIC_MOCK=1`, `CONTROL_PLANE_URL=http://localhost:8787` | `NEXT_PUBLIC_MOCK=0`, реальный URL |
| `lib/mock/boot.ts` | единственное место с `if (!mockEnabled) return;` → старт worker/server | ранний возврат, дерево вырезается бандлером |
| `lib/api/client.ts` | `createClient<paths>({ baseUrl: "/api" })` + dev-middleware `x-mock-scenario` | тот же клиент, middleware не зарегистрирован |
| `packages/mock-server` | фикстурные адаптеры портов | удаляется; порты реализует реальный репозиторий |

Переживает переход и становится приёмкой бэкенда: `@wf/contracts`, `openapi.json`, `schema.d.ts`, фикстуры
и тест «фикстура парсится схемой ответа». Расходится обычно не форма, а **семантика** (мок дал `rev+1`,
сервер — конфликт), поэтому каждый сценарий §5 получает парный e2e-тест, который потом гоняется тем же
кодом против настоящего control plane.

## 8. Что мок обязан врать честно

| Ложь | Как именно | Что спасает в UI |
|---|---|---|
| Задержки по классам операций | `catalog_*` 40 мс, `flow_patch` 120 мс, `flow_compile` 1200–4000 мс, `run_start` 200 мс, `experiment_run` 8–40 с | компиляция и эксперимент не могут быть синхронной кнопкой — это job со статусом |
| Пагинация | `limit=20` по умолчанию из контракта, `next_cursor` всегда, когда есть хвост | списки каталога, трейса, датасета проектируются курсорными сразу |
| Усечение | `include_payloads='truncated'` режет тело и заполняет `truncated{fields,hint}` | «показать полностью» — состояние, а не опция |
| Частичный успех | `ok: true` с непустыми `problems[]` severity `warning` | предупреждения не красятся в провал |
| Конфликт версий | `flow_patch` со старым `base_rev` → `409` + `conflict` с серверной ревизией | откат оптимистичного применения в zustand-документе (§4.4) |
| Идемпотентность | повтор с тем же `idempotency_key` возвращает **ту же** `rev`, не новую | двойной клик и ретрай не плодят ревизии |
| Права | `scope: viewer` → `403` на мутациях, но чтение работает | «нет прав» — состояние экрана, а не пустая страница |
| Обрыв и грязь в потоке | см. §4 | реконнект по `Last-Event-ID`, дедупликация по `(executionId, seq)` |
| Данные | 400 КБ в одном узле, кириллица, эмодзи, 60-символьные id, нулевая стоимость, `null` в `version` | вёрстка не рассыпается на реальных данных |

Чего мок **не** врёт: статистика в `exp_significant`/`exp_flat` посчитана один раз и зафиксирована —
иначе экран сравнения проверяет наше воображение, а не продукт.

## Чего на этих экранах НЕ будет в прототипе

| Отложено | Почему | Когда вернём |
|---|---|---|
| Storybook | вторая сборка ради галереи, которую даёт `/dev/gallery` | второй потребитель реестра `@wf` или дизайнер в проекте |
| Запись фикстур с живого прогона (VCR) | писать нечего — бэкенда нет | как только control plane отдаёт первый настоящий трейс |
| Мок MCP-сервера и агентской сессии | прототип проверяет экраны, а не поведение Claude | фаза 1, вместе с `mode_set` и фазовым раскрытием |
| Запись/воспроизведение LLM-вызовов (replay-кэш) | это ядро доверия, а не UI | вместе с рантаймом |
| `@mswjs/data` как слой сущностей | связи у нас графовые, ORM не окупается | если фикстуры перерастут ручную сборку |
| Аутентификация (better-auth) | сессию мок подменяет заголовком `scope` | когда появится control plane с Bearer |

## Открытые вопросы к заказчику

1. **Перечисления нет в контракте.** В 57 операциях нет `flow_list`, `run_list`, `dataset_list`, `experiment_list`, `version_list` — агенту они не нужны, а человеку нужен экран «мои воркфлоу/прогоны». Добавляем 5 операций в реестр (тогда их получает и агент) или это Server Action вне MCP-контракта? Дизайн стартового экрана зависит от ответа.
2. **SSE-канал прогона не является операцией реестра** — это `POST /workflows/:id/stream` VoltAgent. Он остаётся вне `operationId`-контракта (и вне прав агента) или мы заворачиваем его в `run_stream`?
3. **Какой сценарий по умолчанию открывается на демо?** `normal` + `latency: real` честнее, но заказчик увидит 4-секундную компиляцию. Предлагаю `real`; нужно подтверждение, что это не воспримут как тормоза прототипа.
4. **Нужен ли `/dev/scenarios` в демо-сборке для заказчика**, или сценарий передаётся только ссылкой `?scenario=`?

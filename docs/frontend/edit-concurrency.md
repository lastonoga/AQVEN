# Одновременная правка: человек и агент

> Решает: как человек и агент правят одну спеку в одну секунду, не теряя изменений и не путая авторство.
> Влияет на: [ADR-0009](../adr/0009-op-log-not-crdt.md), [14. MCP-контракт](../14-mcp-contract.md) §2.3/§3, [15. Studio](../15-studio-frontend.md) §6, [frontend/build.md](build.md), [frontend/mocks.md](mocks.md), [30. План фронтенда](../30-frontend-plan.md) (Г6 отменена).

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Модель клиентского состояния | `serverDoc(rev N)` + `pendingIntents[]`, рендер = `project(serverDoc, intents)`; в полёте **намерение** (цель + путь + значение), а не готовый патч | server reconciliation: намерение переигрывается на новой базе, патч — нет; клиентского op-log и клиентского ребейза операций не заводим |
| Канал | SSE `GET /v1/specs/:id/events`, событие `spec_rev` | op-log уже есть (ADR-0009), второго канала синхронизации не заводим |
| Позиции узлов | `ui.layout`, вне `spec_hash` ([04](../04-ir-schema.md) §поля), op `ui_set` с `rebase: "lww"`; `base_rev` для неё **не проверяется** | конфликт позиций невозможен по определению — drag никогда не даёт 409 |
| Ребейз структурных операций | авто только при непересечении путей и живости всех упомянутых id; иначе отказ или вопрос человеку | формальной таблицы коммутативности ещё нет (ADR-0009, «обязаны делать» п.4) |
| Применение потока агента | по умолчанию `batched`: сервер применил, канвас показывает по кнопке | доверие строится на «увидел дифф → принял», а не на дёргающемся графе |
| Границы батча | жизненный цикл `flow_lock` агента | не нужно новых полей контракта, кроме `lock_id` в SSE |
| Авторство | каждая ревизия несёт `actor`; на канвасе — цвет автора, не только плашка | требование заказчика «видно, кто что изменил» |

## 1. Протокол синхронизации

Событие SSE (`id` = `rev`, чтобы `Last-Event-ID` добирал пропуск):

```
event: spec_rev
id: 44
data: {"spec_id":"s_01J…","rev":44,"base_rev":43,"etag":"W/\"44-9f2…\"",
       "actor":{"kind":"agent","id":"claude","lock_id":"lk_01J…"},
       "ops":[{"op":"add_node","path":"/nodes/extract","value":{…}}],
       "summary":{"added":1,"removed":0,"changed":0},
       "truncated":false}
```

`truncated: true` — операций слишком много для кадра, применять дельту нельзя, только перезапрос.

| Шаг | Условие | Что делает клиент |
|---|---|---|
| 1 | `ev.base_rev === localRev` | fast-forward: применить `ops` к `serverDoc`, `localRev = ev.rev` |
| 2 | `ev.base_rev > localRev` или `truncated` | `flow_get(spec_id)` целиком, `pendingIntents` сохраняются, батч сбрасывается; `ev.rev <= localRev` — игнор |
| 4 | есть `pendingIntents` | каждое намерение переигрывается на новом `serverDoc`; пересечение путей → намерение помечено `conflicted`, UI показывает его жёлтым, не отправляет |
| 5 | человек держит мышь (drag/протяжка) | применение отложено в буфер (§4), `serverDoc` обновлён, проекция — нет |
| 6 | обрыв SSE | переподключение с `Last-Event-ID`; после 3 неудач — поллинг `flow_get` раз в 10 с и плашка «живые обновления недоступны» |

Отправка правки — всегда `flow_patch({ base_rev: localRev, ops })`; ответ-конфликт несёт `ops_since`,
те же кадры, что и SSE, поэтому путь обработки один, а не два.

## 2. Матрица конфликтов

Ребейз автоматический ⇔ множества путей не пересекаются **и** все id, которые читает моя операция,
живы после дельты. Иначе — отказ с кандидатами либо вопрос человеку. Вопрос человеку допущен
ровно в двух местах (скаляр и текст) — везде ещё это обход валидатора.

| Моя операция | Операция агента | Результат | Что видит человек |
|---|---|---|---|
| Тащу узел (`ui_set`) | `remove_node` того же узла | Позиция применяется и осиротевает, drag прерывается | Узел под курсором превращается в призрак, тост «Claude удалил `parse_pdf`» + «Вернуть» (обратный `add_node`), 10 с |
| `bind` слота | Сменил `schemaId` выхода источника | **Отказ** валидатора: `problems[{code:"TYPE_MISMATCH"}]` + `candidates[]` | Ребро не рисуется, поповер «тип источника изменился на `Invoice[]`: вставить адаптер / выбрать другой выход» |
| `bind` слота | `remove_node` источника | **Отказ**: `MISSING_BINDING`, авто-ребейз невозможен (id мёртв) | «Источника больше нет», список совместимых выходов |
| Правлю скаляр (`temperature`) | Правит тот же путь | **Вопрос человеку**: `conflict`, `rebase:"manual"` | Диалог на два значения: «ваше 0.2 / Claude 0.7», третья кнопка «открыть журнал» с `rationale` агента |
| Правлю текст промта | Правит тот же промт | Трёхстороннее слияние по базовой ревизии; пересечение диапазонов → **вопрос человеку** | Непересеклись — тихо слито с меткой «слито с правкой Claude»; пересеклись — конфликт-маркеры в редакторе |
| Добавляю узел | Добавляет узел | Авто-ребейз, оба применены | Мой узел — в цвете человека, его — в цвете агента |
| Оборачиваю выделение в компонент | `add_node` внутрь выделения | Эксклюзивная операция (§5): побеждает тот, кто первый | Успел агент — «в выделение добавлен `rerank`, включить в компонент?» с пересчитанным превью; успел я — агент получает `EXCLUSIVE_IN_PROGRESS` и повторяет на новой `rev` |
| Оборачиваю выделение в компонент | `remove_node` из выделения | Эксклюзивная, как выше | Выделение пересчитано, диалог «узлов в компоненте: 4 (было 5)» |

## 3. Advisory-lock

| Вопрос | Ответ |
|---|---|
| Берёт ли UI лок на drag | **Нет.** Drag — это `ui_set`, у него нет конфликтов. Лок на перетаскивание — ложное чувство защищённости |
| Когда берёт | На **сессию структурной правки**: начало протяжки связи, вход в поле инспектора, открытие редактора промта. `flow_lock({ ttl_s: 60 })` |
| Как держит | Heartbeat раз в 20 с, пока фокус в редакторе. Отпускает по `apply`, `blur`, `Esc` и при уходе вкладки в фон |
| Лок агента | `ttl_s: 300`, берётся на ход целиком (§4) |
| Показ | `AgentPresenceBar` (build.md): «Claude редактирует, TTL 4:12» + `rev` + автор последнего патча. Узлы, затронутые его текущим ходом, обведены его цветом |
| Перехват | Кнопка «перехватить» → `flow_lock({ release: true, force: true })`. Агент узнаёт об этом на следующем `flow_patch`: `problems[{ code: "LOCK_TAKEN", severity: "warning" }]` — патч **применяется**, но агенту сказано остановиться и спросить |
| Если оба игнорируют | Работает только `base_rev`. Лок деградирует до индикатора присутствия. Гарантия остаётся ровно одна и она достаточная: **невалидная ревизия физически не записывается** (ADR-0009). Лок сокращает частоту диалогов, а не корректность |

## 4. Поток агента: 20 операций за 30 секунд

Сервер применяет всё немедленно — буферизация **только визуальная**. Поэтому она обязана быть
честной: бейдж «показан `rev 43` · на сервере `51`» висит всё время отставания.

| Режим | Поведение | Когда по умолчанию |
|---|---|---|
| `live` | Каждый кадр применяется сразу, ELK — с дебаунсом 300 мс | Спека пустая или человек не касался канваса 60 с |
| `batched` | Кадры копятся во «входящих», плашка «Claude: 12 изменений — применить», дифф доступен до применения | **По умолчанию** |
| `paused` | Ничего не применяется, счётчик растёт, применение только вручную | Человек нажал «пауза» или держит открытым конфликт-диалог |

Правила буфера:
- Батч = кадры с одним `lock_id`. Конец хода агента (release или TTL) закрывает батч.
- Раскладка ELK пересчитывается **один раз на батч**, переход — одна `View Transition`, не 12.
- Пока мышь зажата (drag, протяжка, рамка выделения) — применение отложено в любом режиме.
- В `batched` батч применяется сам, если ход агента закрыт **и** человек не трогал канвас 2 с
  (кнопка нужна, когда человек работает; тишина не должна требовать кликов), и всегда показывает
  `PatchDiffLayer` на 5 с.
- Буфер не бесконечен: > 200 операций или > 10 ревизий → полный `flow_get` с диффом целиком.

## 5. Что нельзя делать одновременно

Признак эксклюзивности: операция **меняет идентичность существующих узлов** (id исчезает или меняет
владельца), а не добавляет/убирает по одному.

| Операция | Почему эксклюзивна |
|---|---|
| `component_define` (свёртка выделения) | Узлы меняют родителя, рёбра пересекают новую границу |
| Записывающий `component_expand` (раскрытие до примитивов) | Один id заменяется на N новых, внешние рёбра перевешиваются |
| `architecture_instantiate` | Разворачивает подграф целиком, любой параллельный `bind` целится в ещё не существующие порты |
| `flow_import`, `project_import` | Заменяет документ |
| Смена архетипа, миграция версии IR | Меняет форму всех узлов |

Механизм: `flow_patch({ exclusive: true })`. Сервер в той же транзакции отвергает конкурирующие патчи
с `rebase: "none"` (без попытки ребейза) и шлёт `spec_exclusive { phase: "begin" | "end", actor }`.
UI на это время — read-only с плашкой «Claude перестраивает компонент», редакторы закрываются с
сохранением черновика в `pendingIntents`. Это одна транзакция, секунды; нет `end` за 10 с — кнопка `flow_get`.

## 6. Мок

`AgentDriver` поверх `@wf/mock-server`: лента `spec_ops` играется тем же плеером `/dev/tape`,
что и лента прогона — новый механизм не заводится.

```ts
type AgentFrame = { at_ms: number; ops: Op[]; lock?: "acquire" | "release"; target?: TargetRef };
type TargetRef = { pick: "dragged_node" | "editing_path" | "selected" | "id"; id?: string };
```

- **Сценарии как данные.** `agent_flood` — 20 кадров за 30 с с локом на весь ход; `agent_race` — кадр
  ровно в момент `mousedown`; `agent_exclusive` — `component_expand` посреди правки; `sse_drop_at=40`
  (уже есть в mocks.md) проверяет ребейз после resync.
- **DevBus.** UI публикует `focus { dragging_node_id, selected[], editing_path }` в мок-канал, мок
  резолвит по нему `target.pick`. Это и даёт честную коллизию, а не «удалил случайный узел».
- **Кнопки-провокации** на `/dev/scenarios`: «удалить узел, который я тащу», «сменить тип источника,
  к которому я тяну ребро», «править тот же параметр», «забрать лок», «прислать 12 изменений».
  Каждая = вставка кадра «сейчас», поэтому демо воспроизводимо и попадает в Playwright.

## Крайние случаи

| Ситуация | Что делает система | Что видит человек |
|---|---|---|
| SSE оборвался в середине drag | Drag доигрывается локально, `ui_set` уходит после `mouseup` и не требует `base_rev` | Плашка «нет живых обновлений», позиция не теряется |
| Вкладка была в фоне, `rev` ушёл на 30 вперёд | `flow_get` целиком, буфер сброшен, дифф считается против `rev` на момент ухода | «Пока вас не было: +6 узлов, 2 удалено» с кнопкой «показать дифф» |
| Агент удалил узел с открытым инспектором | Инспектор закрывается, черновик полей сохраняется в `pendingIntents` | «Узел удалён Claude» + «Вернуть узел с моими правками» |
| Конфликт скаляра, человек ушёл, не ответив | Диалог живёт до перезагрузки, режим `paused` держится | Счётчик входящих растёт, канвас заморожен явно, а не незаметно |
| Лок истёк посреди правки промта | Правка не блокируется, heartbeat берёт лок заново при следующем вводе | Плашка лока мигает «продлён» |

## Открытые вопросы

1. **Поднимает ли `ui_set` ревизию.** Предлагаю поднимать (op-log линеен), `base_rev` не проверять,
   `spec_hash` не трогать. Тогда `rev` растёт от каждого перетаскивания и «12 изменений» считается по
   структурным операциям, а не по ревизиям. Альтернатива — отдельный `layout_rev` и второй канал.
2. **Чем сливать текст промта.** Без библиотеки трёхстороннего слияния любая параллельная правка
   одного промта уходит в диалог: дёшево и честно, но заметно хуже на ощупь. Нужен выбор.
3. **Границы батча через `flow_lock`** работают, только если агент дисциплинированно берёт лок на ход.
   Иначе нужен явный `batch_id` в `flow_patch` — правка §2.3 контракта.
4. **Порог авто-применения** (2 с тишины) взят из головы; если он читается как потеря контроля —
   убирается, остаётся только кнопка.

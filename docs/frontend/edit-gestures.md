# Жесты прямого редактирования канваса

> Решает: во что превращается каждое действие руками, когда тот же документ параллельно правит агент.
> Влияет на: [14. MCP-контракт](../14-mcp-contract.md) §2.3, §3; [15. Studio](../15-studio-frontend.md) §6; [frontend/build.md](build.md); [ADR-0009](../adr/0009-op-log-not-crdt.md); [04. IR](../04-ir-schema.md) §4.3.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Чем правит человек | тем же `flow_patch(base_rev, ops[])`, что агент | один валидатор, один op-log, один источник конфликтов; второй путь записи означал бы второй валидатор |
| Позиции узлов и свёрнутость | **не операции**: канал `ui` (вне `spec_hash`, §4.3), LWW по полю, `rev` не растёт | ADR-0009 прямо разрешает LWW там, где нет инвариантов; иначе перетаскивание засоряет ленту и ломает `run_diff` |
| Гранула записи | один **жест** = один `flow_patch` = одна ревизия = одна запись в ленте | жест — единица намерения человека и единица отката |
| Оптимистичность | локально применяем сразу, откатываем по отказу сервера | агент занимает документ секундами; ждать round-trip на каждый клик нельзя |
| Undo | **обратные операции новым патчем**, не `flow_revert` | op-log линеен и содержит чужие правки; откат до ревизии молча снёс бы работу агента |
| Типы для подсветки | локальная предрассчитанная копия реестра, инвалидация по `rev` | `isValidConnection` вызывается на каждом движении мыши и обязана быть синхронной (§6.1) |
| Разрушающие жесты | не запрещены, а переведены в «предпросмотр каскада → подтверждение» | запрет заставляет обходить UI; предпросмотр даёт то же и остаётся в контракте |
| Кто автор правки | `actor` в `spec_ops` уже есть; UI красит дифф по `actor` | «видно руку агента» — гипотеза 2 в [build.md](build.md) |

## 1. Жест → операция

`op` — элемент `ops[]` внутри `flow_patch`, если не указан другой тул.

| Жест | Операция | Примечание |
|---|---|---|
| Перетащить архетип из палитры / `⌘K` → выбрать | `add_node{type, name, at?}` | `at` — позиция, уходит тем же патчем, но пишется в `ui` |
| Delete на узле | `remove{kind:'node', name}` + каскад `remove{kind:'binding'}` на его рёбра | каскад считает клиент, показывает предпросмотр, отправляет одним патчем |
| Двойной клик по заголовку → ввод | `set{path:'nodes/<name>/name'}` | сервер каскадит ссылки в биндингах внутри той же транзакции |
| Протянуть от выхода к слоту | `bind{target:'<node>.<slot>', source:'<node>.<out>'}` | |
| Протянуть от слота к выходу | та же `bind` | направление жеста не меняет операцию |
| Оторвать конец ребра и бросить в пустоту | `remove{kind:'binding', target}` | |
| Оторвать и бросить на другой выход | одна `bind` с новым `source` | не пара remove+bind: биндинг слота — поле, а не коллекция |
| Правка поля в инспекторе (модель, температура, шаблон промта) | `set{path:'nodes/<name>/<field>'}` | коммит по blur/Enter, не по каждому символу |
| `concurrency`, `max_iter` на `map`/`loop` | `set{path:'nodes/<name>/concurrency'}` | числовые границы проверяет и клиент, и сервер |
| Выделить N узлов → «Обернуть в компонент» | `component_define{definition}` затем `flow_patch` с заменой на узел-компонент | два вызова, одна запись в ленте: UI показывает как один шаг |
| Раскрыть компонент | **не правка**: `component_expand` — чтение, состояние живёт в `ui` | `rev` не меняется |
| Рамочное выделение → Delete | один патч, `ops[]` = все удаления + каскад рёбер | лимит 50 операций в патче; больше — жест отклоняется до отправки |
| `⌘C`/`⌘V` узла | `add_node` с копией полей, имя `<name>_copy` | биндинги не копируются: источники за пределами копии неоднозначны |
| `⌘Z` | новый `flow_patch` с обратными операциями (§5) | |
| Перетащить узел, свернуть группу, зум | `PATCH /v1/specs/:id/ui` | вне op-log, `rev` не растёт |

## 2. Что руками можно, что с проверкой, что нельзя

| Класс | Жесты | Правило |
|---|---|---|
| **Свободно** | позиция, свёрнутость, зум, выделение, раскрытие компонента, переименование заголовка-`description` | ни один инвариант не затрагивается; локально и сразу, без ожидания сервера |
| **С обязательной валидацией до применения** | `bind`, отцепление обязательного слота, `remove` узла с потребителями, `set` на поле, меняющее сигнатуру (модель со сменой capability, схема выхода), смена `concurrency`/`max_iter`, разворачивание компонента в примитивы «навсегда» | клиент проверяет предикатом до отпускания мыши (§4); сервер проверяет заново — клиентская проверка не авторитетна, она только избавляет от заведомо мёртвых жестов |
| **Не пускаем прямой манипуляцией** | привязка к узлу, который не доминирует над потребителем (источник не гарантированно исполнен на всех путях); ребро, замыкающее цикл вне `loop`; удаление узла, на который ссылается активный `run`/датасет; правка узла внутри свёрнутого компонента из общей библиотеки; редактирование `uses`-пинов (версии/хеши) | первые два — недоказуемые инварианты на клиенте в момент жеста: доминирование считает компилятор. Порт не подсвечивается как цель, курсор `not-allowed`, поповер называет инвариант и даёт кандидата («вставить `join` перед потребителем»). Пины и библиотечные компоненты правятся только через `registry_propose` / форк компонента |

Слово «запрещено» здесь означает **нет прямого жеста**, а не «невозможно»: все пять случаев достижимы
через явный диалог с подтверждением или через свой тул. Никакой жест не обходит валидатор сервера.

## 3. Оптимистичность и откат

Состояние жеста: `local` → `pending` → `applied` | `rejected` | `rebased`.

| Шаг | Клиент | Что видит человек |
|---|---|---|
| 1. Отпустил мышь | применяет операцию к локальному графу, ставит `pending`, кладёт жест в очередь | изменение мгновенно, элемент с пунктирным контуром «в полёте» |
| 2. Отправка | `flow_patch(base_rev = последний известный rev, ops, idempotency_key = id жеста)` | ничего |
| 3. `ok:true` | снимает пунктир, принимает `version.rev` | контур гаснет за 150 мс |
| 4. `ok:false`, `problems[]` | откатывает жест до снимка перед ним, прикрепляет проблему к узлу | элемент возвращается на место с анимацией назад + плашка: текст проблемы, кнопка топ-`candidate.apply`, «оставить как было» |
| 5. `code:'REV_CONFLICT'`, `rebase:'auto'` | берёт `rebased_ops`, переигрывает свой жест поверх, повторяет один раз | тихо; в ленте появляется чужая правка отдельной строкой |
| 6. `rebase:'manual'` | жест остаётся `pending`, локальная правка подсвечена как спорная | диалог «взять моё / взять их» из `candidates[]`, оба варианта — готовые вызовы |

Очередь жестов **последовательная**: следующий патч уходит только после ответа на предыдущий, иначе
`base_rev` второго заведомо устарел. Жесты `ui`-канала идут параллельно и в очередь не попадают.
Откат всегда откатывает **весь жест целиком** — `ops[]` применяются всё-или-ничего, частичного
состояния не бывает ни на сервере, ни на клиенте.

Отклонённый жест не исчезает: он остаётся в панели «не применено» с кнопкой «повторить».

## 4. Валидация на лету

**Решение: локальная копия реестра типов, а не запрос.** Обоснование прямое — `isValidConnection`
вызывается на каждом `mousemove` при протяжке (§6.1) и обязана быть синхронной и чистой; сетевой
запрос внутри неё невозможен физически, а дебаунс превращает подсветку в мигание.

| Что | Откуда | Когда обновляется |
|---|---|---|
| `schemaCompatibility: Map<pairKey, boolean>` | `catalog_list{kind:'type'}` при открытии спеки, предрассчитано в пары | при `rev`, затронувшем `uses`/реестр; по SSE-событию реестра |
| `portIndex: Map<handleKey, Port>` | из локального IR | на каждую применённую операцию |
| ацикличность | `graphology-dag.willCreateCycle` на локальном графе | синхронно |
| доминирование, полнота enum, обязательные биндинги | **не считаем на клиенте** | приходит от сервера как `problems[]` после патча |

Отсюда честное разделение: подсветка порта отвечает на вопрос «соединимо ли это в принципе»
(вид порта, схема, цикл) и **не** обещает, что патч пройдёт. Три состояния handle: совместим —
подсвечен, несовместим — притушен, «непроверяемо на клиенте» — нейтрален, но при отпускании
жест уходит `pending` и может вернуться отказом. Четвёртого состояния «может быть» на канвасе нет.

## 5. Undo/redo

**Undo — обратный патч, а не `flow_revert`.** Причина: op-log линеен и общий. `revert` до ревизии
означал бы снятие всех правок агента, случившихся после, — молчаливое уничтожение чужой работы,
несовместимое с `version_propose(evidence)`.

Клиент держит стек жестов, у каждого — `{ ops, inverse_ops, base_rev, applied_rev }`. `inverse_ops`
считаются в момент применения из снимка затронутых путей, а не выводятся из `ops` задним числом:
для `set` нужно прежнее значение, для `remove` — удалённое тело.

Undo = `flow_patch(base_rev = текущий rev, ops = inverse_ops)`. Он проходит тот же валидатор и может
быть **отклонён** — это нормально и должно быть видно.

| Что случилось между правкой и undo | Поведение undo | Что видит человек |
|---|---|---|
| Ничего | применяется, `rev+1` | обычный откат, в ленте строка «отменено: …» |
| Агент правил **другие** узлы/пути | применяется, авто-ребейз | то же плюс подсказка «поверх 3 правок Claude» |
| Агент правил **тот же путь** (`set` на то же поле) | undo не применяется вслепую: `inverse_ops` вернул бы значение, которое агент уже заменил осознанно | диалог: «Claude изменил это поле после вас. Отменить только вашу правку — значит стереть его. Отменить / оставить / показать дифф» |
| Правка человека — предпосылка правки агента (агент привязался к добавленному узлу) | undo отклонён валидатором (биндинг на несуществующий узел) | `problems[]` с указанием зависимой правки и кандидат «отменить обе» (один патч с обоими инверсами) |
| Между правкой и undo прошло 20 чужих ревизий | стек не протухает по времени, только по конфликту путей | те же диалоги |

Redo — прямой повтор `ops` тем же механизмом и с теми же исходами. Стек **не** глобальный по
документу, а личный: undo человека никогда не отменяет операцию агента. Отмена правки агента —
отдельный явный жест «отменить патч Claude» в ленте, и он тоже обратный патч.

`ui`-канал имеет собственный undo (позиции), мгновенный и без сервера: он ничего не ревизирует.

## 6. Пакетирование

| Ситуация | Патчей | Ревизий | Записей в ленте |
|---|---|---|---|
| Перетащил три узла | 0 (канал `ui`) | 0 | 0 |
| Рамкой выделил три узла и удалил | 1 (`ops[]` = удаления + каскад рёбер) | 1 | 1: «удалено 3 узла, 5 связей» |
| Протянул связь | 1 | 1 | 1 |
| Правит текст промта 4 минуты | 1 при коммите поля (blur/Enter/`⌘S`) | 1 | 1 |
| Вставил узел и сразу привязал два слота | 3 жеста → 3 патча | 3 | 3, схлопнутые в ленте в группу по 8-секундному окну и одному актору |

Правила: **жест = патч = ревизия**; группировка в ленте — только визуальная, поверх ревизий, и
никогда не меняет их число. Промежуточные состояния перетаскивания и ввода не попадают в op-log
вовсе. Драг ребра до отпускания — не жест: жестом он становится в момент валидного `onConnect`.

## Крайние случаи

| Ситуация | Что делает система | Что видит человек |
|---|---|---|
| Агент удалил узел, пока человек тянет от него связь | протяжка продолжается локально; `onConnect` уходит патчем и падает с `problems[]` | ребро отскакивает, узел-источник помечен «удалён Claude», кандидат «вернуть узел» |
| Агент держит `flow_lock` | правки не блокируются, ADR-0009 называет lock мягким | плашка «Claude редактирует», кнопка «перехватить»; после перехвата плашка меняет цвет |
| Человек правит поле, агент правит то же поле | побеждает тот, чей патч пришёл вторым (линейный op-log) | поле мигает и показывает «Claude заменил ваше значение», с кнопкой вернуть своё |
| Сеть пропала на 30 секунд | очередь жестов копится локально, `ui`-канал работает | баннер «не синхронизировано: 4 правки», канвас в приглушённой рамке |
| После восстановления `base_rev` устарел на 12 ревизий | последовательный авто-ребейз очереди, при первом `manual` — остановка | «12 правок Claude пока вы были офлайн: показать дифф» |
| Патч превысил 50 операций | жест отклоняется **до** отправки | «выделено слишком много: удалите частями» |
| Undo после того, как версия уже предложена (`version_propose`) | undo применяется к черновику, не к предложенной ревизии | предупреждение «заявка на версию ссылается на rev 41» |

## Открытые вопросы

1. Коммит текста промта: `blur` или явный `⌘S`? От этого зависит, сколько ревизий даёт одна сессия
   правки текста, и нужен ли здесь тот самый точечный CRDT для текста из ADR-0009.
2. Позиции в `ui` вне op-log — значит, автораскладка ELK после патча агента может перетащить узлы,
   которые человек расставил руками. Побеждает ручная позиция всегда или до следующего `add_node`?
3. Каскадное удаление: считает клиент (быстро, но может разойтись с сервером) или `dry_run`-патч
   перед показом предпросмотра (точно, но +round-trip на каждый Delete)?

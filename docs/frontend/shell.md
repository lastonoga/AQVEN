# Кластер: Оболочка и навигация

> Экраны: AppShell, Командная палитра и глобальный поиск, Индикатор состояния и панель активности, Входящие (аппрувы, задачи, уведомления), Первый запуск
> Приоритет кластера: P0 — без оболочки остальные 17 экранов не связываются в продукт

## Что проверяем прототипом

1. **18+ экранов складываются в 4 пункта навигации.** Гипотеза: «линзы» (граф контекста, карта промтов, эффективная конфигурация, раскрытие компонентов) — не разделы, а вкладки над выбранным воркфлоу. Если эксперт ищет их в меню — гипотеза мертва.
2. **Палитра, а не меню.** Гипотеза: после первого дня ⌘K закрывает ≥80% переходов, сайдбар остаётся только как карта. Меряем в прототипе кликами мимо палитры.
3. **Ссылка = состояние.** Гипотеза: любой экран воспроизводится по URL, и это главный способ передать контекст Claude и обратно (`studio_open` → `ui_url`). Если для воспроизведения нужны слова «а теперь разверни третий узел» — URL-схема неверна.
4. **Один индикатор вместо четырёх.** Гипотеза: компиляция, прогоны, работа агента и бюджет умещаются в одну строку статуса, и человек по ней понимает «система занята мной / собой / деньгами».
5. **Агент виден в интерфейсе.** Гипотеза: журнал решений + advisory-lock + фаза (`mode_set`) в шапке достаточны, чтобы человек не удивлялся чужим правкам; иначе нужен отдельный канал присутствия. И: пустой воркспейс ведёт к первому воркфлоу за один экран — три двери (бриф, архетип, импорт), не больше.

## Информационная архитектура

Навигация — **4 пункта + переключатель воркфлоу**, а не 18 пунктов. Разложение по вопросу, который человек задаёт, а не по сущности:

| Группа (пункт сайдбара) | Что внутри | Почему группа |
|---|---|---|
| **Воркфлоу** | канвас, редактор шаблонов, линзы: граф контекста, карта промтов, эффективная конфигурация, раскрытие компонентов | всё это — виды на **один** IR текущей ревизии; отдельного смысла без выбранного воркфлоу не имеют |
| **Прогоны** | список прогонов, отладчик, дифф прогонов, таймлайны циклов | всё это — виды на **один** run_id или пару |
| **Проверка** | датасеты, покрытие, эксперименты и сравнение, матрица моделей, очередь разметки, калибровка судей | общий вход «работает ли оно», общая ось «датасет × скорер» |
| **Каталог** | реестры типов, моделей, агентов, тулов; версии и дифф; журнал решений; экспорт | долгоживущие объекты воркспейса, меняются редко и только через аппрув |

Обоснование группировки: линзы **никогда** не открываются сами по себе — их всегда открывают «от узла». Сделать их пунктами меню значит заставить человека выбирать воркфлоу дважды. Поэтому линза — параметр `?lens=`, переключается сегментированным контролом в шапке воркфлоу и хоткеями `1…5`; канвас при смене линзы сохраняет вьюпорт и выделение.

Второй уровень (внутри группы) — вкладки, а не вложенный сайдбар. Глубина маршрута максимум 3 сегмента после воркспейса.

## Маршруты и URL-состояние

| Маршрут | Search-параметры (`validateSearch`) | Шарится ссылкой |
|---|---|---|
| `/$ws` | — | нет, редирект: последний воркфлоу или онбординг |
| `/$ws/workflows` | `q`, `sort`, `archetype` | да |
| `/$ws/workflows/$id` | `rev`, `lens=graph\|context\|prompts\|config\|expand`, `node`, `port` | **да, ключевой**: `studio_open` строит именно его |
| `/$ws/runs` | `status`, `spec`, `since`, `cursor` | да |
| `/$ws/runs/$runId` | `node`, `tab=prompt\|provenance\|checks\|cost`, `t` (мс от старта, позиция водопада), `cmp` (второй run_id для диффа) | да |
| `/$ws/prompts/$templateId` | `slot`, `fixture` | да |
| `/$ws/evals/datasets/$id` | `split`, `axis`, `cursor` | да |
| `/$ws/evals/compare` | `a`, `b`, `scorer`, `only=regressions` | да |
| `/$ws/registry/$kind` | `q`, `status=draft\|pending\|approved` | да |
| `/$ws/versions/compare` | `a`, `b`, `granularity` | да |
| `/$ws/journal` | `since`, `actor=human\|agent` | да |
| `/$ws/tasks/$taskId` | — | да (это ссылка из уведомления) |
| `/$ws/export` | `rev`, `target` | да |

**Не в URL:** тема, ширины `resizable`-панелей, открытость аккордеонов, история палитры, вьюпорт канваса (кроме фокуса `?node=`), позиция скролла таблиц. Всё это — `localStorage` по ключу `ws:screen`.

**Правило:** если человек может сказать коллеге или Claude «смотри сюда» — это в URL. Обратное правило: `ui_url` из любого конверта ответа MCP обязан открываться без дополнительных кликов, включая подсветку проблемного узла.

## Плотность: что это значит в числах

| Параметр | Значение | Почему |
|---|---|---|
| Базовый кегль | 13px интерфейс, 12px таблицы и метрики, 12px моно в коде и id | 14px+ «дышащий» интерфейс стоит ~2 строк таблицы на экран |
| Шаг отступов | 4px, рабочий диапазон 4–12px; 16px только между крупными регионами | сетка 8px даёт слишком рыхлые формы для 12-колоночных таблиц |
| Высота строки таблицы | 28px, чекбокс-режим 32px | 20+ строк прогонов без скролла на 900px |
| Шапка | 40px, одна строка: крошки + индикатор + аватар | вторая строка шапки = −3 строки данных |
| Плотность цифр | `tabular-nums` везде, где число обновляется | иначе стоимость прогона «прыгает» |
| Тултипы | один `TooltipProvider`, `delayDuration 200 / skipDelay 300` | при плотной сетке дефолтные 700ms ломают скан |

Запрещено в прототипе: иллюстрации-заглушки, карточки с тенями вокруг каждой метрики, анимации длиннее 150ms (кроме View Transition «узел → инспектор»), любые градиенты.

## Экраны

### AppShell — P0

- **Зачем:** дать единственную рамку, в которой человек всегда знает: какой воркспейс, какой воркфлоу, какая ревизия, какая фаза цикла и кто сейчас трогает спеку — он или агент.
- **Сценарии:**
  1. Вход → редирект на последний открытый воркфлоу (`localStorage`), при его отсутствии — на первый запуск.
  2. Переключение воркфлоу через `⌘P` или поповер в шапке; текущая линза и выбранный узел сбрасываются, ревизия — на `HEAD`.
  3. Человек видит в шапке бейдж `агент правит` (advisory-lock `flow_lock`) → открывает журнал решений в правой панели, не уходя с канваса.
  4. `⌘J` открывает правую панель «журнал/активность», `⌘\` сворачивает сайдбар до иконок, `⌘/` — карта хоткеев.
- **Ключевые элементы:**

| Элемент | Что показывает | Взаимодействие |
|---|---|---|
| Сайдбар (4 пункта) | группа + счётчик активного (прогоны в работе, аппрувы в очереди) | клик, `⌘1…⌘4`, сворачивание `⌘\` |
| Переключатель воркфлоу | имя, архетип, `rev`, статус компиляции | `⌘P`, поиск по списку |
| Хлебные крошки | воркспейс › воркфлоу › ревизия › линза/узел | каждый сегмент — поповер выбора, а не только ссылка |
| Индикатор состояния | см. отдельный экран | клик открывает панель активности |
| Переключатель линзы | 5 линз текущего воркфлоу | `1…5`, сохраняет вьюпорт |
| Бейдж фазы | текущая фаза (`mode_set`): discover / author / run / evaluate / ship / debug | только чтение в v1 |
| Правая панель | журнал решений или инспектор — по контексту | `⌘J`, ширина в `localStorage` |
| Меню профиля | тема (system/light/dark), плотность (нет, зафиксирована), выход | |

- **Состояния:** *пусто* — воркспейс без воркфлоу, сайдбар показан, но пункты «Прогоны/Проверка» задизейблены с подсказкой «сначала воркфлоу»; *загрузка* — скелет крошек и сайдбара (`pendingComponent` маршрута), без спиннера; *ошибка* — баннер под шапкой с кодом проблемы и кнопкой «объяснить» (`help_contract`); *деградация* — SSE отвалился: индикатор серый, подпись «данные от HH:MM», опрос раз в 15с; *нет прав* — пункты остаются видимыми, но действия внутри отключены, в тултипе — недостающая роль (v1 однопользовательский, проверяем только разметку).
- **Операции:** `flow_get`, `flow_lock`, `journal_read`, `help_contract`, `mode_set` (чтение фазы), `studio_open` (входящие диплинки).
- **Мок-данные:** 1 воркспейс, 6 воркфлоу (1 без компиляции, 1 с 3 ошибками, 1 залоченный агентом, 1 пустой черновик), 40 записей журнала с чередованием `actor: human | agent`, фаза `author`.
- **Что проверяем:** достаточно ли 4 пунктов и крошек, чтобы за 5 секунд ответить «где я и что тут сейчас происходит».

### Командная палитра и глобальный поиск — P0

- **Зачем:** основной способ навигации и запуска действий для эксперта; заодно единственное место, где человек делает ровно те же операции, что агент, и видит их именами MCP-тулов.
- **Сценарии:**
  1. `⌘K` → «комп» → `Скомпилировать текущий воркфлоу` → результат ошибок сразу в палитре, Enter переводит на первую ошибку на канвасе.
  2. Вставил `run_01H…` из чата с Claude → палитра распознала префикс id → единственный результат «Открыть прогон» → Enter.
  3. `⌘K` → `>` → режим действий (без навигации), `@` → узлы текущего воркфлоу, `#` → коды проблем (`R-C2`, `G-exp`) с объяснением из `help_contract`.
  4. Пустой ввод показывает «Недавнее» (5 объектов) и 3 действия по контексту экрана.
- **Ключевые элементы:**

| Элемент | Что показывает | Взаимодействие |
|---|---|---|
| Строка ввода | режим по префиксу: пусто=всё, `>`=действия, `@`=узлы, `#`=коды проблем, `/`=переход | `⌘K`, Esc, Backspace выходит из режима |
| Группа «Перейти» | воркфлоу, прогоны, датасеты, версии, записи журнала | Enter — открыть, `⌘Enter` — в новой вкладке |
| Группа «Действия» | компиляция, запуск прогона, реплей узла, предложить версию, экспорт, смена фазы | у каждого — имя MCP-тула мелким моно справа |
| Группа «Объяснить» | код проблемы → текст из `help_contract` прямо в палитре | без перехода |
| Хвост строки | хоткей действия (`kbd`) и область применения (текущий узел / воркфлоу) | |

- **Состояния:** *пусто* — «Недавнее» + подсказка синтаксиса префиксов; *загрузка* — поиск дебаунсится 120ms, строка результатов — скелет, предыдущие результаты не мигают; *ошибка* — поиск упал: «поиск недоступен, доступны переходы по id и действия»; *деградация* — индекс поиска устарел: бейдж «локальный поиск» и ограничение по текущему воркфлоу; *нет прав* — действие остаётся в списке, но помечено замком и объясняет, что нужен аппрув.
- **Операции:** `catalog_list`, `flow_get`, `flow_compile`, `run_start`, `run_replay_node`, `journal_read`, `help_contract`, `mode_set`, `version_propose`, `project_export`, `studio_open`.
- **Мок-данные:** 6 воркфлоу, 30 прогонов, 8 датасетов, 12 версий, 40 записей журнала; среди имён — два почти одинаковых («Классификация тикетов v2» и «…v2 (форк)»), чтобы проверить ранжирование; один id длиной 26 символов для проверки распознавания вставки; 15 кодов проблем.
- **Что проверяем:** покрывает ли палитра переходы **и** действия так, что сайдбар становится необязательным; хватает ли 4 префиксов или нужен пятый.

### Индикатор состояния и панель активности — P0

- **Зачем:** одна строка отвечает, занята ли система мной, собой или деньгами, — иначе человек открывает вкладку прогонов «просто проверить».
- **Сценарии:**
  1. Правка на канвасе → индикатор «компиляция…» 1–3с → `3 ошибки` красным, клик ведёт к первой.
  2. Идёт прогон на датасете → индикатор «2 прогона, 41%», клик → панель активности со списком и кнопкой «открыть отладчик».
  3. Бюджет прогонов перевалил 80% → индикатор жёлтый, в панели видно, какой прогон съедает; при 100% — красный и подсказка, что новые запуски блокируются гейтом.
  4. Агент взял lock и работает → «агент: author, 4 операции за минуту», клик открывает журнал с последними записями.
- **Ключевые элементы:**

| Элемент | Что показывает | Взаимодействие |
|---|---|---|
| Канал «компиляция» | idle / компилируется / N ошибок / N предупреждений | клик → первая проблема на канвасе |
| Канал «прогоны» | число активных + агрегированный прогресс | клик → панель активности |
| Канал «агент» | держатель lock, фаза, время до истечения | клик → журнал; действие «перехватить lock» |
| Канал «бюджет» | потрачено/лимит за период, доля, тренд | клик → разбивка по прогонам и моделям |
| Панель активности | список живых прогонов и последних 10 завершённых с итогом | Enter — отладчик, `X` — отмена (заглушка) |

Каждый канал несёт **иконку, текст и цвет** одновременно (§8.3: цвет не единственный носитель смысла). Пустые каналы схлопываются, но не исчезают полностью — место зарезервировано, чтобы строка не прыгала.

- **Состояния:** *пусто* — «тихо», один серый значок; *загрузка* — каналы серые с пульсацией, без чисел; *ошибка* — канал показывает «?» и время последнего успешного опроса; *деградация* — SSE потерян, переход на опрос: подпись «обновлено HH:MM:SS» и приглушённые цвета, никаких «живых» анимаций, чтобы не врать; *нет прав* — канал бюджета скрыт целиком.
- **Операции:** `flow_compile` (`view='summary'`), `run_get`, `run_stages`, `flow_lock`, `journal_read`, `mode_set`.
- **Мок-данные:** сценарная лента событий на 90 секунд: компиляция → 3 ошибки → правка → зелено; 2 параллельных прогона (один падает на 60%); бюджет 78% → 92% → 100%; захват и истечение lock агентом. Крайние случаи: 12 одновременных прогонов (схлопывание в «12 прогонов»), нулевой бюджет, прогон длиной 40 минут.
- **Что проверяем:** достаточно ли одной строки на 4 канала, или бюджет и агент требуют отдельного постоянного места.

### Входящие: аппрувы, задачи человеку, уведомления — P1

- **Зачем:** агент не имеет права выпускать версии и менять реестры сам — он кладёт заявки; плюс воркфлоу останавливается на human-задачах. Без одного входящего эти два потока теряются между экранами.
- **Сценарии:**
  1. Агент предложил тип в реестр → тост (`sonner`) «заявка на тип `TicketCategory`» с действиями «открыть / позже»; «позже» кладёт в счётчик сайдбара.
  2. Открыл входящие → 3 карточки: заявка на версию (с вердиктом гейта), заявка в реестр, human-задача остановленного прогона → разбирает сверху вниз клавишей `J/K` + `Enter`.
  3. Human-задача открывает форму из JSON Schema, сабмит возобновляет прогон, карточка исчезает с анимацией и попадает в журнал.
- **Ключевые элементы:**

| Элемент | Что показывает | Взаимодействие |
|---|---|---|
| Карточка заявки | вид, автор (человек/агент), обоснование, доказательства, вердикт гейта PASS/WARN/BLOCK | «Открыть предмет заявки», «Аппрув» (заглушка), «Отклонить с причиной» |
| Карточка задачи | прогон, узел, срок, кто ждёт | открывает `/tasks/$id` |
| Тосты | только события, требующие человека; прогресс прогонов — не тост, а индикатор | `⌘.` — закрыть все |
| Фильтр | всё / заявки / задачи / только блокирующие | search-параметр |

- **Состояния:** *пусто* — «разобрано», с подсказкой, что сюда попадает; *загрузка* — 3 скелета карточек; *ошибка* — карточка остаётся, действие помечено «не отправлено», повтор вручную; *деградация* — нет свежих событий: «список может быть неполным»; *нет прав* — заявка видна только для чтения, кнопка аппрува заменена на «нет прав на выпуск».
- **Операции:** `version_status`, `registry_propose` (чтение статуса заявки), `component_propose_to_library`, `journal_read`, `journal_append` (причина отклонения), `studio_open`.
- **Мок-данные:** 3 заявки (версия с вердиктом WARN, тип pending, компонент в общую библиотеку), 2 human-задачи (одна просрочена), 1 отклонённая заявка в истории; пустой вариант фикстуры обязателен.
- **Что проверяем:** один ли это список или два разных (аппрувы и задачи различаются срочностью); нужен ли аппрув из тоста без открытия предмета.

### Первый запуск — P0

- **Зачем:** у воркспейса нет ничего, и именно здесь решается, поймёт ли человек за минуту, что этот инструмент — про цикл «бриф → спека → прогон → проверка», а не про рисование квадратиков.
- **Сценарии:**
  1. Пустой воркспейс → три двери одним рядом: **с брифа** (`brief_submit`), **из архетипа** (`catalog_list kind=archetype` → `flow_create`), **импорт** спеки или бандла (`flow_import`).
  2. Выбрал архетип → карточка с типовыми сбоями и оценкой стоимости → создание → сразу канвас с невалидной спекой и списком проблем (это и есть обучение: инструмент учит на ошибках компилятора).
  3. Четвёртая дверь ниже — **подключить Claude**: готовая строка конфигурации MCP-сервера `volt` с копированием, чтобы второй «пользователь» появился на первом же экране.
- **Ключевые элементы:**

| Элемент | Что показывает | Взаимодействие |
|---|---|---|
| Три двери | название, одна строка «что получишь», ожидаемое время | Enter/клик, `1/2/3` |
| Список архетипов | 5–7 карточек: узлы, стоимость, типовые сбои | превью графа в карточке |
| Блок MCP | команда подключения и имя сервера | копирование в буфер |
| Строка «что дальше» | 14 этапов свёрнуты в 4 шага с отметкой текущего | только чтение |

- **Состояния:** *пусто* — это и есть основное состояние экрана; *загрузка* — скелеты карточек архетипов; *ошибка* — каталог недоступен: остаются «с брифа» и «импорт», архетипы заменены сообщением; *деградация* — каталог из кэша с пометкой даты; *нет прав* — только «импорт» и просмотр.
- **Операции:** `catalog_list`, `catalog_get`, `flow_create`, `flow_import`, `brief_submit`, `help_contract`.
- **Мок-данные:** 6 архетипов с разной стоимостью и числом узлов, один — с длинным списком типовых сбоев (проверка переполнения карточки); бриф-заглушка, дающая 3 `gaps[]`; бандл для импорта, дающий 2 `problems[]` (импорт не бывает чистым).
- **Что проверяем:** выбирает ли эксперт архетип или сразу импорт; читается ли «14 этапов» как понятный путь, будучи свёрнутым в 4 шага.

## Чего на этих экранах НЕ будет в прототипе

| Отложено | Почему | Когда вернём |
|---|---|---|
| Мультиворкспейс и переключатель организаций | v1 — один инженер, один воркспейс; `$ws` в маршруте есть, селектора нет | при первом втором пользователе |
| Реальные роли и права | нет бэкенда авторизации; в UI только разметка «нет прав» на заглушках | фаза 1, вместе с гейтом аппрувов |
| Серверный полнотекстовый поиск | нужна индексация; в прототипе поиск клиентский по загруженным фикстурам | когда появится `search` в контракте |
| Мобильная и планшетная раскладка | инструмент клавиатурный, минимум 1280px | не планируется |
| Кастомизация хоткеев | сначала надо узнать, какие вообще нужны | после замеров на прототипе |

## Открытые вопросы к заказчику

1. **Нет операции списка.** В реестре 57 тулов нет `flow_list` / `run_list` / `dataset_list` / `proposal_list`: `catalog_list` перечисляет каталог (архетипы, типы, профили, тулы, паттерны), но не объекты воркспейса. Экраны `/workflows`, `/runs` и «Входящие» без них не строятся ни для UI, ни для агента. Вопрос: добавляем ли `*_list` в контракт или UI ходит мимо MCP в REST — и тогда правило «UI вызывает те же операции, что агент» перестаёт быть верным.
2. **Глобальный поиск** — отдельная операция (`search` по спекам, прогонам, журналу, датасетам) или только переход по id и клиентская фильтрация? От ответа зависит, остаётся ли палитра главным способом навигации.
3. **Бюджет** — где источник правды? `run_get` даёт стоимость прогона, операции уровня воркспейса («потрачено за период», «лимит») нет. Без неё канал бюджета в индикаторе — фикция.
4. **Human-задачи** — маршрут `/tasks/$taskId` в §1.2 есть, операций `task_list` / `task_submit` в контракте нет. Задача человеку — это MCP-операция или только REST вне контракта?
5. **Перехват advisory-lock человеком** — `flow_lock` описан как «мягкая блокировка, перехватываемая человеком», но операции перехвата нет. Это `flow_lock` с `release: true` от другого держателя или отдельная операция?
6. **Фаза (`mode_set`)** — человек переключает её из UI или только видит? Влияет на то, есть ли команда смены фазы в палитре.
7. **`studio_open` с `elicit`** — UI должен показать модальное подтверждение, блокирующее экран, или достаточно карточки во «Входящих»? Первое ломает работу, второе может быть слишком тихо для побочных эффектов.

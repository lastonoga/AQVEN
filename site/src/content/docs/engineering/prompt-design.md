---
title: Prompt Design
description: Give a model the task, evidence, constraints, and output meaning it needs without hiding workflow logic in prose.
---

Keep the prompt focused on the decision the inference owns. Bind evidence through declared inputs, put stable role guidance in agent instructions, and put structured response meaning in the output type. Preview the complete rendered request before a live run.

Use examples for ambiguous categories or output conventions that a schema cannot express. State what the model should do when evidence is missing, conflicting, or insufficient. Keep provider-specific observations in [Field Notes](/engineering/field-notes/) and verify them on dataset cases.

Use fragments and variants for reusable or controlled alternate text. [Prompts](/engineering/prompts/) covers rendering; [Prompt Variants and Fragments](/engineering/prompt-variants/) covers composition.
